# dsh-client-ui-settings-plugins

[English](README.md) | 中文

侧栏「插件」页上的官方**配置项**：本包拥有的每个宿主平面 settings 命名空间对应一个 `plugins.item` 条目。条目卡片位于该页的「插件配置」分组，带一行摘要；打开后在条目自己的页面上展示该插件的设置表单——绑定到该命名空间的手写控件，每个字段标注用户是否覆盖过它，并提供重置回部署组装值的入口。安装、移除与启用位于同一页面的其他分组，因此「插件」页是这两件事的唯一用户入口。

## 概述

使用侧栏的**插件**页查看并管理本部署随附的插件；使用其「插件配置」分组配置开放了设置的宿主平面插件。每个配置页标明用户覆盖过哪些值，允许把它们重置为部署默认值，在本地保留修改直到保存，离开页面即丢弃。如果配置在页面加载后发生变化，保存会被拒绝，而不会覆盖较新的值。

<a id="what-appears-here"></a>
## 这里会出现什么

「插件」页的「插件配置」分组渲染两份账本的交集：已组装客户端注册的 `plugins.item` 条目，以及 Host 服务的 settings 命名空间。被服务却无条目认领的命名空间什么都不渲染——它归别的界面所有，或本部署没有为它提供浏览器半侧；命名空间未被本部署服务的条目会被过滤，因此未组装的插件不留空壳。卡片按注册顺序出现；对同一个包一起安装的条目这是稳定的，对跨插件的条目则不稳定：包与包之间的 apply 顺序是无约束的。

条目覆盖 shell 执行器（`shell`）、工具调用并行度（`agent-loop`）、委派深度与容量（`subagent`）、精确模型路由（`subagent-model-selection`）以及 DeepSeek 搜索提供方（`web-search-deepseek`）。委派控件保留上游整数校验、重置和帮助说明。深度为零会禁用继承该设置的委派工具；工具显式设置的深度优先。容量统计同一根 Agent 下所有深度的存活后代，不计根 Agent 本身。

处于项目作用域时，这些页面只会开放 Host 注册时同时声明 `owner: project` 与 `projectWrite: manager` 的 namespace。项目 owner 和组织管理员可以保存共享运行时值；其他成员仍能看到表单和行内所有者说明，但不会发出写入请求。账户、组织、部署和模型 Provider 设置继续由各自的所属界面管理。

模型选择表单默认关闭，将实时目录与仍可移除的已保存路由合并，并按草稿 revision 原子保存开关和允许清单。revision 改变后必须放弃陈旧草稿；目录失败保留选择，重连清除目标专属草稿。设置只影响新建会话，不会授予运行时模型治理之外的权限。

<a id="extension-point"></a>
## 扩展点

本包为它拥有的每个命名空间注册一个 `plugins.item` 条目，以表单所编辑的 settings 命名空间为键。该 slot 归 ui-plugin-manager 所有——它在卡片上向条目请求 `view: 'summary'`、在条目自己的页面上请求 `view: 'page'`。带浏览器半侧的插件在自己的命名空间上注册自己的条目，并拥有它的全部：控件、文案，以及页面标题之下的外观。以命名空间为键，正是在本仓库之外分发的插件能出现在这里的原因——它在 Host 上注册命名空间、在浏览器里注册条目，由分组把两者配对，而无需知道命名空间意味着什么。

<a id="writes"></a>
## 写入

表单暂存用户输入，只有用户保存时才写入。每个控件渲染的都是暂存文本，因此屏幕上所见即保存后所存；**放弃修改**丢弃这些草稿。重置暂存的是组装默认值而非立即写入；字段不接受的草稿会阻塞保存，而不是被丢弃。

保存时，每个暂存字段都通过客户端 settings scope 写入，该 scope 用读取时的命名空间 revision 约束每次写入。拒绝、失去写权限或传输失败会停止剩余写入，并保留尚未确认的草稿。已接受字段只清除本次保存提交的草稿；请求进行期间的新编辑仍标为未保存。多字段保存可能部分成功，不声称能够事务回滚。

密钥也可能从别的表层写入——模型页寻址的是同一个引用——而那不改变任何 settings 分节，因此表单会在转发来的 `credentials/reference-updated` 事件报告它所关注的引用时重读。

字段是否被覆盖，取决于它是否出现在原始用户层中，而非取决于它的值；重置会清除该字段，使其重新继承组装层。secret 角色的字段绝不搭乘响应，因此密钥控件初始为空、只报告是否已配置，并经由 credentials 领域而非 settings 分节写入；空草稿不写入任何东西，保留已存密钥。替换必须取得本次写入的成功响应，旧密钥仍然存在不能证明替换成功。即使引用未变，凭据读取也会拒绝已被后续请求取代的响应。

<a id="invariants"></a>
## 不变量

**运行时不变量：** 未发布配套入口。插件配置值位于 Host 插件 settings namespace 中；该包贡献条目注册与基于该远程文档的逐字段绑定。

<a id="model-experience"></a>
## 模型体验

无。该包是浏览器端设置界面，不注册任何面向模型的接口。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓事项

- **只有宿主平面的插件会出现**——由 agent preset 挂载的插件把配置内联在该 preset 的 `agent.cordis.yml` 中，且根本无法注册 settings 命名空间（同一 preset 挂载第二个会话时会因重复注册而失败），因此「插件配置」分组不会列出它。编辑那些值仍是 preset 编辑器的职责。
- **条目仍然需要一份浏览器 bundle**——浏览器半侧必须是按客户端模块系统的 lazy-CJS factory 格式构建的 `dsh.client` 包，而产出它的 `clientBundle` 预设位于 `packages/client/tsdown.client.ts`，并非已发布的包，因此本仓库之外的插件得自行复刻该构建。bundle 纯净度门禁同时禁止以值的形式导入本包的表单外观与模型，所以这样的条目要自行拥有暂存与 revision 设栅。
- **被服务的命名空间只在两种信号上重读**——协议通告的是 settings 文档提交与连接重置，而非注册行为，因此在分组读取之后才被其拥有方注册的命名空间，要等下一次文档提交或重连才会加入列表。
- **shell 条目跟随被组装的执行器**——POSIX 与 PowerShell 两个执行器家族共用 `bash` 命名空间，因为一个宿主只组装其中之一，所以被服务的 schema 随平台不同（PowerShell 多出 `pwshPath`），尽管表单在两者下编辑的都是同样两个字段；而两者都不组装的部署不会显示这个条目。
