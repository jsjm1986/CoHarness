# @deepseek-ai/dsh-userdoc-local

[English](README.md) | 中文

`userDocs` 的本地后端：把文档存成一个配置根目录下的普通文件，默认根目录为 `<home>/documents`。默认部署会在第一次存储操作时迁移同级 `<home>/uploads`：如果 `documents` 不存在就直接替换；如果已存在则合并，绝不覆盖已有文件，冲突项使用与上传相同的 ` (2)` 后缀。自定义根目录只有显式配置 `legacyUploadRoot` 时才迁移旧目录。

迁移使用共享的[写入锁](../../util/atomic-write/README.zh.md)，位于同级 `.<根目录名>-migration.lock`。只有完整记录且进程已被证明退出的锁才会回收。争用在两秒后以 `DOCUMENT_MIGRATION_FAILED` 超时；引擎允许后续重新初始化。不完整记录（包括中断后遗留、没有结尾换行的旧 PID 记录）必须经过运维人员核实才能删除。

写入分两步。`resolveTarget` 验证目标目录并净化不受信任的客户端文件名——手动剥除两种分隔符、移除控制字符、按字节截断到 255、拒绝纯点名称——再挑选第一个空闲叶名，冲突时在扩展名之前加 ` (2)` 后缀，超过一千次冲突则以 `DOCUMENT_NAME_EXHAUSTED` 失败。`save` 写入以 `O_CREAT | O_EXCL` 打开的同级 `.part` 文件，边接收边计数，fsync 后通过排他硬链接发布，因此绝不替换已占用目标。默认配置不限制单个文档的字节数；显式设置 `maxFileBytes` 仍会执行有限的部署策略。取消也会取消正在等待的流读取，并在释放 reader 前等待取消完成。写入失败只清理自己创建的临时文件；排他创建未成功时会保留占用该路径的文件。清理失败会保留错误原因，并可能留下自有临时文件以便恢复。Linux 上的普通保存从创建暂存文件起，到发布或清理完成为止，始终保留父目录描述符，因此父目录替换不能把这些文件操作重定向到替换后的目录。

只有匹配 `.userdoc-<24 个十六进制字符>.part` 的提供方暂存文件名会被隐藏。`archive.part` 等已完成的普通文件仍可列出和读取。上传名称若匹配暂存命名空间，会使用正常的 ` (2)` 后缀。新解析的文件和文件夹名称去掉末尾 ASCII 句点及空格，UTF-8 截断后也执行此规则，使存储名称在 Windows 上保持可用。

公开文件和目录选择条件对根级维护名称的大小写及 Windows 后缀别名一并保留。目录对象检查还拒绝其他拼写的别名，包括文件系统短名称。公开读取和扫描要求文档根目录是真实目录，并拒绝链接路径组件。只有内部分块上传最终确认会使用经过校验的私有临时路径。

读取接受 store 作用域内的 `docId`——即以正斜杠表示的根相对路径——而不接受调用方持有的 `UserDocRef.path` 副本。每次读取都会重新推导路径，并同时证明词法路径和真实路径都位于根目录内，因此目录遍历和指向根外的目录符号链接都会被拒绝。`list` 递归返回所有普通文档；`listDirectory` 返回直接子文件夹与文件；`listDirectoryPage` 与 `listTrashPage` 提供有界筛选分页；`listDirectories` 枚举移动目标。创建和重命名文件夹只接受一个净化后的叶名，删除要求目标为空且不是根目录，`move` 绝不替换已有目标。`openRead` 流式下载，`remove` 将文件本已不存在视为成功。`trash`、`restore` 与 `purge` 通过私有清单和隐藏文件移动文档，`trashRetentionDays`（默认 30 天）控制自动过期；恢复时会重建已被删除的原目录，名称仍遵循普通的不覆盖目标策略。

默认独立提供方使用按路径寻址的回收站清单，并以 `DOCUMENT_TRASH_CONFLICT` 拒绝复用路径上的第二次回收操作。Gateway 通过显式私有存储位置选择身份引擎。该引擎保留独立的发布实例和回收操作 id，允许同一地址保留多个版本，并在变更前核对授权的精确修订号。恢复会选择可用名称，不会消耗其他保留版本。

身份模式的一次性保存会在暂存、等待根锁和准备运行时文件权限之后、物理发布开始之前检查调用方取消。拒绝发布时清理其暂存字节。身份模式的缓冲读取在源取消完成后拒绝中断操作，并同时保留独立的读取与取消失败原因。

回收站清单在列出或修改前必须整体通过校验。未知版本、无效或重复记录、不安全路径，以及仍有隐藏文件时缺失的清单，均以 `DOCUMENT_TRASH_NOT_FOUND` 失败；记录不会被静默丢弃或替换。应保留隐藏文件并恢复完整的清单备份后重试。只有没有隐藏文档文件时，缺失清单才表示空回收站。

恢复通过排他硬链接发布文件。如果其他写入方在发布前占用了选定名称，恢复会以 `DOCUMENT_RESTORE_CONFLICT` 失败并保留原回收站记录；重试会重新选择空闲名称。发布后若失败，会先恢复隐藏链接，再移除可见副本；若回滚也失败，则保留两个原因和剩余副本以便恢复。Linux 在发布与回滚期间保留私有源与公开目标的父目录。重建缺失的目标目录时也会保留其父目录；检测到替换时移除本次创建的空目录，并保留回收站记录。

文件移动回滚也会先恢复源，再移除目标。若恢复失败，`DOCUMENT_MOVE_FAILED` 会保留两个原因，目标副本仍可用于恢复；占用源位置的新文件保持不变。

目录改名使用操作系统的排他移动，即使目标在选定后被新建为空目录，也会保留该目录。Linux 和 macOS 相对于保留的上级描述符逐层打开父目录，并相对于这些描述符改名；Windows 通过不共享删除权限的句柄阻止父目录替换。Linux x64 和 arm64 直接调用内核的排他重命名，包括 musl 未提供 `renameat2` 包装函数的环境。检测到父目录变化时拒绝确认。原生改名已完成时，管理模式的恢复会保留标记和日志，在提交元数据前重试目录同步，并保留无法明确判定的副本。不支持排他移动的平台或文件系统会拒绝操作，不会回退到覆盖式改名。

Linux 上移入回收站会在移动与回滚期间保留两边的父目录描述符。清单提交失败时，通过排他硬链接恢复源；若源位置被替换文件占用，则同时保留该替换文件和隐藏的原文件，并在错误中保留两个失败原因。

保留期清理会在清单写入锁内重新检查每个候选项当前的隐藏文件标识和截止时间。已恢复、替换或续期的记录会跳过；计数只包括已提交的清理。写入锁会在候选项之间释放。

Linux 上的永久删除和保留期清理会在获取锁、移除载荷、替换元数据和释放锁期间保留清单目录。目录替换会拒绝确认，不会通过替换后的目录删除或写入。恢复原控制目录后，可以重试并完成对已被本次清理移除的载荷的元数据处理。

相同的在途列表请求会共享一次文件系统扫描；单个调用方的取消只影响自己，只有最后一个等待方离开时才会停止底层扫描。

导出的 `LocalUserDocFs` 引擎承载同一套文件系统操作但不依赖 Cordis `Context`，使非运行时宿主——Gateway 的本地文档 broker——能对授权作用域根提供完全相同的行为。

引擎接受公开树之外的可选 `controlRoot`，用于保存上传清单及私有文件数据。它必须是位于文档文件系统、互不包含的真实目录，其私有父目录由提供方持有。Gateway 管理的身份模式还提供私有 `stateRoot`，存放 SQLite 元数据与变更锁。Gateway 在写入前登记三个根，只授予运行时账号访问普通已发布文件的权限。独立模式在公开根下保留隐藏控制目录。

宿主可提供 `backgroundWrite`，为初始化、读取触发的身份变更、中断操作恢复、投递确认、上传最终确认和清理申请写入资格。准入会保留写入计数直到持久工作完成。拒绝准入时保留身份日志和可续传上传。维护期间，未变化文档的已初始化读取仍可使用；需要持久化的观察会被拒绝，直到重新开放准入。显式变更请求还需要调用方持有自己的写入计数。

引擎关闭时停止接收新操作，取消普通保存、分块请求体读取和扫描，并在停止上传最终确认任务前等待所有已接收操作结束。重复关闭会等待同一任务。`openRead` 返回的流交由调用方所有，调用方必须读取完或取消；引擎关闭不会关闭该独立下载。操作与文件关闭若分别失败，错误原因会同时保留两者。

`mediaType` 由存储文件的扩展名推导。文本、Markdown、CSV、JSON、YAML、XML、常见源代码、图片、PDF 和 Office 扩展名会得到对应的展示类型；无法识别的扩展名记为 `application/octet-stream`。它只是展示用的元数据：这里既不解析内容，也不拒绝未知格式。

受管目录改名先把所选目录移入同文件系统的私有存储，核验目录对象和完整的已授权文件清单，再记录捕获状态并排他发布目标。源目录被替换时，提供方排他恢复该替代目录并拒绝操作。源位置被占用会阻止回滚；私有字节、日志及两个错误都会保留。恢复会重试命名空间同步并保留结果不确定的副本。被普通编辑器移走的已结束标记，只能凭保留的私有锚点回收，读取和扫描也遵循该规则。已经打开的可写文件仍可在改名期间被编辑；私有捕获不会撤销既有文件描述符。

已发布目录的恢复核验记录的目录对象，并完成已接纳的路径变更；普通原子保存、新增、删除及子文件移动在观察时独立对账。替代文件获得新的、未归属的文档实例，原创建者及改名发起人仍保留在各自原有记录上。缺少目录对象证据的旧意图继续核验完整文件清单。

外部文件移动在完整根目录清单上对账，然后才结束缺失身份。保留对象的唯一匹配即使遇到原名称被复用，也保留实例及创建者；地址互换的元数据和投递记录一同提交。额外或有歧义的硬链接不会获得另一地址的创建者。单文件及目录读取遇到未知或被替换的对象时会对账整个根。已观察对象发生变化时，扫描会拒绝并保留身份依据，供后续重试。

私有 SQLite 第 4 版在可写打开时，先验证原存储绑定，再迁移第 2、3 版。备份验证只读检查这些版本，不修改原库字节；恢复在验证所有保留版本后才执行迁移。目录捕获保留其[恢复规则](../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/document-directory-capture/guide.zh.md)。在 macOS 上，保留描述符为文档、保留对象及元数据绑定提供持久文件系统 UUID。UUID 与目录 inode 不变时，可在记录、待完成变更及投递数据中归一化重新挂载后的设备号，保留逻辑 id、修订、发起人及游标位置。进程内路径校验继续使用当前设备号与 inode；复制的根及变化的 UUID 仍被拒绝。没有持久 UUID 的主机保留严格的设备号与 inode 校验。

旧绑定仅在原设备号与 inode 证据仍一致时补充 UUID。离线 `recoverDocumentIdentityMount` 要求重新挂载前已独立验证的备份、原目录／数据库／文件 inode，以及匹配的保留文档版本和摘要；它保留后续永久删除历史及未完成上传。已变化或未被证据覆盖的当前版本要求完整的兼容恢复。恢复失败及其验证重试期间，须持续停止所有写入方并保持作用域不可用。见[卷身份升级指南](../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/document-volume-identity/guide.zh.md)。

身份引擎在 Linux 上读取证据、捕获、发布和移除时保留父目录描述符。受管备份验证要求完整文件摘要和原始内核对象证据。恢复会保留逻辑 id、创建者与投递位置，重建文档与目录标记的保留硬链接，并重新绑定目录及文件对象；普通文件复制不能授权这种重新绑定。证据不一致时拒绝恢复，部署维护继续保持关闭。参见[身份设计](../../../.agents/notes/proposed/architecture/2026-10-25-document-incarnations-and-trash-actions.zh.md)。

## 概述

使用 `dsh-userdoc-local` 作为本地 `userDocs` 后端，把文档以普通文件存放在一个可配置根目录下。上传先写入同级 `.part` 文件再经排他硬链接原子发布，被占用的目标永不被替换；不可信的客户端名称会被清洗，重名获得 ` (2)` 后缀。默认部署首次使用时迁移旧的 `uploads` 树；显式 `maxFileBytes` 提供有界部署策略。

## 可续传上传

本地后端实现 Web 客户端使用的 `resumable-v1` 上传会话。它一次只接收一个请求大小的分片，使用 SHA-256 校验每个分片，把私有 manifest 和部分文件保存到 `.upload-sessions/v1/`，并在完整 SHA-256 校验通过后才发布最终文件。会话可在运行时重启后继续，并按配置的默认 24 小时保留；过期的接收中会话与终态记录会自动清理。默认分片大小为 8 MiB，低于公网 Cloudflare 请求体限制；所有上传安全参数都可以通过后端配置调整。

未完成的身份绑定会话使用必须包含所有者的第 2 版 manifest；第 1 版仍然没有所有者。携带 `UserDocRef.identity` 的已完成发布使用第 3 版，在状态查询和重启后保留该元数据。第 3 版必须包含完成状态的引用，且已接收字节数必须匹配；存在原始所有者时继续保留。目录布局和公开的 `resumable-v1` 协议保持不变。存储先校验所有者，再执行过期清理或取消最终化任务。指纹复用要求身份相同，准入为活动上传预留不同名称，同时保留整个根目录共用的并发和磁盘预算。取消、失败或过期的会话会释放名称预留。

已认证的组合不能认领无身份会话。临时文件仍按正常保留策略清理；使用新指纹重新上传，容量已满时等待旧预留过期。旧后端拒绝第 2 或第 3 版 manifest。升级和恢复规则见[文档上传指南](../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/document-upload-actors/guide.zh.md)。

已接受的 `verifying` 工作保留其字节、目标名称预留和并发名额，直到完成、失败或经认证的取消，不受接收阶段期限或清理进程影响。状态查询和指纹续传保持可用，进程停止后启动会恢复保留的校验工作。清理只删除有效清单能够证明已过期的接收中或终态会话。未知、损坏或超出大小上限的清单会使清理失败，但保留清单及部分字节；缺少清单时也保留部分字节。恢复需要兼容的读取器或原始清单备份。全部清理任务结束后才释放写入准入，独立的错误会一并保留。

只有普通文件能作为文档打开。目录、链接和 POSIX 命名管道会被拒绝。POSIX 读取会以非阻塞方式取得描述符并重新检查类型，因此在打开期间把普通文件替换成管道，不会让操作一直等待另一端。

普通保存和可续传分片都会重试部分完成的文件系统写入，直到全部字节落盘。零进度或中断的写入会失败，不会发布文件或确认未完成的分片；续传重试会覆盖尚未确认的前缀。取消操作保留原始原因。

`uploadManifestMaxBytes` 限制每次读取的 manifest 大小（默认 256 KiB）。`uploadMaxConcurrent` 同时限制过期会话清理和最终化 worker 数量；存储停止或取消上传时，排队中的最终化任务会被取消。`uploadCleanupIntervalMs` 限制为 Node 的最大计时器延迟（`2,147,483,647` 毫秒），无效间隔不会被钳制成高频的一毫秒循环。

后端将准入锁所有者的 PID 记录在 `.admission.lock` 中。只有进程探测证明所有者已经退出，启动过程才会恢复该锁。并发恢复者使用独立的恢复锁，并在移除孤儿锁前重新读取所有权，以保留后继写者的锁。存活、格式错误或结果不确定的所有者不会被回收。恢复操作中断后留下的协调锁需要操作员核验；普通上传竞争仍使用 30 秒期限。

## 模型体验

经由宿主提示词组装消费方间接产生影响；已存文件的一切模型可见渲染决策均由该消费方负责。

#### KV Cache 影响

无直接失效；消费方负责请求前缀的任何变化。

## 已知限制与待完成工作

<a id="known-limitations-and-deferred-work"></a>

- 设置 `DSH_MANAGED_DATA_MANIFEST` 的受管启动会在写入数据前登记实际解析后的文档根及可选的旧上传根。清单无效时拒绝初始化；保留旧根和部署批准遵循[清单与备份规则](../../util/managed-data/README.zh.md)。
- **没有业务存储配额** — 默认不限制单个文档或用户总字节数，但后端仍通过可配置的最低剩余空间、并发会话数和未完成会话清理保护主机。
- **已完成文档的保留策略是显式的** — 活动文档会一直存在到删除；移入回收站的文档只在 `trashRetentionDays` 内可恢复，之后由提供方清理。包括完成状态元数据在内的会话记录是临时的，按配置的上传保留期清理。
- **`list` 每次调用都遍历整棵目录树** — 没有索引，因此存有数千个文件的根目录每次列举都要付一次完整扫描的代价。
- **只能删除空文件夹** — 删除目录树前必须先移动或删除其中内容；本包不提供递归删除操作。
