# @deepseek-ai/dsh-userdoc-local

[English](README.md) | 中文

`userDocs` 的本地后端：把文档存成一个配置根目录下的普通文件，默认根目录为 `<home>/documents`。默认部署会在第一次存储操作时迁移同级 `<home>/uploads`：如果 `documents` 不存在就直接替换；如果已存在则合并，绝不覆盖已有文件，冲突项使用与上传相同的 ` (2)` 后缀。自定义根目录只有显式配置 `legacyUploadRoot` 时才迁移旧目录。

写入分两步。`resolveTarget` 验证目标目录并净化不受信任的客户端文件名——手动剥除两种分隔符、移除控制字符、按字节截断到 255、拒绝纯点名称——再挑选第一个空闲叶名，冲突时在扩展名之前加 ` (2)` 后缀，超过一千次冲突则以 `DOCUMENT_NAME_EXHAUSTED` 失败。`save` 写入以 `O_CREAT | O_EXCL` 打开的同级 `.part` 文件，边接收边计数，fsync 后通过排他硬链接发布，因此绝不替换已占用目标。任何失败路径都会删除部分文件。

读取接受 store 作用域内的 `docId`——即以正斜杠表示的根相对路径——而不接受调用方持有的 `UserDocRef.path` 副本。每次读取都会重新推导路径，并同时证明词法路径和真实路径都位于根目录内，因此目录遍历和指向根外的目录符号链接都会被拒绝。`list` 递归返回所有普通文档；`listDirectory` 返回直接子文件夹与文件；`listDirectories` 枚举移动目标。创建和重命名文件夹只接受一个净化后的叶名，删除要求目标为空且不是根目录，`move` 绝不替换已有目标。`openRead` 流式下载，`remove` 将文件本已不存在视为成功。

`mediaType` 由存储文件的扩展名推导，无法识别的扩展名记为 `application/octet-stream`。它只是展示用的元数据：这里既不解析内容，也不拒绝未知格式。

## 模型体验

该包通过主机的提示装配消费方间接影响模型：消费方把已存储的引用转换为内联文本，或转换为一个由 agent 用常规工具读取的路径。

#### KV 缓存影响

无；该包既不组装也不发送提供方请求。

## 已知限制与待完成工作

- **没有按用户的磁盘配额** — `maxFileBytes` 限制单次上传，`maxMessageBytes` 限制单条消息，但没有任何限制作用于一个根目录的总大小，因此多用户共享磁盘的部署需要在该包之上再加配额。
- **保留策略需手动处理** — 已存储的文档会一直存在，直到用户删除；没有过期机制或垃圾回收。
- **`list` 每次调用都遍历整棵目录树** — 没有索引，因此存有数千个文件的根目录每次列举都要付一次完整扫描的代价。
- **只能删除空文件夹** — 删除目录树前必须先移动或删除其中内容；本包不提供递归删除操作。
