# @deepseek-ai/dsh-archive-gateway

[English](README.md) | 中文

把 Gateway 启动的运行时中的 Workspace 归档状态同步到 Gateway 归档索引。提供方发送带 revision、可幂等重试的批次，其中包含已归档 ID、根会话谱系、会话头、原 Workspace 位置、消息数量以及标题／正文搜索投影；该 revision 的全部批次成功后才应用 Gateway 下发的命令。

单次同步请求最多承载 1,000 个会话 ID、5,000 条搜索记录和 4 MiB 搜索文本。索引中的每条搜索内容上限为 64 KiB；文本记录本身不会改变。跨请求拆分的根会话会收到最终聚合消息数量；同步运行期间的重复触发会合并为一次后续同步；dispose 会中止并等待活动请求结束。单次响应最多承载 1,000 个待处理命令；应用非空命令页会安排下一次同步，直到命令队列清空。

会话标题、消息数量和搜索投影使用 32 MiB 的 LRU 缓存。连续的 live `session/event` 会以 O(1) 队列工作追加到缓存 projection；序号缺口、标题事件或读取竞态只使对应会话失效并回退到完整读取。这样频繁的归档更新不会重新读取未变化的日志，同时保持 revision 一致性。缓存写入由 generation 围栏防止读取期间的事件发布旧结果；失效 token 会随会话离开或 LRU 淘汰一并删除，因此 churn 不会在有字节上限的值之外留下另一份无界名单。

归档读取器还会在进程内保留一份谱系／header 索引，只在会话拓扑变化后重建。并发读取共用同一次索引加载；事件和清理失效会阻止陈旧加载结果成为下一份缓存索引。

提供方还注册仅限 loopback 的 `/api/internal/archive/read` 路由。Gateway 签发的归档能力可以按需读取个人根会话及其子会话；该路由不接受浏览器来源请求或非管理员断言。

这是仅供运行时使用的集成。独立启动的本地 DSH 不加载该提供方，继续使用本地归档注册表。

## 模型体验

没有影响。该提供方只读取和同步已经记录的会话状态，不增加提示词、工具或模型请求字段。

#### KV Cache 影响

没有影响。它不组装模型请求，也不改变可复用前缀。

## 已知限制与延期工作

- 只有使用 Gateway 凭据启动的运行时才会同步；独立的本地组合继续使用原有归档行为。
- 所属运行时不可用或持久化日志损坏时，个人正文无法读取；Gateway 会保留归档索引行并报告正文不可用。
- 归档读取会拒绝包含超过 10,000 个子会话的谱系，或应用序号下限后保留记录超过 100,000 条、总计超过 64 MiB 的结果。`fromSeq` 是分别应用于每个子会话的包含式序号下限，不是全局时间顺序游标。
- 运行时提供的个人详情也必须符合相同的子会话、事件页和字节上限；替换结果无效或超限时，会保留索引详情并将 `syncState` 设为 `unavailable`。
