## 8-f — LAN/公网真实双用户验收

**台账行：** L8、L9（部分）、解除发布冻结。
**状态：** `open` · **执行人：** 发布执行人 + 两台独立机器上的两名用户。

### 前置条件

- 从 tarball 安装打包后的发布候选（`pnpm run release:pack` 产物），不是源码检出。
- 两名用户可达的共享 Gateway 部署，或同一 LAN 上各自独立运行会话的两台机器。
- 每个参与者的主机都有 `DEEPSEEK_API_KEY`。

### 步骤

1. 用户 A 安装打包产物，启动 web 客户端，创建会话，发送提示词，跑完一个带工具的轮次（文件读取 + shell 命令）到完成。
2. 用户 B 对同一部署（或共享项目运行时）重复步骤 1，并在同一 Workspace 中再开一个会话。
3. 双方分别演练：客户端刷新后会话恢复、会话中切换模型、一次权限提示、文档/附件插入路径。
4. 可选 Gateway 路径：共享一个项目会话；确认另一用户侧能看到参与者归属标注。

### 通过判据

- 无崩溃、无卡死轮次、无无可读诊断的错误；双方会话都能持久化并正确恢复。
- 工具调用渲染结果；权限提示经 UI 解决；Workspace 状态在刷新后存活。

## L9 — 生产一致备份 / 恢复演练

**台账行：** L9（余量——迁移演练与发布闭包已绿）。
**状态：** `open` · **执行人：** 持生产级数据的发布执行人。

### 步骤

1. 对生产形态的数据根（session JSONL + SQLite 存储 + settings）做一致备份——按部署程序在写入飞行中或静默后执行。
2. 恢复到干净主机；以打包产物指向恢复后的数据根运行。
3. 核验：会话列表与恢复、事件计数与备份清单一致、SQLite `SCHEMA_VERSION` 单调性保持、无代次文件丢失（不可变代次规则）。

### 通过判据

- 恢复后的运行时服务同一会话集且持久数据一致；无格式降级或重新生成。
