## 部署与采纳原则

产品面向中小企业内部团队，部署主机可以具备 GUI，成员通过局域网或公网隧道访问同一工作台。自动化在部署主机执行，不控制访问者的电脑。Linux、macOS 和其他平台的实际能力分别核验，不能从操作系统名称推断是否存在可用桌面。

以上游新版实现为首选，重放仍有必要的本地差量；二开功能允许重构和由上游等价物替代，但必须先证明功能、授权和数据语义不丢失。能力引入、默认启用和生产验收分别记录。内部 API 可整体迁移，已发布数据遵守 [Session 格式规则](../../packages/session/session-format/README.md)。

入站隧道、浏览器出站请求、模型请求、外部日志上传分别配置。LAN 与公网使用相同身份和权限检查。第三方驱动或 MCP 子进程的监听地址、凭据、下载行为须检查；源码未搜索到 listen 不是无网络暴露的证据。

## 已批准的产品决定

| 能力 | 决定 | 放行前提 |
| --- | --- | --- |
| Session 日志上传 | 默认关闭，保留显式启用、端点限制和紧急关闭 | 独立核验完整会话的外发，不与 OTel 开关混淆 |
| Messages 协议 | 引入，不自动改写存量 BYOK 和组织代理端点 | 两种协议都经过模型治理、配额和真实凭据来源归因 |
| browser-use | 提供可用入口，默认独立启动，不附着宿主日常浏览器 | Session 资源清理、专属配置档、截图权限、模型路由和依赖检查 |
| computer-use | 正式纳入升级，个人授权后可用；共享项目默认未授权，管理员可开启 | 主机桌面调度、系统权限、驱动就绪及强制执行检查 |
| auto-review | 提供实验入口，不自动选中；管理员授权后由用户在当前会话选择 | 不扩大组织或项目权限；审查调用计费，原生及 PTC 内层调用均覆盖 |
| SSH 与终端 | 引入并贯穿项目和用户授权，不默认授予远程主机访问 | 凭据引用、会话范围、取消和进程清理验收 |
| 上游删除的包 | 消费者迁移并证明能力等价后才能删除 | E2B 部署依赖未核验前不删除；无法等价替换则保留适配 |

上游 auto-review 是模型审查工具调用后以 Full access 执行的实验性权限模式，不是普通代码审查。无桌面能力的节点应保持其他功能可用；显式启用但配置错误时报告错误，不显示虚假的可用状态。

## 桌面占用与团队交互

拟按执行节点与交互桌面标识统一调度，个人、共享项目、子 Agent 和 PTC 使用同一准入规则。上游 provider 注册排他不提供跨运行时桌面独占；具体协调服务、存储与认证实现尚未完成。租约不能复用为人工审批记录。

| 状态 | UI 文案 | 用户操作 |
| --- | --- | --- |
| 空闲且有权限 | 桌面空闲 | 申请使用 |
| 自己持有 | 你正在使用 | 查看任务、停止并释放 |
| 他人持有 | 桌面使用中 | 申请排队 |
| 已排队 | 等待中，前方 N 项 | 取消排队 |
| 停止中 | 正在停止操作 | 等待确认停止 |
| 不可用 | 显示驱动、权限或桌面原因 | 查看诊断 |
| 断线或未同步 | 状态待确认 | 重连，不可假定空闲 |
| 无授权 | 未获授权 | 不提供申请操作 |

使用桌面图标和文字，自己占用时可有轻微呼吸动画；遵循减少动画设置及无障碍播报。默认不公开他人的会话标题、截图或任务正文。拟通过现有 `shell.overlay` 扩展点展示，并在调用入口提供一致提示；连接状态不代替桌面状态。

占用覆盖一段连续任务，不按单次点击交错发放。默认 FIFO、重复申请去重、不自动抢占；时限和队列容量是经过验证的部署配置。状态查询、申请、取消与强制停止均需授权；客户端不能自行指定可信租约持有人。

执行端核验租约代次与当前权限，失效持有者不得继续提交操作。心跳丢失或超时先进入停止/待确认状态，确认旧动作结束后才释放；无法确认则标记不可用。撤权、Session 结束、运行时退出和管理员停止都收敛到同一清理流程。协调者重启不能仅清空数据库记录就重新发放桌面。

停止不撤销已经送达的输入。租约只能协调本产品调用，不能阻止本机人工操作或其他应用；建议使用专用自动化桌面，并提供管理员紧急停止。模型可见的排队、拒绝与执行结果需要写入 Session 日志，不能只存在于 UI。

## 数据迁移与回滚

先在脱敏副本盘点 Session 代次、未知必读事件、SQLite schema、PostgreSQL ledger、附件和归档引用，再确定迁移步骤。不能仅凭 upstream 版本变动就增加 Session 格式版本；仅结构变化才需要新增相邻步骤。JSONL 发布新代次，不覆写、删除或移动旧代次；数据库 migration 编号依实际 ledger 续排，不预占编号。

迁移前停止相关写入并取得一致备份；SQLite 用在线备份机制，PostgreSQL dump 要完成恢复校验，附件、运行时目录及外置加密密钥纳入同一恢复方案。迁移需验证重跑、中途终止、损坏与未来格式拒绝；记录迁移前后对象数量、引用完整性和校验摘要，不在升级记录中写入秘密。

代码切回不代表新数据可降级。新事件是否 `ignorable` 由语义决定，不为方便回滚而放宽。恢复旧产物需要配套一致数据恢复；切换后的新写入先隔离保留，明确业务损失窗口，不能悄悄丢弃。生产迁移或停机不在 Phase 0 执行。先在 staging 演练，再批准生产窗口，不能让新旧运行时同时写同一资源。

## 验证与未完成项

使用 [测试策略](../../docs/testing.md)区分定向单测、组装快照、真实 API、built artifact、平台及生产验证。局部修改先跑相关检查；全量 coverage 和平台矩阵由必需 CI 承担，vendor 同步遵守其全量 test/build 特殊要求。无 API Key、GUI 权限或生产备份时明确记录未验证，不把 skip 当通过。

Phase 0 尚不证明任何运行时能力实现完成。包级库存可由 Git 树完整枚举，但逐文件语义审查、逐提交归属、E2B 替代方案、vendor js-yaml 差量、发布 families、生产数据规模和各平台驱动仍需逐项完成。上次升级的未验证项也必须显式承接，不能因更换目标 tag 清空。
