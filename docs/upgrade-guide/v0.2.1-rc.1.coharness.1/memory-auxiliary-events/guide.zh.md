# 记忆辅助请求保留精确输入

[English](guide.md) | 中文

## 变更

召回在模型发送前写入 `memory/recall-request`。提取或整理的每个轮次写入 `memory/curation-request`，携带遍类型、轮次和完整已解析请求。这些读取时必须理解的事件使用 Session 格式版本 7；不认识它们的构建会拒绝包含它们的日志。它们不进入主对话。召回还会在 Session 销毁时取消，插件卸载会等待未完成选择器结束清理。

实时记忆设置会取消对应的在途提取或整理操作，包括排队模型准入和游标写入。已撤回的操作不再发送后续轮次或提交完成进度。关闭其中一种操作不改变另一开关，并等待清理完成后再运行另一操作；已经准入的耐久写入保留其结果。

## 迁移

启用召回、提取或整理前，一并升级 Session 读取器和写入器。自定义事件消费者应保留这些请求事件，并根据当前 Session 事件定义接受其请求字段。供记忆插件使用的自定义 LLM 服务实现必须实现 `prepareCall()`，并在发送前保持已解析的适配器。已有记忆域记录无需转换。

需要不同的模型输出限制时，分别在 `memory-context` 与 `memory-curation` 条目配置 `maxOutputTokens`。两者均默认 5,000，配置值必须为正安全整数；对话输出设置不会覆盖它们。

跟踪 `ctx.memory` 可用性的消费者应订阅 `memory/switches-updated` 并重新读取自己注入的服务。单靠 `settings/updated` 无法报告提供者挂载或组合配置回退。替换或移除提供者后，有效开关关闭对应操作时，排队工作会取消；配置的回退值保持不变。

project 整理保留捕获时的执行签发方，并在每次请求发送和排队游标提交时复核记忆资格。实现 `writeCursor()` 或 `writeCursorIfUnchanged()` 的自定义记忆服务必须在队列与存储等待结束后调用末尾可选的 `beforeCommit` 回调，并在持久化前再次检查取消、立即执行其返回的同步检查。回调不得在同一写链上排队写入。仅有执行权限不足以授权 project 整理；已有记忆记录与计费身份无需转换。

召回在消息准入确立问题的执行参与者和路由后启动，在发送与注入期间保留该签发方，并跟随主回合取消、丢弃失败或中止的选择器终态。只读召回独立于项目记忆写入资格，使用执行权限；应一并更新 memory-context 包及其 execution-authority 依赖。
