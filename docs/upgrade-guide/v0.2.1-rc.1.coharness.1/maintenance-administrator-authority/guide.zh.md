# 升级维护管理

[English](guide.md) | 中文

## 变化

维护管理读取、进入、退出、节点状态变更和恢复登记将已认证的当前活跃企业管理员资格保留到事务提交。浏览器传入的操作者字段不授予权限。资格撤销前已排队、但尚未准入的请求返回403。可信独立应用器显式传入 `null`，继续按部署归属执行。

进入、退出和节点状态变更与其操作记录一同提交。并发进入只产生一个维护纪元和一条进入记录。操作记录写入失败会回滚状态转换并返回503。恢复登记会检查属于本企业、已验证且完整的备份，并将其资格保留到待处理请求提交。接受请求前已撤销验证的备份返回409。已接受的请求仍由独立应用器按照既有维护与恢复检查执行。

## 迁移

1. 升级完整 Gateway。既有配置、PostgreSQL schema、操作记录和 HTTP 响应字段无需迁移。
2. 收到403后刷新账号、角色、成员资格和企业状态。收到409后检查选中的备份，选择完整且已验证的记录后再重试。
3. 验证并发进入维护窗口，以及正常管理员进入和退出流程。确认只有一条进入记录且维护纪元符合接受的状态。数据库事务被拒绝时必须保留原集群和节点状态。
4. 保留独立应用器和部署恢复访问。参见[维护参考](../../../../gateway/README.zh.md)。
