# 为 SDK 子代理进程提供准入与所有权

[English](guide.md) | 中文

## 变更

发起 Agent 的 Context 提供模型策略、资源容量、LLM 中间件和执行身份，包含隔离实现。提供方注册保留生命周期清理所有权。

安装资源准入时，`subagent-dsh-sdk` 在构造 SDK 客户端前申请进程许可。必需准入缺失、拒绝准入或排队取消时，不会启动。确认运行时进程退出后才释放许可；无法确认的清理保留不确定占用。提供方卸载和许可撤回会取消并等待待启动及已发布的子进程。单次子任务完成后自动关闭，显式释放共用同一次清理。

`reasoningEffort` 设置子运行时默认值，请求覆盖值优先。

资源完成在许可发布前保留操作，在资源准入或关闭前重试失败的确认。已证明的静止状态释放不确定占用；迟到的不确定报告不能反转它。不确定操作计入 `maxControlOperations`。完成消息标明已结束的登记尝试；连续取消可回收旧 id，不丢弃已登记的操作。

模型／进程准入按原始 id 重试未确认的模型关闭。取消与提供方撤回会等待暂停消费的适配器清理；清理、待处理准入和最终确认共用一个关闭时限。

已认证的上传在正文截止时间到期；拒绝时关闭未完成连接。HTTP 并发允许每个操作使用两个请求。

Workflow/Ralph 在启动、结果收集、资源释放与失败移交前进入 `engine.withForeground(parent, signal, operation)`。PTC 保留原 subagent 准入。撤下会取消并等待消费方。委派在子模型预检前捕获原 subagent 运行时；撤下会取消并等待元数据连接，阻止创建子级或 Job。前台子代理使用 `retainFailedCleanup(parent, run)`；工作流使用 `run.retainFailedCleanup()`。异步观察确认。原始／后台持有方保留控制权。一次性 Job 在释放等待期间收到终止请求时保留一次合并重试；再次清理失败后仍保留占用，直到另一次终止请求到达。工具撤下后记录与进度继续保留。运行时替换后，保留失败继续存在。提供方保留未发布启动的回滚。 父级退出会重试已接管清理并等待迟到移交。正在退出的父级不新增注册；未被接收的移交重试原租约。

启动在异步清理前固定资源与执行所有者。替换或撤销不能转交启动，也不能使其变成独立执行。校验先于原生启动、发布与首个任务派发。未使用的许可归还原提供方；失败回滚仍被保留。

## 迁移

绑定 SSH 的 Session 需要支持其目标的后端；本地 SDK 在进程准入前拒绝这些 Session。

1. 重建版本匹配的 `dsh-subagent`、`dsh-tool-subagent`、`dsh-workflow`、`dsh-workflow-ptc`、`dsh-tool-workflow` 与 `dsh-tool-ralph`。设置 `profile`、有序 `patches` 和绝对独立 `dshHome`。`dshBin` 选择 CLI 模块，默认使用同版本依赖。移除 `command`、`args` 和提供方级 `cwd`；请求提供目录。
2. 在确认清理前保留进程占用。不要通过私有启动绕过拒绝。归属变化后，恢复提供方并重试委派。
3. 卸载提供方依赖前完成关闭。不确定占用仍属于未完成清理，容量不可用。
4. 使用版本匹配且支持私有引导和完成登记元数据的父级与子级 CLI 构建。模型与进程容量及模型权限配置在父级；子模型调用独立申请许可，并通过父级治理 outbox 上报实际用量。子适配器和凭据仍在其 profile 配置。
5. 保持 `controlPollMs < controlRequestTimeoutMs < controlCleanupTimeoutMs`，并在 SDK EOF 宽限内完成协作关闭。验证进程与模型独立准入、父级归属用量，以及被拒绝的模型从未联系提供方。
6. 保留失败的模型与资源确认，恢复后按原始 id 重试。处理关闭失败。验证物理清理归还不确定容量，无需替代许可。
