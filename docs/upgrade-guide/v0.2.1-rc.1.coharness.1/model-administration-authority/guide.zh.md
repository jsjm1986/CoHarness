# 升级模型管理权限

[English](guide.md) | 中文

## 变更

组织 Provider、模型、凭据、访问及额度写入在事务内复核已认证管理员。降权、停用或删除的发起者不能凭早先 HTTP 检查提交。模型发现在读取公司凭据或发出草稿密钥探测前授权准备。权限拒绝返回403并记录失败尝试审计。

访问及额度写入要求未删除的账号或活跃项目。停用账号仍可配置。SQLite 将接受的数字账号额度 ID 存为规范十进制文本，因此补零 ID 在回读时作用于同一账号。组织与项目模型配置写入使用一致的组织优先锁顺序。

替换额度、恢复继承及删除账号会移除该账号的旧数字别名。SQLite 导入保留此前有效的规范额度，并通过 `skippedQuotaAliases` 报告未生效的别名。重复导入替换源库账号的额度，没有规范覆盖项时恢复继承，仅在 PostgreSQL 中存在的账号保留其额度。冻结源库保持不变。

纪要模型读取以及固定/清除写入也保留当前管理员。候选与校验使用所属组织；仅属于其他组织的路由被拒绝，精确的已提供模型 ID 仍可选择。选中模型与 Provider 的资格保持到提交，写入返回其已接受视图。

## 迁移

1. 升级完整 Gateway 构建，不需要数据库迁移或浏览器请求字段变化。
2. 自定义治理适配器在管理写入及模型发现准备期间传递已认证账号 ID。保留事务持有的权限及目标检查；治理发起者省略只供受信任的内部维护使用。纪要服务始终要求认证发起者，固定/清除返回已接受设置和候选。
3. 收到403后，先刷新管理员会话与当前角色，再重试。确认当前管理员可以保存，而撤权管理员的排队请求既不改变设置，也不发出发现请求。参见 [Gateway 模型规则](../../../../gateway/README.zh.md)。
4. 检查导入报告中的 `skippedQuotaAliases`。通过管理员额度 API 配置确实需要的替代额度并验证回读；再次导入会恢复冻结源库的额度配置。参见 [SQLite 导入参考](../../../../gateway/deploy/postgres/README.zh.md)。
