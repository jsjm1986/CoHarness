# 账户写入与删除串行化

[English](guide.md) | 中文

## 变更

并发修改项目成员和接受邀请不能为已删除账户恢复访问。账户删除与项目变更使用一致的事务锁顺序。目录授权更新会识别已确认的并发删除，不重启被删除账户，也不声称已写入其授权。未知账户和无法核实的失败仍作为错误处理。

接受邀请与认证用户发起的创建还要求账户和组织成员身份当前有效、组织可用；邀请还要求项目活跃。在停用或归档前已通过认证的请求会返回403，不会创建授权或项目。已删除的参与账户也收到403。恢复临时权限后可以重新尝试；逻辑删除不会恢复账户。

管理员创建和导入要求在分配目录前确认当前有效的组织管理员身份。延迟至撤权后的请求返回403，不会登记项目或留下新的管理员目录。

新邀请还要求收件人的组织成员身份有效，且项目和组织当前可用。缓存的收件人查询不能在这些状态变化后授权发出邀请。收件人不可用返回409；发起者或作用域权限撤销返回403。SQLite 的资格检查及邀请发布与账户变更串行化。

个人模型授权、额度写入、intake-token 签发及启动分配恢复使用相同的账户锁。经过验证的历史执行用量仍可在撤权后送达；已删除用户的无证明用量会被拒绝。

## 迁移

1. 使用既有 [Gateway 部署流程](../../../../gateway/README.zh.md)。应用 PostgreSQL 迁移 073–074 并启动匹配产物前，先停止旧 Gateway 写入者。
2. 迁移移除涉及已删除账户的项目成员与邀请，以及这些账户的模型授权和个人额度。仅涉及未删除账户的关系、保留的账户记录、项目所有权和文件、对话、用量与审计历史保持完整。保留的 intake 凭据可提交具有执行记录证明的历史用量。无需手动移动文件。

3. 两个第一方用户存储都提供 `GatewayUserService.isDeleted(id)`。自定义适配器可实现它以确认保留的删除标记；未知 ID 返回 false。`applyGrantsToUser` 的调用方需在 `written`、`restarted` 之外处理 `deleted` 结果。省略实现或核实失败不能将账户判定为已删除。参见[删除决策](../../../../.agents/notes/implemented/feature/2026-08-16-gateway-user-logical-deletion.zh.md)。
4. 确认账户管理中不再出现已删除账户，历史报告仍可查看保留的用量。
5. 自定义 `GatewayProjectService.create` 和 `createManaged` 调用方在认证创建时传入 `actorUserId`，并从同一身份推导创建者及受管项目所有者。省略参与者表示受信任的内部维护。浏览器请求字段不能提供认证。没有新增迁移或传输字段。
6. 自定义项目移除路由遵循[删除生命周期要求](../project-deletion-lifecycle/guide.zh.md)，包括初始停机权限与最终目录权限。
