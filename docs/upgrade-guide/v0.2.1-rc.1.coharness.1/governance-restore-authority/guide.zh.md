# 治理库恢复的权限归属

[English](guide.md) | 中文

## 变更

协调 SQL 恢复会依据目标当前状态，核对受保护 schema 的校验和、节点内容卷、目录归属、Runtime 归属与退役状态、实例代次及节点／项目状态。不兼容的归档被拒绝，SQL 事务回滚。互备策略指纹、凭据轮换、启停状态及已确认历史继续属于目标当前状态；修订号推进，排队或运行中的 claim 失效。

早于受保护 schema 的备份不承担就地归属迁移。恢复失败后，维护保护状态保持关闭，不自动恢复服务。

## 迁移

1. 恢复前保留已验证的保护备份及当前部署身份。协调就地恢复应选择受保护 schema 与归属均匹配目标的备份。
2. 对于旧 schema，或卷、目录、Runtime、代次及电脑已变化的情况，使用隔离恢复部署；连接活动节点内容前，应协调其身份与凭据。不能降低写纪元、复用已撤销批准或关闭 SQL 检查来适配归档。
3. 治理库成功恢复后，重新授权互备工作。确认当前停用策略仍停用、轮换后的指纹仍有效，旧 claim 不能完成或发布。
4. 使用可丢弃数据演练：包含早先活跃 Runtime 的归档必须让目标 Runtime 继续退役，并保留部署的写入保护状态。事务与重试语义见[维护决策](../../../../.agents/notes/implemented/architecture/2026-09-25-gateway-deployment-maintenance.zh.md)。
