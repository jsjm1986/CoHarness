# 升级当前节点配置

[English](guide.md) | 中文

## 变更

节点配置查看、保存与登记应用重新校验当前活跃组织管理员。资格撤销前已排队的 HTTP 请求返回403，不修改配置或登记应用。浏览器的参与者字段不授予权限。每次成功写入返回自身已接受的 revision 和设置，即使另一写入者在响应发送前已经提交。

写纪元捕获使用已有部署租约连接，支持只有一个可用连接的情况。意外数据库故障返回503。读取拒绝特殊文件，不等待 FIFO 写入者，并在检查后文件增长时仍限制实际字节数。临时获取失败及发布后暂存路径被重用时，保留其他写入者的文件。

配置健康确认要求节点目标请求头与响应头携带期望电脑身份，同时确认已应用代次和已配置的 release。应用器拒绝缺少该身份的端点。原生服务控制客户端使用 `HGW_SYSTEMD_COMMAND_TIMEOUT_MS`，不继承 Gateway 凭据，并在取消或超时后等待进程实际关闭。就绪检查使用单调时间，每次响应受剩余期限及已配置响应字节数限制。

## 迁移

1. 一起升级完整 Gateway 与独立配置应用器，确保健康端点提供节点身份。配置版本、可编辑字段和浏览器请求字段不变，已有记录无需重写。
2. 收到403后刷新当前账号角色、成员资格及组织状态。保存不会重启 Gateway；应用仍是单独的显式动作，并遵循既有维护状态和数据检查。
3. 配置应保持为私有普通文件。修复无效或不可读状态，而不是用默认值替换有效配置。收到503后重试前读取当前状态，因为已发起的 rename 仍可能提交。
4. 验证当前管理员、已撤权管理员拒绝、并发保存，以及受限连接池下的登记应用。参见[节点配置参考](../../../../gateway/deploy/node-configuration/README.zh.md)。
