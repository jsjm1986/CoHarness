# 文档根目录与私有名称

[English](guide.md) | 中文

## 变更

本地文档提供方列出普通的已完成 `.part` 文档。其 `.userdoc-<24 个十六进制字符>.part` 暂存模式被保留：同名的新上传使用正常数字后缀，公开读取不能选择暂存文件。

根级维护名称 `.upload-sessions` 和 `.dsh-trash` 同时保留大小写及 Windows 末尾句点、空格别名。公开遍历还拒绝实际私有目录对象的另一种拼写。文档根目录必须是真实目录。新解析的文件和文件夹名称在字节截断前后移除末尾 ASCII 句点及空格。现有文件及 Session 代次不会被改名或重写。

## 迁移

1. 停止文档写入方，并在改名现有条目前备份配置的 `uploadRoot`。
2. 如果 `uploadRoot` 是目录链接，将提供方配置为其真实目录，保留现有内容和文件系统权限。该目录仍需位于模型已获授权的文件系统根目录内。
3. 检查匹配维护别名的用户所有根级条目，以及匹配 `.userdoc-<24 个十六进制字符>.part` 的用户文件。通过文件系统将这些用户条目改为普通名称。保留真正的上传会话和回收站目录；未知临时文件应保留待检查，不要按后缀删除。
4. 启动提供方，确认普通 `archive.part` 上传同时出现在递归和文件夹列表中，并可读取。确认维护别名被拒绝，暂存模式上传得到可见的带后缀名称。

[私有路径决定](../../../../.agents/notes/implemented/architecture/2026-10-26-document-private-paths-and-staging-names.zh.md) 记录这些检查。持久实例及目录迁移仍是独立工作。
