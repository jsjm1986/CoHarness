# Managed execution registers resource admission

English | [中文](guide.zh.md)

## Change

Gateway-managed LLM dispatch, registered native DeepSeek Messages search, subprocess allocation, plugin-market parse Workers, JSONL migration verifiers, Stagehand connection Workers and owned Chromium ranges, Inspector Workers, local SSH transport processes, Python interpreter probes/programs, and MCP stdio probes/servers require a registered resource provider. An older supervisor-owned Runtime without registration cannot be reused as ready. Ordinary subprocess `spawn` returns a promise, and resource completions are awaited. Standalone compositions can omit resource admission. Cold Runtime starts also wait for fresh node pressure before allocation.

Rebuild `dsh-commands` with the Runtime payload. Pending command admission and real handler cleanup prevent automatic idle retirement; an invocation whose original Agent was disposed or replaced cannot enter its handler. Withdrawal cancels accepted commands and waits for real completion before releasing idle protection. Handler cancellation includes both the UI request and service lifetime.

Rebuild `dsh-user-questions`, `dsh-host-apiproxy` and their Typert descriptors together. Direct TypeScript callers await `answer(agent, callId, batch, signal)`; Remote clients still pass three business arguments, with cancellation carried by the transport. Managed late answers register their actual message under the answerer's identity before queuing. Rebuild GatewayExecution, UserQuestions, CollaborationContext and generated client descriptors together so project answerer snapshots reach the contribution log and paired model notice. Historical replies without attestation cannot authorize privileged execution. Session data needs no migration.

Managed `/compact` requires the matching `dsh-command-compact` and `dsh-execution-authority` packages. Rebuild both consumers and providers together: the command attests its current caller before resource admission and summarization, refuses revoked execution, and retains that caller for summary attribution. Independent compositions can omit execution authority.

Cold-start admission honors an explicit Runtime ID together with owner, computer and generation. A stale or mismatched environment reference cannot consume another assignment's pressure credit or change its allocation state. Legacy owner-only selectors keep their existing generation lookup; persisted data needs no migration for this check.

The CLI declares managed model, resource and execution requirements from inherited credential-channel markers before SDK bootstrap and profile entries run. Provider startup failures cannot turn these operations into independent execution. Environment-file values do not select managed mode. Deploy the matching compiled CLI with the Runtime payload so these requirements apply during startup.

Local background job admission reserves exact-owner capacity before execution-identity capture and producer startup. Rebuild `dsh-jobs-local` so synchronous authority callbacks cannot overfill the configured limit; capture failures release the reservation without starting work.

Slash commands recheck cancellation before handler entry after publishing their run event. Managed `/plan` text and attachments require input attestation before changing mode or queuing a request. Rebuild Commands and PlanMode with the matching execution-authority API package; the updated workspace manifests and lockfile declare that dependency. Independent compositions still need no authority provider, and Session data needs no migration.

## Migration

Local launch inheritance excludes Gateway deployment settings and credential-named variables. Supply workload settings through explicit runtime configuration or an operator-selected default env file; see [runtime environment](../../../../gateway/README.md#performance-and-runtime-admission). Unavailable supervision returns `503 INSTANCE_UNAVAILABLE` while occupation remains retained; restore the supervisor's control access before retrying.

1. Deploy Gateway and Runtime payloads from the same release, including PostgreSQL migrations 062 through 072, through the existing deployment procedure. Stop older managed Runtimes before reopening traffic; restart them through instance management so each new generation registers its provider. Linux unit names include the generation, and stopped units remain masked; preserve these files and use instance management instead of manually restarting supervisor units. See [Runtime admission](../../../../gateway/README.md#performance-and-runtime-admission).
2. Confirm older local Runtimes stopped before replacing their Gateway. Local macOS/Linux execution includes a private independent supervisor; preserve `HGW_STATE_ROOT/local-runtime-supervisors` across replacement and application-data restore, outside custom backup roots. Include the complete compiled Gateway directory, including supervisor entry points, and the native flock package. Initialization preserves active assignments; missing legacy ownership leaves the Runtime unavailable until its stop is confirmed. Preserve the managed patch's `gateway-resource-budget` entry (`@deepseek-ai/dsh-gateway-runtime/resource-budget`) and the `resourceBudget` injection on `llm` and `subprocess`. Keep registration ahead of readiness and preserve `gateway-runtime.requiredPlugins`: model governance, execution authorization and the enabled directory guard must activate. See the [provider reference](../../../../packages/context/gateway-runtime/README.md#resource-admission).
3. Await every `ctx.subprocess.spawn(spec)` call. Custom subprocess providers implement `spawnProcess` and `spawnTerminalProcess`; the shared service owns admission. Custom resource consumers observe `lease.signal`, await completion reports, and retain uncertain occupation until cleanup is confirmed. Execution-authority providers implement `current()` for captured asynchronous work.
4. Set JSONL `verificationConcurrency` and `maxQueuedVerifications` for the deployment's migration capacity. Each backend owns its queue; overload refuses work without marking healthy history corrupt. Provider unload waits for accepted migrations. See the [storage configuration](../../../../packages/session/session-persistence-jsonl/README.md#config).
5. Confirm a cold Runtime waits without fresh pressure and a cancelled wait never launches. `HGW_RUNTIME_MAX_RESIDENT` defaults to `0`; set a positive emergency ceiling when required. This ceiling is independent of pressure admission.
6. Confirm authenticated Runtime readiness and queued model/child cancellation. Surviving descendants remain accounted until their managed range exits. Other direct worker integrations remain separate; see the [resource reference](../../../../packages/context/resource-budget/README.md#known-limitations-and-deferred-work).

MCP stdio exposes `processGraceMs` (2000), `processCloseTimeoutMs` (5000) and `startupTimeoutMs` (120000). Programmatic clients can retain `mountMcpClient(...).dispose()`; await it before releasing a browser reservation. Failed closure rejects and keeps its namespace reserved until cleanup succeeds. See the [MCP client reference](../../../../packages/mcp/mcp-client/README.md).

Stagehand native launch uses private local subprocess admission and adds `processGraceMs` (2000) and `processCloseTimeoutMs` (5000). `operationTimeoutMs` includes process-capacity waiting; published browsers remain alive after startup completes. Range confirmation precedes profile removal. See the [native browser reference](../../../../packages/experimental/browser-use-stagehand-native/README.md).

Browser resource cleanup supports explicit retry after termination or completion-report failure. `SessionResources.dispose()` keeps acquisition stopped while retrying; failed SDK drainage still blocks connection reuse. Parent owners must await actual cleanup handles because a Cordis effect retains its first rejection.

Stagehand `model` configuration uses `{ provider, model, maxTokens? }` from registered Harness routes. Replace `modelName`/`apiKey`/`headers`; configure credentials and headers on the model provider. Every extension inference uses host admission, current authorization, cancellation, and usage middleware, with exact input logged before dispatch. Include an attachment store. Older builds that do not know `browser-use/stagehand-llm-request` refuse affected Sessions; existing Sessions without that event remain readable.

Gateway project-progress inference uses its own model-only process generation and kernel lock under the stable `HGW_STATE_ROOT/gateway-model-locks/<node-id>` directory. Preserve that private directory while processes run. Stop all older Gateway processes before applying migrations 065–072 and restarting on this payload; manual background passes from older builds do not participate in the new drainage. Include the native flock module and its Gateway package link. Do not substitute a Runtime generation for Gateway HTTP ownership. Project-progress candidate selection, lease admission and model dispatch require the project's fixed computer to match the Gateway. Other computers leave its generation state untouched.

Migration 068 marks existing synthesized progress entries invalid and resets their material watermark; migration 069 establishes exact source-consumption receipts and resets selection once. Source conversations, invalidated rows and usage history remain stored. The panel rebuilds from currently shared sources within its configured window, automatically when its gates pass or through a writer’s Generate action. Source visibility/deletion changes also trigger a rebuild. `HGW_PROGRESS_RESPONSE_LIMIT_BYTES` defaults to 1048576 and `HGW_PROGRESS_USAGE_REPLAY_BATCH` to 64. Migration 070 adds immutable Session-format input snapshots to new request evidence; earlier rows retain their request JSON. Migration 071 cascades progress evidence on permanent project deletion; archival retains it. Migration 072 adds pressure capture bounds and clears unused observations once; active reservations remain occupied until their owners finish. Include the Session package entry and Gateway link in the payload. Interrupted requests retain resource accounting until physical recovery and then replay missing usage. See the [Gateway progress reference](../../../../gateway/README.md#project-progress).

Gateway document-account resolution is asynchronous. Project-profile and document UID/GID queries use the existing `HGW_READINESS_TIMEOUT_MS` deadline, filter inherited credentials and join child closure before failing or acknowledging cancellation. No data migration or new configuration is required.

Cold Runtime completion retains its readiness deadline and cancellation through resource registration and ready publication. The deadline uses monotonic time; each HTTP probe is bounded by the remaining wait. A backend refusal preserves its structured error. A failed start confirms physical rollback before freeing its resident reservation; unconfirmed termination remains occupied. Existing settings and stored records need no rewrite.

Terminal descendant and Windows shell grace periods also use process-monotonic time, preserving termination escalation across wall-clock adjustments. Confirmed session cleanup still precedes resource release.

A disposed local provider retains its exit callback through unconfirmed cleanup and removes it when the last owned process, terminal and control endpoint has drained, including a terminal close retried after failure.
