# 保留 SSH helper 清理归属直到确认完成

[English](guide.md) | 中文

## Change

SSH helper 关闭会等待当前清理尝试，并保留失败的端点和目录清理供重试。此前，重叠或重复关闭可能在仍有资源时报告完成，进程清理失败也可能释放其 provider 和私有现场。

关闭开始后仍拒绝普通操作。后续 close 请求可以重试临时清理故障，但不会重放进程效果。原始进程直接结果保留现有的有界缓存语义。协议版本 2 和请求字段保持兼容。

## Migration

1. 重建并安装完整且匹配的 SSH helper 分发包，将每个目标的 `helperHash` 设置为安装后入口的 SHA-256；摘要不一致时必须在就绪检查时失败。
2. 清理失败表示归属尚未确认，只重试支持的 close 操作，不要重试结果不确定的进程启动或修改。
3. 验证并发归属关闭调用会等待、临时清理失败仍可见，且资源只在原生进程退出后完成结算。参见 [SSH 参考](../../../../packages/ssh/ssh/README.zh.md)。
