# 升级归档身份与管理

[English](guide.md) | 中文

## 变更

每份归档记录具有不透明的 `archiveId`；`rootSessionId` 保留原始 Host Session 标识。不同 Runtime 或电脑中相同的 Host ID 对应独立记录。PostgreSQL 迁移097保留既有 Runtime 分配、搜索、命令和排队文件清理；创建新 Runtime 时，未分配的历史数据仍独立保留。

归档客户端使用 `/admin/api/archives/records` 和 `/records/:archiveId`，状态与导出分别追加 `/status` 或 `/export`。批量操作使用 `/records/actions`，请求字段为 `archiveIds`，逐项结果字段为 `archiveId`。旧的按根会话寻址路径返回410。空白草稿预览与清理保留已审核的 Runtime/Host 配对，参见[会话身份迁移](../postgres-session-runtime-namespace/guide.zh.md)。

归档恢复、移入回收站、永久清理、结束等待和空白草稿清理现在会检查活跃组织、已认证的管理员账号及成员资格，并保留到事务提交。资格撤销前已通过认证、但仍在排队的请求不能在撤销后改动归档。幂等重试也需要当前资格。浏览器传入的操作者字段不授予权限。

批量端点保留逐项结果：HTTP200 可以包含被拒绝的条目，其错误说明权限已丢失。空白草稿清理返回403。此前已接受的命令仍等待所属运行时处理；可信维护仍可在永久清理与结束等待的服务调用中省略操作者。

归档列表、状态、空白草稿预览、正文与导出现在会在数据库读取期间保留当前资格。个人 Runtime 读取在等待前释放数据库连接，将真实管理员带入启动和读取 principal，并在完成或失败后重新核验资格。撤权后返回403，不返回正文或索引回退数据。操作租约使用返回的 Runtime generation。省略服务操作者仍只用于可信内部读取。

空白草稿预留会拒绝尚未恢复的归档根会话，同一草稿重试时提议另一个 Session id 也不能绕过检查。等待根会话锁期间预留被释放时，返回 HTTP400，需要重新请求。空白草稿预览与确认会排除已归档、回收站、已清除及刚恢复的根会话；恢复旧空白 Session 后，清理等待时间重新计算。

## 迁移

1. 同时升级完整 Gateway 和内置 Admin UI；Gateway 启动时应用迁移097。自定义客户端需要改用记录路由和不透明 ID。旧路径返回410时清理过期浏览器资源。缺少归档 ID 时不得用 Host ID 替代。
2. 报告成功前按 `archiveId` 检查每个批量结果。权限丢失后先刷新账号、组织状态、角色和成员资格，再重试。
3. 确认两个 Runtime 中相同的 Host ID 列为独立记录，操作和回执只影响所属 Runtime，清理其中一份保留另一份记录及文件。确认活跃管理员可以恢复归档并移入回收站。在排队操作被接受前撤销管理员资格，确认归档状态与命令账本均未改变。参见[归档参考](../../../../gateway/README.zh.md)。
