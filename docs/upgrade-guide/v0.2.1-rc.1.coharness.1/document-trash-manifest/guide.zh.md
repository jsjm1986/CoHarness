# 校验文档恢复元数据

[English](guide.md) | 中文

## 变更

本地文档回收站拒绝未知清单版本、无效或重复记录、不安全路径，以及仍有隐藏文档文件时缺失的清单。列出、移入回收站、恢复、永久清理和保留期清理会在修改文档文件前以 `DOCUMENT_TRASH_NOT_FOUND` 失败。旧版本可能把这些元数据当成空清单，或丢弃记录后替换清单。有效的版本 1 清单和普通空存储无需转换。

恢复以 `DOCUMENT_RESTORE_CONFLICT` 拒绝被并发占用的目标，并保留回收站记录。旧版本可能覆盖并发文件。重试会选择另一个空闲名称。

保留期清理在取得写入准入后检查当前文件标识和到期时间。等待期间已恢复、替换或续期的记录会跳过，不会删除其较新状态或报告清理成功。

原路径存在活动替代文件且较早记录仍在回收站时，删除以 `409 DOCUMENT_TRASH_CONFLICT` 拒绝。旧 HTTP 路由可能在替代文件仍活动时报告删除成功。拒绝后两份副本均保留。

## 迁移

1. 备份文档根目录，包括私有的 `.dsh-trash/` 目录。
2. 如果回收站操作报告恢复元数据无效，保留所有隐藏文件，并恢复属于同一根目录的完整 `.dsh-trash/manifest.json` 备份。不要通过删除清单来清除错误。
3. 使用升级后的提供方列出回收站并恢复一条已知记录。核实内容后再恢复保留期清理。若没有完整备份，保留目录以便手动恢复；提供方不会重建缺失的所有权或文件名元数据。
4. 普通发布冲突可以重试。如果恢复同时报告发布与回滚失败，应先保留剩余的可见副本和隐藏副本以便恢复，再进行重试。
5. 对于 `DOCUMENT_TRASH_CONFLICT`，应检查两份文档，并先将较早的回收站记录恢复为其他名称，再重试删除活动文件。不要通过删除恢复元数据绕过冲突。
