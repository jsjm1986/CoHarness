# 单电脑模式与明确的主入口配置

[English](guide.md) | 中文

## 变更

迁移101增加组织级部署模式。新组织默认只使用本机资源，保留原有多用户、多 Runtime 和项目协作。只有已配置的主入口聚合受管电脑，直接访问接入电脑的 Web UI 仍只使用本机。`HGW_NODE_SERVICE_FORWARDING` 在兼容初始化时标识原主入口，不能覆盖已保存策略。浏览器元数据由入口 Gateway 提供，与当前 Runtime 分离。

## 迁移

1. 通过现有受控升级流程部署匹配的 Gateway、Web 和 Admin 资源并应用迁移，保留组织与电脑身份、Runtime UUID、私有目录及 Session 代次。兼容初始化待完成时，历史受管执行继续校验其租约。
2. 在原转发 Gateway 保留 `HGW_NODE_SERVICE_FORWARDING=on`，打开“Admin → 部署 → 部署模式”，开启多电脑并确认已配置的公开地址。其他电脑不能认领该主入口。确认主入口的 `/account/api/deployment/context` 返回 `multi`、`primary`、`organization`，接入电脑直接入口返回 `local`。新单电脑部署不需要转发设置。
3. 按[部署参考](../../../../gateway/docs/deployment-topology/README.zh.md)单独安装经过核对的 Node Agent 服务，使其操作系统账号、发布和私有配置路径与 Gateway 一致。在主入口选择现有电脑身份或预登记新名称，再在该电脑自己的部署页填写接入码。通过正常部署流程准备数据库访问、原有加密密钥和允许来源，接入码不分发这些秘密。
4. 正式受管接入前确认旧本机 Runtime 已停止。关闭聚合前，停止受管 Runtime 工作与传输，并逐台明确退出接入。退出后的电脑保留数据和身份，以新代次独立运行；重新开启需要明确重新接入，主入口本机任务保持不变。
5. 验证本机入口拒绝远程 API、项目邀请权限、文档归属、双标签页隔离及 Runtime 按需启动。确认模式变化保留草稿和未保存配置。数据库恢复保留当前拓扑与接入授权，旧连接代次不能复活。迁移102之前的备份需在隔离恢复部署中升级。完整多电脑备份继续受现有覆盖检查限制。

项目治理需部署匹配的 Admin 资源：项目模型分配、额度、用量和成员贡献请求保留所选项目电脑；组织模型配置、角色／用户权限和组织报表保持共享范围。加载这些视图不会启动 Runtime。

自定义 Gateway 组合需向 HTTP/WebSocket 路由和按入口过滤的目录构造器提供拓扑策略。自定义客户端连接句柄需提供 `metadataTiming`，由已配置的就绪超时和重试间隔解析。参见 [API 与配置参考](../../../../gateway/docs/deployment-topology/README.zh.md#api-reference)。

账号拥有多个个人 Runtime 分配时，普通登录仍直接进入原有 Harness 界面。部署匹配的 Gateway 路由与目录代码，验证不带目标的 `/` 入口跳转到有权限的默认个人环境，不强制先选择工作环境，也不启动其他 Runtime；已保存的精确链接必须保留原目标。

自定义 Client 组合必须提供 Runtime 所属的管理目录、带精确目标的工作区创建能力，以及匹配的 Connection／Remote 库，并一同重建浏览器资源。未限定 Session ID 所属环境的已保存布局会保留引用，直到确认原环境；移除未决窗格只改变布局。工作区资源键包含分配 UUID，不重写任何已提交 Session 代次或用户文件。

升级后的 Web 客户端可在版本化的创建请求中同时读取限量的首屏历史。接入电脑省略此可选字段时，客户端会在该电脑上读取已返回会话的历史，沿用原草稿预留和工作区。

已保存的旧草稿标识仍能读取所属节点的当前值。更新客户端后，恢复指针带有修订号，复制标签页可取回被原标签修改前的版本。节点升级前未记录或已超出保留窗口的版本会显示不可用，编辑中的文字继续保留在本页。已发布项目需应用节点内容迁移 015；个人草稿库在原位置升级。
