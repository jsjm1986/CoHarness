# 单电脑模式与明确的主入口配置

[English](guide.md) | 中文

## 变更

迁移 101 增加组织级部署模式。新组织只使用本机资源，保留多用户、多 Runtime 和项目协作。只有主入口聚合受管电脑，接入电脑的 Web UI 仍只使用本机。`HGW_NODE_SERVICE_FORWARDING` 标识兼容初始化入口，不能覆盖已保存策略。迁移 130 区分永久灾难隔离与普通退出接入。

## 迁移

1. 通过受控升级部署匹配的 Gateway、Web 和 Admin 资源。保留组织与电脑身份、Runtime UUID、私有目录及 Session 代次。兼容初始化期间，历史受管执行继续校验租约。
2. 在原转发 Gateway 保留 `HGW_NODE_SERVICE_FORWARDING=on`，打开“Admin → 部署 → 部署模式”，开启多电脑并确认已配置的来源。确认 `/account/api/deployment/context` 返回 `multi`、`primary`、`organization`，接入电脑入口返回 `local`。新单电脑部署不需要转发设置。
3. 按[部署参考](../../../../gateway/docs/deployment-topology/README.zh.md)安装经过核对的 Node Agent 服务，使账号、发布及私有配置路径与 Gateway 一致。选择现有身份或登记新名称，再在该电脑填写接入码。单独准备数据库访问、加密密钥和允许来源，接入码不分发秘密。
4. 正式受管接入前确认本机 Runtime 已停止。关闭聚合前，停止工作和传输，并使普通登记退出接入。退出后的电脑保留身份和数据，以独立新代次运行；重新开启需明确接入。已核验的永久灾难隔离也允许关闭，但原身份不能执行、接入或成为主入口。替代电脑需使用新身份，主入口本机任务保持不变。
5. 验证本机入口拒绝远程 API、邀请权限、文档归属、独立标签页及按需启动。模式变化保留草稿和未保存设置。恢复保留当前拓扑和接入授权，旧连接不能复活。迁移 102 之前的备份需在隔离恢复部署中升级。完整备份继续检查覆盖范围。

部署匹配的项目治理资源：模型分配、额度、用量及成员贡献请求跟随所选电脑；组织模型策略和报表保持共享。读取这些视图不启动 Runtime。

自定义组合需向路由和目录提供拓扑，提供 Runtime 管理目录、面向目标的工作区创建、匹配的 Connection/Remote 库及已配置的 `metadataTiming`，并重建浏览器资源。参见 [API 参考](../../../../gateway/docs/deployment-topology/README.zh.md#api-reference)。

验证不带目标的 `/` 登录直接进入获准的默认个人 Harness 环境，不显示环境选择器或启动其他 Runtime。精确链接保留目标。未限定环境的已保存 Session 引用，在原环境确认前保持未解析；移除窗格只修改布局。工作区键包含分配 UUID。

组合创建可携带有界初始历史；旧节点仍对返回的 Session 后续读取历史，保留草稿预留和工作区。草稿 ID 在所属节点解析，固定修订保留复制标签页的文本。保留修订不可用时，输入继续留在标签页。为已放置项目应用节点内容迁移 015，个人草稿数据库原地升级。
