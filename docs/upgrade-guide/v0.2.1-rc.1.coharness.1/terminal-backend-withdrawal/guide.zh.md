# 等待终端后端撤下

[English](guide.md) | 中文

## 变更

`ctx.terminals.registerBackend()` 返回 `() => Promise<void>`。显式撤下会以 `NO_BACKEND` 取消该注册尚未发布的启动，并等待启动及回滚。回滚失败时，返回的 promise 会拒绝。此前，撤下只删除后端类型，可能在待完成的启动发布终端之前就完成。

已发布的会话在后端重载后仍归属于原来的 Agent。替换注册拥有独立的取消信号。所有者内待使用的名称会一直预留，直到对应启动结算。

## 迁移

1. 将保存的后端释放函数类型更新为 `() => Promise<void>`，并在释放依赖之前等待显式调用完成。通过插件上下文注册的贡献仍由 Cordis 拥有并等待。
2. 未发布的启动应响应后端 spawn 信号。只有拥有的回滚完成后才能结算启动，并应通过已有终端错误路径报告清理失败。
3. 验证启动中撤下会拒绝发布、停止原生进程并等待回滚。同时验证已发布会话在后端重载后继续存在，直到其 Agent 将其关闭。
