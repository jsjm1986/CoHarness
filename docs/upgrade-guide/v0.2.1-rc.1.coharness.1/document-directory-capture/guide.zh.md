# 升级受管目录恢复

[English](guide.md) | 中文

## 变更

Gateway 受管文档身份数据库使用私有 SQLite 第 4 版。可写打开会迁移第 2、3 版，文档实例、创建者、回收动作和目录投递位置保持不变。目录恢复会在目标发布前记录所选目录对象及已经核验的私有捕获。变化后的源和被占用的目标都会保留；排他回滚失败时保留私有字节和恢复证据。

第 2 版待完成目录操作在原始源或已移动目标可辨认时仍可恢复。结果不确定的操作会拒绝后续变更，同时保留副本及日志。已核验目录发布后，普通文件编辑独立对账，不会阻止改名恢复。原子替代文件获得独立且未归属的身份；记录中的原创建者与改名发起人保持不变。旧读取器拒绝第 4 版。[卷身份指南](../document-volume-identity/guide.zh.md) 定义持久卷绑定及旧数据重新挂载后的恢复。不可变的第 2 版备份仍以只读方式验证；恢复兼容备份时迁移其可写副本。

普通外部移动在原名称被复用或文件地址互换时，仍保留可唯一辨认文件的实例及创建者。未知或被替换文件的单文件读取可能扫描整个文档根。有歧义的硬链接目标保持未归属。地址对账使用现有 schema 及通信版本。

Linux x64 和 arm64 支持在 musl 上执行排他目录移动，无需 libc 提供 `renameat2` 包装函数。不支持该操作的内核或文件系统仍会拒绝操作，不会替换已占用目标。

## 迁移

1. 停止 Gateway 及其文档写入方。使用经过验证的部署备份流程，一起备份每个作用域的公开文档根、私有元数据根和私有保留文件根，包含未完成上传及恢复记录。
2. 同时升级 Gateway 和本地文档提供方，然后启动 Gateway。不要降低 SQLite 版本，也不要移除日志、私有锚点或捕获目录。恢复被拒绝时保留所有副本，并在重试前恢复原先记录的目录；回滚使用完整的兼容备份。
3. 列出受管文档作用域，把选定文件夹改成一个空闲名称。确认 Gateway 重启后文档实例和创建者保持不变。目标被占用时必须返回冲突，且不替换其文件。参阅[提供方的失败与恢复规则](../../../../packages/attachment/userdoc-local/README.zh.md)。
