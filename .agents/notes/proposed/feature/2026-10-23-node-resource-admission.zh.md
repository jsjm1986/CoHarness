# Agent Note: 节点级模型与进程准入

Status: proposed

[English](2026-10-23-node-resource-admission.md) | 中文

## 问题

节点范围的压力与公平队列设置要求准入贯穿 Runtime 执行。[Runtime 进程准入](../../implemented/architecture/2026-10-23-gateway-runtime-admission.zh.md)限制常驻进程和冷启动，不能管理这些进程内部并发的模型请求、子进程、终端或持久 worker。各 Runtime 独立的信号量也不能执行共享节点策略。

Runtime 内的注册序号不能唯一标识一次操作。替换 provider 时，旧请求若发生延迟，两个 provider 可能取得相同的下一个序号。相同的执行者和 Session 元数据不能让不同操作共享一份许可。

## 提案

围绕 PostgreSQL 节点记账器和宿主压力采样器，完成 Gateway 与 Runtime 的组合。具体的 [ResourceBudget](../../../../packages/context/resource-budget/README.zh.md) provider 在托管 Runtime 就绪前注册其代次。每个操作取得不透明身份，并在重试时保留；序号负责安排注册和取消顺序。同一序号对应不同身份时产生冲突。断连、经过一段时间或替换 provider 均不能证明执行已停止。

Gateway 已启动记账器与采样器，并提供有界、经过 bearer 认证的准入消息。普通认证要求组织处于活跃状态且所有者仍有效；当前 Runtime 停止或账户权限撤销后，完成认证仍可用。确认进程范围终止后，按句柄捕获的代次回收资源；记账提交失败时保留句柄供重试。注册和 Linux 内存观测均采用已提交的部署策略，即使样本由旧协调器发布。独立的 wire bundle 内置校验器；发布校验只在已编译 API 导入资源协调时要求相应产物。Runtime provider 已组合，模型派发及普通／终端子进程分配会申请许可。捕获的来源跨排队保留，排队状态重新检查当前权限，最终模型检查在派发前读取当前策略。直接 worker、完整应用快照与原生平台生命周期验收仍待完成。

冷 Runtime 在本地分配与 systemd 派发时共享相同的新鲜节点压力额度。有界等待保留已认领的代次和调用方取消。持久化分配状态区分准备工作与可能存在的进程，避免引导死锁，同时为未验证的存活进程保留保护。常驻应急上限默认为零，不替代压力准入。

数据库启动只领取已停止的实例记录，停止写入匹配捕获的代次。每个 Linux 代次及其凭据指纹独占一个监督单元，使备份恢复后重复出现的编号能够使用新凭据启动。终止会先原子地把单元替换为空文件，再重新加载并停止；systemd [把空单元视为已屏蔽](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)，拒绝激活。启动写入采用独占创建，迟到的启动器无法覆盖停止标记。保留这些小文件，可以阻止停止后的迟到命令分配未记账进程。单靠数据库代次检查无法保证这一点。终止同时屏蔽并停止旧式单元名称；新代次不复用这些名称。

模型准入位于实际 adapter 派发之前，包括重试和辅助调用。进程准入位于分配之前，覆盖普通子进程、终端、持久执行 worker 和 SSH 消费方。采用可等待的分配 API 时，所有 provider 和消费者必须一起更新。记账持续占用，直到完整的所属执行停止；无法确认的清理保持不确定状态，直到监督者确认终止。

插件市场解析 Worker 采用 Runtime 基础设施归属，因为缓存填充属于服务，可以在工具调用者停止等待后继续。它在分配前申请准入，并在终止期间保留捕获的许可。取消不会无限等待待定的终止承诺；不确定占用持续保留，直到线程退出或终止完成。JSONL 迁移校验器同样申请基础设施进程许可，每个后端拥有有界队列，并在确认物理终止前保留本地空位。持久化卸载先等待已接收的迁移发布完成，再关闭其存储所有者。其他直接创建 worker 的所有者仍需接入。

Gateway 从已认证 Runtime 和捕获的执行上下文解析执行者及项目。容量许可不授予执行权限。历史计费见证不能替代最新授权，也不能建立删减后的参与者集合。排队执行必须保留原始归属，并在派发前重新检查所需权限。Runtime 自有基础设施和已认证的无 Agent 操作需要明确归属，不能借用随后到达的浏览器请求。

托管组合在预算 provider 撤下时必须拒绝执行。独立组合可以省略它。Provider 销毁必须停止准入、取消所有者，并在报告传输仍可用时等待已接纳操作完成。队列元数据、HTTP 工作、轮询和清理等待均需要经过验证的限制。

SenseVoice 工作进程启动以准备任务的取消信号请求基础设施进程准入。获准前取消会阻止原生分配；迟到且未使用的额度会归还。发布就绪状态会解除准备信号的绑定，已完成录音的取消不会终止共享工作进程。推理取消与提供者关闭仍会终止并等待受管进程范围退出。

Stagehand 连接 Worker 在分配前，以确切的活动 Session 获取进程额度。已发布 Worker 继续绑定额度取消。终止失败会保留未确认占用，以及容纳错误、接受后续退出证明所需的错误和退出观察器。自有 Chromium 分配使用私有本地子进程提供方，确切 Session 贯穿准入和进程范围确认。获取期限包含排队与 CDP 就绪等待，浏览器发布后脱离该期限。清理失败保留配置目录与可重试的所有者。每次扩展模型回调通过公开 ClientLLM API，使用确切活动 Agent 的已注册 LLM 路由。每次当前工具操作捕获其异步执行上下文，避免后续执行者归属继承首次连接的上下文。模型准入、最新授权、凭据解析和用量中间件保持在宿主中；独立凭据不进入 Worker。确切的辅助输入在派发前记录，图像先保存为持久引用。浏览器取消会中止宿主请求，清理在 Worker 终止之外独立等待请求完成。由于 LLM 接口不公开原生响应格式或工具选择选项，结构化及必需工具响应采用已记录的指令并严格校验。

Inspector 在构造 Worker 前申请基础设施进程额度，不借用交互调用方。普通 effect 清理会等待插件初始化，因此使用 Cordis 的提前释放通知取消排队启动。线程物理退出后确认完成；终止失败保留未确认占用，启动失败则把剩余清理交给所有者。已发布 Inspector 会在许可撤回时关闭。

SSH 主连接与转发控制命令使用带基础设施归属的隔离本地子进程消费者，公开远端子进程提供方保持独立。[SSH 所有权决策](../../implemented/architecture/2026-09-11-posix-ssh-runtime.zh.md)记录传输如何保留到已接纳消费者清理结束。

Python 执行器通过隔离的本地子进程提供方执行基础设施归属的解释器探测，以及 Session 归属的程序。公开远端子进程选择不会移动主机引导资产或主机沙箱权限。可信加载器将继承的控制通道映射到既有 fd-3 协议，并移除启动标记，保留程序的最小环境。原生所有者保留各平台语义；进程组回退无法确认脱离范围的后代，因此完整范围验收与准入覆盖仍需分别验证。

MCP stdio 在协议发现、服务和重连之间共用一个私有本地子进程提供方。公开 SDK 的分帧与协商继续负责协议；仅用于发现的传输会拒绝旧版 initialize 握手，避免可丢弃探测执行服务初始化。探测范围静止后，新的准入进程采用 SDK 的现代或旧版结果。作用域服务器一次捕获最近的精确活跃 Agent；全局服务器使用 Runtime 基础设施归属。编程所有者保留显式挂载句柄，因为 Cordis 作用域释放通过日志报告子项清理错误。清理失败会保留进程占用和服务器命名空间，直到重试成功；浏览器附着预留也等待同一次清理。

Worker 终止与协调器确认拥有独立的完成点。清理保留已成功的 SDK 排空结果，允许后续重试终止或完成报告；排空失败仍阻止复用。浏览器资源所有者在单次 Cordis effect 包装器之外保留实际清理回调，避免 Agent 作用域失败阻止外部故障恢复后的提供方清理。提供方释放及重试期间始终拒绝新获取。

## 已考虑的替代方案

**只限制常驻 Runtime。** 一个已接纳的 Runtime 仍可启动大量模型请求或子进程。

**按序号和执行者元数据去重。** 替换 provider 时，完全相同但彼此独立的操作可能复用序号，取得前一操作的许可。

**只使用 Runtime 内的信号量。** 多个 Runtime 或 Gateway 协调者会各自花费同一份节点容量。

**超时或断连时归还。** 执行可能在两种事件后继续存在，后续调用方会花费仍被使用的容量。

## 验收标准

- 真实 PostgreSQL 和 HTTP 场景证明跨 Runtime 公平性、代次拒绝、有界队列、过期压力拒绝、幂等重试及不同操作间的冲突。
- 真实组装后的模型与进程流程等待许可，在派发前响应取消，并通过源码及构建入口报告已确认或不确定的清理。
- Provider 替换、上层所有者退出、监督器留存进程和进程树终止失败均保留记账，直到确认静止。
- 配置、文档、升级指南和不含身份标识的诊断描述实际执行的限制。

## 风险

准入会为执行启动增加数据库和传输工作。压力采样可能不可用，不确定清理的记账可能要求明确重启 Runtime。滚动升级期间，旧托管 Runtime 不能安全绕过注册。嵌套工作需要分析实际归属，避免保留中的进程造成无限排队，或让独立工作遭到不必要的拒绝。
