# Agent Note: 多电脑运行环境与统一管理

Status: proposed

[English](2026-10-28-multi-computer-personal-runtimes.md) | 中文

## 问题

现有单电脑系统已经支持多用户和独立运行时。同一个已认证前端需要把这套管理能力扩展到多台组织受管电脑。现有账号／项目选择、回环代理目标和节点本地路径需要明确的设备／运行时寻址。缓慢或断线的电脑不能拖延其他环境或浏览器的输入响应。

## 提案

初版通过一个 Web UI 管理 macOS/Linux 电脑。用户按授权使用一台或多台电脑，同一用户在同一台电脑上可以拥有多个独立个人运行时，由权限和配额控制分配。每个协作项目固定在一台选定的电脑上，不同项目可以分布在不同电脑。Windows 节点、单个项目跨电脑、目录同步、迁移和自动故障转移分别后续实现。

每台电脑部署同一份项目 release，复用现有多用户、多运行时服务。中心承载共用 Web UI、Admin 和组织 Gateway，也可以运行自己的 Runtime。受管电脑保留现有本机实例管理器、Launcher、Supervisor、插件 Profile 和资源 Provider，其本地服务操作通过中心已认证的节点连接访问。多电脑支持扩展服务寻址、授权下发与配置投影，保留能力实现及空间行为。现有 Gateway 组装的职责分离服务于这些部署角色，不另建替代运行时体系。

中心拥有认证、授权、环境目录、路由、策略和操作回执。节点拥有本地进程、资源准入、目录解析、终端和配置投影。节点建立经过认证的出站连接，使同一种部署方式同时适用于局域网和跨网络。选择生产隧道提供方前，传输验证必须覆盖现有公网入口。

环境身份是带品牌的 `RuntimeId`，与账号／项目归属、计算节点放置和进程代次分开。账号归属不能唯一标识运行时。项目在选定的电脑上保留一个共享执行位置。现有实例通过[迁移 076](../../../../gateway/deploy/postgres/migrations/076_runtime_environment_directory.sql)取得持久身份。实例分配移除后，目录仍保留已退役身份。历史属主／节点 UUID 有意不引用存活行；当前读取关联现行账号、成员资格、项目和节点记录。迁移093允许多个个人实例；旧私有目录的唯一性及每个项目只有一个共享 Runtime 的限制继续生效。属主选择存在歧义时需要精确 Runtime 身份，包括用户界面尚在扩展选择流程期间。

会话路由、浏览器草稿、工作区、预览、上传身份和环境专属设置都包含 `RuntimeId`。原始 Session 日志 ID 和已提交的 JSONL 代次保持不变。账号偏好和项目授权保留现有属主。个人文件和文档保留在所属电脑上；协作项目文件保留在该项目选定的电脑上。

## 目录基础

[PostgreSQL 目录](../../../../gateway/src/postgres/runtime-catalog.ts)读取经过认证的元数据，不启动运行时、不探测网络、不扫描目录。账号分页只公开调用人的个人环境和当前获授权的项目；管理员分页重新核验组织管理员资格。键集游标绑定组织、账号和读取方类别。行数及完整 UTF-8 响应预算都是部署设置。节点传输尚未实现时，远端元数据明确报告路由不可用。

本地[运行时监督](../../implemented/architecture/2026-10-25-local-runtime-supervisor.zh.md)、[运行时准入](../../implemented/architecture/2026-10-23-gateway-runtime-admission.zh.md)、[工作台归属](../../implemented/architecture/2026-09-23-principal-owned-workbench-layouts.zh.md)和[部署维护](../../implemented/architecture/2026-09-25-gateway-deployment-maintenance.zh.md)决策继续有效。目录增加环境身份，不替代这些生命周期、授权或恢复机制。

## 节点接入基础

[电脑权限服务](../../../../gateway/src/computer-access.ts)通过迁移079为账号按登记节点保存使用权。现有个人实例及首次个人空间保留所在电脑权限；其他电脑需要管理员明确决定。中心 API 写入保留当前管理员权限与乐观修订号，并将审计记录和授权一同提交。项目成员、目录读取、个人实例启动及普通 Runtime 请求凭证不能替代电脑使用权。已捕获执行参与者重新检查相同权限。撤权后，仅用于清理的运行时凭证仍可完成所属资源上报。

迁移080为现有六类能力资格表增加节点归属，各电脑的决定及修订号独立。项目策略归属所分配节点。本地进程、文件及执行消费者使用 `scopeAccessMonitor`；中心转发代理保留组织级事件送达，仅取消变更节点的连接。按节点撤权不停止其他电脑或其他参与者的共享项目进程。活跃属主没有实例分配却保有启用资格时，迁移会拒绝；已有实例策略保留原节点与修订号。[权限场景](../../../../gateway/tests/computer-access-postgres.spec.ts)覆盖真实认证的中心 API、离线节点配置、项目准入、管理员排队撤权及独立电脑使用权，且不启动 Runtime。

迁移081将启动的 Runtime 代次绑定到已接入节点的精确连接 UUID 和租约代次。没有登记代理的现有本机 Gateway 保留本机准入。启动、就绪进程复用及普通凭证拒绝不可用或已换代的连接；重新连接不能授权旧代次。执行监听心跳通过有超时且不重叠的查询复核该凭证。因此，即使提示丢失、租约过期或权限查询卡住，监听流也会关闭，由现有执行插件取消并收敛工具。清理凭证只保留原有运行代次的资源完成权限。连接丢失不证明进程已停止，也不释放物理资源。

[节点接入](../../../../gateway/docs/node-agent/README.zh.md)使用管理员一次性令牌、节点生成的持久凭证和 PostgreSQL 连接租约。HTTP 控制请求由节点主动发往中心源站，无需节点入站监听或数据库凭据。凭证修订号使令牌和存活租约失效；连接 UUID 与代次阻止延迟心跳和释放影响后继连接。重复接入绑定原始候选凭证；签发秘密仅返回一次，响应丢失后需要显式重发。缓存节点分页具有行数与字节限制，控制准入也有上限。

节点连通性拥有独立元数据，不发布现有维护写者确认。新节点在执行层保持离线，并报告 `executionReady: false`。因此可以先验证接入和入口，再允许运行时分发授予任务或影响进程归属。已在本地验证两个独立源码和编译节点进程；公网入口与跨电脑验收仍然必需。

## 本地路由与 Admin 接入

[运行时路由器](../../../../gateway/src/runtime-router.ts)在调用本地适配器前解析精确、经过账号授权的环境。放置判断使用真实节点 UUID，与目录的可用性标签分开。本地适配器读取当前项目授权服务并准备现有账号／项目上下文；现有生命周期属主继续校验本地分配和进程代次。显式环境身份贯穿 HTTP 与 WebSocket 分发，并计入失败 HTTP 审计详情。缺失、冲突和远端环境不会回退到其他属主或本地端口。WebSocket 拒绝保留声明的 HTTP 状态。

Admin 部署页独立管理节点接入，不等待其他部署读取。它只保留一个有界分页，刷新不连接节点，轮询不会与未完成读取重叠。接入码保留在组件内存，默认遮蔽且仅显式复制。变更结果不确定时要求检查目录；显示成功前验证回执的节点、修订号和签发身份。连接状态与维护写者状态使用不同标签。待接入计算节点预留保留现有完整备份限制，登记时在提交前说明该影响。

## 现有 Gateway 服务转发

[服务代理](../../../../gateway/src/node-service-proxy.ts)先解析账号获授权的 RuntimeId 或管理员显式获授权的节点，再打开[节点服务流](../../../../gateway/src/node-service.ts)。出站代理只连接运维配置的回环 Gateway，核验其组织／节点／发布身份，并转发既有 HTTP 或 WebSocket 协议。同一项目保留本机 Launcher、Supervisor、策略投影及插件组合；节点 Gateway 使用现有共享组织控制面。目标电脑再次检查浏览器认证及业务操作。一次性流身份与当前连接代次阻止其他节点或过期租约提供连接。

控制探测与服务连接分别限额。HTTP 数据按背压传输，二进制消息有大小限制；元数据／文件的总大小限制由原有服务负责，保留大附件下载及安装流。请求取消、节点撤销、通道断开及关闭流程释放所属连接，不重试转发操作，也不证明进程已经终止。节点凭证失败转换为服务不可用，不作为浏览器认证失败。组织级权限通知只停止本机管理器分配或仍持有的运行时，保留各 Gateway 独立的权限监听。

现有 Admin 外壳通过 `/admin/computers/<节点 UUID>/...` 绑定所选电脑。Router 链接保留前缀；现有 API 方法、安装流和下载提交明确目标。切换电脑替换整个文档，不在旧页面操作仍存活时修改共享请求目标。中心身份与有界目录分页独立加载，登记操作仍由中心处理。远端项目设置快捷入口不能启动中心 Runtime，在用户界面接通选择前保持不可用。

[编译场景](../../../../gateway/tests/run-built-node-service.mjs)使用两个独立 Gateway、一个节点代理进程、PostgreSQL 和项目提供的 Web Profile，覆盖中心登录、精确 Admin 管理、同账号两个 Runtime 并行、所选环境元数据、真实工作区事件、公网 Webhook 转发、代次校验的生命周期控制及保留的退役回执。服务转发仍需显式开启验证开关，默认关闭。该场景使用本机进程；真实电脑／公网网络验收及用户界面选择仍是独立工作。

## 现有 Admin 与空间管理

现有 [Admin 路由](../../../../gateway/admin-ui/src/App.tsx)与[管理操作](../../../../gateway/src/admin-api.ts)继续作为管理入口。多电脑支持扩展这些操作的目标解析与下发。组织、账号和项目策略保留现有归属；选择电脑不会产生另一套账号、模型目录或配额账本。

[创建账号](../../../../gateway/src/postgres/user-service.ts)时配置个人空间。现有账号管理流程承载电脑授权和额外个人运行时分配；获得电脑使用权不引入个人运行时自助创建权限。[项目分配](../../../../gateway/src/postgres/project-service.ts)保留管理员配置空间和用户创建、自主管理空间两种来源，继续使用当前成员邀请与读写权限。新分配的空间记录选定电脑。项目成员身份不授予电脑使用权：成员进入项目前需要取得承载电脑的使用权限。

[目录授权](../../../../gateway/src/runtime-directory-grants.ts)在所属电脑上保留账号主目录及已获授权的项目挂载。同一账号在同一电脑上的个人运行时使用现有获授权工作目录，每个运行时分别保存 Session、插件组合和运行时设置。不同电脑解析各自本地根目录；新增电脑不复制绝对路径或同步文件。现有文档归属及私有存储协调规则继续有效。

管理员保留现有账号、空间、文档、归档、插件、终端和部署管理操作。现有用途受限的管理凭证仍绑定对应操作；设备管理不能替代插件资格、会话确认或物理资源准入。共享桌面按真实节点／桌面组合独占，因此不同电脑可以并行操作。经过授权的 Gateway 连接丢失后，继续拒绝新任务并收敛受影响的执行。原电脑上的现有数据予以保留；导入其他独立部署后续实现。

| 现有 Admin 范围 | 保留原属主的策略与数据 | 电脑／运行时扩展 |
|---|---|---|
| 账号与空间 | 同一组织账号、角色、状态、个人空间、项目属主、成员及邀请模型 | 在现有账号／空间流程配置电脑授权与运行时分配；生命周期操作明确作用于单运行时或整账号 |
| 插件与资格 | 现有 Profile、设置层、受保护模块和资源资格 | 在所属电脑上查看、配置及应用到精确运行时，保留期望／已应用／运行版本校验 |
| 模型、配额与用量 | 组织目录及凭据、账号／项目覆盖与配额账本 | 向全部受影响运行时投影策略，跨电脑汇总用量；新增运行时不重置配额 |
| 文档与归档 | 现有账号／项目归属、可见性、文档 incarnation 和不可变 Session 代次 | 列表、内容读取、传输及退休操作携带真实电脑／运行时定位 |
| 终端、SSH 与桌面 | 现有终端归属、SSH 授权、VNC 查看／控制确认及 Computer Use 准入 | 同时解析运行时所在电脑与真实资源所在电脑，保留各能力的并发及撤权规则 |
| 部署与管家 | 现有维护、配置版本、备份覆盖及专用管家授权 | 中心网络／数据库／签名设置留在中心；机器本地路径、压力及进程设置应用到所属电脑 |
| Webhook 与审计 | 现有端点权限、投递回执、执行账号及审计操作人 | 执行和回执绑定所选运行时／电脑，并随操作记录该身份 |

现有[节点设置](../../../../gateway/src/node-config-fields.ts)同时包含 Gateway 服务设置与机器本地设置。远程配置需要保留这一差别。节点代理只接收获授权的本地配置与凭据，不接收中心完整配置或数据库秘密。Admin 筛选与目标选择只影响对应操作；组织级设置保留现有范围。

## 精确 Runtime 记录

现有目录只在一个获授权环境匹配时解析属主选择；选择存在歧义时要求 Runtime UUID。本地服务选择之前先解析所在电脑，包括空间切换、根资源及 WebSocket。管理员服务分发不依赖管理员个人 Runtime 所在电脑。生命周期队列和签名操作生产者保留所选 UUID，运行时消费者要求凭据／请求凭证的 UUID 一致。这保留现有授权和生命周期归属，同时防止操作到达同属主的其他实例。

[个人存储](../../../../gateway/src/runtime-layout.ts)把每台电脑的账号工作目录与 Runtime 私有设置、Profile 及 Session 数据分开。现有实例保留已发布目录和监督进程名称；隔离实例使用 UUID 目录及监督进程名称。工作目录授权保留账号／项目归属。账号偏好保持组织账号级，沿用现有旧设置迁移来源。插件期望状态行及已应用标记归属精确 Runtime。模型策略文件使用其私有目录，计费及模型配额仍按账号／项目统计。

模型回传凭据归属 Runtime／电脑，用量计费仍归属账号／项目。投影在复用凭据之前解析精确、已准备的本机实例；同属主其他实例的启动或策略刷新不能使现有回传方失效。旧回传凭据保留用于一并升级时的清理。准备中的分配既不接收策略投影，也不获得执行准入。生成的个人监督进程键使用账号名称不允许的下划线命名空间，防止新增 Runtime 复用旧账号的监督进程名称。

迁移082在实例分配删除后保留属主／节点的进程代次计数器。因此，现有资源协议可以继续使用数值代次，不会在独立 Runtime 之间碰撞，无需另建执行坐标命名空间。资源登记同时保留 Runtime UUID，确认停止后的清理不能回收同属主其他环境的占用。真实桌面键仍为节点加桌面。排队工作分配时重新核验绑定的节点连接；活动及不确定资源要求所属完成报告或确认进程终止。

文档目录和文件系统投影根归属某台电脑上的账号／项目。该电脑上的个人 Runtime 共享其账号工作文档；不同电脑上的同名路径及文件实例仍是独立记录。Session 执行来源、持久化会话元数据及归档命令保留 Runtime 身份。归档文件清理留在文件所在电脑。未分配历史元数据不授权替代 Runtime，已发布 Session JSONL 代文件保持不可变。[节点参考](../../../../gateway/docs/node-agent/README.zh.md#runtime-isolation)负责面向运维人员的存储和凭据要求。

[分配服务](../../../../gateway/src/runtime-management.ts)在本地配置之前预留身份和账号总配额，文件系统操作不持有数据库锁。持久请求 UUID 用于恢复原始结果或继续准备中的实例。存储准备不完整时拒绝启动。覆盖策略在清除及重建时保留修订号，防止旧编辑器覆盖较新的策略。这些决定支持慢电脑及离线电脑，不自动重试修改操作。

退役复用现有管理器的进程所属破坏性租约及代次校验的静止证明。它保留数据、存储历史及回执，并关闭受管账号的自动实例修复。删除账号前检查所有电脑上的分配；远端进程尚未确认时拒绝删除，不把断连视为已停止。本地配置变更枚举每个实例，现有 outbox 向各 Gateway 送达权限变化。现有生命周期、监督、资格和资源策略继续由各自服务负责。

Webhook 端点与回执保留精确 Runtime 及电脑。现有配置编辑保留绑定；预留操作在准入事务中检查当前修订号及节点。公网入口把原始签名字节转发到所属 Gateway。已退役个人 Runtime 的清单继续作为备份属主。这些后端操作不启用默认关闭的服务转发，也不完成用户界面和真实网络验收。

## 管理模型与实现盘点

登记电脑承载相互独立的运行时插件组合、运行状态目录和进程生命周期。工作目录保留上文的账号／项目授权。一个运行时可以包含多个 Session、Agent 和子进程。节点身份、稳定的 `RuntimeId`、账号／项目归属、进程代次及资源归属分别表达不同事实。Gateway 负责统一发现、授权、配置意图和路由；节点本地 Provider 负责执行及资源操作。运行时业务能力保留 Service Definition、Provider 和 Consumer 分工，传输基础设施不接管各插件的授权或共享规则。

Admin 管理接入电脑、账号授权、运行时分配与生命周期、插件组合、配置应用、资源占用和诊断。用户端展示调用人实际可用的电脑与运行时，在每个工作视图持续标明设备／运行时身份，并在开始工作前明确目标。账号／项目权限、会话当次确认和当前资源可用性保持为不同事实。

共享输入资源使用节点加桌面等资源身份；持有者包含精确运行时、进程代次、工作流和已授权参与人。把 RuntimeId 加入资源键会错误地让每个运行时分别锁住同一个桌面。不同电脑的资源相互独立。Computer Use 资格、会话显式确认与独占租约保留各自检查；无法确认驱动已停止时，不能把桌面交给另一个运行时。VNC 查看与控制、终端会话、文件系统根目录、SSH realm、CPU／模型准入分别保留由各能力拥有的共享、确认、并发和撤权规则。

授权需要明确哪些用户的哪些运行时可以使用某台设备的能力或具体资源。使用资格、会话当次明确同意和当前租约持有者分别判断。运行时所在电脑与资源所在电脑可能不同，例如 SSH 目标或远程桌面；资源授权及占用跟随实际资源属主，用户端和 Admin 都要保留这一差别。

账号停用和删除需要在全部节点撤销权限，并枚举该账号的个人运行时及以其参与人身份执行的工作。停止请求、确认进程退出和节点不可达分别表达不同结果。必要的节点清理尚未确认时，数据退休不能报告完成。移除某个参与人不停止其他账号仍在使用的共享项目运行时。单运行时破坏性操作与整账号退休需要明确各自范围，并保留迁移 078 对替代启动的保护。

后端保留现有各能力的共享与独占规则。用户／Admin 交互改动消费其精确环境目录、电脑权限、生命周期控制和操作回执。为部署开启服务转发之前，仍需要完成真实网络验收。

## 实施顺序

[浏览器身份与文档位置决策](../../implemented/architecture/2026-10-29-browser-runtime-and-document-location.zh.md)记录已实现的标签页隔离、电脑卡片、直接存储授权和经校验的跨电脑复制。本提案继续保留更广泛的部署验收及延后的平台要求。

1. 以现有 Admin／空间行为，以及身份、权限和能力资源盘点作为实施基准。
2. 将组织账号身份与节点本地进程分配分开，再把精确运行时寻址迁移到存储、请求凭证、运行时回调、客户端归属及每项现有管理操作。放宽属主唯一约束前，保留现有生命周期及授权保证。
3. 通过已认证出站传输扩展现有账号／空间分配、配置、插件管理和节点 Provider。电脑使用权同时落实到目录读取及实际启动／执行准入，包括排队任务和运行时回调。验证生产入口，并在完整授权路径就绪前保持远端执行关闭。
4. 后端完成后，再一并完善现有用户端与 Admin 流程，包括资源占用、排队、撤权、重连、性能隔离和按设备恢复。之后通过同一能力接口增加 Windows。

## 性能要求

前端首次目录来自中心元数据。每个环境分别拥有新鲜度、完整性、就绪和失败状态。远端搜索在各节点完成时发布部分结果。目录失败不构成删除证据，非活动环境不因刷新列表而启动。

目录使用有界的可恢复枚举或节点本地扫描快照；分页不能重复完整递归扫描和排序。只有展开层级和可见行需要读取及 DOM 节点。文件内容和 Session 历史使用带版本的窗口。缓存键包含已认证账号、环境和版本；保留量有上限，撤权会失效相关条目。

节点队列与全局准入分别有界。交互控制和内容拥有独立于大文件传输的预留容量。取消沿所属请求穿过 Gateway、隧道和节点；关闭一个视图不能取消另一个视图共享的读取。重连恢复有界且带修订号的元数据，不发送全部文件或会话全文。

## 考虑过的替代方案

**浏览器连接独立 Gateway URL。** 本版拒绝：组织登录、项目权限、凭据及原生资源路由需要同一个已验证目录和路由属主。否则每个浏览器都要实现部署联邦。

**为账号／项目 ID 增加电脑选择器。** 拒绝：同一账号可以拥有多个个人环境，而运行进程可以改变代次。节点名、端口和显示标签无法保持会话归属。

**首版让单个协作项目跨电脑运行。** 延后：每个项目的共享执行、文档归属和持久写入保留在一台选定的电脑上，不同项目可以放在不同电脑。

**等待所有节点或向中心镜像全部文件树。** 拒绝：最慢节点决定响应延迟，索引、内存和传输成本随每个远端目录增长。中心保留有界摘要；节点拥有文件枚举和搜索索引。

## 验收标准

- 同一个账号在同一台电脑及不同电脑上使用多个个人运行时，并遵守当前授权与配额。
- 不同用户拥有不同的可用电脑／运行时集合；每个工作视图标明实际设备和运行时。
- 切换电脑时，现有 Admin 操作保留各自策略范围；延迟返回或操作不能查看或修改其他运行时。组织／账号／项目配额继续由所属运行时共同使用。
- 不同协作项目可以分布在不同电脑上，每个项目仍只由一台电脑承载。
- 邀请或项目成员资格不能在缺少承载电脑使用权时授权进入或执行。现有个人及项目目录保留获授权归属。
- 两个运行时竞争同一桌面时不能交错控制；独立桌面可并发使用。撤权和清理结果不确定时保留现有确认要求。
- 发现和执行都重新核验当前账号及项目授权。已退役、已停用和跨组织身份不能授权工作。
- 环境身份跨 Gateway 替换和普通进程代次变化保持稳定；已发布的 Session 数据不被重写。
- 缓慢或不可达节点不能拖延健康节点结果、浏览器输入或停止请求。大目录、受限网络和大文件传输场景经过已构建的前端资源及真实 Gateway／节点路由。
- 接入、控制和变更回执绑定节点身份、环境、代次及操作 ID。停止结果不确定时，绝不释放进程归属或在其他位置启动替代进程。
- 在全部所属节点的数据与已停止写者得到确认前，继续拒绝完整多节点备份／恢复。节点和中心备份标识各自实际覆盖范围。

## 风险

目录发现本身不启用远端执行。凭据、principal、插件状态、资源准入、归档身份及电脑本地路径，需要一并部署各自支持 Runtime 身份的实现。前端模块 release 需要兼容性准入；不能将任意节点插件图注入同一个页面。性能要求需要可复现测量和浏览器输入证据，之后才采用数值化发布预算。
