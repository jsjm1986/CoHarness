# Agent Note: rc1 client-lane audit

Status: proposed

English | [中文](2026-09-30-rc1-client-lane-audit.zh.md)

## Problem

Upstream `v0.2.0-rc1` rebuilt the client channel. Six new `packages/api/*` controllers (`session-controller`, `workspace-controller`, `settings-controller`, `job-controller`, `workspace-files`, `account-controller`) own Typert Remote namespaces plus React-free `/client` object layers, and eighteen new `packages/client/*` packages arrived beside them. The [alpha.2 audit](../../implemented/architecture/2026-09-20-upstream-alpha2-client-lane-audit.md) adjudicated the alpha-era file residue and rejected wholesale replacement of the local stack (`client/runtime` object layer, `client/connection` + `host/apiproxy` wire, `ui-conversation`/`ui-workbench` surfaces). rc1 moves that same object layer into the controller packages' `client/` halves and rebuilds `ctx.remote` on a PeerScope authorization model the local Typert does not have, so adoption is again per-behavior, and every added package needs a recorded verdict against a named local anchor.

## Proposal

Keep the local client stack; adjudicate each rc1 package as **port** (wire-agnostic behavior absent locally), **adapt** (behavior exists upstream but rides the Typert/api-controller transport, so adoption means a `client/runtime`/`apiproxy` adapter), or **skip** (duplicates a deliberate local surface or an absent upstream host capability).

## Alternatives considered

**Adopt the rc1 controller stack wholesale.** Rejected for the same reason as alpha.2, now stronger: the controller `client/` halves are generated against `ctx.remote.<ns>` Typert namespaces plus gateway `RemoteJournalStream`/`RemoteSnapshotStream` carriers and the `PeerScope`/`invocation.peer` authorization model (`packages/typert/protocol`, `connection/src/operator-peer.ts`), none of which exists on the local wire; adopting them would discard the Workbench and `host/apiproxy` ownership the fork deliberately keeps.

**Adopt only the controller `client/` halves.** Rejected: `api/session-controller/src/client/sessions/remotes.ts` shows the object layer is a transport projection of the Remote namespaces — without those namespaces the halves are dead code, and `client/runtime` already carries the same lineage with local extensions (`conversation-*`, `queue-mirror`, `pending`, `pool`, `steering-history`, `subagent-lineage`, `tool-call-tree`).

**Skip `ui-settings-*` wholesale because the cards exist.** Rejected as stated but narrowed: the packages are skipped, while the *namespace drift* (`bash-sandbox`/`pwsh-sandbox`, `subagent-model-selection-settings`) is recorded as a schema hazard for future syncs rather than ignored.

## Acceptance criteria

- All six rc1 api controllers and eighteen new client packages carry a verdict, a local anchor, and evidence paths in this note.
- Every `Only in upstream` `src/` entry in shared client packages is either re-affirmed from the alpha.2 ledger or named in the un-ported table.
- Each adopted feature lands with its own Agent Note and consumer; an unported entry with no scheduled work stays listed here.

## Risks

- The tables record disposition, not feature equivalence; upstream-only files inside a skipped package (e.g. `ui-chat` conversation nodes) are still unadjudicated behavior until their own port lands.
- Namespace drift between upstream profile-entry settings ids and local capability namespaces means copying an upstream card or form verbatim writes the wrong namespace; every settings port must resolve the namespace on the local host first.
- `PeerScope` absence gates any future controller adoption on a Typert upgrade, so the skip verdicts are structural rather than editorial.
- `ui-sidebar-documentpreview` splits preview ownership across client parsing (upstream) and host `renderOffice` (local); adopting pieces piecemeal can leave two render paths for the same document type.

## Verification

- `diff -qr $UPSTREAM/packages/client/<pkg>/src packages/client/<pkg>/src` per shared package reproduces the only-upstream lists (upstream root: the `dsh-v0.2.0-rc1` worktree).
- `diff -qr $UPSTREAM/packages/api/<controller>/src/client packages/client/runtime/src/client` reproduces the object-layer overlap for `session-controller`.
- `grep -rn "@Remote" $UPSTREAM/packages/api/<controller>/src` vs `grep -n "RpcResponse" packages/host/apiproxy/src/api/<domain>.ts` reproduces the endpoint parity claims.
- `grep -rn "PeerScope\|PeerId" packages/typert packages/api` (empty) vs the upstream tree confirms the authorization-model gap.
- `grep -rn "remote.pluginManager" packages/client` (empty) confirms the missing local consumer for `ui-plugin-manager`.
