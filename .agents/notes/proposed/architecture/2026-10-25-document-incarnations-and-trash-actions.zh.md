# Agent Note: 文档实例与回收站操作身份

Status: proposed

[English](2026-10-25-document-incarnations-and-trash-actions.md) | 中文

## 问题

文档路径目前同时标识活跃文件、保留的回收站文件和目录索引行。复用已清除的路径可能隐藏新文件，复用已回收的路径可能沿用旧上传者为所有者。延迟的完成或目录回调无法区分旧文件与替代文件。字节相同不能证明当前目标文件由某次上传发布。

## 提案

保留 `UserDocId` 作为普通相对文件地址。每次发布分配持久的 `UserDocIncarnationId`，每次回收操作分配独立的 `UserDocTrashId`。原位编辑和 API 移动保留文档实例；新上传创建另一实例，即使名称和字节与旧文档相同。每次变更和目录更新携带预期实例及单调修订号。

本地提供方拥有独立的 SQLite 身份数据库。Gateway 组合把权威元数据与变更锁放在模型可写的项目及个人根之外、由服务端拥有的目录中。文件对象链接仍留在文档文件系统。数据库记录活跃、回收、清除和缺失的文档实例、原始创建者来源、已使用的回收站 id，以及一个已准备的文件系统变更。独立的单调变更序号阻止已放弃的操作提交后续重试。目录改名一次性提交所有已授权路径，并拒绝授权后发生变化的清单。

目录投递使用持久且有序的日志，与文档元数据在同一事务提交。每条记录用变更序号及变更内序号链接到前一个投递位置。这样既能在大型目录变更中进行有界分页，也能区分已放弃的变更预留所留下的序号空隙与实际缺失的投递记录。分页同时限制条目数和完整序列化 UTF-8 响应字节数。单条记录过大时会失败，但不会丢弃它。接收方把根 id 绑定到授权作用域，在同一事务提交目录变更和游标，然后确认已投递的前缀。确认失败会从接收端已验证的游标重试；确认不能跳过未知位置或未来位置。

操作的认证发起人与文档原始创建者分别保留。后续浏览器轮询、恢复任务或投递调用方不能给早先变更换成另一个发起人。未知发起人保持未知。所有权转移修改目录所有者，不替换不可变的原始创建者。

提供方拥有的一把文件系统锁覆盖跨实例的恢复和文件变更。准备记录先于普通文件变化写入。私有对象链接固定每个活跃或可恢复实例，防止 inode 复用冒充该实例。缺失或已清除的实例释放该链接。临时变更锚点在元数据提交和物理清理完成前保留精确的源对象；内容哈希仍只校验完整性。硬链接标记跨重启标识被移动的目录，元数据提交覆盖完整的已授权清单。恢复在接纳下一次变更前等待记录的操作结束，并保留无关替代文件和所有结果不确定的剩余副本。

普通文件对账在完整根目录内解析保留对象的唯一匹配，然后才释放缺失身份。原地址被替代文件占用，不会使新地址上的原对象失去身份。地址互换的元数据及关联投递原子提交，不操作物理文件，也不引入新的持久意图格式。额外及有歧义的硬链接保持未归属；未变化的精确地址保留原身份。单文件读取遇到未知或被替换的对象时也会请求根目录对账。已观察对象发生变化时，扫描会拒绝，保留其身份依据；已完成上传的重试会解析原实例的当前地址。

目录准入除保留对象身份外，还检查所选文件的大小和修改时间。[文件夹决策](../../implemented/feature/2026-08-19-document-workspace-folders.zh.md)拥有私有目录捕获、排他回滚及取消证据。请求报告选择失效；恢复完成已经证实的取消，不再重复该请求的失败。元数据提交失败会保留发布证据。

分块上传发布使用上传的持久身份和经过认证的原始参与者。重放已完成或已清除的实例不能再次发布。运行时 HTTP 消费方、Gateway 代理与目录、复制和管理员操作、浏览器行键、草稿及生命周期请求一同迁移。延迟回调不能覆盖较新的实例或修订。所有权转移仍由目录决定；创建者来源不能覆盖后续所有者。

导入旧回收站时不改变其字节。保留旧目录历史和每个已提交的 Session 代次。当历史上传证据无法区分活跃替代文件与旧路径所有者时，新实例的创建者保持未知，要求显式所有权决定。不根据大小、时间或摘要推断上传者。在改变任何必读的持久字段前检查实际序列化的文档提示准入数据。

生产部署使用 root Gateway 和独立的 systemd 运行时账号。已完成文件必须允许所属运行时账号访问，经过认证的上传参与者与投递记录则必须位于该账号可写目录之外。把上传清单交给共享运行时拥有，会让其模型能够伪造另一参与者的身份绑定。因此，受管运行时需要一同接通由 Gateway 提供的文档服务和受保护控制存储；仅改变 Unix 所有权无法完成迁移。受保护发布和保留对象链接还需要文档文件系统上、运行时可写挂载之外的位置。

[元数据日志](../../../../packages/attachment/userdoc-local/src/identity.ts)、[投递日志](../../../../packages/attachment/userdoc-local/src/projection.ts)、[文件执行器](../../../../packages/attachment/userdoc-local/src/mutation.ts)及[连接持有方](../../../../packages/attachment/userdoc-local/src/identity-fs.ts)服务于受管 Gateway 后端。显式且互不包含的根分隔公开文件、私有元数据及同文件系统保留对象。私有 schema 版本 4 在支持的主机上使用持久文件系统 UUID 绑定目录对象及数据库文件；Gateway 清单在写入前登记所有根。经过验证的部署恢复核对摘要与原始对象证据、重建硬链接并重新绑定新对象，同时保留逻辑身份和投递位置。[生命周期决定](../../implemented/architecture/2026-08-27-document-index-pagination-and-trash-lifecycle.zh.md)负责当前受管及独立模式行为。

[Gateway 提供方](../../../../packages/attachment/userdoc-gateway/README.zh.md)将捕获的执行引用与交互断言分开，并在有界元数据之外流式传输文件字节。生产接收方认证运行时令牌、解析当前参与者并授予精确变更选择。运行时通知只触发受保护对账，不信任其提供的文档事实。待完成请求持有方等待已接纳的调用；已移交读取仍由消费方持有。

运行时分发器在维护准入前分类操作，并保留已接纳变更的写入计数直到响应结束。读取触发的观察、中断恢复及投递确认也持有写入计数；未变化文档的已初始化读取仍可使用。独立发布检查覆盖包链接、非空运行时入口，以及普通 Node 对文档协议和服务端导出的导入。

Linux 文件证据、锚点捕获、发布与移除保留已打开的父目录描述符，并在拒绝操作时保留恢复链接。真实运行时账号验证覆盖已发布文件访问，以及对元数据、发起人清单和保留对象的访问拒绝。原生排他目录移动保留父目录、保留验证后出现的目标，并重试中断的命名空间同步。macOS 与 Linux Node 22/24 的指定屏障验证了源和目标父目录替换。验收仍需完成更多保留根归属检查，以及剩余平台矩阵；提案继续保留以约束这些要求。

## 已考虑的替代方案

**永久保留旧名称。** 这会阻止普通文件复用，且没有改变路径身份问题。

**用内容哈希或 inode 作为文档 id。** 相同上传是不同文档，而编辑器的原子保存可能更换 inode，却不转移所有权。

**只保存设备号与 inode。** 文件系统可以在取消链接后复用 inode。活跃或可恢复的实例需要存活的对象链接；清除或缺失转换完成时释放该链接。为已清除或缺失的历史保留链接，会在没有可恢复承诺时继续保留字节。[Node 文件系统时间戳](https://nodejs.org/api/fs.html#stat-time-values) 不能代替存活对象：创建时间可能退化为变更时间或零。

**只改变目录唯一索引。** 本地回收站选择和过期文件系统请求仍会指向错误文件。

**只在单个进程中串行化回调。** Promise 队列既不能在重启后恢复丢失的回调，也不能给运行时和 Gateway 代理之间的操作排序。已确认的持久位置允许重试，且不让过期回调重新激活另一个文档实例。

## 验收条件

- 真实个人及双成员项目流程能在同一路径保留多个回收站条目和活跃替代文件。新上传者拥有新实例；永久清除保留历史且不隐藏替代文件。
- 旧回收站 id、旧授权快照、延迟上传完成及延迟目录回调不能移动、删除、恢复、清除替代文件或改变其归属。
- 文件编辑、移动、目录改名及恢复到另一名称保留预期身份。目录授权覆盖准确的当前内容，包括并发新增文件。
- 已准备的文件系统操作和已提交的清理能跨进程退出、取消及 I/O 失败恢复，且不覆盖无关文件。所有者关闭数据库前等待已接纳的工作结束。
- 源码与构建应用组合、真实 PostgreSQL 迁移及目录测试、浏览器流程一起验证物理字节、身份、所有权和审计历史。受支持的 Node 版本与平台语义仍受覆盖。
- 所有公开消费方使用迁移后的身份与协议版本。保留旧数据和不可变 Session 代次；无法证明的历史归属明确呈现。
- 元数据与投递追加在失败时一起回滚。延迟或重复确认不能删除尚未投递的工作。真实接收目录测试证明根绑定、事务游标推进、重试和原始发起人审计归属。
- 受管备份与恢复通过已验证的快照证据保留逻辑身份及原始所有权，并重新绑定新的内核对象。逐文件复制旧设备号与 inode 记录不构成有效恢复。移除作用域时，也会关闭身份所有者，并把受保护元数据纳入数据保留处理。

## 风险

元数据数据库引入另一份由提供方拥有的持久介质。其生命周期、备份、schema 迁移和恢复必须与文件存储共同验证。私有目录冲突、元数据不可读或无法证明的恢复结果必须保留数据并显式失败。不区分大小写的路径别名需要规范化为真实文件系统地址。单独的模块测试不能证明组装后的授权或文件系统与目录一致性。

接收目录不能仅因文档根下的可写元数据通过解析，就把它视为经过认证的授权依据。启用前必须审查受管文件系统和 shell 策略、发布身份及服务端发起人证据，包括共享项目中的模型是否能伪造创建者、发起人或投递记录。
