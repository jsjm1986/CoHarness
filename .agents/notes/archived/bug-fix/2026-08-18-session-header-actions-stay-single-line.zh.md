# Agent Note: 会话头部操作保持单行

Status: implemented
Archived: 2026-08-18

[English](2026-08-18-session-header-actions-stay-single-line.md) | 中文

## 问题

会话头部在同一行组合对话标题、项目可见性、Agent preset、子代理目录和工具入口。项目共享操作还常驻显示一个具有独立最小宽度和多行文本的参与者卡片，子代理入口则允许数量标签换行。在桌面端对话列宽度受限时，这些控件会占尽标题区域，使相邻标签堆叠或相互遮挡。

## 决策

项目共享操作只渲染一个包含可见性、参与者数量和展开图标的行内入口。创建者姓名、参与者姓名和参与次数继续放在现有菜单中，不再重复显示在入口下方。共享入口和子代理入口分别保留单行宽度，不改变各自菜单内部的文本布局。现有面包屑继续承担可伸缩区域，并在这些紧凑控件发生碰撞前截断。

## 验证

协作组件测试固定了菜单关闭时不显示参与者详情、打开菜单后才显示详情的行为。组装后的 Chromium 场景在 1024px 桌面视口同时挂载项目共享、PTC preset 标签、6 个子代理和会话工具入口；几何 golden 验证单行布局、矩形按顺序且互不重叠、参与者详情只存在于菜单，以及子代理入口使用禁止换行样式。

## 曾考虑的替代方案

**保留参与者预览并让整个头部换行。** 否决，因为可选插件出现时会改变对话头部高度，并让操作入口脱离其所描述的标题。

**在桌面宽度受限时隐藏 preset 或子代理操作。** 否决，因为两者都会说明当前会话的实际行为。压缩重复的协作详情可以在不丢失上下文的前提下保留三个入口。

**继续把参与者标签放在可见性入口旁边。** 否决，因为菜单已经负责完整参与者列表和参与次数；重复显示会为只在检查协作详情时才需要的信息持续占用头部宽度。

## 后果

会话头部在桌面宽度受限时仍保持稳定的单行高度，并保留所有操作入口。参与者详情需要打开共享菜单查看，但可见的参与者数量仍会提示当前存在协作活动。
