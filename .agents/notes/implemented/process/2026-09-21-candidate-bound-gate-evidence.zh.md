# Agent Note: 候选提交绑定的门禁证据与 fork 消费方

Status: implemented

[English](2026-09-21-candidate-bound-gate-evidence.md) | 中文

## 问题

汇总状态成功仍可能漏掉 fork 消费方、接受没有解释的跳过，或引用其他提交及产物。升级记录可能仍有未完成的源码审查，而发布只校验包版本。替换上游执行器会增加持续合并冲突，却不能补齐这些遗漏。

## 决策

现有执行器保留三态结果和依赖顺序。Hygiene 使用现有模式，共享静态检查负责 vendored 解析、作用域改写、覆盖率排除有效性、测试诚实性和消费方引用检查。全量、分片与增量覆盖率共用测量策略；纯类型声明从源码语法派生，运行时代码缺少测量数据仍会失败。

[消费方关系](../../../../scripts/ci-consumer-relations.json)将循环与 Session 关联到两个 SDK，将模型治理关联到 Gateway 和 Admin UI，将通知协议关联到 Android。源入口和 workflow job 必须存在。选检保留影子运行：公开分类器记录旧计划、候选计划和实际执行计划，CI 执行并集。退役并集需要两批代表性 CI 验收，没有未解释的缩减、扩张或新增执行故障，并通过审查提交记录。耗时不能触发切换。

[执行证据](../../../../scripts/gate-evidence.ts)将稳定身份、原始结果与观察字段分开。[发布就绪校验](../../../../scripts/release/readiness.ts)从候选差异推导最低检查要求，确定唯一升级记录，拒绝未完成验收和未认领路径，并通过认证的 GitHub 产物核对报告原文。发布消费已测试的字节。缺少必需的原生平台、API 或沙箱证据会阻止发布；本地通过不能替代这些环境。

当前非包对齐矩阵记录修改过的上游门禁输入、重放说明、回归源入口和退役条件。上游目标或源码身份变化时，升级记录检查会使旧重放验收失效。上游提供替代实现后，只有消费方回归通过才能退役本地适配。

证据产物名由生产它的 job 定义，区分矩阵分支与运行尝试。构建失败且没有产物时仍记录失败；构建通过时必须匹配每个声明的产物模式。源码兼容性任务准备可用的沙箱，固定的 Ubuntu 软件包来自指定日期的快照，避免常规归档轮换移除下载输入。

## 考虑过的替代方案

**新的登记中心、调度器和六态执行器。** 不采用，因为这些改动会与上游精确固定的门禁清单和结果断言冲突。派生报告可以提供发布证据，同时保留执行语义。

**仅用 import 决定范围。** 不采用，因为 Cordis 叠加配置、worker、发布入口及共享 UI 源码会影响静态导入图之外的消费方。显式关系和保守的组合规则可以审计。

**由发布调用方提供的报告直接证明就绪。** 不采用，因为报告可能省略必需检查或声称使用另一次成功运行。仓库策略决定最低证明要求，GitHub 提供权威报告原文、job 结果及提交身份。

## 后果

源码审查和产品问题修复独立于本实现。待审升级决定、缺失测试环境及存量红灯仍保持红灯。选检可以回滚到并集而无需回退产品工作；发布守卫故障时暂停发布，直到修复或由明确批准的等价验证替代。

Android 是可选功能：原生验证只通过显式 android-audit 套件运行，不属于必需汇总和默认发布要求，并在选检证据中标记为仅手动验证。编译、原生桥接插桩和真实推送送达分别提供证明。严格 Python 类型检查仍后置，在公共 SDK 类型变化或下一次上游 SDK 更新时复评。不引入统一脚本覆盖率门槛，也不新增永久生成的双语门禁目录。
