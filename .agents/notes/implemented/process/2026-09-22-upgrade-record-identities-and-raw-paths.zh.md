# Agent Note: 唯一升级决定与上游原始路径清单

Status: implemented

[English](2026-09-22-upgrade-record-identities-and-raw-paths.md) | 中文

## Problem

两个记录行可以为同一升级 area 指定不同处置，同时都通过普通字段校验。把上游重命名统一改写为目标路径，还会隐藏已删除的源路径，甚至引入比较树中从未存在的目标路径。行数与非空覆盖声明都无法发现这两种歧义。

## Decision

Schema v3 扩展[升级记录校验规则](2026-09-13-upgrade-records-gate.zh.md)。矩阵的 `area` 与清单决定的 `id` 必须显式填写、没有首尾空白，并在各自记录内唯一。当前同步 tag 要求 v3 或更新版本；较早版本的冻结记录保留原有解释。

检查器将 `cumulativeFiles` 及适用的 `incrementFiles` 与记录提交之间的 `git diff --no-renames --name-only -z` 结果比较。每个变化路径只能归属一行。重命名的源路径和目标路径分别保留，使用原始 UTF-8 拼写。漏项、多项、重复认领，以及与实际清单不符的摘要计数都会失败。`historicalPathAliases` 保留早期归一化引用及其来源记录，不将它们计作当前变化。

[CI 输入准备](../../../../scripts/fetch-upstream-baseline.ts)只从固定的公开上游仓库获取本地缺失的比较快照，使用完整提交身份和 `--depth=1`。声明目标必须与同步固定值一致，已有但身份不符的本地 tag 不会被覆盖。输入无效或不可取得时，流程会在校验报告成功前失败；已有快照不会再次触发 fetch。

这些检查证明记录身份和比较范围，不代表源码审查完成、消费者行为等价，也不会把旧 CI 结果转移给新候选。[绑定候选的证据规则](2026-09-21-candidate-bound-gate-evidence.zh.md)继续负责验收。

## Alternatives considered

**只给当前 JSON 去重，不接入实际执行的检查。** 这样只能修好一份记录；下一次升级仍可能接受冲突身份和不完整的重命名清单。

**用新 schema 重写全部历史记录。** 冻结记录描述各自审查代次。只升级当前记录可以增加约束，同时保持历史证据不变。

**统计归一化路径，或获取上游完整历史。** 归一化名称会丢失删除证据；比较只需要已声明的树，完整历史却增加传输成本。原始路径和浅层快照可以直接满足当前检查。

## Consequences

实施中的记录可以通过结构校验，但 pending 审查状态仍会阻止发布。归并重复路由行会保留全部原始路径认领和历史来源，不会把实施或验收标记为完成。

真实 CLI 测试覆盖唯一与冲突身份、Unicode 文件重命名两端、清单漏项和多项、重复路径、错误计数、当前 schema 降级及冻结 schema 兼容。独立的真实 Git 测试验证缺失快照获取、固定 URL 的浅层 fetch、不重复获取、拒绝无效固定值，以及保持身份不符的本地 tag 不变；未请求的更早祖先仍不存在。
