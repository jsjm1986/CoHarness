# Agent Note: 手机视口紧凑密度细化

Status: implemented

[English](2026-10-13-compact-density-refinement.md) | 中文

## Problem

第二轮 390×844 真机审计显示紧凑视口仍有大块桌面级残留：会话头部沿用了约 83px 的"标题+标签"两行配方，输入卡座占约 128px 桌面内边距，代码块保持 16px 卡片圆角和 44px 横幅，消息操作落在 44px 目标上，而每个会话行常驻三个尾部按钮——把 "NavScenario: first run…" 标题挤成了 "NavS…"。两个交互泄漏加重了臃肿感：触屏点按合成的 `mouseenter` 会武装悬停 tooltip、把气泡画在刚点过的控件上，审批接管卡则缺少紧凑配方（而提问卡、计划审阅卡早已具备）。

## Decision

只做密度收紧，不改布局结构。所有改动都是所属包内的 `[data-viewport='compact']` 或 `pointer: coarse`/`max-width: 767px` 规则——除两处刻意的行为修正外，没有 JS 契约、槽位或数据路径改动。

**会话头部。** 紧凑头收敛为应用顶栏下方的一条 36px 横带；标签轨道降到 34px、内部 28px 药丸、`mobile-font-secondary` 字体并可横向滚动，长标签不再挤压工具区。根侧间距降到 12px，正文列间距收紧为 `--dsw-space-3`，滚动区内缩为 clearance+6。

**输入区与正文。** 输入卡内边距收紧为 `6px 12px 8px` 并使用移动卡片圆角，工具行间距 4px；图标行继续沿用 40px 单行方案。用户气泡降为 `--dsw-radius-lg` 圆角、8px/12px 内边距；消息操作沿用同一 40px 目标族、放在可换行的 36px 行内；代码块采用 10px 卡片圆角、40px 横幅行、40px 复制钮和 10px 代码内缩——横幅是修饰而非点按行，因此跟随输入区的图标族而非 44px 触控目标。

**行与接管卡。** 会话行尾部只保留省略号菜单：`row.action` 槽位按钮包进 `display: contents` 壳，在紧凑与粗指针下整体隐藏——每个贡献者（置顶、归档）本就同时以 `menu.item` 发布同名动词，330px 宽的行上常驻三个 44px 按钮等于用标题换重复的可达性。选中行改为 `interactive-bg-active` 平铺填充——全宽抽屉里的凸起卡片读起来像按钮而非选中标记。`ApprovalPanel` 补齐了共享的紧凑接管配方（16px 圆角、`space-3` 内缩、可换行操作行），输入卡座切换不再跳宽度。

**悬停门禁。** `Tooltip` 在 `matchMedia('(hover: hover)')` 报告设备不支持悬停时不再武装 hover 触发；触屏和 jsdom 环境保留 focus/click 路径，合成 `mouseenter` 无法再把快捷键气泡钉在刚激活的控件上。

**触屏隐藏快捷键提示。** 菜单 `shortcut` 键位提示在 `@media (pointer: coarse)` 下隐藏：无键盘设备上 sheet 行尾部的提示宽度换来的只是不可用信息。`aria-keyshortcuts` 声明保留给辅助技术，混合设备行为不变——仅隐藏视觉提示。

**统计胶囊次要段。** 紧凑视口下每个 composer 统计胶囊只保留主数字：速度段与缓存命中段收进 `detail` span 隐藏——390px 下两个胶囊互相挤压导致数字中间截断，信息价值配不上占位。点开弹窗仍携带全部数字，胶囊 `aria-label` 保留完整读法。

**抽屉栈。** 手机抽屉收窄到 `min(82%, 300px)`，遮罩后露出更多会话内容；侧边栏槽位按抽屉的实际解析宽度挂载——固定的 `SIDEBAR_DEFAULT`（280）会在 ≥366px 手机上留下 20px 死条并顺带让品牌居中偏左；logo 行的紧凑内距在两侧镜像浮动开关钮的占位，使标志按抽屉真实宽度居中。头部堆叠（品牌行、新会话 CTA、面板导航列、分组头）削掉约 12px 纵向内距，列表更早开始。会话行保持 44px 触控目标但恢复相对时间戳（caption 层级）——没有它单行"未命名"行读起来像稀疏占位符；空闲行前导状态槽坍塌（`:has(> :only-child:empty)` 匹配 display:contents 宿主），标题落到组标签缩进附近而不是悬在行中段。

**平台按压与列表节奏。** `-webkit-tap-highlight-color: transparent` 去掉浏览器默认灰色点击闪烁（可交互面本就带显式 `:active` 填充）；紧凑态下项目/会话/搜索结果行的按压反馈改为即时 `interactive-bg-active` 填充而非桌面 0.98 缩放——整宽单元格被捏扁读起来是弹性而非可点。会话单元格连续排列，行间用 0.5px 内嵌发丝线（画在每行的 HoverCard 包装 `span:not(:last-child)::after` 上——行类名属于另一个 CSS module 作用域，包装元素的兄弟位置才是可靠的分组末尾判据）。新会话 CTA 在手机上用主按钮填充——整宽中性灰块读起来像禁用条而非按钮。抽屉列表与转录滚动口加 `overscroll-behavior: contain`，触底惯性不再串到遮罩后面的页面。

**手机手势。** 紧凑抽屉由滑动驱动：从左缘 24px 热区向右拖拽打开、在已开抽屉上向左拖拽关闭，均跟手并联动遮罩透明度，阈值为过宽度 30% 或速度阈值。`useSheetSwipeDismiss` 为 Modal 与 Menu 底部弹层提供平台式关闭——sheet 任意位置下拉跟手、遮罩渐隐，释放超过 96px 或速度 0.35 即关闭，短程释放经内联 transform 过渡滑回；不在顶部的可滚动祖先接管拖拽。监听器为原生非 passive，因为 React 的触摸绑定是 passive 而手势需要 `preventDefault`；两条路径在 `max-width: 767px` 之上和 `prefers-reduced-motion` 下均不生效。

**文档频道扁平列表。** 768px 以下文档与文件夹行去掉每行卡片的描边、圆角与层填充，改为与会话抽屉相同的连续行加内嵌发丝线语法；行尾只保留 `⋯` 入口，其动作 sheet 本就承载全部动词。概览与回收站行同样压平；范围选择器变为带底部发丝线的裸标签行；空态去掉虚线投放区边框（`.drop` 浮层保留品牌虚线——它是真实的拖拽提示而非装饰）。搜索框与上传/更多按钮并入同一工具行——桌面 `flex-basis: 460px` 的过滤组会强制换行，手机端给它 `flex-basis: 0; min-width: 0`；面包屑 crumb 条降为 36px 文本行。范围选择器保持单行：其第二行与正下方的说明行信息重复。

**文档频道密度下潜。** 后续一轮去掉了残余的桌面尺度：`.panel` 包装器不再内含卡片（sheet 本身就是表面）；目录 `h2` 降为 13px 节标签；弹窗自身标题行落在共享的 44px 导航行上；骨架占位与真实行一样采用发丝线行；空态主图标改为裸字形；其整宽堆叠动作按钮——与确认/重命名表单按钮、概览头部按钮对一样——读作 40px 圆角矩形（`--dsw-radius-lg`）而非桌面胶囊。工具条的上传/更多按钮对齐共享 `Input` 的 40px coarse 指针下限（16px 文字是硬性要求——低于它 iOS Safari 聚焦时会缩放页面），双行动作 sheet 选项从约 72px 降到 52px 有效高度。

**空间切换器：手机走 sheet 语法而非 hub。** 宽侧栏的内嵌空间 hub——当前空间卡片、分段可见性控件、亚触控头控件——是被塞进 300px 抽屉列里的桌面习惯。`ScopeControl` 现在导出 `hub = wide && !phone`：紧凑抽屉组合与折叠轨道相同的一组条目（带勾选的空间列表、可见性菜单区段、置底操作行），并回到 `Menu` 的 portal 通路——即带下滑关闭手势的共享底部 sheet。触发器在手机上脱去卡片底与中性模式药丸，读作与文档/设置同排的平发行；维护警告丸保留。hub 块本身不变，桌面端仍渲染在触发器上方。

**content-box 算术。** 仓库没有全局 `box-sizing`，`min-height` 量的是 content box，垂直内距会叠加在上：`min-height: 56px; padding: 4px 0` 实际是 64px 行，不是 56。以有效高度为目标的紧凑规则必须减去内距——文档行现在是 `min-height: 44px` + `space-1` 边距，落出约 52px 行。`.scopePickerOption` 自己声明了 `box-sizing: border-box`，其 52px 是含内距的；要读盒模型属性，而不是只看数字。

**设置尾随附属行。** 快捷键行并入"标签+尾随附属"语法（`编辑快捷键 ›`，透明控件；桌面保留药丸），开发者工具开关行补齐选择行已有的紧凑 `space-3` 内距。模型区同样压平：已配置提供方的 `.rowCard`、`.addCard`/`.setupCard` 编辑面与虚线 `.addButton` 占位框全部改为透明发丝线行——虚线框是桌面端"拖入/起草于此"的提示，在手机上只会读成缺失的插图。两个"添加"控件各占独立整宽行（`flex-basis: 100%` 使按钮对换行）而非对半分割——320px 下第二个按钮的文字会词中换行；同时去掉药丸形态的 14px 内距，使标签与区段左缘对齐。已归档会话页的搜索框与行补齐共享的 44px 紧凑目标，第三个设置标签页不再是触控目标偏低的例外。外观选项由三个描边方块收进共享静色轨道上的分段控件（`interactive-bg-hover` 底轨，选中段为 `bg-raised` 凸起块）——与紧凑会话标签同一语法；Agent 预设区的描边 `.card` 网格改为连续发丝线行，选中项仅以底色标识。

**纯色。** 移除紧凑设置标签条右缘的 `linear-gradient` 滚动渐隐——被裁切的标签本身就是可滚提示，调色板保持纯色。骨架微光与思考文本的透明度渐隐保留：它们是透明度遮罩，不是品牌色渐变。

**级联顺序纪律。** `DocumentsModal.module.css` 包含多个 `max-width: 767px` 块，且块间夹着一层无条件规则；写在第一块里的紧凑规则会被同优先级的后置普通规则覆盖。针对该后置层的手机修正必须落在最后一个紧凑块中。

**贴边头部座位。** `.headerCorner` 的 `margin-right: -16px` 伸进桌面头部的尾部内距，但紧凑头部内距只有 `space-3`——角座按钮右缘在每个手机页面上都超出视口 4px。紧凑规则把伸出量重锚为 `calc(-1 * var(--dsw-space-3))`，按钮齐平视口物理缘（边缘目标更易点中），且角座幽灵钮并入紧凑行的 36px 目标族。

## Alternatives considered

**处处保持 44px 触控目标。** 否决：360–390px 宽下一行放不下五个 44px 控件的单行输入工具条和单行消息操作条；40px 族已是成文的紧凑折中（[输入区单行图标行](../bug-fix/2026-09-18-composer-single-icon-row.zh.md)），真正可交互的行（菜单行、选项行、会话行）仍保持完整触控目标。

**会话行操作改用滑动或长按手势。** 否决：行组件没有手势层，且省略号菜单已承载全部动词；把置顶/归档常驻成行内按钮只会继续挤压标题。

**接管卡单独做一套紧凑呈现器。** 否决：`QuestionComposer` 和 `PlanReviewPanel` 已共享 `@media (max-width: 767px)` 配方；ApprovalPanel 的分叉是遗漏而非意图，直接采用同一套规则。

## Consequences

手机端固定纵向开销减少约 40px，正文卡片不再像缩放的桌面窗口；会话列表恢复完整标题和单一尾部入口。非紧凑的粗指针设备（中宽度平板）保留 44px 规则；桌面构建在所有门禁规则之外逐字节一致。纯触屏设备上的悬停 tooltip 没有实际损失——气泡本就不适配该交互；具备悬停能力的设备（触控板、混合平板）行为完全不变。

## Verification

`apps/web/tests/mobile-density.e2e.ts` 在 390×844 下启动真实装配的应用并播种会话，断言紧凑标记生效、会话行可见尾部只剩菜单触发器、正文滚动口无横向溢出、合成悬停不产生 tooltip 气泡。`compact-chrome-styles.client.spec.ts` 与 `compact-styles.client.spec.ts` 的词法契约现在锁定 36/34/28px 头部配方和 40px 代码横幅族。390×844 截图审计覆盖了着陆页、抽屉（折叠与展开）、会话、输入区、详情浮层、轨迹流和设置底部弹层；1440×900 对照截图确认桌面框架不变。`ui-workspace`、`ui-conversation`、`ui-sidebar-right`、`ui-primitives` 测试套件全部通过。`apps/web/tests/swipe-check.e2e.ts` 在 390×844 下用真实 TouchEvent 序列回放手势层：边缘滑动打开抽屉、抽屉拖拽关闭、慢速短程拖拽 sheet 回弹、长拖拽关闭 Menu 与 Modal 弹层、已滚动 sheet 不接管拖拽。
