# Agent Note: 从所属 Gateway 恢复已保存的个人历史

Status: implemented

[English](2026-11-21-personal-history-restore-admission.md) | 中文

## 问题

页面恢复对话时已能识别其账号、Runtime 和会话。等待事件流以及完整的会话与工作区列表会增加最近消息呈现前的往返次数。所属 Gateway 还需在组织数据库中核验历史读取权限，远端访问可能跨越多次广域网往返。

## 决策

浏览器在确切的保存目标上调用[准备历史接口](../../../../packages/host/apiproxy/README.zh.md)。该请求只能使用已就绪的 Runtime 代次。Host 可核准活动中的个人根会话，使标签页在权威目录加载时恢复。用户导航会撤销待恢复的选择。权威目录到达后决定可见性。核验账号和 Runtime 期间，编辑器把新文字留在标签页。只在账号、电脑和会话相符后保存。发送前须核验 Host 目标。首屏使用[同一个有界历史窗口](2026-11-21-node-prepared-history-limit.zh.md)。

符合条件的个人 Runtime 读取由[试点 Gateway](../../../../gateway/README.zh.md#performance-and-runtime-admission)在主入口同步核验组织权限。结构化启动、普通目录读取和历史读取须声明预期账号。准入绑定浏览器登录、请求方法、路径和确切目标。所属端在 Node Agent 有效凭据认证的数据连接上接收准入。撤权监听必须已应用准入中的确切修订号，监督器必须持有获准的代次。主入口在返回结果前复核当前签发方密钥、治理权限和代次。Host 仍验证会话归属和可见性。

## 考虑过的替代方案

**从浏览器历史副本或目录行恢复。** 目录缓存无法证明撤权或归档后的可见性，浏览器持久化还会把内容保存在另一台电脑。

**复用签名准入执行写入。** 创建会话、持久受理消息和登记执行都需要核验提交时的权限。

## 影响

经过核验的首屏可早于目录和事件流呈现。获准的启动和目录请求也可省去远端治理查询。签名、连接、修订号或就绪代次无法确认时，试点沿用普通 SQL 准入。启动保留转发审计，Runtime 完成时仍写入活动时间。防重放记录保留每条有效记录，满额时拒绝新的断言。

[浏览器组合测试](../../../../apps/web/tests/deferred-remote-entry.e2e.ts)延迟 Host 和目录请求，验证保存的历史依然可呈现。[双 Gateway 夹具](../../../../gateway/tests/fixtures/versioned-node-service.mjs)核对同一请求在主入口与所属端的 SQL 次数。[节点服务测试](../../../../gateway/tests/node-service.spec.ts)验证主入口第二次准入失败时拒绝返回内容。
