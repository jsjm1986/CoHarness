# Agent Note: 复用已验证的冷会话列表元数据

Status: implemented

[English](2026-10-26-verified-cold-list-metadata.md) | 中文

## 问题

当投影提示缺失或仍为空白时，重复的会话列表可能反复验证相同的小型冷日志。JSONL 正文读取需要跨项目目录发现目标。一个包含 27 个目录、123 个当前代次会话和 77 次合格探查的固定目录，每次列表会执行 4,281 次代次目录查找，即使重复列表的输出完全相同。工作台使用的个人目录也会承担这项成本。

## 决策

ApiProxy 只保留成功完成有界正文验证后生成的标量摘要。每次列表仍获取最新的持久化快照；复用要求完整头部和带存储来源的修订标识均相同。投影、在线会话接管、可读性及协作信息仍按当前请求获取。[有界空白验证决策](../bug-fix/2026-08-13-bounded-cold-blank-verification.zh.md) 继续负责探查条件、降级方向和排序语义。

新验证的摘要先进入请求内的有界暂存缓存，直到额外一次快照列表确认其存储来源。来源改变或缺失时丢弃候选项；可选验证失败则跳过保留并记录警告，取消仍向上传播。异步验证后再次以在线摘要替换冷结果。不保留日志正文、授权结果、定时器或共享的在途操作。

`coldSummaryCacheMaxEntries` 默认为 512，`coldSummaryCacheMaxBytes` 默认为来源标识和摘要 UTF-8 JSON 合计 1 MiB。任一项设为零会关闭复用及额外验证。ApiProxy 缓存及每个请求内暂存缓存分别遵守这些界限。编码字节计数不代表 JavaScript 堆开销。ApiProxy 卸载会清空缓存，并阻止晚完成的读取重新写入。

## 考虑过的替代方案

**缓存完整列表响应。** 拒绝，因为在线状态、投影检查点和当前身份权限必须独立于持久化日志修订保持新鲜。

**信任空白提示或跳过失败探查。** 拒绝，因为优化未命中时必须保留现有保守可见性规则。只有成功读取正文后推导的元数据可以复用。

**为每个候选项单独查询修订。** 拒绝，因为 JSONL 的目标查找需要扫描项目目录。统一的快照验证避免为首轮列表中的每个合格会话再增加一次项目扫描。

**保留完整解码日志或写入摘要旁文件。** 拒绝，因为标量列表字段不需要事件正文或另一套持久化索引。现有的小型完整日志交接缓存和不可变会话代次继续由各自组件持有。

## 影响

内容未变的重复列表可以省去有界正文探查，目录发现与来源验证仍执行。首次填充缓存的列表会额外读取一次元数据快照。缓存未命中、超过字节界限、没有修订标识或受到目录修订变化影响的条目继续走普通验证路径。该缓存不会加快首个模型请求、文档转换或网络传输。

单元测试覆盖输出一致性、独立行对象、头部与修订变化、并发追加、新投影与权限、验证失败、取消、字节和条目淘汰、关闭复用及卸载。真实压缩 JSONL Web 场景在页面刷新后再次验证侧边栏快照。`packages/host/apiproxy/tests/cold-list.perf.mjs` 中的普通 Node 诊断通过已构建的 ApiProxy 和 JSONL 提供方，以固定元数据提示数量记录工作量和全部样本，不把耗时阈值加入 CI。
