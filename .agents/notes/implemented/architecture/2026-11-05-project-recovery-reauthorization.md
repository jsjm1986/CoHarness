# Agent Note: Scoped backup coverage and recovery reauthorization

Status: implemented

English | [中文](2026-11-05-project-recovery-reauthorization.zh.md)

## Problem

A recovery point does not prove that every storage domain was captured. Runtime files, account documents, plugin state and scheduled deliveries can advance independently. A stopped source also cannot safely resume writing when a later policy change invalidates its recovery approval.

## Decision

Each exporter identifies its covered domains and keeps explicit gaps. Personal PostgreSQL records are limited to the selected organization, computer, account and Runtime; account documents retain their shared account-and-computer identity. Consistent native file snapshots include only approved roots. Unknown plugin state, independent watermarks and missing file snapshots prevent complete protection. An approved scoped provider can certify personal domains through independent validation; installing it alone establishes no coverage. Governance inventory version 7 retains opaque placement, computer permission, quota, name-HMAC, non-content audit, isolation and execution approval fields; versions 1–6 remain readable as partial inventories. None restores login, node credentials or writer authority.

On Linux, the project exporter omits the private model-policy projection at the Gateway's reserved Runtime-home path. That file contains a node-local intake credential that the Gateway issues again at launch. Before the first persisted Runtime generation, an empty home or a home containing only that projection has no managed-file inventory to export. A previously established Runtime with a missing inventory and a home with undeclared files both retain coverage gaps. [Linux backup prerequisites](../../../../gateway/deploy/node-content/README.md) define the approved snapshot roots.

A same-node filesystem move keeps the published paths and writership. Offline reattachment verifies retained physical identities, copied bytes and UserDoc roots before replacing the inode witnesses in a new content revision. UserDoc public and private objects share one mount for hard-link operations. Btrfs snapshots map configured bind mounts through one witnessed source subvolume. After a remount, the filesystem UUID, subvolume UUID and retained inodes authorize a refresh of the kernel's device numbers.

Project recovery rechecks the active administrator, project owner, target computer grant, node admission and current policy before irreversible commits. Policy continuation records a separate immutable approval for the same point, destination and inspected policy revision. A current-revision independent drill is required. Source retirement receipts remain immutable. Ordinary quota and recovery-objective edits cannot change an unfinished recovery.

The target records exclusive directory ownership before installing staged data. Parent and inode witnesses permit retries to reuse only that operation’s installed roots. Cancellation withdraws its candidate and records cleanup before another attempt can use the destination. Nonempty withdrawn directories remain outside the active layout for operator inspection. A local OS-backed project lock serializes workers without retaining a governance database connection while they borrow another connection.

The target activates only the published higher writer epoch after verifying its files and delivery receipts. The same governance transaction records activation and pauses the former source’s policy. Protecting the new source requires a separate policy, receiver and credentials. Unavailable sources and expired leases provide no stopped-writer proof. [Maintenance restore](2026-09-25-gateway-deployment-maintenance.md) independently preserves present-day approvals and fences.

Schedule evidence respects bounded receipt retention and explicit task deletion. All committed schedule messages remain in the recovery digest, even when their task or receipt is absent. Retained receipts must match committed messages, and an active occurrence must follow the Session's recorded deliveries. An ambiguous inbox commit without a corresponding task advance blocks promotion; historical pruning alone does not.

Disaster recovery accepts an administrator's physical isolation attestation bound to the source generation, writer epoch, point and policy revision. It quarantines the whole source identity, revokes credentials and leases, and preserves its unknown process observation. Each project retains a separate approval. The target suspends schedules only in its restored private copy and computes new file and delivery digests; source digests and supervisor stop evidence remain absent. Governance restore cannot erase the attestation, quarantine, execution hold or review receipts.

A stopped target can prepare a separate new-conversation permit without releasing historic work. An immutable node-private policy binds the point, Runtime, node, writer epoch, restored Session set and reviewed artifact/configuration hashes. Governance retains only digests, counts and management metadata. Runtime admission rejects restored Session execution before preset composition; startup and reload require the exact approved composition. Individual component approvals queue another stopped inspection and never stop active work. Uninspectable dynamic code remains suspended. Project encryption and maintenance file selection include these policy files; missing or altered bytes cannot create authority.

Preparation first commits a queued request that denies Runtime admission in SQL. An OS-backed project lock spans profile projection and inspection without holding a governance connection. Publishing the review rechecks that same request, current node lease, stopped Runtime and exact placement. This prevents single-connection self-waits and prevents a second Gateway from changing a profile after the first review permits startup.

Physical isolation and ordinary detachment carry different authority. Immutable isolation evidence, revoked credentials, consumed tickets and stopped desired state let organization administration exclude the retired writer from maintenance and aggregation-close blockers without rewriting process observations. Its original identity remains quarantined through mode changes and cannot enroll or become primary. Replacement computers use new identities.

Governance reconstruction resets credentials and authorization instead of replaying a stale access decision. The bootstrap administrator receives a new password; every other account remains disabled until reviewed and then returns as an ordinary member. Original grants are retained as non-content review metadata while effective grants are denied. Quotas and usage are preserved. The latest monotonic reconstruction epoch owns Runtime admission; wall-clock timestamps and older scope permits cannot select an earlier authority. Release opens account configuration, not Runtime execution.

During governance review, only the new bootstrap administrator can use the dedicated recovery page. Ordinary business, the existing Admin routes, internal APIs and WebSockets remain closed. Recovery commands use their own transaction checks while the cluster is restoring; the deployment and backup exemptions do not authorize them. Organizations without a reconstruction receipt retain the ordinary request path without an additional database lookup. Fresh import records the denied-access projection as each node’s invalidation baseline; discarded old notification history does not prevent restricted startup.

A surviving computer binds existing data only after read-only supervisor proof, exact process-generation checks and local Session/index verification. Unknown writers are never stopped for recovery. The binding keeps actual paths and frozen Session IDs in node-private immutable files, with only hashes and opaque IDs in governance. Runtime preparation, startup, model and directory-grant projection, personal documents and backup collection consume the same verified node-local paths; absent or changed evidence never falls back to an empty standard directory. Manual inspection failures require explicit path resubmission and cannot enter the automatic standard-path queue. Model projection checks the retained directory inode across policy lookups and disables parent creation in the shared atomic writer. Storage relocation retains sealed Runtime homes instead of deriving new locations from root settings. Successful quiescence inspection releases stale in-memory capacity only. A new reconstruction requires a fresh binding and component review, even when an older scope permit is missing.

Account data outlives individual Runtime assignments. An accepted private account-home receipt remains usable after its originating Runtime retires; all accepted receipts for that account and computer must agree and retain a valid physical root. A new ordinary Runtime shares only that home, with separate Runtime storage and no inherited execution permit. Missing bindings prevent allocation before quota or files are reserved; a missing retained root is never recreated as an empty home.

Planned relocation after governance reconstruction binds the current reviewed governance policy, never an older project permit. Its immutable transfer lineage carries only the frozen Session set into fresh destination review. A target receipt proves the installed transferred policy before retirement phases are admitted, so workers without the protocol cannot move the writer. Writer epochs are compared with writer epochs; process generations independently retain their original fence.

The ciphertext receiver and the replacement writer have independent immutable identities. A separate, expiring read credential binds current policy, topology and connection generations; the configured backup operation timeout bounds its lifetime. Transaction-owned admission locks both generations and the grant through drill certification and writer transitions. The point limits operations and manifest access; shared Restic blobs and a repository key do not provide cryptographic isolation between historical points. Target staging verifies platform, volume, files and suspended work before a new disaster isolation can be recorded. Already-isolated older operations can verify missing target evidence without contacting their source.

Schema-135 governance reconstruction packages retain their original checksum and column validation when imported into schema 136. New read approvals and node protocol heartbeats are ephemeral and remain empty after reconstruction. Heartbeats distinguish repository protocol from actually assembled project and personal recovery workers, and renew independently of long backup jobs. Closing a Gateway joins both loops. Legacy receiver-equals-replacement operations retain their identities; source point manifests are never rewritten.

Governance reconstruction validates every historical package against its original column manifest and the matching migration prefix. Schema 145 capture classifies delivery outcomes and device registrations as transient. Import establishes a restoring cluster row even for source organizations that have never entered maintenance. The restricted review therefore applies before a new Gateway can serve recovered identities. [Rebuild organization governance](../../../../gateway/docs/peer-backup/README.md#governance-rebuild)

## Alternatives considered

**Call copied directories complete backups.** Mutable files do not establish a shared checkpoint with databases or external plugin effects. Missing evidence remains a coverage gap.

**Restore the old policy revision or reopen the source.** This could revive withdrawn credentials or create two writers. A new immutable approval authorizes continuation without reversing retirement.

**Delete any occupied staging path before retrying.** A path can contain another operation’s or an operator’s data. Cleanup requires the recorded physical ownership witness.

## Consequences

Native personal format 3 permits an independently verified personal replacement. It retains the account and Runtime, requires existing target access and quota, preserves tab identities and gives account-shared documents one immutable publication receipt. Occupied targets, incompatible Session paths and incomplete points reject preparation. Personal execution uses separate approvals and the same old-Session guard; all restored work remains paused. Governance inventories 1–7 remain partial. A separate reconstruction package restores reviewed management identities into an empty database with admission closed. A missing Mac snapshot service or unverified volume remains a deployment gap. Live tasks are not stopped to obtain a daily backup. Runtime identity and project membership survive replacement; members still require target computer access. Disaster replacement permits reviewed new conversations while retaining old history read-only. A second disaster requires a new permit at its new writer epoch. Planned moves bind the current source’s first immutable review and verify its encrypted policy before retirement. They preserve that exact frozen set, retain later conversations and require new destination approval; they never import source component approvals. Single-computer mode retains execution review for exact published local placements, without authorizing remote management or new takeovers. The primary cannot attest its own isolation through its serving entry.

Personal and project disaster recovery suspend restored `HGW_*`, `DSH_*`, libpq connection settings and `DATABASE_URL` in the target copy. Admin shows only affected setting names for explicit target-side configuration; the encrypted source point retains the original values. Business environment settings remain intact. Ordinary upgrades and planned migration preserve their current environment.

## Verification

Three-identity project and personal fixtures use actual Restic HTTP transfer, independent target rehearsal and target publication after source removal. An administrator-owned project without a personal owner follows the same recovery checks. A schema-135 fixture records isolation before target preparation, applies migration 136, and verifies the missing target evidence from the encrypted point before publication. It preserves source unavailability, suspended schedules and read-only old conversations. Database barriers cover read revocation during drill certification; renewed node identity rejects previous approvals. These checks do not establish native Windows snapshot coverage.

Real SQL export and encrypted restic recovery feed a fresh governance database after removing the source files. The imported database has no old cookies or node credentials; actual Admin HTTP review requires new passwords, preserves denied grants and retains Runtime holds after release. Kernel-backed ownership, real SQLite/JSONL data and managed profiles verify a selected nonstandard Runtime home, frozen root/child history and node-private backup coverage. The real Gateway source entry starts the imported database in restricted mode, accepts new bootstrap credentials, releases reviewed access without creating a steward or starting a Runtime, and pauses queued inspection during maintenance. Real document reads and stopped-assignment retirement verify account-home continuity for a newly allocated Runtime, rejection of conflicting or altered evidence, and continued refusal of retired Runtime access. These fixtures do not assert that production computers have completed reconstruction.

Disposable PostgreSQL instances exercise owner revocation, policy rotation, stale confirmations, current-revision drills, maintenance restore protection, second disaster recovery and activation. The restic assembly removes the source before recovery and drives real Admin HTTP approval on desktop and mobile. Its execution review uses a single-connection governance pool, rejects concurrent starts and stale requests, and excludes a second preparation worker. Private policy export, digest verification and missing-file refusal use actual restored files. A subsequent real restic planned move preserves the original frozen set, keeps a later conversation eligible, preserves Schedule bytes and requires fresh destination approval. A missing transferred policy rejects preparation before source retirement.

The personal assembly uses a complete native fixture, real restic HTTP transfer, an independent drill and target-owned file installation after removal of source files. It checks unchanged root/child history, account document identity, separate tab drafts and fresh stopped-Runtime execution approval. Removing peer-backup provisioning does not bypass or disable the installed approval checks.

The TypeScript source CLI and SDK and the built Python SDK share a recovery transcript: old root and child resume/prompt requests are refused, existing JSONL and inbox bytes stay unchanged, and a new conversation receives a real loopback model HTTP response. The assembled WebHost replays read-only history, preserved drafts and new-message ARIA output. These isolated assemblies do not claim a new native three-computer acceptance run.

Filesystem tests interrupt distinct staging phases, retain foreign files and verify cancellation retry. Separate processes exercise worker lock release after process death. Earlier native Mac-to-Windows encrypted recovery verifies bytes, Session order and delivery receipts after the source and transport are removed; it does not establish full production coverage or a complete promotion time.
