# Agent Note: 节点服务转发检查线协议版本

Status: implemented

[English](2026-11-20-node-service-wire-compatibility.md) | 中文

## Problem

生产中心打开节点服务连接时，将发布目录名作为强制要求。使用相同服务协议但发布目录不同的两个 Gateway 会拒绝转发。中心单独升级时，仍然兼容的计算节点也无法通过中心访问。

## Decision

中心发送既有的 v1 控制命令，字段为 `release: null`。旧命令解析器接受此格式，节点代理要求本机 Gateway 验证节点、组织及当前连接租约。本机身份响应与二进制 WebSocket 子协议共用一个服务协议版本。不受支持的身份响应或流协议会在转发前拒绝操作。旧中心发出的明确发布要求继续生效。

每次传输准入仍由中心认证租约并解析目标。目标端仍执行自己的账号、电脑和 Runtime 检查。池化连接遵循 [HTTP 连接复用规则](2026-11-02-node-service-http-reuse.zh.md)，包括借用时重新核验凭据和租约。

## Alternatives considered

**要求相同的发布目录。** 兼容产物的目录名可以不同。发布或回滚会中断节点转发，直到所有电脑的目录名一致。

**在 v1 控制命令中添加必需的兼容字段。** 现有严格解析器拒绝额外字段，这会要求先替换代理才能升级中心。

## Consequences

先升级中心，使兼容的节点服务在发布目录变化期间保持可用。服务握手或转发协议出现不兼容改动时需要新的协议版本。可共同部署的发布组合仍取决于共享数据库迁移和应用 API 的兼容性。

## Verification

节点服务测试使用两个发布标识不同的 Gateway 监听器和独立 Node 代理进程。它验证获授权请求能转发，未授权目标被拒绝，以及更高协议版本、错误节点或组织和过期租约在请求送达前被拒绝。旧中心要求发布一致的拒绝路径访问真实的本机 Gateway 身份接口。测试也可以运行保留的编译版 v1 代理。独立编译产物验收场景同样使用不同的中心和节点发布标识。
