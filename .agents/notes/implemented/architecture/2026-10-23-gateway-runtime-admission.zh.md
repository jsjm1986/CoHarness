# Agent Note: 受管 Runtime 进程准入

Status: implemented

[English](2026-10-23-gateway-runtime-admission.md) | 中文

## Problem

一个 Gateway 可以为每个账户启动个人 Runtime，并为每个项目启动共享 Runtime。按目标串行化生命周期可以阻止同一目标的重复进程，但不同目标同时启动仍会耗尽 Mac 的内存和 CPU。每实例 systemd 限额不构成节点共享预算，也不适用于 macOS local 启动器。

## Decision

[InstanceManager](../../../../gateway/src/instances.ts) 在物化策略、维护准入或启动进程之前，先取得一个常驻预留和一个冷启槽位。就绪只释放冷启槽位。确认整棵进程树终止后才释放常驻预留；终止失败保留句柄和预留。本地子进程退出通知触发串行清理，启动失败与显式停止遵循相同的终止规则。Gateway 在等待写入者清空之前调用 `beginShutdown()`，先关闭启动准入并取消待启动操作，包括对压力额度的等待。已有就绪进程继续可用，直到后续 `stopAll()` 等待已接纳启动结束并清理本地进程；已关闭的 manager 拒绝新启动和热复用请求。这些规则补充 [Gateway 启动所有权](../bug-fix/2026-08-18-gateway-startup-resilience.zh.md)与[维护](2026-09-25-gateway-deployment-maintenance.zh.md)决策。

[容量控制器](../../../../gateway/src/runtime-capacity.ts) 按 FIFO 顺序接纳不同的 Runtime 目标。常驻预算满时等待已有进程停止或满足空闲回收条件，不驱逐忙碌进程。队列大小与等待时间有界，同一目标和启动意图的重试共享待完成操作，停止会取消该目标的排队启动。热 Runtime 调用不申请冷启槽位。PostgreSQL 与 SQLite 仓储在接纳请求前枚举活跃分配；由 supervisor 保留的进程，包括未完成的启动与停止，即使超过调低后的限额也计入预算。不确定的存活状态在确认终止之前持续占用预留。未完成的启动或停止立即拒绝替换；恢复需要管理员成功停止该 Runtime，再显式启动。启动器拒绝时须确认没有遗留进程，或通过 `RuntimeLaunchCleanupError` 交回仍需清理的句柄。

节点记账器在每个启动器完成策略和 supervisor 准备之后、实际分配的位置消耗共享压力额度。它先调度等待中的模型与子进程任务。观测缺失、过期或额度耗尽时，按已提交的节点截止时间和调用方取消进行等待。迁移 064 记录分配状态：未验证、尚未开始、等待或可能已发生。已知未分配的启动代次不会作为未注册的存活 Runtime 阻塞引导；已准入或未经验证的代次保留这项保护，直到提供方注册或确认终止。部署策略变更会使未使用的额度失效，等待新观测，但不释放已有执行预留。

主机观测从读取传感器前开始携带进程单调采样时间，直到发布。传感器、连接获取、维护和节点锁等待共用同一新鲜度期限。数据库时钟探测前后的采样年龄包围实际采样时刻。正额度从保守下界计算过期时间，并要求该下界比前次上界至少晚一个配置的采样间隔。新鲜告警立即将未使用额度置零，即使更旧的告警延迟到达，也保留最新排序凭据与告警期限。这可能推迟恢复，直到出现可证明更晚的健康采样；不确定的先后关系不能清除告警。迁移 072 增加上界，使缺少上界的未使用采样失效，但不释放活跃请求。

macOS 压力传感器持有原生命令直到实际关闭。采样期限会强制终止不响应的客户端，报告测量失败，不发布正额度观测。采样器释放会等待该命令及已接收的发布，因此停滞传感器不会遗留进程或无限期占用关闭所有权。

排队选择会先锁定目标请求，再有条件地扣除新鲜压力额度。该次扣除同时检查请求截止时间；检查失败时保持排队，或清除过期请求。数据库等待前观察到的就绪状态不能授权等待后的分配。持锁与延迟时钟回归覆盖剩余有效期、观测先后、即时告警及选择与预留之间的过期。正常恢复仍会接纳更晚的健康观测。

事务通过 `harness.lock_node_resources` 获取节点行并清理过期排队请求。`harness.schedule_node_resources` 在同一 PostgreSQL 连接上完成旧代次清理、未登记进程检查、用户／项目公平选择以及当前额度的条件扣减。迁移105安装两个沿用调用者权限的函数。调用方保留事务，直到 Runtime 归属检查、结果与提交结束；资格或压力结果不会成为可复用的授权缓存。数据库内调度消除选择与扣减之间的网络等待，并保留当前请求期限及实际占用。

节点记账与实例活动按配置的语句超时有意串行执行。事务内的锁等待使用这一时限；语句不设限时保留连接池的锁超时。其他客户端保留各自的连接池设置。争用耗尽时返回503，不重放操作或释放未确认的预留。

活动准入先取得分配行的写锁，再在新语句中检查账号、成员资格、电脑、就绪状态和代次。等待前的快照不能为已撤权的调用者授权。资源代次锁持续保留至记账结束。

仓库初始化修复缺失的分配记录，不改变现有进程状态、凭据或代次。第二个协调器或 Gateway 重启不能证明先前进程已经停止。因此，活跃的本地分配也会保留容量；缺少其进程句柄的协调器拒绝替换，也不能报告停止成功。本地启动器的 JavaScript 退出钩子无法在 `SIGKILL` 后运行，因此自动恢复失去所有者的本地存活进程，需要独立且可验证的进程所有者。

`startRequest.admission` 在有界队列接纳请求、立即预留槽位或可复用热运行时后完成；`startRequest.completion` 仅在通过鉴权的就绪检查后完成。普通 HTTP 代理先等待准入，再返回等待响应，因此队列已满时返回 HTTP 503 `INSTANCE_CAPACITY` 和 `Retry-After`。接纳后，HTML 请求沿用 200 等待页，API 请求沿用 503 `INSTANCE_STARTING`，启动在后台继续。之后的排队超时或取消会拒绝 completion，并保留在准入计数中，但不能替换已经返回的 HTTP 响应。

冷启动就绪在同一进程单调期限内覆盖签名 HTTP 挑战、资源登记与就绪发布。每次探测使用剩余时间。后端等待之后及返回成功之前都检查取消与过期；已发出的发布可能先完成，再进行物理回滚。只有 HTTP 传输、响应数据和挑战证明失败会作为探测暂不可用重试。后端拒绝保留原始错误并发起所持有进程的清理，不能变成通用就绪超时。

经过校验的节点设置提供 `HGW_RUNTIME_MAX_STARTING`、`HGW_RUNTIME_MAX_RESIDENT`、`HGW_RUNTIME_MAX_QUEUED` 与 `HGW_RUNTIME_QUEUE_WAIT_MS`。默认值为 2 个冷启、无常驻应急上限（`0`）、32 个排队目标和 30 秒容量排队期限。常驻上限可选正数；压力准入仍控制新启动。这些设置没有经过单 Runtime 内存校准，不证明 16 GiB Mac 能承载 300 个个人 Runtime 或 100 个混合 AI 任务。既有节点配置缺少新增设置时，读取启动环境值或声明的默认值；显式非法值仍会校验失败。

公开快照报告当前及峰值进程／队列数、拒绝数、队列取消与超时数、目标标识符字节数和固定的累计等待分桶。标识符字节数不包含调用方持有的请求数据，不是队列总内存测量。一个 Gateway 所有者对一个节点上的受管进程记账；共用主机的独立 Gateway 与非受管进程不共享这份内存预算。

浏览器表单失败渲染本地化 HTML；scope API 保留 JSON。手动重试保留原 Runtime 和项目并重新检查授权。目标被拒绝时提供环境选择，不回退到其他 Runtime。错误页保留原始服务端诊断，不改变进程准入或监督。繁忙提示表示启动容量暂不可用，不断言已达到常驻进程上限。

## Alternatives considered

**先等待写入者结束，再取消启动。** 启动任务本身持有写入计数，也可能等待只会在关闭时停止发布的压力额度。先取消准入才能让这些写入者结束；等待期限不构成取消。

**把每 Runtime 的 CPU 与内存限额当成节点预算。** 这些限额依赖平台，其总和仍可能超出主机容量。Runtime 进程准入适用于两种启动器，但不声称限制获准 Runtime 内的 CPU 或内存消耗。

**有新目标等待就立即驱逐常驻 Runtime。** 已有租约与任务生命周期规则拥有安全空闲释放职责。带期限的 FIFO 等待保留这些职责，不因容量而终止活跃工作。

**请求终止或子进程根节点退出后立即释放。** 后代进程仍可能占用资源与端口。只有启动器的异步终止完成后才能复用容量；无法确认的终止继续保留预留。

**把后端失败当作 Runtime 不可达重试。** 数据库准入或发布拒绝与探测不可用具有不同的恢复方式和 HTTP 语义。保留其失败，同时继续执行既有物理回滚及代次检查。

## Consequences

冷启突发具有有界的启动进程数与队列长度，重试不能绕过常驻预算。容量耗尽可能延迟或拒绝尚未启动的空间；调低限额不终止已有空间。Runtime 准入不调度常驻 Runtime 内的 Agent 回合、LLM 请求、工具、终端或其后代进程。这些操作需要自身的跨进程资源所有权与准入；单靠进程数限制不能保护整机免受混合负载影响。

确定性的控制器测试覆盖 100 个目标突发、FIFO、两类限额、取消、超时、既有进程记账与幂等释放。InstanceManager 测试执行真实本地子进程启动、其他目标等待时的热调用、重复重试、排队停止取消、崩溃清理、终止失败时保留预留和关闭静止性。[真实 HTTP 代理测试](../../../../gateway/tests/proxy.spec.ts) 将实际 manager 与可控启动器组合，验证就绪前的满队列拒绝、已接纳请求的等待响应和释放容量后的恢复。配置测试拒绝非法值，节点配置测试覆盖持久化与新增字段读取。[Gateway 浏览器记录](../../../../apps/web/tests/runtime-start-feedback.e2e.ts)覆盖个人／项目启动拒绝、键盘手动重试、标签页独立选择和仅读取元数据的恢复入口。夹具受控的准入失败不证明主机容量。时延、常驻内存校准与混合负载基准仍是独立证据。
