# Agent Note：按节点受理对话操作

Status: implemented

[English](2026-11-04-node-qualified-conversation-admission.md) | 中文

## 问题

打开远端对话或在默认工作区创建对话需要浏览器串行往返数次。20 台电脑、1,600 个对话的工作区目录序列化后占 1,514,969 字节。执行电脑与组织数据库之间的网络距离还会增加等待。

在 Windows 上，签发方按同机进程的时钟差选择签名生效时刻，到期仍以真实签发时刻为基准。Host 继续核验签名、签发者、目标、Runtime 代次及有效期。

## 决策

冷准备在启动获准后返回。续等保留原账号、电脑、Runtime、Session、草稿和操作 ID。进程内凭据标识这次已接受的启动及其最终就绪代次，不授予权限，也不能准入新代次。每个 Runtime 的凭据仅保留到该就绪代次结束，晚到的观测不能删除新凭据。创建和读取历史的准备请求只在收到明确的待启动响应时续等。准备期间响应丢失、普通失败、撤权或代次变化仍需显式重试。热操作仍只需一次请求，取消等待不取消已接受的启动或正在运行的任务。

浏览器把电脑、Runtime、账号和空间固定在每个操作上。直接进入时，经认证的 Host 描述从启动凭据取得所属电脑。目标 Gateway 按现有准入规则启动所选 Runtime。版本化 Host 路径把默认工作区登记和 Session 创建合为一次请求，仅返回该 Session 的成员关系。普通历史读取和打开活动窗格分别沿用各自的归档可见性。

可见的输入区在编码图片前可以等待一次绘制。发送文字和已上传的文档引用不依赖动画帧，切到后台后仍能提交。

已持久受理的输入在同一条 Session 收件箱插入事件中带有指纹。Host 刷盘后按确切序号从 Session 已提交的日志中读回该事件。核验回执期间，模型仍可追加后续事件。并发重试串行进入同一个会话，并沿用原 Session 和请求标识。标签页在提交前记录不透明的操作 ID 和该次输入的加盐校验值。状态查询核验原提交者身份，查询不会执行输入。原会话对象释放后，刷新仍可确认此前的输入。缺少写入所有者时无法返回成功回执。 回执查询复用连接退避。同一电脑与 Runtime 的 Host 重新验证后可提前查询，发送准入仍由目标端核验。 个人 JSONL 回执直接从一次校验的当前代读取确切事件，在保留落盘核验的同时省去独立句柄对同一文件的重复定位。

治理目录展示用户获准使用的 Runtime。展开分组时按 Runtime 分页读取。项目内容放置和已迁移的个人目录具有持久归属。所属电脑不可用时返回错误，目录不采用旧副本。维护恢复在提交前核对目标端的归属、退役状态和写入代次。 只有提交导航后才写入本标签页的对话选择。重连期间列表暂缺原对话时，仍保留原目标以供重试。切回页面使私有目录缓存失效。可见的个人分组可通过所属节点的一份限长授权响应读取工作区和对话的首页，两者保留各自的游标。

组织数据库在一次调用中记录 Runtime 活动。取得部署锁后，再核验账号、授权、节点租约、进程代次和空间。个人目录和草稿共用每个 Gateway 按需启动的 SQLite 进程，只访问本机受保护的私有存储。浏览分配目录不会启动用户 Runtime。

标签页副本继承浏览器恢复指针，因此把可变草稿 ID 当作已保存正文会让原标签的编辑进入副本。节点按数量和字节限制保留前版本，客户端读取固定修订后将正文写入副本自己的 ID。超过保留范围的指针保持不可用。

更改部署模式时，入口电脑、已验证账号、Runtime 和 Session 全部一致，打开的草稿才会在节点写入服务与单机标签页恢复记录之间交接。标签页的当前值优先于旧节点修订，主动清空也是有效值。其他电脑的草稿继续归原电脑所有。

空白对话可能已属于入口电脑之外的 Runtime。预设选择器和对话标题在保留的 Session、Host 代次、账号和提供方均匹配时共享进行中的名单读取。Cordis 每次查询都会返回新的跟踪代理。控件比对原始提供方的身份，通过所选 Session 的代理调用方法。

准备失败由标签页内的对话意图负责，因此发起操作返回后，错误仍显示在可编辑草稿旁。意图只携带安全类别和既有操作 ID；服务端消息可能含有私有路径，不进入展示状态。预设无效或缺失需要修复配置并显式重试，不能进入冷启动续等机制。

排队消息由原提交标签页恢复。标签页在临时传输故障和身份核验期间等待，读取原回执，仅当当前所有者报告未知时沿用同一请求 ID。延迟补发中途引导可能打断另一轮正在运行的工作，因此该操作仍需显式重试。Gateway 自动退役过期代次前，要求取得按需 Runtime 新签发的空闲证明，并确认没有未完成工作。常驻或无法确认的进程继续保留占用。

## 考虑过的替代方案

在组织 Gateway 缓存完整目录会把私有元数据写到另一台电脑。浏览器等待所有电脑的读取结果会让单个离线节点拖慢每个窗格。按需向所属节点分页读取可以同时满足这两个约束。

## 后果

旧 Host 会在修改 Session 前拒绝版本化接口。请求已受理后，使用相同 ID 改变输入会被拒绝。个人索引切换前必须持久保存完整的本地快照，覆盖所有活动的原有根会话。切换完成后，旧发布者无法恢复向中心的写入。

## 验证

无密钥 `cold-session-preparation` 快照让编译后的客户端通过两个普通 Node Gateway、出站 Agent 和实际 Web profile 工作。测试沿用正式 Gateway 的顺序，在监听前生成启动指纹。受控启动超过单次 HTTP 截止时间后，仍返回同一个 Session、默认工作区和历史。单次请求载体会拒绝待启动响应。停止重启使真实 PostgreSQL 代次前移，旧续等凭据仍不可用且不会触发另一次启动。聚焦测试还覆盖并发凭据发布、撤权、取消和待启动响应变化。

`queued-prompt-reconnect` 快照替换出站 Agent 租约，核对新 Runtime 绑定，并读回一条持久输入及完整模型回复。Host 测试覆盖独立新建、重试、活动窗格历史和并发重发后的 JSONL 落盘事件。工作台 PostgreSQL 组合测试覆盖原有对话、分页、个人目录发布与撤权。源数据恢复、配额和租约分别核验各自的权限。

[现有部署采样](../../../../scripts/existing-deployment-latency/README.zh.md)分别记录浏览器可输入、收到持久受理确认、回答可见和驱动开销。入口要求明确 QA 目标和执行参数，保留失败及未执行数量，结果不确定时停止后续写入。合成延迟测试和周期性资源遥测不能证明部署环境的操作分位数；手工入口的离线检查不代表真实平台性能结果。
