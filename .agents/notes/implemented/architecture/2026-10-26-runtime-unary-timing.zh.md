# Agent Note: Runtime 一元响应计时

Status: implemented

[English](2026-10-26-runtime-unary-timing.md) | 中文

## 问题

浏览器等待响应的时间包含 Gateway 准入、Runtime 执行与传输。累计进程直方图无法归因某次缓慢的文档或历史请求，客户端总耗时也无法区分这些阶段。请求日志还会保留与计时问题无关的内容和身份。

## 决策

[Connection](../../../../packages/client/connection/README.zh.md)提供默认关闭的 `serverTiming` 选项。ApiProxy 回退 POST 响应携带两个固定名称的数值耗时：`dsh_conn` 覆盖请求通过信任检查后在 Runtime 的上下文 waterfall 与响应构造；`dsh_rpc` 覆盖一元负载校验、调用与 JSON 构造。两者均在响应体消费前结束。Gateway 的既有性能选项控制受管配置中的该开关。

时钟属于单个请求，不保留样本、标识、路径或内容，也不引入定时器或监听器。已注册 Remote 路由、流生命周期、下载和进入请求 waterfall 前的拒绝继续使用既有载体。授权、取消、状态码、信封和历史编码仍由原载体定义。

## 考虑过的替代方案

**只使用累计延迟直方图。** 它们描述进程活动，无法标识某个浏览器请求的处理时间。

**从浏览器等待响应推断服务耗时。** 该区间包含网络和上游准入，不能隔离 Runtime 处理。

**记录每次请求和负载。** 逐响应数值指标无需保留敏感请求数据，也无需另一套日志生命周期，即可回答阶段耗时问题。

## 后果

两个耗时区间相互包含，应相减估算 Runtime 中一元执行之外的工作，不能相加。它们都不是完整的 Gateway 到浏览器延迟。载体拒绝没有 `dsh_rpc` 表示未测量执行，而不是执行耗时为零。默认值保留独立配置的行为，部署方可通过既有性能观测开关关闭受管计时。

载体测试比较响应体和状态，控制单调时钟，并重叠请求以验证独立耗时。物理 Connection 测试覆盖启用和关闭配置。可运行的 Office 浏览器场景从真实转换响应读取两个指标，同时保留其可选择正文快照。
