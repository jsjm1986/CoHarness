# Agent Note：Workbench 目录读取的归属

Status: implemented

[English](2026-10-26-workbench-catalog-read-ownership.md) | 中文

## 问题

初始化导航会让工作台控件在加载页头、空白对话和已有对话页头之间移动。如果请求由组件持有，移动时就会重新发起请求，即使 viewport 仍需要同一份已验证账户目录来恢复保存的布局。

## 决策

每个工作台插件持有未完成的目录读取。各调用者可以独立取消等待。没有调用者的请求仅在它仍是当前读取、且 viewport 仍要求恢复布局时保留；恢复需求撤回后会取消请求。调用传输前就会登记请求归属，因此同步发生的卸载也会包含该请求。卸载插件会取消调用者，并等待所有底层 fetch 和响应体读取结束，包括取消后才结束的传输。

每次打开选择器和明确重试目录都会发起新请求。选择器 store 独立于组件挂载记录打开次数。已完成的响应不缓存。账户解析、可见性检查和[按身份归属的布局规则](2026-09-23-principal-owned-workbench-layouts.zh.md)继续约束恢复；不同插件所有者之间不共享请求或响应。

## 考虑过的替代方案

**仅在工具栏挂载期间共享。** 初始化导航可能先移除旧控件，再挂载替代控件。viewport 的显式恢复需求负责这段间隔。

**保留已完成的目录，或延迟取消。** 已完成目录需要针对成员关系和 Session 变化设置失效机制。延迟取消是在猜测另一个控件何时挂载；显式 viewport 需求无需计时器就能提供该信息。

## 影响

通过屏障控制时序的[完整浏览器场景](../../../../apps/web/tests/frontend-responsiveness.e2e.ts)要求初始化导航只读取一次目录，随后打开保存的面板。工具栏直接读取目录时，该场景因两次请求而失败。它保护的是重复工作，不是公网延迟预算。恢复请求可能在工具栏缺席时完成；若没有调用者，结果会丢弃。[读取器测试](../../../../packages/client/ui-workbench/tests/catalog.client.spec.ts)覆盖取消、恢复需求撤回、新鲜度、独立所有者以及等待底层工作结束的卸载。
