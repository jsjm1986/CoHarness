# Agent Note: 受管 SDK 子模型与进程请求

Status: implemented

[English](2026-10-24-sdk-managed-model-requests.md) | 中文

## 问题

SDK 子级是完整运行时。预留其进程不等于准入内部各次模型调用或子级拥有的子进程；独立 profile 也无法自行得知发起父级的实时权限和计费凭据。

## 决策

逐运行的认证环回连接将控制操作绑定到发起父级。CLI 在 profile 配置项之前安装私有子插件，启动探测也受其控制。子级确认激活后才会发布。控制凭据不进入普通进程继承、启动环境查询或持久配置。即使没有资源预算或模型策略服务，执行权限服务仍要求此连接；缺少前两者不授权绕过父级按执行范围实施的模型校验。

每个子级资源操作使用独立父级许可。模型授权要求许可已经交付且中间件范围仍然存活；模型范围关闭会撤回对应模型许可。进程保留调用方自己的取消信号，不受创建它的模型调用结束影响。单调注册 id 限制重试历史的空间，已完成操作不会再次分配。完成消息通过私有 `settledRegistration` 元数据携带最后一个已结束的登记尝试。父级丢弃不晚于该 id 的早期取消记录，因为后续登记无法复用它们，即使连续尝试均未到达父级。已经登记的操作和待交付许可仍保留所有权。排队取消会等待晚到许可；缺少清理确认时保留不确定占用。同一单调计时的清理时限覆盖已准入操作、模型中间件和 HTTP 清理处理器，等待中的报告不会重新进入无限等待。模型输入、原生预备操作、适配器、凭据和持久请求检查点保留在子级。

父级与子级在确认被拒绝后保留原始许可。报告串行执行，并保留已证明的静止状态；已经确认的不确定状态，可以在后续清理后推进为已释放，迟到的不确定报告不能反转该证明。父级与子级均保留不确定操作，直到静止状态得到确认；父级将其计入配置的操作容量。不确定期间，子级仍观察原许可的取消状态，只有最终释放或提供方关闭才停止。因此，父级撤回仍能传到尚未确认清理的原生执行。父级关闭被拒绝后可重试记账，不重新开放 HTTP 监听器。子级在许可发布前即持有报告所有权。已取消但尚未发布的准入在确认失败后保留原始完成报告；后续准入先重试未完成报告，再分配另一操作，关闭时仍未确认的清理会被拒绝。模型范围关闭也会保留原始 id，直到确认成功，父级完成后响应丢失的情况亦然。模型和进程准入在新登记前恢复保留的关闭报告，持续失败时拒绝准入。提供方撤回会等待这些报告，并将未确认错误与资源清理失败一起报告。不需要后台重试或替代许可。

[SDK 进程所有者](2026-10-24-sdk-subagent-process-ownership.zh.md)通过已发布 run 的提供方与共享 subagent 句柄保留可重试的释放。

模型策略、资源准入、LLM 中间件与执行权限从发起 Agent 的 Context 解析，注册上下文持有提供方清理。请求等待前捕获父级策略身份。串行 `llm/authorize` 事件在适配器 I/O 前执行全部授权所有者，瀑布监听器不能省略必需所有权。同步捕获并在控制回调中恢复父级执行范围，使后续父级活动不会替换发起人。Cordis 跟踪代理按底层提供方身份比较。

`llm/delegated-stream` 使用父级治理计量器，同时保持会话重放独立。全局守卫与计量包含隔离的 LLM 服务。单条输入与输出交接提供背压，并将父级变换后的输出返回子级。父级短路可以避免执行子适配器。提供方撤回会关闭准入、等待子级清理，并使必需的子级守卫保持关闭，直到根释放。适配器取消与模型范围完成独立于输出消费持有；暂停在已输出块上的消费者不能阻止清理。完成流程先等待启动结束，再等待已捕获的适配器转发工作。子级控制客户端为每次清理尝试持有一个时限，嵌套的模型与资源清理及其 HTTP 请求继承该时限。消费者宽限为最终报告预留一次请求间隔。超时会取消范围内的请求并拒绝清理；原身份的完成记录保留到后续具有新时限的尝试。

## 已考虑的替代方案

**每个 SDK 进程仅持有一个模型许可。** 运行时可以并发调用模型，并创建其他进程。

**复用父会话重放。** 子调用拥有独立日志历史，却会共享父级游标。

**运行时退出后释放全部许可。** 进程退出并不确认远程推理或逃逸子进程的清理。

## 后果

受管 SDK 子级使用父级容量与授权服务；独立组合保留独立执行。私有控制协议验证字节数、操作数和时限。模型请求内容用于守卫与计量观察，不追加到父对话。

已认证的请求正文使用配置的控制请求超时执行独立截止时间。到期返回有界错误，并在登记前释放请求槽位；所有者关闭会中止待处理的正文读取。未完成请求在响应后关闭连接，解析前被拒绝的流量也遵循此规则。Node HTTP 超时扫描不持有此截止时间。超大部分正文也会保留连接，直到能够返回有界拒绝。

HTTP 请求上限允许每个配置的控制操作同时进行两次交换，并受安全整数上限约束。输入与输出转发、资源观察与完成报告均为独立交换。若请求上限复用操作计数，已经准入的模型调用可能无法观察许可。逻辑操作容量仍在登记时独立执行。

## 验证

环回服务测试覆盖独立许可、并发容量、嵌套所有权、排队时策略替换、许可撤回、消费者提前返回、有界清理、原生操作输入、token 来源传递、输出变换和父级短路。通过 Loader 组装的 Agent 工厂验证了独立于提供方注册的隔离模型和进程拒绝。可运行的源码及构建版 TypeScript SDK 与 Python SDK 启动真实嵌套运行时，调用 Messages 和 Sonar 环回推理，并在 HTTP 前持久保存精确输入。PostgreSQL Gateway 组合在父级出现后续请求时保留最初计费人，在 HTTP 前拒绝排队期间发生的模型或执行撤权，并通过父级节点预算准入子级创建的原生进程。

[资源完成示例](../../../../packages/subagent/subagent-dsh-sdk/tests/fixtures/resource-completion.mjs)启动 Loader 父级和真实 SDK 子级，在资源登记前使已认证但未完成的控制上传超时，在两个上传仍待处理时观察既有许可，停止原生孙进程，恢复未发布及被拒绝的完成请求，并推进已确认的不确定状态。连续丢失登记交换后发送精确的未启动报告，验证没有中间准入时取消容量仍可恢复。[模型关闭示例](../../../../packages/subagent/subagent-dsh-sdk/tests/fixtures/model-shutdown.mjs)在另一个模型准入前恢复被拒绝的模型关闭，关闭仍有未消费流的真实 SDK 运行时，验证适配器在消费者关闭前完成清理，随后停止独立准入的原生子进程并报告其完成。受控时钟覆盖最终报告超时、嵌套时限和原身份重试。通道屏障证明许可观察与模型双向转发重叠；挂起请求同时验证传输上限。环回记账器观察每个资源仅准入一次且仅成功释放一次；聚焦的父级与子级报告模块满足逐文件覆盖率门槛。这些证据不替代真实模型提供方或 Windows 进程验证。

[启动所有权示例](../../../../packages/subagent/subagent-dsh-sdk/tests/fixtures/startup-owner.mjs)还使用仅安装执行权限的父级运行真实 SDK 子进程，验证每个模型请求恰好经过一次父级授权，允许已授权的子级适配器调用，并在没有模型策略服务和资源预算时阻止被父级执行校验拒绝的派发。
