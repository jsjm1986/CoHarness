# Agent Note：浏览器终端的有序待写输入批次

状态：已实施

[English](2026-10-27-terminal-pending-input-batches.md) | 中文

## 问题

浏览器终端模拟器可能为每次按键产生一个输入回调。若每个回调都独立等待一次 Remote 请求，在前一写入尚未完成时输入的命令就会累积多次网络往返，即使全部待写字节都属于同一终端与连接。

## 决定

[终端 Client 模型](../../../../packages/api/terminal-controller/README.zh.md) 在既有有序写入队列内，用实例拥有的一个批次保留相邻待写输入。首个请求不等待延迟计时器。在待写请求开始前到达的输入追加到该批次；已经发出的请求保持不变。尺寸调整结束当前待写批次，输入不能跨过尺寸调整操作合并。

现有 UTF-8 字节预算同时覆盖发出中与排队中的输入。每个批次在其排队操作完成时释放全部字节计数，包括被丢弃的操作。不增加请求大小、并发配置、计时器或全局队列。

每个批次捕获终端与连接身份。断开连接将后续输入隔开，排队操作在发送前复核当前连接归属与可写状态。控制权转移后被拒绝的输入不重发。迟到的失败不能禁用替代连接。[Web 终端决定](../feature/2026-09-09-web-sidebar-terminal.zh.md) 继续规定流、进程及显式关闭的归属；[私有用户终端](2026-09-23-private-user-terminals.zh.md) 继续规定创建者隔离与授权。两条记录均未被替代。

## 考虑过的替代方案

**并发发送输入请求。** HTTP 完成顺序不能保证 PTY 输入顺序，也不能保留尺寸调整的位置。

**先等待批处理计时器再发送首个按键。** 待写操作已经提供积累位置；计时器会增加延迟和额外调度选择。

**把排队输入带入替代连接。** 替代连接可能对应另一份控制授权。被丢弃的输入必须保持丢弃，不能在控制权改变后执行。

## 验证

模型用例保留首个回复，核对后续完整输入、请求数量、尺寸调整位置、UTF-8 预算释放及陈旧连接行为。断言依赖受控回复与操作顺序，而非耗时上限。组装后的 Web 终端用例通过真实浏览器和 Host 向明确配置的可移植 shell 输入命令，核对文件结果与请求数量，再验证刷新保留和显式清理，不启动模型回合。

## 影响

当输入到达速度快于回复时，请求数量减少。此变更不保证所有输入节奏都使用固定请求数，也不消除输出绘制和网络延迟。只读状态仍由连接归属决定；输入聚合不会放松或修复该策略。
