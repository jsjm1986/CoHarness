# Agent Note: 本机运行时之间的 Office 字体元数据

Status: implemented

[English](2026-10-26-local-runtime-office-font-metadata.md) | 中文

## 问题

本机 Gateway 运行时使用同一操作系统账户，但拥有独立主目录。首次 Office 渲染可能重复检查相同系统字体。三组交替的独立进程加载已构建提供方，转换单页拉丁字母与中文 DOCX：各自空缓存耗时中位数为 2.22 秒，复用元数据时为 1.25 秒；Node 最大 RSS 中位数分别为 943 与 287 MiB。首次共享缓存填充耗时 8.59 秒，这项成本仍然存在。另一次使用更大合成 DOCX 的 kit 诊断在两种缓存模式下产生相同的逐页渲染图像。测量不包括原生子进程内存、网络和浏览器渲染，不能解释所有预览延迟。

## 决策

[Office 提供方](../../../../packages/document/office-to-pdf/README.zh.md)开放已安装 kit 的有界元数据缓存选项。Gateway 本机启动器通过运行时配置提供一个节点所有的共享目录。字体发现、物理文件标识校验、原子发布、损坏缓存恢复与取消仍由 kit 负责。每次操作仍发现自己的字体来源。共享缓存不包含原始字体字节、文档输入、转换后的 PDF 或授权结果。

Gateway 接受部署指定的目录或 `off`。Systemd 运行时使用不同操作系统身份，因此保留独立缓存，并拒绝显式共享目录。[有界转换决策](2026-09-15-bounded-office-conversion.zh.md)继续定义源准入、完成的 PDF 与引擎生命周期。[授权预览决策](2026-09-23-authorized-office-preview.zh.md)继续定义 Session 访问与版本校验。

## 考虑过的替代方案

**跨运行时身份共享转换后的 PDF。** 这会增加内容与授权所有者；字体派生元数据复用无需这项改变。

**为每个运行时保留常驻原生转换器。** 用户空闲时也会保留引擎进程。元数据复用无需常驻字体 Worker 或原生引擎。

**缓存命中后跳过来源发现。** 这会遗漏字体变更、新增或删除。kit 在复用前重新校验发现的文件。

## 后果

节点首次填充缓存仍需支付检查成本。后续可复用元数据的渲染避免重复解析，同时保留来源顺序与字体匹配。元数据缺失、无效或不可访问影响性能，不影响文档可用性。该目录属于可丢弃缓存，不是必需备份或 Session generation。共享进程必须具有相同操作系统权限。

提供方与 Gateway 测试覆盖选项传递、无效路径、字节限额、本机装配与关闭共享。可运行的 Office 浏览器场景使用显式元数据目录及损坏缓存，将可选择 PDF 与既有快照比较，并检查转换恢复。包内诊断单独测量加载构建产物的独立提供方进程，不将其视为浏览器就绪时间。
