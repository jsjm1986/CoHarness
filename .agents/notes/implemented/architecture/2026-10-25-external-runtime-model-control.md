# Agent Note: Parent control for external model requests

Status: implemented

English | [中文](2026-10-25-external-runtime-model-control.zh.md)

## Problem

Codex, Claude Code and ACP runtimes issue their own model requests. Parent process admission and an authorized external turn do not authorize every nested inference, reserve its capacity or establish its usage attribution. A real Codex child can reach a loopback inference endpoint while its parent policy forbids every model.

## Decision

Codex one-shot runs and persistent members can use an initiating-Agent-owned Responses transport. Explicit `modelProvider` enables it; a managed parent also requires it. `requiresParentModelControl()` classifies installed or required model policy, resource admission and execution authority for SDK control, Codex model selection and opaque refusal. An authority-only parent must retain its execution-scoped guards even when optional budget and model-policy services are absent. The actual initiating Agent supplies the selected route, LLM service, resource owner, Session and execution scope. Missing routes or unsupported adapter protocols refuse before process allocation. Independent compositions retain native authentication and execution.

The run owns an authenticated loopback listener, bounded requests and responses, and an awaited disposer. Each authenticated body has an independent `modelRequestTimeoutMs` deadline. Expiry returns `504 TIMEOUT` without creating a native request event or model permit. Completed uploads clear the timer before model preparation; downstream model work retains its own cancellation. Native Codex receives only its run credential and command-line provider overrides, with WebSocket inference and internal request retries disabled. The parent’s prepared `native-stream` adapter operation retains the endpoint generation, resolves upstream credentials after admission, parses SSE with backpressure and reports actual token counts. Neither child headers nor URLs select the upstream endpoint. Malformed child JSON is classified at parsing as `INVALID_REQUEST`; unexpected parent persistence or execution errors retain the server-failure class. A failed required Session flush prevents model dispatch without claiming rollback of any committed event. SSH execution uses a retained reverse loopback forward on the actual Agent’s standing connection; [its decision](2026-10-25-managed-codex-ssh-model-requests.md) defines ownership and cancellation.

Each request appends the exact secret-free `subagent/codex-model-request` and checkpoints it before dispatch. `prepareDelegatedOperation()` uses `llm/delegated-stream`, preserving parent conversation replay. Every request obtains its own model permit and passes the parent’s live authorization plus the provider registration’s retained policy after queue waits and again after asynchronous credential resolution. Both policy owners are rechecked after capability lookup before opening the listener. Retained registration and parent resource owners are rechecked before requests and after dispatch waits; replacement or withdrawal requires a new child run. An independent parent resource owner cannot bypass the registration owner. The captured execution scope preserves the initiating Session and actor during later parent activity.

Persistent Codex members register `LlmAdapter.callKind: orchestration`. Their outer turn uses `llm/orchestration`, retaining required policy ownership without reserving a synthetic model permit or metering the member alias. Each native request passes through the managed member Agent’s delegated operation, policy and resource owners. Before publication, the binding store captures native authentication or the exact upstream provider/model, including inherited parent selection; cold resume does not infer a new route from the alias or current parent settings. New one-shot and continuable delegations through that same provider instance inherit the saved upstream when settings are omitted. The orchestration alias carries no native model authority. Conversation checkpointing, title scheduling and positional replay observe orchestration turns; model governance and SDK model relaying observe their physical requests. Recovery only reads rollouts. Disposal cancels pending model/process allocation, joins late owners and preserves independent cleanup failures.

Opaque external inference still uses `assertExternalModelExecution()`: Claude Code, ACP and unsupported external transports refuse governed execution. Their member routes also register as orchestrations. Required model policy remains checked by the LLM service, while unsupported turns reach their guard before model admission; exhausted capacity cannot postpone refusal or consume a synthetic permit. Both registration and actual Agent contexts apply. Loading a dormant provider remains available. The [SDK child decision](2026-10-24-sdk-managed-model-requests.md) owns its separate child control protocol.

## Alternatives considered

**One permit for the external turn.** An external turn may make several concurrent or sequential model calls without another parent callback.

**Authorize only the member route.** The route identifies an external agent, while native settings select the actual models, retries and auxiliary calls. Persistent members need admission for their native requests without holding a synthetic conversation-model permit around the whole external turn.

**Copy provider secrets into the child.** That would let native authentication issue inference outside parent policy and obscure credential-source attribution.

## Consequences

Managed Codex requires a registered Responses route with explicit API-key or configured protocol authentication. Provider-native OAuth is unsupported. Unsupported external capabilities fail closed; they are not treated as completed per-request integration. Legacy persistent bindings without model authority remain intact and require a new member. The required input event extends the current Session vocabulary without rewriting committed generations or changing its structural format version.

## Verification

A runnable Loader application holds parent model admission behind a controlled grant. ACP and Claude Code members refuse without entering that wait or requesting model/process capacity. Old private artifacts enter the wait and release an unnecessary model permit before refusing. Provider regressions cover model-policy and resource-provider presence or requirements in both shared and isolated contexts, across start, member creation and resumed inference. A missing required model policy retains its dedicated failure.

A real Loader composition cold-resumes a member and delegates a one-shot native Codex run through its inherited upstream, preserving member-owned input events, usage and actor attribution; queued revocation prevents the second upstream request. Real package-local Codex tests resume explicit and inherited managed members for two turns under one model slot, with separate native requests, child-owned input events and no upstream child credential. Deterministic barriers cover pending model/process disposal and independent cleanup failures. Binding-store reloads retain selections and reject malformed, conflicting or late authority records. One-shot tests issue two native requests in one turn, record separate usage and permits, and revoke registration policy during the second queue wait with both shared and isolated parent policy. Transport tests cover endpoint generations, credential resolution, cached usage, truncation, malformed or oversized responses and cancellation. Runnable SDK fixtures record the exact model input before loopback HTTP and observe the parent Session through both SDK projections. An incomplete authenticated upload times out before native Codex startup in the runnable one-shot fixture; the following real native requests retain their original permits and persisted inputs.

Real PostgreSQL Gateway composition preserves the original member, project and initiating Session after a later administrator request for both one-shot and persistent members, rejects queued model or execution revocation before the second upstream HTTP, and confirms zero remaining model/process occupancy. Embedded Gateway fixtures bind their workspace modules to the source resolver; SDK fixtures use their process’s complete source or built runtime. Both SDKs project two persistent turns and resume the same child in a fresh host process. Consumer regressions cover checkpoint refusal, unchanged-header title revisions and replay without native execution, including interceptor disposal.

Authority-only coverage includes root and isolated contexts across one-shot starts, member preparation and resumed inference. The opaque Loader replay confirms refusal before native allocation; a native Codex Loader example confirms permitted upstream dispatch and denied requests under the captured parent scope, without a model-access service or budget.
