# Agent Note：跨 Gateway 授权失效

Status: implemented

[English](2026-09-22-cross-gateway-access-invalidation.md) | 中文

## 问题

Gateway 本地的取消回调无法关闭另一个 Gateway 已准入的流量。仍有效的签名 principal 和先前成功的 Session 读取，也不能证明账号、项目成员身份或对话仍可读取。PostgreSQL 审计写入独立于业务事务，不能提供原子性的撤权投递。

## 决策

[Gateway](../../../../gateway/README.zh.md) 在修改权威数据行的同一事务内，将授权变更记录到现有 PostgreSQL outbox。每个事务由一个组织版本和一份去重主体列表覆盖。组织行锁按照提交可见性排列版本；独立分配的序列可能让读取者跳过较早但尚未提交的事务。这种串行化仅用于授权变更，不涉及普通消息写入或上传。

`LISTEN`／`NOTIFY` 唤醒有界的持久版本读取器。通知不承载授权，可以重复或丢失。监听连接中断时取消已准入流量，重连和请求准入则先读取已提交记录，再继续执行。本地回调仍即时执行。目录变更还会停止受影响的运行时，使新进程加载当前文件系统授权。撤权历史不可用或不完整时，准入被阻断，不依赖断言生命周期放行。

[API 代理](../../../../packages/host/apiproxy/README.zh.md) 合并尚未完成的读取，不永久保存已通过的授权。Mux 与 Host 在每批发布前复核 Session 可见性，包括已缓冲的基线和聚合引用。取消会丢弃缓冲帧。Session 操作保留当前逐操作授权和目录包含关系检查。

## 考虑过的替代方案

**在服务调用后尽力发送通知。** 提交和通知之间发生崩溃会丢失撤权。事务触发器覆盖同一批授权数据行的所有写入者。

**只依赖 principal 过期或成功读取缓存。** 这会将陈旧权限保留到过期，并可能让曾经可读的 Session 在流内无限期可见。

**每次数据行写入都撤销流量。** Session 创建、追加计数、登录活动和文档登记不会撤销现有权限。取消它们可能中断发起写入的上传或创建请求。

## 结果

每个 Gateway 保留一个数据库监听连接。改变权限的事务短暂地在组织行上串行执行；多个受影响行只产生一条通知和一条重放记录。冷启动进程从计算节点上次成功应用的运行时版本继续处理。运行中的进程重连时保留自己的游标，即使另一进程已在同一节点确认了更新的版本。每次读取先按主体合并全部已观察积压，再停止运行时；取消和停止必须完成后才能确认版本或允许重连准入。取消失败会保持准入关闭。

Outbox 记录保持留存；`completed_at` 不授权删除。离线节点必须收到每个尚未应用的版本，自动压缩需要单独的节点登记与留存策略。轮询覆盖丢失的唤醒，新准入也会重新读取以限制延迟。它扩展现有 PostgreSQL 控制面，不引入独立消息代理或逐消息审计流。

真实 PostgreSQL 测试覆盖两个 HTTP／WebSocket Gateway、提交和回滚、批量主体、监听丢失、重连补读、受影响用户隔离，以及普通上传／Session 写入。这些测试的上游运行时是传输夹具；实际目录隔离仍由提供方测试验证。受控 API 流测试覆盖已读 Session 和排队发布。传输取消不会擦除浏览器已经渲染或缓存的内容，也不能证明共享项目运行时中该参与者已启动的模型／工具任务已静止：这些任务需要由参与者拥有的取消机制。这些 Client 与共享任务行为需要独立验收证据。
