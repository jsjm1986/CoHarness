# Agent Note：模型策略所有者跨请求等待保留

Status: implemented

[English](2026-10-24-model-policy-owner-lifetime.md) | 中文

## 问题

排队中的模型调用可以比授权插件存活更久。在资源等待后查找派发前监听器，可能找不到任何防护，进而派发原本需要策略的请求。新调用也需要区分有意独立运行与提供方消失的受管运行时。

## 决策

Gateway runtime 在根上下文生命周期内发布 `modelAccessRequired`。LLM 流在构造中间件前捕获当前策略所有者，跨模型预备与准入保留其身份，并拒绝缺少必需所有者或任何所有者替换。在异步派发防护之后，核心执行所保留提供方的路由决定。策略提供方仍负责刷新其数据。

提供方身份通过 `symbols.original` 比较 Cordis Service 跟踪代理，路由决定仍使用捕获的代理及调用方上下文。同一 Service 的新代理仍属于同一所有者，底层 Service 被替换时仍拒绝派发。

治理在等待 watcher 与 outbox 销毁前，把访问服务标为不可用。迟到的有效文件通知不能重新开启已停止的所有者。原生模型操作共用这条策略路径，不能在所有者撤下后切换到独立传输。

普通 `PreparedAdapterCall.stream()` 和直接 `LlmAdapter.stream()` 实现会收到运行时传入的、保留授权所有者的回调。DeepSeek 在凭据和请求扩展准备完成后以及每次 Files 操作前调用它；授权失败不会转为内联回退。pi-ai 在显式准备完成后，以及提供方完成内部认证并提交载荷时再次检查。序列化的提供方错误事件不能替换原始授权失败。

策略服务与执行权威分别拥有归属。[逐请求执行保留](../bug-fix/2026-11-01-model-request-execution.zh.md)负责在策略提供方仍然安装期间，保留执行签发服务、Agent 与计费见证。

## 考虑过的替代方案

**读取准入后存在的任意策略。** 不同提供方可能授权归属与中间件属于前一所有者的请求。

**仅依赖监听器注册。** 销毁监听器会删除正在其他位置等待的请求所需的检查。

## 影响

被策略替换打断的调用必须在新提供方下重试。既无策略也无必需要求的独立组合仍可使用。策略决定在提供方刷新防护之后执行，因此不会在提供方读取数据前用陈旧快照拒绝刚刷新的权限。

## 验证

实际治理 fiber 在模型准入期间被销毁时，原实现仍会派发。回归用例现在拒绝该调用并释放许可，在缺少策略时拒绝新的受管调用，并在异步模型预备期间保留所有者。原生搜索组合用例还会在排队时撤销路由访问、执行权限和治理所有者；均不联系 HTTP。

普通预备与未预备提供方案例在显式凭据解析期间撤权，pi-ai 案例还阻塞其内部已存凭据读取。DeepSeek Files 拒绝保留失败码，不发出回退推理。源码与构建版 SDK profile 转录覆盖两种真实提供方路由：上游请求和用量均为零，一次许可申请和释放，并完成失败的回合。Node22 和24 的构建版运行还保留原生 Codex SDK 请求投影。
