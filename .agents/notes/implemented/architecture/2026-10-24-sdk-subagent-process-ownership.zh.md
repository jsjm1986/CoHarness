# Agent Note: SDK subagent process admission and ownership

Status: implemented

[English](2026-10-24-sdk-subagent-process-ownership.md) | 中文

## Problem

SDK 客户端在 Cordis subprocess 服务之外拥有子进程。清理环境变量不能提供资源准入。如果提供方不拥有待启动事务和子进程清理，注销提供方时其私有 SDK 子进程仍可能存活。

## Decision

SDK subagent 提供方在构造 SDK 客户端前，以发起方 Session 和执行来源预留进程许可。缺少必需预算时拒绝启动。SDK run 接收该许可，只有 SDK 清理确认运行时进程退出后才释放；清理失败时报告不确定占用。构造失败会归还尚未使用的许可。

启动在等待未发布清理前捕获发起方资源提供方、其必需标记和执行权限。在许可准入、控制监听器启动、原生初始化和发布期间，这些所有者保持固定。`SdkRunSpec.assertOwnership` 在原生启动与首轮派发前校验它们，并在调用方校验后重新检查取消。所有者变化会拒绝旧尝试，不申请替代容量；回滚失败时保留原运行时与许可。初始独立执行时的资源缺省不能静默采用新安装的准入。

同一个提供方生命周期拥有待启动事务和已发布 run。调用方取消、许可撤回和提供方卸载会停止子工作。卸载等待延迟许可及清理结束。单次任务完成会自动关闭；显式释放共用同一事务。清理失败的 run 仍由提供方释放流程拥有，不能算作成功归还许可。

已发布运行时的清理在 SDK 提供方、subagent 服务和共享进程外句柄中保留可重试的完成请求。各所有者共用未完成或已成功的释放，并在拒绝后允许再次尝试。即使物理进程已经退出，许可确认失败时仍保留原始 run；恢复后释放该许可，不创建另一运行时，也不改变已结算的子级结果。

未发布的失败启动通过 `SdkStartupCleanupError` 转交原始回滚。提供方在待启动事务结算后仍保留这些所有者，在下一次启动前重试，并在卸载时与已发布 run 一起等待。无法确认回滚时拒绝替代启动。清理共用未完成工作与成功确认；再次尝试可以重试被拒绝的报告。失败启动不发布子级生命周期事件，已回收的进程在完成确认前仍持有许可。

两套独立 SDK 都在终止或退出确认失败后保留原子进程。关闭后永久停止新工作，与清理是否成功无关。TypeScript 共享未完成和已成功的尝试，并允许重试失败尝试；Python 串行执行尝试，并把配置的超时用于强制退出确认。Python 高层实例在释放前清除初始化状态，因此关闭失败不能允许另一轮任务。

Python SDK 将 stdin 交给一个受其拥有的写入线程。排队与正在写入的帧共用 `max_output_bytes`；调用方独立等待响应，不受原生管道写入阻塞。EOF 加入队列，close 在释放句柄前确认进程退出与写入线程结算。结算失败时保留同一句柄。逐请求超时在产生协议副作用前校验。从读取回调关闭时，等待线程的操作排除当前线程。

该后端在本地执行。绑定 SSH 的父 Session 会在准入前被拒绝，绝对目录不能替代其选定的执行目标。

子路由默认值在启动前统一解析。请求中的提供方、模型、推理强度和输出上限覆盖配置默认值；省略请求字段不会静默丢弃其中某个配置值。

SDK 启动诊断在实际 stdio 结算时结束，包括只发出 `close` 而没有 `exit` 的失败启动。错误交付不能依赖无关的存活事件循环句柄。

## Alternatives considered

**交付子结果时释放。** 模型活动结束后，SDK 运行时进程仍可能存活。只有清理能够确认进程退出。

**把注销提供方视为子进程清理。** 注册表 disposer 只停止发现，已发布子进程和待启动事务仍拥有各自资源。

**为整个子运行时持有一个模型许可。** 子运行时可以发出多个并发模型请求。单个进程预留不能证明逐模型请求准入，也不能传递模型授权与用量。

**在调用线程写入 stdin。** 运行时停止读取后，同一管道锁可能同时阻塞请求时限与 shutdown。有界 FIFO 让原生 I/O 不占用这些控制等待。

## Consequences

独立组合可以省略资源预算。受管进程准入由 Consumer 拥有，不改变 SDK 协议或独立 SDK 客户端的启动 API。SDK 进程许可只记录运行时进程本身。[受管子请求](2026-10-24-sdk-managed-model-requests.zh.md)另外执行模型策略、逐请求准入和用量归属。

## Verification

定向测试覆盖构造前拒绝、排队卸载、发布时取消、启动失败、不确定清理和入账失败。真实 SDK 子进程测试在归还许可前检查记录的 PID 已退出。可运行 SDK 组合通过真实委派工具驱动第二个完整 SDK 运行时，验证获准和拒绝启动，以及子进程收到配置的推理强度。这些检查不证明子模型继承治理、付费推理或完整逃逸后代进程限制。

[资源完成示例](../../../../packages/subagent/subagent-dsh-sdk/tests/fixtures/resource-completion.mjs)使用 Loader 父级和完整 SDK 运行时，连接本地记账器。它在物理退出后拒绝第一次运行时许可完成请求，再重试公开释放，观察原运行时仅分配一次且仅成功确认一次。

[启动恢复示例](../../../../packages/subagent/subagent-dsh-sdk/tests/fixtures/startup-recovery.mjs)在拒绝第一次完成报告前，确认失败子进程的 PID 已消失。同一提供方确认原始许可后才分配下一个运行时，只有成功子级发布生命周期事件。单元屏障还覆盖恢复期间取消、持续记账失败和控制初始化回滚。运行驱动器与准入所有者满足逐文件覆盖率门槛。

[SDK 关闭示例](../../../../packages/sdk/client/tests/fixtures/close-recovery.mjs)及其 [Python 投影](../../../../python/sdk/tests/test_close_recovery_snapshot.py)完成确定性模型轮次，保持插件释放未完成，并拒绝进程终止。重试同一客户端会回收原运行时，同时持续拒绝新请求。Python 单元屏障覆盖 shutdown 期间的准入和有界强制退出确认。

[完整 Python SDK 组合](../../../../python/sdk/tests/test_write_deadlines_snapshot.py)先完成模型轮次，再把下一请求阻塞在运行时事件循环中，随后让另一提示词超时并回收原进程，且无需救援。原生管道测试覆盖输出容量、写入失败、保留写入清理、拒绝非法超时导致的修改，以及从通知过滤器关闭客户端。
