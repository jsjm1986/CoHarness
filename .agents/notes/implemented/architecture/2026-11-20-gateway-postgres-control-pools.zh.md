# Agent Note: Gateway 为控制流量保留 PostgreSQL 容量

Status: implemented

[English](2026-11-20-gateway-postgres-control-pools.md) | 中文

## Problem

访问监听器长期占用一个业务连接，业务池只有一条连接时前台请求无法取得连接。较大的业务池也可能让就绪检查、写者心跳和精确租约续期排在无关操作之后。阻塞的 Runtime 停止还会延迟发现随后提交的撤权。

## Decision

Gateway 使用有界业务池、独立的单连接访问监听池和可单独配置的控制池。访问监听读取已提交的 outbox，并在对应清理完成后确认版本。如果处理期间又提交了新的版本，监听器通过有界版本读取发现积压，立即阻断已准入流量，同时保持原有顺序追赶持久版本。

就绪检查先确认监听器能观察变更并发出取消通知，无需等待清理确认。随后通过控制池的一条查询，在同一个数据库快照中核验组织和节点处于活动状态，并比对启动时的写入代次。远程 Gateway 可少一次网络往返，监听器观察期间提交的恢复也会被发现。Runtime 准入和续期仍要求按顺序应用的变更完成。写者心跳保留已观察的维护代次和在途写者数量。节点续期在更新精确连接租约的同一语句中核验当前服务写入代次。普通业务写入准入和管理员操作继续使用业务连接。

两条 Runtime 流控制路由通过保留池检查目标的当前精确凭据和代次。事件续期还核验原浏览器会话、电脑和项目范围。续期前后的 outbox 同步和已登记连接身份继续决定签发。普通 Runtime 和浏览器请求沿用业务准入。启动失败时先关闭已登记的监听消费者，再关闭连接池。正常关停也先收敛消费者，再释放连接池。

## Alternatives considered

**提高业务池上限。** 监听器仍长期占用一条连接，繁忙业务仍可占满其余连接。

**让监听器与查询共享控制池。** 单连接控制池仍会被监听器占满。独立监听器也避免受短期控制连接获取影响。

## Consequences

运维可配置一个业务连接。每个 Gateway 的默认预算额外包含一个监听连接和最多两个控制连接。查询锁冲突和数据库故障仍可能导致控制工作被拒绝。Gateway 就绪时仍可能有待完成的 Runtime 停机，需要确认清理完成的调用方使用持久访问版本。现有管理员性能接口提供额外连接池计数。

## Verification

监听器聚焦夹具挂起一个版本的清理，验证观察到后续提交即可取消既有流量，且无需业务连接。续期夹具验证同一所有者和代次的 Runtime 无法续期另一分配的连接。Gateway 饱和夹具占满业务池，验证发出取消后，就绪检查只需一次控制池查询，Runtime 停机此时尚未确认。夹具还检查节点续期和业务池恢复后的持久确认。PostgreSQL 就绪测试核验写入代次推进或电脑进入排空时的拒绝。
