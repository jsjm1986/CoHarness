# Agent Note: Native model operations retain ordinary model policy

Status: implemented

[English](2026-10-24-prepared-model-operations.md) | 中文

## Problem

辅助提供方可能通过私有协议发出完整模型请求。单独取得资源许可并不能提供模型路由授权、持久化请求检查点、执行归属或用量报告。每个 Consumer 各自实现这些能力，会为同一模型容量产生不同的策略路径。

## Decision

`LlmOperationMap` 声明操作参数、精确的无密钥请求和结果。捕获的 `PreparedAdapterCall.operations` 工厂使用与普通调用相同的模型元数据和连接代次来预备操作。`LlmRuntime.prepareOperation()` 发布分离且冻结的请求。Consumer 在调用仅能执行一次的 `run()` 前记录该请求。

执行使用普通的 `llm/stream` 中间件、模型许可和最终的 `llm/pre-dispatch` 检查。`GenerateOptions.operation` 携带操作名称和请求；对话消息为空。普通分派不能接收操作描述符，预备调用也不能替换描述符或配置。

物理模型流在中间件执行前捕获资源归属。预备、排队准入、授权和受防护的 HTTP 回调均要求同一提供者仍然有效，并保留原有的受管要求。撤销或替换时返回 `RESOURCE_BUDGET_UNAVAILABLE`；已经取得的许可归还原所有者。新的 Cordis 跟踪代理保留底层 Service 身份。编排轮次不取得模型许可，每个嵌套物理请求分别拥有自己的准入。将旧请求迁移到替代提供者会把其待决准入与另一个所有者的容量混用。

适配器在终止结果前报告实际累计用量，包括后续失败之前已经获得的用量。缺失用量保持缺失。中间件可以拒绝调用，但没有真实执行结果的成功终止标记不能制造成功。提供方拒绝和取消使用现有的终止失败协议与资源清理。

Web 能力通过一个 `registerModelSearch()` 生命周期服务 Messages 与 Sonar Consumer。安装或要求模型策略时使用预备的 LLM 操作，独立传输则获取自己的模型许可。独立等待期间出现策略会拒绝请求，不在准入后切换传输。两种协议均记录精确输入并保留凭据归属；取消会观察延迟凭据结算，并等待传输清理。

## Alternatives considered

**为每个辅助传输单独实现授权和计费包装。** 分别实现时，可能对排队中的撤权、凭据所有权或产生费用的输入见证得出不同结果。

**解析模型元数据后再选择另一个传输。** 请求可能混用一个代次的能力与另一个代次的端点或凭据引用。

**把终止标记当作操作结果。** 中间件短路可能在从未执行操作时结束流。调用方需要适配器的真实结果。

## Consequences

操作保持为适配器能力，不支持时显式报错。Consumer 继续负责记录精确请求；适配器工厂在预备阶段不分派 HTTP。预备操作保留普通调用的配置校验，且不能重复使用。类型化模块扩展提供操作词汇，不使用进程全局注册表，也不在序列化请求中隐藏回调。

## Verification

定向用例覆盖捕获代次、冻结输入、排队时撤权、取消后的许可清理、提供方失败前实际用量、缺失用量、缺失结果、单次执行，以及拒绝普通调用中的操作描述符。原生搜索组合验证实际 API key 路由、凭据文件、HTTP 请求与治理 outbox，包括排队时撤销路由、执行权限和策略所有者。源码与构建模式的 TypeScript SDK 流程，以及 Python SDK 执行真实 web 工具、Messages 与 Sonar chat-completions 适配器，在本地 HTTP 前验证持久输入，并在新进程恢复。这些夹具不证明付费外部提供方行为或完整 Gateway 准入与 PostgreSQL 入账。

无密钥的 Loader 应用在准入和凭据等待期间替换或撤销资源提供者，断言不发送本地 HTTP，并归还原许可。单元用例还覆盖中间件、预备及授权等待、有效的跟踪 Service、受管要求变化，以及编排等待后的新嵌套准入。
