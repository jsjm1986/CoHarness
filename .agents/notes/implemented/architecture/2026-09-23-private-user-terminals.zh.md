# Agent Note：受管运行时中的私有用户终端

Status: implemented

[English](2026-09-23-private-user-terminals.md) | 中文

## 问题

共享 Session 可以有多个获授权的参与者。仅靠 Session 身份无法隔离每个参与者的 shell，浏览器请求断言也会早于保留终端过期。管理员需要终止资源，但不应取得他人的屏幕或执行身份。

## 决策

上游[终端控制器](../../../../packages/api/terminal-controller/README.zh.md)和[侧栏界面](../../../../packages/client/ui-sidebar-terminal/README.zh.md)保留 PTY、有界屏幕、连接、空闲回收和明确关闭行为。CoHarness 在每个 Session 内增加创建者归属。独立模式使用本机操作者；受管运行时的政策消失时不会回退到该身份。

Gateway 准入要求用户资格，项目终端还需要项目授权及可写成员身份。Session 可见性独立检查。PostgreSQL 授权绑定组织、节点、runtime 代次、Session、用户和资格版本。浏览器断言用于准入，不会被保留。现有失效通知流重新核验授权；断连或撤权停止所属进程并等待清理。重新授予资格不会恢复旧所有者。

普通终端 Remote 仅操作调用者的创建者身份。管理员有两个独立操作：最小进程清单和明确终止。专用签名请求用途仅允许这两个 HTTP 端点，并重新核验数据库中的当前角色。清单和清理绑定当前节点及 runtime 代次；读取不会启动空闲实例。管理响应不包含终端文本、路径、标题和 shell 参数。清理失败保持可见且可以重试。

Client 关联、未完成关闭请求和 shell 偏好携带经过核验的账号/runtime/Session 归属。身份变化清空屏幕模型并拒绝晚到响应。清理保留原始地址。唯一右侧栏负责布局，终端恢复覆盖空白和已有内容的 Session，不创建替代 shell。读取流使用现有连接的独立有界 NDJSON 响应；无效帧和业务拒绝结束流，卸载等待迭代器清理完成。

终端 Client 插件在创建模型前，通过 Gateway 拥有的贡献注册 effect 挂载生成的 Remote 命名空间；插件释放时一并释放该命名空间与终端模型。共享 Remote 组装不导入终端 Client 代码：运行节点服务为终端提供身份，把终端反向导入该组装会形成依赖循环。

## 考虑过的替代方案

- **以 Session ACL 作为终端归属：**允许其他参与者读写私有 shell。
- **给予管理员创建者身份：**使其取得超出清单和终止范围的私有执行及输出权限。
- **让进程保留浏览器断言：**要么使有效的保留工作过期，要么在没有重新核验的情况下延长陈旧授权。

## 相关决策

本决策细化[用户终端权限](2026-09-16-user-terminal-permissions.zh.md)中的归属规则。该文对人工 shell 和 Agent sandbox 的区分继续有效。Gateway 资格属于组织准入，不是第二套 Agent 权限选择器。[Web 终端决策](../feature/2026-09-09-web-sidebar-terminal.zh.md)继续负责进程和屏幕归属。

## 影响

获准终端使用所选 subprocess 提供者的系统用户权限执行。Agent 审批或 Auto 资格不会授予终端资格。终止失败会保留所有权，直至清理成功。管理页提供资格控制和仅含元数据的监督，不能连接他人的终端。原生平台和远程执行验收仍独立于源码级政策测试。
