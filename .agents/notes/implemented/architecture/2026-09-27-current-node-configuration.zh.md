# Agent Note: Current-node configuration with independent application

Status: implemented

[English](2026-09-27-current-node-configuration.md) | 中文

## 问题

Web 服务不能完整持有修改自身监听或数据库配置的操作：应用这些值可能终止负责返回结果的请求。配置编辑也与备份、恢复竞争，而恢复出来的排队操作不能静默作用于另一个数据代次。

## 决策

节点持有一个私有、带版本的配置文件。管理员变更绑定组织、节点及期望 revision。期望值、已应用值和在服进程实际生效值保持区分。可编辑字段由显式集合声明，可执行命令、凭据内容、身份及隔离不进入其中。普通保存不会重启服务。

Web 查看、保存和登记应用在数据库事务内保留活跃组织、当前活跃管理员账号及成员身份。Gateway 提供认证参与者，浏览器的参与者字段不授予权限。保存与应用返回配置写锁内捕获的视图，后续写入者不能替换响应中已接受的 revision。启动初始化显式没有账号参与者。已登记的应用是一条已接受的指令，由独立工作进程按既有写纪元、维护状态和数据检查消费。

独立托管的应用器在共享数据库部署租约和本机配置锁下消费显式请求。请求绑定数据库写纪元。节点配置变更与备份、恢复共用租约，包括首次创建文件；已有文件的启动身份核验只读。macOS 不可变 release 还与 release 控制器共用激活锁。

预检要求维护窗口、运行时写者已停止、数据库身份兼容、数据路径已准备。发布前保留上一可用值，再执行宿主机管理的固定服务动作。健康检查必须确认已应用代次及 release。失去租约时停止发布，不发起新的回滚，由新持有者核对持久的应用中记录。本机恢复仍检查数据兼容性。备份恢复保留当前控制文件，在写库前拒绝不兼容的存储位置。

Gateway 心跳确认维护写入开关已关闭后，压力采样在捕获下一次观测前暂停。已开始的发布仍计入写者并等待结束；反复进行的只读开关检查不会占用写者记录、阻止配置应用器等待静默状态。开关重新打开后，恢复采样并产生新的准入额度。

每台电脑把 Runtime 请求和结算期限写入资源登记插件已有的配置。默认值保留为 5000 和 30000 毫秒，结算期限必须长于单次请求。数据库往返较慢时须明确修改节点设置，不改变资源权限、准入或结算结果不确定时的占用规则。

同一节点配置将现有浏览器连接插件的就绪和事件流建立期限投影到每个受管 Runtime，默认值保留为 15000 和 3000 毫秒。较慢的电脑使用显式覆盖，不改变其他电脑，也不要求用户修改受保护的核心插件。

浏览器有界 RPC 期限默认仍为 30000 毫秒，可独立于就绪等待配置。页面及其复用的目标连接沿用该 RPC 值；只增加连接就绪期限，不能延长已被浏览器载体取消的查询。

健康请求通过节点目标协议指定期望电脑，并要求响应携带相同身份。另一 Gateway 的配置代次或 release 相同也不能确认应用。就绪检查使用进程单调截止时间，每次在途响应受剩余时间及实际字节数限制。原生重启客户端不继承 Gateway 凭据，使用已配置的命令期限，并将租约取消订阅保留至进程实际关闭；客户端关闭不证明服务任务本身已停止。

配置写入在部署租约已有的后端事务中保留管理员。写纪元捕获使用同一后端，不需要第二次从连接池获取连接。后端丢失会在文件发布前中止租约信号。私有文件读取不等待 FIFO，拒绝非普通文件，并在 stat 后文件增长时仍限制实际字节数。临时清理要求已成功排他取得文件，并在 rename 发布后结束；排他取得失败及旧暂存路径被重用时，都保留其他写入者的文件。句柄释放保留独立的读写与关闭失败。[原子获取决策](../bug-fix/2026-10-26-atomic-file-acquisition.zh.md)负责这些清理规则。

## 考虑过的替代方案

**在在服请求内重启。** 请求的进程生命周期无法覆盖自身终止与后续核验。独立托管的工作进程在 Gateway 重启时仍持有操作所有权。

**开放环境文本或任意重启命令。** 这会授予超出声明设置的文件与命令权限，也无法可靠验证。Web API 只接受有类型的非秘密设置，服务命令由宿主机引导配置管理。

**逐字恢复旧备份中的每个文件。** 排队应用和连接设置可能让节点转向其他位置，或重放过期操作。不可变备份保留这些值供检查，当前控制文件保持权威，写纪元使旧请求失效。

## 影响

macOS launchd 和 Linux systemd 需要单独安装配置服务。外部 TLS 与路由仍由运维负责。路径变更核验已准备的数据，不按文件夹名称推断；移动密钥不执行密钥轮换。遗留写锁需要明确核验持有者并在本机恢复。服务重启成功不意味着退出维护。
