# Agent Note: Current-node configuration with independent application

Status: implemented

[English](2026-09-27-current-node-configuration.md) | 中文

## 问题

Web 服务不能完整持有修改自身监听或数据库配置的操作：应用这些值可能终止负责返回结果的请求。配置编辑也与备份、恢复竞争，而恢复出来的排队操作不能静默作用于另一个数据代次。

## 决策

节点持有一个私有、带版本的配置文件。管理员变更绑定组织、节点及期望 revision。期望值、已应用值和在服进程实际生效值保持区分。可编辑字段由显式集合声明，可执行命令、凭据内容、身份及隔离不进入其中。普通保存不会重启服务。

独立托管的应用器在共享数据库部署租约和本机配置锁下消费显式请求。请求绑定数据库写纪元。节点配置变更与备份、恢复共用租约，包括首次创建文件；已有文件的启动身份核验只读。macOS 不可变 release 还与 release 控制器共用激活锁。

预检要求维护窗口、运行时写者已停止、数据库身份兼容、数据路径已准备。发布前保留上一可用值，再执行宿主机管理的固定服务动作。健康检查必须确认已应用代次及 release。失去租约时停止发布，不发起新的回滚，由新持有者核对持久的应用中记录。本机恢复仍检查数据兼容性。备份恢复保留当前控制文件，在写库前拒绝不兼容的存储位置。

## 考虑过的替代方案

**在在服请求内重启。** 请求的进程生命周期无法覆盖自身终止与后续核验。独立托管的工作进程在 Gateway 重启时仍持有操作所有权。

**开放环境文本或任意重启命令。** 这会授予超出声明设置的文件与命令权限，也无法可靠验证。Web API 只接受有类型的非秘密设置，服务命令由宿主机引导配置管理。

**逐字恢复旧备份中的每个文件。** 排队应用和连接设置可能让节点转向其他位置，或重放过期操作。不可变备份保留这些值供检查，当前控制文件保持权威，写纪元使旧请求失效。

## 影响

macOS launchd 和 Linux systemd 需要单独安装配置服务。外部 TLS 与路由仍由运维负责。路径变更核验已准备的数据，不按文件夹名称推断；移动密钥不执行密钥轮换。遗留写锁需要明确核验持有者并在本机恢复。服务重启成功不意味着退出维护。
