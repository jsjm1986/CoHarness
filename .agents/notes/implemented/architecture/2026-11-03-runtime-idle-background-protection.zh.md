# Agent Note: Runtime 空闲回收保护后台工作

Status: implemented

[English](2026-11-03-runtime-idle-background-protection.md) | 中文

## Problem

所有浏览器断开后，受管 Host 仍可能拥有定时提醒、后台记忆处理和长时间插件工作。HTTP 活动与 WebSocket 引用不能单独证明进程空闲。释放 Session Agent 也不同于停止拥有插件和定时器的 Host。

## Decision

自动进程回收需要明确选择每 Runtime 的按需策略，并取得新的受认证 Host 判断。兼容默认值是常驻，因为现有任意插件可能拥有监督器无法直接检查的工作。策略复用现有 Runtime 设置提供方和项目管理员授权，不增加第二套配置存储。

插件通过 `runtime/idle-release-check` 声明自己拥有的义务。Host 也检查确切 Agent 的资源；循环会在公开状态为空闲时报告维护操作和待处理输入。Schedule 为活动的持久任务及已接受的管理或投递工作保留进程。记忆处理在清理结束前保留占用。这些声明用于自动回收，不改变显式关闭或权限撤销流程。

空闲判断使用独立 HMAC，覆盖挑战、所有者、代次、策略和结果。Gateway 保留不可用或不支持检查的 Host，并将终止绑定到确认的代次。挑战凭据只随进程 handle 保存在内存中。恢复接管后缺少该凭据的进程保持受保护，不推断其空闲状态。

PostgreSQL 先获取与资源准入相同的节点锁，再锁实例，申请空闲停止。申请重新检查活动时间和代次，并为排队、活动及清理未确认的预留拒绝停止。新执行或者先获得预留而阻止停止，或者在停止状态下无法开始。这扩展了[活动准入决策](2026-11-01-atomic-runtime-activity-admission.zh.md)，保留其中对当前权限的检查。

由持有者管理的工作流将否决注册在应用根上，在引擎卸载后仍保留，直到运行与子任务清理完成。Jobs 将 Runtime 和确切 Agent 的占用声明保留在根上，直至提供方 fiber 完成卸载；Loader 移除插件时，可能在清理结束前就删除其条目。Schedule 的声明持续保留到 domain 关闭完成。

Jobs 还将生产方的资源所有权与注册表记录分开跟踪。卸载取消抛错后，强制失败允许提供方完成移除，而原始生产方确认仍可能未完成。根上的 Runtime 和确切 Agent 占用声明持续到生产方确认资源释放、且输出清理完成。确认 promise 拒绝或清理失败会保持不确定状态，阻止自动释放。

## Alternatives considered

**使用连接数或公开 Agent 状态。** 二者都不能表达等待中的定时器、轮次结束后的记忆工作、维护操作和原生资源清理，仍需检查插件实际拥有的义务。

**为所有现有插件默认启用按需。** 未适配的监听器和定时器没有声明，缺少忙碌响应不能证明其安全。现有组合默认常驻。

**将调度搬到 Gateway。** Schedule 插件拥有周期、Session 绑定和持久投递语义。保留其 Host 即可保障运行，不必引入另一套调度器或改变错过投递的规则。要在两次定时触发之间停止进程，需要另行提供持久唤醒能力。

**在一条语句中合并加锁和检查。** 语句可能在等待节点锁之前取得快照。等待期间提交的资源预留必须对空闲判断可见，因此条件更新在获取锁之后使用新的语句快照。

**在提供方移除时无限等待异常生产方。** 取消抛错时，注册表强制失败保留非阻塞卸载行为。根上的独立所有权在空闲检查中保留尚未确认结束的工作，同时保持这一移除行为。

## Consequences

已激活的常驻 Runtime 保留进程，直到显式停止、故障或现有授权失效收敛流程。未使用的环境仍只按实际需求启动。相较于只检查连接的回收方式，可能保留更多进程，继续由现有节点限额管理准入；不假定任何资源节省比例。

定时器在运行中的 Host 内唤醒原 Session Agent，不启动已停止的进程；常驻策略也不会自动启动电脑或恢复已停止的环境。部署需要保留运行工作，不能依赖重启来应用这项策略。

真实 Loader、设置文件、持久化与 HTTP 场景覆盖常驻默认值、按需切换、维护操作和无活动 Session 的未来定时任务。原生受管进程场景覆盖签名及不支持的空闲判断。PostgreSQL 场景覆盖未释放预留、新活动、代次变化和并发准入。Session 身份、文件、草稿、模型权限和标签页选择仍由现有机制管理。
