# Agent Note：Client Session 引用

状态：已实施

[English](2026-09-23-client-session-references.md) | 中文

## 问题

由目录驱动的 scope 会在读取者消失后继续保留浏览器资源。同一 Session id 下替换 scope，也可能让旧 context 解析到替代对象。持久辅助视图需要独立于选中会话的所有权。

## 决策

在 [client/runtime](../../../../packages/client/runtime/README.zh.md) 中采用 alpha.2 的显式引用与代次身份模型。独立消费方共享打开过程，但分别持有和释放。取消获取等待只影响自身就绪状态；调用方仍需释放引用。最后一个引用结束本地代次，但不取消 Host Agent。借用 binding 或观察计数不会分配 scope。

CoHarness 的会话选择与 Workbench 适配器通过同一分配器获取普通引用。面板关闭后，目标运行时池仍为独立消费方保留连接。输入草稿和正在提交的操作持续持有代次，直到清空、丢弃或销毁，使视图切换保留本地输入。引用观察者可以同步请求导航；协调过程先发布已获取的视图所有者，再处理后续请求。

导航意图的取消生命周期独立于 Session 所有权。工作区创建、fork、初始选择与跨运行时 Workbench 加载在更新视图时仍须属于最新意图。显式选择、清空、布局变化和插件销毁使旧更新失效，但不撤销 Host 侧操作，也不丢弃其他视图的草稿。

视图导航持有临时引用，直到历史可用。选择操作先把所有权交给视图，再释放该引用。加载失败保留原视图及其草稿；导航消费方显示错误并允许重试。引用就绪保留上游的尝试结束语义，需要历史可用的操作调用方须检查返回快照。

每个代次都有独立 scope 标记和取消信号。根节点销毁会拒绝未完成的就绪等待，并使 binding 失效。已退役 context 不能解析到或向相同持久 id 的替代对象分发事件。异步清理只移除自身拥有的输入 shell。

这是[上游引用决策](2026-09-15-client-session-references.zh.md)在 CoHarness 中的适配；原记录继续保留更完整的 UI 所有权与调用期所有权依据。池化的当前选择适配器仍由本地保留；这一增量不代表 Host 事件调用期所有权已接通，也不代表辅助 UI 迁移完成。

## 考虑过的替代方案

**把目录成员关系保留为隐式所有者。** 每个列出的 Session 都可能在没有读取者时积累插件状态，辅助消费方也无法表达独立所有权。

**用上游会话外壳替换 Workbench。** 显式生命周期不要求修改 CoHarness 导航、项目目标或四面板布局。

## 影响

列表操作在执行期间持有 Session，直到操作结束。创建或 fork 返回的身份已进入目录，但借用 binding 前仍须获取引用。单测覆盖独立等待者、重复释放、根销毁、同 ID 替换、重入选择与目标连接所有权。输入测试保护草稿和清理；应用测试还须证明真实组装中的导航与 Workbench 流程。
