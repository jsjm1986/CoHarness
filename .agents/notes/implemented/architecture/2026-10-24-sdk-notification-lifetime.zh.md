# Agent Note: SDK 通知生命周期与活跃谱系

Status: implemented

[English](2026-10-24-sdk-notification-lifetime.md) | 中文

## 问题

通知过滤器可以关闭自身或同次分发中稍后处理的其他订阅。分发快照不能证明过滤器返回后订阅仍接受新帧。活跃谱系的生命周期也长于单条排队通知：谱系容量与队列容量绑定时，即使所有队列持续被取空，也可能静默移除祖先。

## 决策

两套 SDK 在调用过滤器后重新检查订阅所有权。Python 在调用快照中的各订阅前也检查成员关系，并在最终成员检查与入队期间持有客户端锁。过滤器在锁外执行，以便关闭订阅。

活跃父子关系使用独立的正整数容量，默认为 10000。子任务结束时释放对应关系。新增边超限时，以 `TransportClosedError` 终止现有和未来通知订阅，清空不完整谱系，并禁止重新启动该客户端。调用方关闭它，以足够容量创建新客户端。

## 已考虑的替代方案

**淘汰最早的活跃边。** 后代通知会从会话树订阅中消失，既不发生队列溢出，也不报告错误。

**持有客户端锁执行过滤器。** 过滤器关闭自身订阅时需要同一把锁，可能死锁。

**只在过滤器之前检查成员关系。** 过滤器可以先关闭自身，再返回匹配结果。

## 后果

队列容量限制各消费者待处理的帧，谱系容量限制同时活跃的父子边；两者不会静默削弱彼此。关系超限会明确终止交付，避免调用方把不完整树误认为完整任务输出。这些变更新增 SDK 配置，不改变运行时协议或 Session 事件。

## 验证

TypeScript 与 Python 回归覆盖自关闭过滤器、移除其他订阅和独立谱系容量。可运行 SDK 组合通过真实工具委派子会话和孙会话；持续取空的单帧队列必须保留三个助手输出。启动测试还覆盖没有无关事件循环句柄时的进程启动失败。

自有运行时子进程先发出通知批次，再返回工作目录响应。这些协议屏障覆盖自关闭过滤器、取空的单帧谱系、溢出隔离，以及200 帧上限内的两批 160 帧通知；不调用私有派发或订阅生产方法。关系溢出通过运行中的传输触发，并拒绝后续订阅和重启。
