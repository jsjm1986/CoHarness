# Agent Note: 分阶段加载远端 Runtime 入口

Status: implemented

[English](2026-11-19-remote-entry-deferred-index.md) | 中文

## Problem

从主入口 Gateway 直接打开远端 Runtime，需要等到该 Runtime 完成 HTML 渲染，才开始获取共享的浏览器静态文件。节点较慢时，用户想先写草稿，浏览器还在等待页面。

## Decision

主入口按指定 Runtime 查询当前账号可访问的目录后，提供本机发布包中的公共页面。选中的电脑通过原有 index 鉴权入口提供启动注入行。浏览器验证响应中的账号和 Runtime 后应用这些行。原始 HTML 转换走与直连入口相同的原生 index。

启动页面接收当前文档的文字。加载状态更新或必需插件失败时，输入框保留焦点，完整工作区链接仍可在单独的标签页打开同一账号、电脑和运行环境。确认原会话的账号、Runtime 和电脑以及草稿写入服务就绪后，只有该会话可接收文字。原会话不可用时，草稿仍留在原浏览器页面。原会话的准备历史请求共用首次对话窗口。当前会话的选择仍由正常目录校验决定。

结构化响应要求打开完整 index 时，浏览器继续正常的页面导航，不报告插件故障。只有草稿为空时，完整页面才会替换启动页。草稿非空时，原编辑框仍可用；完整工作区链接在新标签页打开同一目标，因此打开完整页面不会丢弃草稿。

## Alternatives considered

用响应预加载浏览器静态文件，首次可见的页面仍需等待远端节点。绑定到已确认位置的草稿让用户可以更早动笔。

## Consequences

公共页面由已认证的入口本地提供。页面发送 `x-dsh-bootstrap-preload: 1`，所属 Gateway 据此保留应用 `script-preload` 行。安装注册队列后，页面以低优先级启动一个同源且带固定修订号的应用脚本，同时按序执行高优先级的启动脚本。受保护的脚本使用 `private, no-store`，仅发出预加载提示不能保证下载会被复用。模块系统接收实际结果：组合脚本已执行时，仅为缺失的工厂请求单资源；提前下载失败时，计为该批次的首次尝试。带修订号的启动脚本下载失败后按原 URL 重试一次。未携带请求头的旧版页面收到省略应用预加载行的有界结构化启动响应。完整应用等待必需插件和连接状态就绪。远端入口的模型引导等工作区基线结束后进行。插件审批清单通过连接事件恢复。

## Verification

构建后的浏览器场景暂停两个标签页的远端启动响应，分别输入不同文字。其中一个标签页的启动下载收到 503 后重试恢复，并与单一应用批次并发重叠，模块系统创建后不会重复下载该批次。应用恢复场景验证：丢弃一个工厂后只请求一个单资源；提前下载失败时，先重试一次普通批次，再请求单资源。每份草稿只交给原账号和 Runtime 的原会话。暂停期间没有提交消息或访问其他 Runtime。
