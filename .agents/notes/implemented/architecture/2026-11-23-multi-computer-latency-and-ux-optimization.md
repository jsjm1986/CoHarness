# Agent Note: Multi-computer forwarding, governance fast paths, and Admin SPA switching

Status: implemented

English | [中文](2026-11-23-multi-computer-latency-and-ux-optimization.zh.md)

## Problem

Multi-computer deployments route remote browser traffic through the center Gateway while each remote Gateway reaches the central PostgreSQL governance database over a high-latency tunnel. Every cold service stream previously incurred a remote cross-tunnel `authorizeChannel` query, the idle pool defaulted to two streams per node and cleared every node's idle pool on any organization-level invalidation, and `LISTEN`-healthy nodes still polled PostgreSQL every second. Browser JSON payloads and remote `/plugins/*` bundles crossed the center uncompressed and uncached, interactive Web Terminal writes fell through full proxy admission and multi-statement SQL authorization, cold `/api/prepare/v1/*` requests waited on fixed two-second polling intervals, forwarded requests repeated `monitor.synchronize()` on both gateways while forwarded `node_content` project reads fell off the `readySession` fast path, project and `node_content` model turns executed multiple sequential governance queries and a second status round-trip before streaming, and switching computers in the Admin UI triggered a full browser reload.

## Decision

The forwarding and HTTP transport layers in `gateway/src/node-service-http-pool.ts`, `gateway/src/node-service-proxy.ts`, `gateway/src/node-service-stream.ts`, `gateway/src/http-compression.ts`, and `gateway/src/runtime-assets.ts` reduce tunnel round-trips and wire volume without weakening authorization. Idle HTTP pool defaults are `httpMaxIdleConnections = 32` and `httpMaxIdlePerNode = 6`, organization- or user-scoped invalidations leave healthy node pools intact, remote bridge attestations use a single-flight invalidation-backed cache (`HGW_NODE_SERVICE_IDENTITY_CACHE_MS`, default `5000`), and `LISTEN`-healthy invalidation polling relaxes to `HGW_ACCESS_INVALIDATION_HEALTHY_POLL_MS` (default `15000`) while reverting to the fast interval on listener disconnect. Heavy JSON responses negotiate Brotli or gzip above 1024 bytes while preserving `vary` headers and excluding streaming formats. The center caches immutable remote `/plugins/*` bodies up to `HGW_RUNTIME_ASSET_CACHE_MAX_BYTES` (default `33554432`) strictly after `qualify()` and `monitor.synchronizeTo()`, evicts on node invalidation, and exposes forwarding, pool, and cache counters on `GET /admin/api/performance`.

Remote admission, cold-start readiness, and cross-node fan-out avoid redundant tunnel waits. `gateway/src/access-invalidation.ts` tracks the live revision and exposes `ensureAtLeast(revision)`; signed forward claims (`gateway/src/forwarded-principal.ts`) carry the center's verified `accessRevision` so the remote gateway skips a redundant cross-tunnel `synchronize()` whenever its `LISTEN` cursor has already caught up. `gateway/src/runtime-asset-admission.ts` admits forwarded `node_content` project reads onto `readySession` while re-verifying issuer key identity and revision. `gateway/src/instances.ts` probes fresh runtimes with stepped intervals `[50, 100, 150, 200, 300]` ms and `gateway/src/proxy.ts` performs a bounded server-side short-wait (`HGW_RUNTIME_PREPARE_WAIT_MS`, default `1500`) with `retry-after: 1`. Interactive terminal writes and resizes (`/api/terminal/write`, `/api/terminal/resize`) route as `interactive` priority onto `readySession`, and `gateway/src/execution-identity.ts` collapses personal terminal authorization into a single auto-commit CTE. Document overviews (`gateway/src/browser-documents.ts`) fan out with bounded concurrency `6`, and independent `workbench.ts` and `beforeStart` preparations run concurrently.

Model first-token governance in `gateway/src/postgres/model-governance-service.ts`, `gateway/src/runtime-resource-api.ts`, `gateway/src/execution-identity.ts`, and `gateway/src/postgres/instance-repository.ts` extends fast paths to project and `node_content` runtimes. `resolveRuntimeCredential` resolves personal, organization-managed project, and `DSH_PROJECT_*` credentials in one statement with active-project and cluster serving/epoch fencing; `instance-repository.ts` caches project `RuntimeCredentialSubject` rows alongside personal entries under the existing deferral gate; immediate active scoped model grants inline post-reservation `authorizeSession` confirmation (`x-hgw-resource-qualified-grant: 1`) and attach a change cursor for queued calls; and `execution-identity.ts` folds project scope, actor, steward-policy, membership, and `node_content` placement checks into two SQL statements. Cross-log correlation carries `ResourceLease.operationId` into `ModelAttemptTiming.resourceOperationId` and `enterOperationId`/`authorizeOperationId` in `gateway/src/operation-timing.ts`.

The Admin SPA (`gateway/admin-ui/src/App.tsx`, `ComputerSelector.tsx`, `pending-edits.tsx`, `deployment-context.tsx`, and `pages/DeploymentPage.tsx`) keeps `DeploymentContextProvider` and `ComputerSelectorProvider` mounted above a computer-keyed `RouterProvider` so clean computer switches update history in-SPA without reloading the document or refetching topology and node directories, while dirty forms keep the unsaved-edits confirmation dialog and new-tab fallback. Passive window `focus` and `visibilitychange` refreshes are throttled over a two-second window while explicit policy-change notifications refresh immediately. The [production deployment runbook](../../../../gateway/deploy/README.md) documents HTTP/2, upstream keepalive, compression, unbuffered streaming, WebSocket upgrade mapping, and multi-computer Gateway tuning variables.

## Alternatives considered

**Disable `entryReadRelease` or pre-response authorization on the center.** Dropping the center's post-header verification would weaken runtime-restart detection and violate existing versioned node-service guarantees. Keeping center-side local PostgreSQL checks intact preserves security invariants at negligible local latency.

**Serve cached remote `/plugins/*` bundles before `qualify()` or without `vary` preservation.** Caching ahead of request qualification would bypass per-user and per-node authorization. Performing `qualify()` and `monitor.synchronizeTo()` before serving any cached body guarantees every hit respects live access rules and encoding negotiation.

**Replace per-keystroke Web Terminal writes with a brand-new bidirectional WebSocket protocol immediately.** Introducing a parallel terminal input frame protocol across client, host, and gateway would widen the wire surface and duplicate revocation handling. Routing interactive terminal paths through `readySession` with a single-statement CTE authorization delivers immediate multi-RTT latency reduction while keeping existing `stream-principals` semantics intact.

**Keep a single global `createBrowserRouter` with nested `/computers/:id/*` routes in Admin UI.** Rewriting every Admin `<NavLink>`, `<Link>`, and relative `useLocation().pathname` consumer would touch every page. Mounting a computer-keyed `RouterProvider` beneath persistent `DeploymentContextProvider` and `ComputerSelectorProvider` eliminates full page reloads and redundant context fetches while preserving every existing route contract.

## Consequences

Under the reproducible multi-computer benchmark (`gateway/tests/multi-computer-latency.perf.ts`, 40 ms simulated tunnel PostgreSQL RTT and 4 ms center PostgreSQL RTT, ×5 for a 200 ms production tunnel), a six-request page-open burst drops from 6 to 1 remote cross-tunnel `authorizeChannel` queries and from 6 to 0 remote `accessSync` queries; ten sequential warm `/api/terminal/write` calls drop median latency by ~60% (from ~150 ms to ~60 ms at 40 ms RTT, ~750 ms to ~300 ms at 200 ms RTT); an unrelated user invalidation leaves all four node-pool streams warm (`poolOpened: 0`, ~70% faster burst); dual WebSocket upgrades drop median latency by ~72–79%; three-node document overviews run ~3× faster; and warm cached remote `/plugins/combo.js` hits drop latency by ~75–86% and wire bytes by 98.2% (`br`). Personal terminal authorization drops from 11 sequential SQL statements to 1, and active project or `node_content` model turns eliminate a full status HTTP round-trip plus multiple governance tunnel queries.

These optimizations add bounded memory usage on the center for cached remote plugin assets (capped by `HGW_RUNTIME_ASSET_CACHE_MAX_BYTES`) and rely on PostgreSQL `LISTEN` health to skip redundant remote polling or access synchronization; when `LISTEN` disconnects, the monitor falls back immediately to the fast poll interval and explicit synchronization.

## Verification

Unit suites cover forwarding pools, compression, remote asset caching, access revision propagation, forwarded `node_content` admission, single-statement terminal and model credential fast paths, and Admin SPA in-page computer switching (`gateway/tests/http-compression.spec.ts`, `runtime-assets.spec.ts`, `node-service.spec.ts`, `proxy.spec.ts`, `instances.spec.ts`, `access-invalidation-poll.spec.ts`, `forwarded-principal.spec.ts`, `terminal-authorize-fast-path.spec.ts`, `model-first-token-fast-path.spec.ts`, `runtime-api.spec.ts`, and `gateway/admin-ui/src/computer-switch.spec.tsx`). End-to-end synthetic latency verification runs through `node --import tsx/esm gateway/tests/multi-computer-latency.perf.ts`. Live PostgreSQL integration tests self-skip without `HGW_TEST_DATABASE_URL` and remain covered by CI.
