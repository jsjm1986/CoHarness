# Agent Note: Multi-computer forwarding, governance fast paths, and Admin SPA switching

Status: implemented

English | [中文](2026-11-23-multi-computer-latency-and-ux-optimization.zh.md)

## Problem

Multi-computer deployments route remote browser traffic through the center Gateway while each remote Gateway reaches the central PostgreSQL governance database over a high-latency tunnel. Every cold service stream previously incurred a remote cross-tunnel `authorizeChannel` query, the idle pool defaulted to two streams per node and cleared every node's idle pool on any organization-level invalidation, and `LISTEN`-healthy nodes still polled PostgreSQL every second. Browser JSON payloads and remote `/plugins/*` bundles crossed the center uncompressed and uncached, interactive Web Terminal writes fell through full proxy admission and multi-statement SQL authorization, cold `/api/prepare/v1/*` requests waited on fixed two-second polling intervals, forwarded requests repeated `monitor.synchronize()` on both gateways while forwarded `node_content` project reads fell off the `readySession` fast path, project and `node_content` model turns executed multiple sequential governance queries and a second status round-trip before streaming, and switching computers in the Admin UI triggered a full browser reload.

## Decision

Topology visibility checks share work only within an applied access revision. An unrelated revision can start a new check while an earlier one settles. Node or organization invalidation still fences all outstanding positive results for the affected computer. If either legacy workbench request fails, the Gateway cancels its sibling and returns the available project catalog.

The forwarding and HTTP transport layers in `gateway/src/node-service-http-pool.ts`, `gateway/src/node-service-proxy.ts`, `gateway/src/node-service-stream.ts`, `gateway/src/deployment-topology.ts`, `gateway/src/http-compression.ts`, and `gateway/src/runtime-assets.ts` reduce tunnel round-trips and wire volume without weakening authorization. Idle HTTP pool defaults are `httpMaxIdleConnections = 32` and `httpMaxIdlePerNode = 6`, both ends of node-service TCP sockets disable Nagle (`noDelay: true`), user- and project-scoped invalidations leave idle node transports available, while node and organization changes drain the affected transports, explicit logout invalidation cancels both local proxy and forwarded node-service operations, remote bridge attestations and secondary topology reads use a single-flight invalidation-backed cache (`HGW_NODE_SERVICE_IDENTITY_CACHE_MS`, default `5000`), `PostgresDeploymentTopology.assertNode()` deduplicates visibility checks at the same access revision and caches up to 256 positive `entry_node_visible` results for up to 5 s while `LISTEN` remains connected (clearing cached and outstanding checks on topology save, node/organization invalidation, or listener disconnect, skipping stale cache writes when unrelated revisions advance mid-query, and never caching refusals), local `?dshNode=<local>` Admin and document requests bypass redundant proxy re-authorization on the destination Gateway, each borrowed connection rechecks its exact node lease, the primary verifies authority and process generation before releasing delegated reads, and `LISTEN`-healthy invalidation polling relaxes to `HGW_ACCESS_INVALIDATION_HEALTHY_POLL_MS` (default `15000`) while reverting to the fast interval on listener disconnect. Account (including `/account/api/users`, `/account/api/document-locations`, `/account/api/documents/transfer/*`, and project SSH/model-discovery endpoints, with `/account/api/workbench/catalog` running `projectsForUser` and `workbenchCatalog` in parallel), Admin (`/admin/api/*`), and forwarded compressible HTTP responses (including eligible chunked responses with no declared length) negotiate Brotli or gzip while preserving `vary` headers, weakening changed `etag` values, and excluding streaming media types. The center caches immutable remote `/plugins/*` and hashed `/assets/*` bodies up to `HGW_RUNTIME_ASSET_CACHE_MAX_BYTES` (default `33554432`) strictly after per-request `qualify()` and `monitor.synchronizeTo()`, partitions entries by computer, Runtime generation, account, and space, and evicts affected entries when access changes, and exposes forwarding, pool, and cache counters on `GET /admin/api/performance` and an on-demand collapsible section on the Admin Deployment page.

Remote admission, cold-start readiness, and cross-node fan-out avoid redundant tunnel waits. `gateway/src/access-invalidation.ts` tracks the live revision and exposes `ensureAtLeast(revision)`; signed forward claims (`gateway/src/forwarded-principal.ts`) carry the center's verified `accessRevision` so the remote gateway skips a redundant cross-tunnel `synchronize()` when its `LISTEN` cursor has applied the required revision. A pending access change disables the revision shortcut while readiness can still observe cancellation. `gateway/src/runtime-asset-admission.ts` admits forwarded `node_content` project reads onto `readySession` while re-verifying issuer key identity and revision. `gateway/src/instances.ts` probes fresh runtimes with stepped intervals `[50, 100, 150, 200, 300]` ms and `gateway/src/proxy.ts` performs a bounded server-side short-wait (`HGW_RUNTIME_PREPARE_WAIT_MS`, default `1500`) with `retry-after: 1`. Interactive Web Terminal input uses a persistent attachment-bound text WebSocket channel (`/api/terminal/input`, registered through `ctx.connection.ws.handle(...)` in `packages/client/connection` and `packages/api/terminal-controller`), isolating active attachments by creator, verifying creator ownership (`verifyUpgradeCreator`), closing on revocation/expiry/logout, enforcing a bounded client acknowledgement timeout, scheduling bounded exponential-backoff reconnects, and falling back transparently to HTTP `/api/terminal/write` and `/api/terminal/resize` (which remain routed as `interactive` priority onto `readySession` with single-statement personal CTE authorization in `gateway/src/execution-identity.ts`). Cold terminal opens overlap speculative shell discovery with `environment` and `list` lookups, and `SessionRuntimePool` (`packages/client/runtime/src/client/sessions/pool.ts`) starts `workspace.list` concurrently with `session.list` on target connect to save one remote round-trip per computer switch. Document overviews (`gateway/src/browser-documents.ts`) fan out with bounded concurrency `6`, validate local `/account/api/node-document-overview` sub-requests without session row locks, and skip redundant `monitor.synchronize()` calls on provisional streaming frames while `LISTEN` is caught up (still synchronizing on `complete`), independent workbench reads run concurrently, and instance-owned `sessionStorage`-backed verified project display caches (`packages/client/runtime/src/client/project-display-cache.ts` and `gateway/admin-ui/src/project-display-cache.ts`) avoid `#id` flashes while preserving live authority verification and eviction on 401/403 or sign-out. Runtime launch overlaps the plugin-state read with grants and model-policy preparation. The launch owns both operations through settlement, and it writes the plugin profile only after preparation succeeds. The applied revision update requires the launch generation. Offline recovery inspection can prepare the same files while leaving the applied revision intact.

Model first-token admission covers personal, project and `node_content` Runtimes. `resolveRuntimeCredential` reads the current Runtime authority, write epoch and managed credential in one statement. The model credential endpoint may select cached project coordinates. Personal execution admission selects only personal coordinates. Immediate scoped model grants carry the result of post-reservation `authorizeSession` confirmation (`x-hgw-resource-qualified-grant: 1`). Queued calls can carry a change cursor. `node_content` execution authorization combines project placement, steward qualification and membership checks in one governance statement that locks the matching project and placement rows. Cross-log correlation carries `ResourceLease.operationId` into `ModelAttemptTiming.resourceOperationId` and `enterOperationId`/`authorizeOperationId` in `gateway/src/operation-timing.ts`.

Each Admin document uses one data router for center and computer routes. The deployment and computer directory providers remain mounted through route changes. Computer-scoped links and requests derive their node from the committed route. A computer switch remounts page state for the new target. One blocker protects browser history across both route scopes and keeps dirty forms mounted with a link to open the destination in another tab. The Admin Deployment page consolidates initial mount reads (`deployment`, `backups`, `tunnel`, `nodeConfiguration`, optional `nodeConnection`, and center-only `runtimeAllocationPolicy`/`nodeAccess`) through one compressed `GET /admin/api/deployment/overview` snapshot (falling back to individual endpoints on `404`), and pauses hidden-tab tunnel polling. Passive window `focus` and `visibilitychange` refreshes are throttled over a two-second window while explicit policy-change notifications refresh immediately. The [production deployment runbook](../../../../gateway/deploy/README.md) documents HTTP/2, upstream keepalive, compression, unbuffered streaming, WebSocket upgrade mapping, and multi-computer Gateway tuning variables.

A forwarded WebSocket borrows a revalidated node connection from the HTTP pool. From upgrade until close the WebSocket owns it exclusively, including under a one-connection quota. Terminal input coalesces consecutive unsent resize frames within each attachment, preserving the order of user input. The account context reads project membership and display policy together so the number of directory reads is independent of the number of remote projects. The current-node response derives forwarding scope and deployment metadata from a single authorized revision. An administrator can explicitly retry a refused project-label read after the directory clears its affected cached labels.

## Alternatives considered

**Route delegated reads with only the access revision.** Lease and Runtime generation can change independently of that revision. The primary checks current authority at response release.

**Serve cached remote `/plugins/*` bundles before `qualify()` or without `vary` preservation.** Caching ahead of request qualification would bypass per-user and per-node authorization. Performing `qualify()` and `monitor.synchronizeTo()` before serving any cached body guarantees every hit respects live access rules and encoding negotiation.

**Keep Web Terminal keystrokes strictly on per-keystroke HTTP POSTs without a WebSocket input channel.** Even with `readySession` and single-statement CTE authorization, every keystroke batch over HTTP still crosses Center and Remote admission gates and PostgreSQL checks. Binding a text WebSocket (`/api/terminal/input`) directly to an already-authenticated `follow()` attachment through `ctx.connection.ws` eliminates per-keystroke HTTP/PG overhead while retaining exact creator verification, immediate revocation closure, and transparent HTTP fallback.

**Recreate the Admin router when its computer basename changes.** With a different router for each computer, the browser can leave an edited page before its blocker handles the transition. A compensating push discards browser Forward entries. A document-wide router gives the blocker ownership of the entire history.

## Consequences

Under the reproducible multi-computer benchmark (`gateway/tests/multi-computer-latency.perf.ts`, 40 ms simulated tunnel PostgreSQL RTT and 4 ms center PostgreSQL RTT, ×5 for a 200 ms production tunnel), a six-request page-open burst drops from 6 to 1 remote cross-tunnel `authorizeChannel` queries and from 6 to 0 remote `accessSync` queries; ten sequential warm `/api/terminal/write` calls drop median latency by ~60% (from ~150 ms to ~60 ms at 40 ms RTT, ~750 ms to ~300 ms at 200 ms RTT); an unrelated user invalidation leaves all four node-pool streams warm (`poolOpened: 0`, ~70% faster burst); dual WebSocket upgrades drop median latency by ~72–79%; three-node document overviews run ~3× faster; and warm cached remote `/plugins/combo.js` hits drop latency by ~75–86% and wire bytes by 98.2% (`br`). Personal terminal authorization drops from 11 sequential SQL statements to 1, and active project or `node_content` model turns eliminate a full status HTTP round-trip plus multiple governance tunnel queries.

These optimizations add bounded memory usage on the center for cached remote plugin assets (capped by `HGW_RUNTIME_ASSET_CACHE_MAX_BYTES`) and rely on PostgreSQL `LISTEN` health to skip redundant remote polling or access synchronization; when `LISTEN` disconnects, the monitor falls back immediately to the fast poll interval and explicit synchronization.
