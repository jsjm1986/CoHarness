# Agent Note: 按来源身份复用客户端列表投影

Status: implemented

[English](2026-10-23-client-list-projection-reuse.md) | 中文

## 问题

一个 Session 更新会重新发布供行选择器读取的列表快照。即使 manager 条目保留身份，重建所有摘要也会改变无关选择器的结果。账号池还会为包含 runtime 信息的 id 和项目标签增加一次投影。复用必须区分 Session 数据变化与所属 runtime 描述变化。

Documents 管理器通过同一浏览器包内的工厂创建 HTTP 客户端，该客户端必须提供 `browseScope` 方法。将这个方法视为可选并检查 `listScope` 的参数个数，为生产环境从未替换的客户端实现增加了第二套兼容机制。

## 决策

runtime 按不可变的 manager 条目记忆 `SessionSummary`。账号池按该来源摘要和 runtime 描述的身份记忆带所属 runtime 信息的摘要。弱键跟随来源行的生命周期，无需第二个强引用保留注册表。项目名称或 runtime 目标变化会替换池中的投影。manager 复用条目时会将可见性和项目 id 与其他已发布字段一起比较。

Documents 管理器直接调用具有静态类型的 `browseScope` 方法。HTTP 客户端现有的路由缺失回退继续兼容旧 Host，并保留目录和分页参数。组件 fixture 提供与生产工厂相同的必需方法。

[客户端架构](2026-07-19-gui-web-client-architecture.zh.md)、[多 Session 工作台](2026-09-08-cordis-multi-session-workbench.zh.md)和[文档作用域切换](../bug-fix/2026-08-27-stable-document-scope-switching.zh.md)决策继续分别负责加载、所有权和元数据缓存规则；行投影复用不会取代其中任何一项。

## 考虑过的替代方案

**在 React 中比较完整列表数据。** 这会让每个消费者重复比较，也无法阻止对象层为未变化的行发布新引用。由生产者复用行即可继续使用 `Object.is` 选择器。

**仅按 Session id 缓存。** id 无法标识摘要版本或 runtime 描述。此类缓存还需要独立的失效和淘汰机制，才能避免元数据过期与已删除行被保留。

**保留其他本地文档客户端实现。** 管理器没有生产客户端注入协议，而是自行创建具有静态类型的工厂。真实兼容应由已经实现的 HTTP 响应与路由处理负责。

## 影响

无关更新期间行身份保持稳定，列表顺序、Session 引用、连接所有权和通知节奏均不改变。列表构造仍会遍历目录；此变更减少摘要重建和选择器失效，并非将每个列表操作都改为增量处理。上游不可变条目和 runtime 描述的身份是缓存版本信号。

列表诊断测量行投影复用。[客户端交互工作](2026-10-23-client-interaction-work.zh.md) 单独定义选择性结算重放、导航失效和浏览器验证；投影计数不测量这些操作。

## 验证

runtime 和池的回归覆盖无关行身份、状态变化、可见性与项目元数据，以及 runtime 标签重命名。文档组件测试通过必需的客户端方法覆盖作用域导航；HTTP 客户端测试保留路由缺失回退用例。

包内的[源码诊断](../../../../packages/client/runtime/tests/list-projection.perf.client.ts)在三份独立对象图中分别创建 1,000 行合成数据，并施加 100 次单行状态更新。runtime 和池各替换 100 个已发布摘要，未复用时各替换 100,000 个。本地 Node 25.8.1 源码运行的三次耗时为 276.13、248.64 和 193.66 ms，未复用时为 409.36、272.62 和 297.99 ms。这些耗时包含源码执行和引用计数，只是诊断观察，不是浏览器测量或 CI 预算。
