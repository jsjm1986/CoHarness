# Agent Note：浏览器 Runtime 身份与文档位置

Status: implemented

[English](2026-10-29-browser-runtime-and-document-location.md) | 中文

## 问题

只包含所属账号的 Runtime 键会混淆多个个人分配。文档与 Runtime 进程的生命周期不同，浏览器全局选择还可能改变另一标签页的操作目标。通过任意 Runtime 解析存储，会让缓慢或退役的进程成为文件访问的前提。

## 决策

受管浏览器会话使用分配 UUID，个人文档使用账号和电脑标识。页面在初始化连接前固定分配身份，已认证的 Host 握手必须确认同一身份。空间 Cookie 或其他标签页的选择不能替换它。同一账号的个人分配具有不同的会话键；显示元数据不参与键值。文档浏览独立于对话执行目标，固定自己的存储位置。每次可续传上传在开始前解析创建路由；所有元数据和原生分块请求保留该路由及带电脑身份的空间，不复用仅面向执行环境的路径。

浏览器文档授权不借用个人 Runtime，也不构造进程代次。它直接检查当前账号、电脑使用权和项目成员权限。个人存储还要求已保留归属于该电脑的账号主目录，不能回退到其他电脑的主目录路径。现有 Runtime 回调仍需实际凭证与执行参与。电脑本地的账号主目录在分配退役后保留。元数据发现查询中心维护的有界分页，不启动 Runtime，也不探测文件系统。复制预览读取选中文件的响应头，不遍历文件夹。

复制预览保留双方带电脑身份的空间以及操作账号。提交时重新检查双方授权，流式复用现有经校验的可续传上传协议，并在目标电脑记录来源关系。Runtime 和浏览器复制使用同一上传实现。路由完成后移除 Gateway 专用选择参数，同时保留模块加载器的不透明查询语法。启动资源和插件包在连接校验组件安装前也固定当前标签页的分配。

待完成的环境目录读取和缓存页归属于已验证账号与连接。账号变化或连接失效时取消这些读取并清除分页。电脑元数据尚未获得时，会话文档请求保留具体 Runtime 地址；位置缺失不授予改用当前标签页的权限。账号入口保留本地界面目标，不接受外部地址或 API 重定向。

统一空间入口用已有身份寻址个人分配和固定电脑的项目。电脑标签说明当前页面或所渲染 Session 的归属，不会迁移资源。按账号隔离的收藏和最近使用 ID 不会成为导航状态。文档浏览在管理器重新打开时保留来源电脑、文件夹和搜索；账号或基础作用域变化会丢弃缓存位置。筛选等待尚未完成的文件夹切换提交，因为读取上一层会取消缓慢的导航。加入附件时单独说明对话目标，其他来源先复制再附加。

个人空间只有一个导航入口。工作区浏览器按电脑组织已授权分配，对话、目录操作和视图排序记录保留各自的 Runtime 身份。Runtime 使用已认证的进程代次发布已提交的工作区元数据；新修订替换旧发布，目录读取按当前电脑权限筛选。浏览缓存不会连接其他 Runtime，也不扫描文件。显式导航在准备和视图接管期间保留目标连接。按账号区分的标签页选择记录在启动身份确认后只恢复选中的对话。设置保持并标识其启动环境的配置归属，避免对话导航改变未完成编辑的写入目标。

共享账号管理、模型、用量和预算由中心处理；将其转发到所选执行电脑，会使组织管理依赖该电脑的连接状态。账号偏好、推送设备登记及项目目录不要求选择 Runtime。工作台目录从元数据解析所选分配，不要求本机 Runtime 存储，也不连接其所在电脑。电脑资料、项目操作和本地资源保留各自的电脑选择。浏览器 SVG 图标继承来源标签页中已验证的分配，账号存在多个个人 Runtime 时也保持这一归属。

文档加入前的预检和接收均检查固定目标 Session 的实时输入状态与授权策略。即使加入失败，已完成的复制仍是持久文件；保留目标引用以支持只重试加入。已保存的导航 ID 是不可信的查询输入，按当前权限执行的有界元数据查询使快捷入口不依赖目录分页。Admin 编辑仍由每个页面中挂载的表单持有，同页面历史导航在表单卸载前被拦截；在另一标签页打开目标可保留凭证和未完成写入，无需在页面之间同步草稿值。

执行电脑归属放在对应空间或 Session 标题旁。紧凑顶部栏解析选中 Session 的 Runtime，每个工作台面板保留自己的电脑。只有没有选中 Session 时才使用页面启动环境；位置元数据缺失不代表归属于启动环境的电脑。纯身份标签保持非交互，环境操作由空间导航统一持有，切换和打开新标签页保留同一入口。

桌面空白空间在工作区创建对话之前显示已验证的启动电脑。收起侧栏时由顶部栏持有该空状态标识，手机保持同样的单处显示；单电脑模式同时移除标识及其无障碍文字。

不含会话地址的 Remote 消费者同时固定 Runtime 连接与调用者的查找上下文。每个 Runtime 的缓存、事件订阅和文件提供者不单独使用个人／项目所有者键。保留的 Connection 句柄跨越流关闭而存在，每条流的清理只属于打开它的那次操作；复用句柄因此能保留观察器，同时不允许旧所有者控制替代连接。

动态 Cordis 定义保留 Host 身份，浏览器模块、视图与主题键增加 Runtime 命名空间。审批、Host 调用、目录读取和 inspect 请求保留相同所有者。管理页面只保留明确选中的 Runtime，关闭或取消只撤回导航与读取，不取消 Host 已接受的工作。配置表单固定启动所有者，其他环境在独立文档中打开。

没有限定运行环境的已保存布局会保留未决身份，直到用户确认原 Runtime 或明确移除窗格引用。确认涵盖全部命名布局，但不准备未活动窗格。目录不完整或迟到的恢复不能静默替换更新的布局选择；元数据可见不等于获准启动 Runtime。

项目目录成员资格按项目固定电脑与浏览器入口的部署范围判定。跨已授权电脑的目录可见性不授予入口电脑执行该项目的权限。项目尚无对话时仍保留电脑与所有者元数据；成员目录读取直接携带这些信息，不逐项目追加详情请求。

## 后果

客户端与 Gateway 发布必须携带匹配的分配感知 API 和浏览器资源。保留的文档主目录无需 Runtime 即可访问。每个界面操作固定资源所属电脑和分配；连接故障不授予改选其他位置的权限。

未携带目标的浏览器入口在隐含所有者选择不唯一时，可以选取一个个人启动分配。它按入口电脑、保留的原个人存储、分配时间和 UUID 排序，并沿用精确目录读取中的当前账户和电脑授权；连接状态不改变该身份。默认选择只适用于页面捕获目标之前，显式链接和所有者 API 仍保留原有的不唯一与拒绝行为。因此入口本机默认值可恢复直接登录工作台，同时不重定向既有标签页，也不启动全部已分配 Runtime。

## 考虑过的替代方案

选择第一个个人 Runtime 会让文档归属依赖分配顺序，并在退役后失效。为浏览器存储生成执行令牌会引入不对应运行进程的权限。两者都不能证明文档访问权。浏览器全局的当前电脑值则会让一个标签页的切换改变另一页的写入目标。现有[多电脑提案](../../proposed/architecture/2026-10-28-multi-computer-personal-runtimes.zh.md)继续记录更广泛的部署和延后的平台工作；其个人空间模型沿用这里的存储与执行区分。

## 验证

构建产物的节点服务场景运行两台真实 Gateway、出站代理和正式 Web 配置，验证独立 Runtime 进程、精确 Admin 控制、浏览器复制预览、内容校验、跨电脑来源关系，以及撤销电脑使用权后的元数据与内容拒绝。聚焦浏览器测试覆盖不同分配中相同会话编号、明确的文档位置、标签页独立校验及归属于对话框的电脑菜单。发布过的会话代次保持原格式。
