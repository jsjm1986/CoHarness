# Agent Note: Independent-review hardening across node, deployment, and admin surfaces

Status: implemented

English | [中文](2026-11-07-independent-review-hardening.zh.md)

## Problem

A multi-angle independent review of the active branch (Windows node/deployment, admin and Remote Desktop UI, node-lease concurrency, postgres service layer, peer backup, client runtime pools) confirmed real defects on shipping paths: Win32 error codes were read on the wrong thread, forwarded peer assertions accepted non-finite timestamps and replayable nonces, `schtasks /end` could orphan the node agent while it held the control lease, admin surfaces rendered raw machine error codes, the lease SQL functions' success payload was trusted blindly, `recoverSteward` allocated ports outside the documented advisory-lock critical section, steward dry-run `EXPLAIN` could be steered into `EXPLAIN ANALYZE` execution past both the approval gate and the read-lane deny-list, and `node_channel_lease` lacked the deployment-topology gate that `node_heartbeat` enforces. Later rounds found lock-order cycles between advisory and row locks in project/auth/recovery paths, an uncancellable `retiring` recovery phase that froze a runtime and held the project's takeover slot, a detached node-content creation whose cleanup deleted only `spaces` while fourteen non-cascading child tables guaranteed a 23503, a client session pool that could reap an entry mid-handshake and swallow a verified node migration, and admin/remote-desktop surfaces that kept stale picks, grants, and credential state across target switches.

## Decision

**Win32 errno honesty.** [directory-move-win32.ts](../../../../packages/attachment/userdoc-local/src/directory-move-win32.ts) calls `CreateFileW`/`GetFileInformationByHandle`/`MoveFileExW` synchronously: `call.async` executes on a koffi worker thread while the callback runs on the JS thread, where `GetLastError` reads stale thread-local state and every failure collapsed to `EIO`, breaking the `EEXIST`/`ENOENT` recovery branches in `store.ts`/`mutation.ts`. [windows-inspector.ts](../../../../packages/subprocess/subprocess-local/src/windows-inspector.ts) pairs every `koffi.alloc` with `koffi.free` in `finally`, matching `win32-process`'s `freeNative` ownership convention.

**Forwarded assertions.** [forwarded-principal.ts](../../../../gateway/src/forwarded-principal.ts) requires `Number.isSafeInteger` on `issuedAt`/`expiresAt` (an `Infinity` expiry previously passed `typeof` checks and never expired), and `index.ts` holds a caller-owned nonce ledger (`Map` keyed by nonce with TTL pruning, no module-level state) so a captured assertion cannot replay inside its TTL. `server.ts` comments now state that `x-dsh-target-node` is a client-settable routing marker, not arrival evidence. A second round found the verified assertion was a **bearer credential**: `currentUser` accepted it with no session cookie at all, so a captured assertion granted full `claims.user` access on every gateway-local endpoint (including `/account/password`) within its TTL. `issueForward` now signs a `request` binding — method, pathname, and `sha256(sessionToken)` — and `forwardRequestMatches` refuses acceptance unless all three match the arriving request; `x-dsh-target-node` remains a routing marker, not evidence. Assertions minted before the binding lack `request` and fail-closed into ordinary session validation, keeping rolling deploys compatible. `NodePrincipalDirectory.issuerKey` caps its memoization at the lease deadline read in the same query and evicts the oldest entry instead of clearing the map under spray pressure; the nonce ledger clamps retained expiry to `principalAssertionTtlMs` and bounds at 4096 entries; accepted forwards on non-`/api` paths journal an `auth.forwarded` audit row carrying `issuerNode`+`nonce` — `/api` mutations are already attributable to the bound session, while gateway-local mutations would otherwise be forensically identical to the user's own traffic. Peer private keys still persist per node — remediation for suspected key compromise is credential revocation plus deleting `principalKeyDir` so a fresh keypair republishes.

**Lease payload boundary.** `acceptedLease` in [node-access-service.ts](../../../../gateway/src/postgres/node-access-service.ts) parses the `node_heartbeat`/`node_channel_lease` JSON through a `leasePayloadSchema` discriminated union instead of `as` casts, so a malformed `ok` payload throws a plain `Error` rather than fabricating `node-access/<garbage>` codes or `RangeError` from `new Date(undefined)`. Migration `126_channel_lease_topology.sql` adds the `computer uuid` parameter and a `deployment_topology` gate (a mode-disabled organization no longer authorizes channels until lease expiry), and narrows `projects_steward_per_node` to `status='active'` rows so an archived bound steward cannot poison reseeding. The gate cannot copy `node_heartbeat`'s primary-only shape verbatim: `node_channel_lease` also serves the node-local `/internal/nodes/service` identity check on every secondary Gateway's service bridge, so `127_channel_lease_local_gateway.sql` admits the caller when it is the topology primary **or** the agent's own computer — a foreign computer is still `mode-disabled`. `issue()` maps a losing `node_agents` 23505 race to `node-access/name-conflict` instead of a raw violation.

**Windows task host.** [node-agent-task.ps1](../../../../gateway/deploy/windows/node-agent-task.ps1): `-Restart` sweeps surviving agent processes after `/end` because Task Scheduler terminates only the tracked `powershell.exe` — but only when the target task's actions host the agent (`Test-HostsAgent` requires the `-Run` invocation, so restarting the watchdog or a sibling task cannot kill a live agent), and the sweep (`Sweep-AgentOrphans`) matches `node-agent-main.js` on the command line scoped to the task's `-GatewayDir` rather than a `node.exe` name filter, so a pinned `-NodeExe` or a surviving `cmd.exe` shim is still caught while a co-hosted second install is left alone; a second sweep runs after the confirmed stop (a mid-launch shim can spawn the agent between the first sweep and the stop landing), and `-Uninstall` now performs the same `/end`+sweep teardown before `Unregister-ScheduledTask`, which never terminates a running instance (an uninstalled agent would otherwise keep heartbeating on its lease as an unsupervised orphan until reboot). The watchdog-vs-`-Restart` race treats a stop followed by a Running state as success; `-Install` asserts `$PSCommandPath`, absolutizes and creates `StateRoot`/`LogFile`/`ConnectionFile` parents, splits `AlsoWatch` on `[,;]`, and rejects `"`/`%` in names and paths that land inside `cmd /c` quoting; the env file reads UTF-8 with a BOM-detection fallback for UTF-16 files, strips one surrounding quote pair, and is applied before the unit's own assignments to match systemd precedence; the agent log rolls at 10 MB per launch and the watchdog log at 1 MB per pass; `schtasks /run` exit codes are checked; `node-connection.ts start()` passes `-NonInteractive`; `validate_release` requires the script.

**Runner liveness.** `WindowsJobOwner.signal` in [windows-job.ts](../../../../packages/subprocess/subprocess-local/src/windows-job.ts) bounds the terminate IPC with a 5-second `RUNNER_TERMINATE_TIMEOUT_MS`; a connected-but-wedged runner is killed so Job close sweeps its tree (the disconnect path already relies on `releaseOwnedJob`). A single `failAndKill` guard prevents double failure reports across the send callback, sync throw, and timeout paths. A runner that emitted its result and then froze used to hang `waitForExit` forever because the delivered-result early return skipped the kill path entirely; signal now arms the bounded terminate timeout whose expiry — or a dead IPC channel — force-kills even with a latched result, while an ordinary late delivery failure still lets the runner finish its own exit path so the Job Object sweep is not wasted.

**Peer-backup retreat.** `registerStop` commits phase `retiring` before the irreversible source fence lands; a crash or permanent gate between those commits left an uncancellable operation whose trigger kept the runtime stopped and whose row held the project's single takeover slot. Migration `128_recovery_retreat.sql` adds `retreat` as a pending-decision phase: `cancel()` moves `retiring` operations there under the same administrator locks the fence window holds, and the source node's worker resolves it by reading `node_content.recovery_source_fences` — no fence means retirement never became irreversible and resolves to `cancelled`; a landed fence with matching evidence completes `old-fenced` from the fence's own record. The freeze trigger covers `retreat` while the truth is unknown. A leftover `active` recovery candidate blocked every later takeover with a raw 23505 retry loop: `stagePeerProject` maps candidate-uniqueness collisions to a terminal `peer-backup/already-recovered`, `request()` maps the `one_project_takeover` violation to a typed 409, and the worker parks `PeerBackupError`s marked `terminal` at `retry_at='infinity'` until an explicit reapproval re-arms the operation; unexpected causes are logged instead of collapsing into `recovery-unavailable`. `withdraw()` marks a stage-root row withdrawn when the recorded parent's inode/device no longer matches rather than moving a foreign path.

**Lock ordering.** Project `insert()` held user/membership row locks while waiting on the `gateway-port` advisory lock, so a concurrent revocation deadlocked; the advisory lock now precedes every row lock and a queued create observes the committed demotion instead. `login()` wrote `login_attempts` before re-reading identity rows, inverting `user-service.remove()`'s order — the identity `FOR SHARE` now precedes attempt-row writes. Peer-recovery `activate()` takes the target's `gateway-port` advisory lock before administrator rows through the `admin()` `preLock` hook, matching the documented convention; `NOWAIT` contention maps to typed 409s instead of raw 500s. `verifyApproval` compares TTL against `clock_timestamp()` so an approval granted inside a long transaction does not expire mid-check.

**Node-content discard.** `discardDetachedCreation` deleted only `node_content.spaces`, but fourteen child tables hold non-cascading foreign keys, so every discard hit 23503 — the cleanup was dead code. The table inventory moved to [node-content-project-tables.ts](../../../../gateway/src/node-content-project-tables.ts) (`peerProjectTables` in dependency order plus `projectScopedTables` for the journal tables keyed by `(organization_id, project_id)` rather than `runtime_id`), shared between `peer-backup-project-export.ts` and `node-content-store.ts`; the discard now deletes children in reverse dependency order under `SET CONSTRAINTS ALL DEFERRED`, mirroring `discardPeerCandidate`.

**Client session pool.** `runtimeForTarget` could start a handshake with no `runtimeOperations` hold, so a concurrent releaser stopped the entry mid-connect; the entry now holds a claim for the acquisition attempt — prepared flows keep it until readiness settles, ordinary waits drop it in `finally` so a cancelled wait is reaped immediately instead of lingering on the readiness timeout. `setBaseRuntimeTarget` skipped the verified retarget when the key was unchanged, silently swallowing a real node migration; it always re-verifies the descriptor and refreshes node/name/project metadata, and the verified `setBaseTarget()` runs before presentation-key and map mutation so a throw cannot leave a half-applied retarget.

**Admin copy discipline.** `PeerBackupSection` moves all 118 strings into [peer-backup.copy.ts](../../../../gateway/admin-ui/src/pages/peer-backup.copy.ts) (`zh` source-of-truth + `en` `Record<PeerBackupCopyKey, string>` + `{name}`/`{count}` placeholders through `translateCopy`), merges the `PeerRecoveryActions` `problem()` map into the shared `message()` so both error channels take identical localized codes, and replaces the raw-code fallback with a localized `unrecognizedOutcome`. `RemoteDesktopPage` maps the full `remote-desktop-*` code family plus auth/maintenance codes through `ERROR_KEYS`, localizes `timeLabel`, gates `changeLevel` on `busy`, and surfaces `endpointInvalid` instead of silently ignoring invalid saves. `NodeAccessSection` gains `modeDisabled`/`notFound`/`nodeDetached` mappings, moves the "more candidates" button out of the `Field` label, and both sections take `randomUUID` from `dsh-util-crypto` because `crypto.randomUUID` is absent on insecure origins. A later round swept cross-target residue: `RemoteDesktopBody` resets mouse picks, mid-connect phase, and credential/fullscreen state when the desktop target changes; `DesktopsPage` restarts its polling loop instead of accumulating polls across switches; `ResourcePermissions` clears the previous selection's grants while the new target loads; `StewardPage` renders an explicit copy re-read error in both locales instead of reporting success for a copy that never ran.

**Steward service surface.** `recoverSteward` acquires `pg_advisory_xact_lock(hashtext('gateway-port:<node>'))` before `allocateInstancePorts`, matching every other allocation call site's documented critical section; without it a recovery racing an ordinary allocation could lose on `instances_assigned_node_id_port_key` and abort the whole mount-revival transaction. `stewardTarget` additionally binds `steward_node_id` to this gateway's node so a foreign node's steward token is not accepted. `ensureSteward` reconciles the live mount to the configured workspace path on both the healthy and the collision (`recoverSteward`) paths, so a workspace path changed since seeding cannot leave the Runtime bound to the retired directory. `explain()` emits `EXPLAIN (ANALYZE OFF)`: with an explicit option list the grammar requires an ExplainableStmt, so a payload-led `ANALYZE` (which used to complete the text into `EXPLAIN ANALYZE` and execute the inner statement with no approval and no deny-list) is now a planning-time syntax error; `READ_LANE_DENY` screens dry-run previews the same as executions and journals the dry-run flag on denial.

**Miscellaneous.** `instances.ts` seeds `.env` files `0600`; `login()` verifies a fixed valid `DUMMY_PASSWORD_HASH` for ineligible attempts so response time does not enumerate usernames; `config.ts` rejects an `HGW_STEWARD_PROJECT_NAME`/`HGW_COMPUTE_NODE_NAME` combination that can never normalize at load instead of at first seed; `restore-check.sh` requires an absolute dump path (its `-f` ran pre-`cd` while the restore read post-`cd`) and `backup-postgres.sh` suffixes `-$$` so same-second runs cannot overwrite one dump; `node-agent.ts` documents that `executionReady` reports configured bridge endpoints, not probed health; `windows-inspector` documents the identity-check/taskkill TOCTOU bound.

## Alternatives considered

**Koffi async + manual error capture.** Koffi offers no per-call last-error channel on the async path, so synchronous calls are the honest fix; all three syscalls are local and fast.

**Reject instead of generic-fallback unmapped codes.** Keeping a localized generic fallback preserves operator trust for the long tail of worker `error_code` values while specific, actionable codes stay individually mapped.

## Consequences

Win32 directory-move failures now reach the `EEXIST`/`ENOENT`/`EACCES` branches their callers implement; forwarded assertions carry bounded lifetimes and single-use nonces; `schtasks /end` no longer strands a heartbeating orphan; admin banners never render machine codes; the lease functions' output is contract-checked at the database boundary. `verify-client-ui-i18n` does not scan `gateway/admin-ui`; the `Record<keyof typeof zh, string>` typing is the parity gate there.
