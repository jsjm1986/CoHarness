# Agent Note: Runtime 活动原子准入

Status: implemented

[English](2026-11-01-atomic-runtime-activity-admission.md) | 中文

## Problem

并发元数据请求进入同一个 Runtime 生命周期队列。分开的资格、状态、代次和活动查询增加了占用队列期间的数据库往返，使远端数据库拖慢原本相互独立的元数据操作。

## Decision

实例仓库通过一条带条件的活动更新准入 HTTP 和 WebSocket 活动。它检查组织、分配电脑、所有者、准备状态、运行就绪状态、节点执行凭据，以及提供时捕获的代次。个人分配还要求账号和组织成员身份有效，并具有电脑使用权限；项目分配要求项目有效。调用者授权仍由 Gateway 路由及其响应发布检查负责。

明确的 Runtime 身份直接进入其生命周期队列，由带条件的更新验证所有者与电脑归属。仅提供所有者的选择器先解析无歧义的分配。请求之间不缓存身份或资格结果。

只有活动更新成功后，管理器才保留内存引用。启动、停止、空闲回收与准入继续使用同一 Runtime 队列。释放先移除引用，再写入活动；写入失败不能恢复已释放的引用。不提供捕获代次时，接受当前就绪的代次。

热路由通过同一数据库快照读取明确分配、状态、端口和代次，再检查捕获代次的真实监督进程与资源登记。重新挂接的监督句柄只有在另一份快照确认代次、端口与就绪状态一致后才会发布。保留的旧监督句柄不能服务替换代次，即使未配置资源记账也是如此。返回的端点属于状态观测，并不授予操作权限；转发仍需通过捕获代次的活动准入与当前路由权限检查。

过期的受管节点连接不能授权已有 Runtime。重新进入时，启动资格检查失败后，只有带条件的更新证明明确代次仍绑定无效的受管连接，才会提交停止意图。生命周期队列随后确认进程真实终止，再重新检查资格，并通过正常启动签发新代次与新凭据。管理员发起的恢复保留当前管理员授权检查。终止不确定时，分配保持停止中并保留占用；节点离线时不能启动替代进程。目录读取不会进入这条恢复路径。

## Alternatives considered

**缓存资格或代次。** 撤权和代次替换必须影响下一次准入。缓存需要额外的授权失效机制，并重复维护仓库中的当前事实。

**并行读取后单独写入。** 这仍保留多条数据库语句，并允许检查与活动修改观察到不同状态。

**将准入移到生命周期队列之外。** 空闲回收或停止可能在持久准入与保留引用之间执行。单条语句减少队列占用，同时保留原有顺序。

**分别读取端点字段。** 分开的分配、状态、端口与代次读取增加数据库往返，也可能混合不同观测的结果。同一快照使这些字段保持一致，无需缓存权限或跳过监督检查。

**将已有 Runtime 重新绑定到续接的节点租约。** 这会恢复原连接失去权限后已失效的凭据。确认终止后再启动新代次，既保留连接检查，也保留同一 Runtime 身份、本地文件和 Session 数据。

## Consequences

明确分配的准入只需一条语句，检查条件保持完整。拒绝准入不会修改活动或引用计数。原有授权检查继续约束准入后的操作和响应发布。不需要修改数据库结构、Runtime 身份或 Session 代次。
