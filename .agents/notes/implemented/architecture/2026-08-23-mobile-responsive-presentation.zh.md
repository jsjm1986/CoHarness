# Agent Note: Web 工作台的移动响应式呈现

Status: implemented

[English](2026-08-23-mobile-responsive-presentation.md) | 中文

## 问题

Web 工作台只有一套业务模型，却包含多个手机可见领域：工作区与会话导航、空白会话创建、对话、输入区接管、工具输出、Trajectory 检查、设置和文档管理。当前 compact 布局保留了桌面信息顺序，再由各组件追加局部 CSS 例外。短屏手机因此会出现重复外壳、输入区遮挡对话内容，以及诊断控件与阅读任务争夺空间的问题。如果继续分别修补这些例外，每个新插件都必须重新发明一套移动策略。

## 决策

保留一套业务和插件系统，同时建立共享设计基础，并在信息架构确实不同的边界使用模式专属呈现。客户端对象层、Session 事件语义、Workspace 操作、slot 所有权、composer chain，以及 Tool/Trajectory 数据保持共享。`ui-layout` 拥有视口档位、compact 外壳几何和统一的浮层/滚动策略。共享原语拥有移动顶部栏、抽屉、底部 Sheet、操作溢出菜单和页面脚手架。当功能层级与桌面有实质差异时，功能包可以提供移动呈现器；只有密度差异时，继续使用共享呈现器和 CSS token。

手机工作台使用一个上下文顶部栏、全高导航抽屉、一个明确的对话滚动拥有者，以及按实际高度预留空间而不是覆盖内容的输入 dock。常用次级操作通过触控尺寸控件或一个底部 Sheet 保持可达。统计、原始 Tool Payload、Trajectory 时序、设置分区和文档操作采用渐进披露，但保留桌面端能力。Workspace 与 Session 行继续遵守现有的复用、归档、重命名、fork、搜索、待处理交互和 subagent 规则；只改变移动端分组和操作位置。`ui-primitives` 统一持有手机 Sheet 遮罩和 `Modal` 焦点循环；只有信息层级真正变化的功能 presenter 才增加手机专属返回行。

响应式约定由外壳在边界处根据视口宽度、短屏状态、安全区和指针能力计算。功能组件不创建平行的业务 store，也不直接读取 Host 服务。新的移动呈现器使用现有的四种 props share 和 slot 声明；共享状态仍按客户端架构规则归对象层或声明它的 entry store 所有。

相关的已交付局部决策包括[响应式外壳视口模式](2026-08-14-responsive-shell-viewport-modes.zh.md)、[compact 外壳密度](2026-08-19-compact-chrome-density.zh.md)、[设置浮层 portal](2026-08-19-settings-overlay-portal.zh.md)和[移动端 composer 模型席位](../bug-fix/2026-08-17-composer-mobile-model-seat.zh.md)。

## 曾考虑的替代方案

**在同一份桌面 DOM 上继续增加 compact CSS。** 否决：它保留了错误的信息顺序，并把每个新功能都变成新的断点例外；现有 compact 密度、composer seat 和设置修复不能解决统一的浮层与优先级问题。

**维护独立的移动应用和业务实现。** 当前快速迭代阶段否决：重复的 Session、Workspace、插件和交互逻辑会逐渐分叉，并要求维护两套行为测试。只有在信息层级确实改变时，才允许使用独立呈现。

**建立一个拥有所有功能的巨型移动外壳。** 否决：它会绕过插件所有权，让可选能力依赖中心组件。外壳拥有模式和浮层；各包仍通过现有 slot 系统拥有自己的内容与操作。

## Consequences

- 手机外壳只有一个上下文顶部栏、一个导航抽屉和一个活动滚动拥有者；主要内容和回答操作不会被固定输入区遮挡。
- 工作区选择、空白会话创建/复用、会话导航/搜索、发送/排队/插话、模型选择、权限切换、审批、提问、Tool 详情、Trajectory 检查、设置和文档附件在手机视口仍可到达。
- 手机和桌面共享同一套 Session/Workspace 状态和操作结果；呈现改动不新增模型可见内容或持久事件。
- 新功能贡献必须有明确的移动放置方式，并复用共享原语，不得添加临时 viewport listener 或互相矛盾的断点。
- 浏览器检查覆盖 320–430px 竖屏、短屏手机、键盘可见、安全区、暗色主题、长标签、待处理接管和桌面回归。

## 风险

少量信息层级复杂的区域会增加一条移动标记路径，因此需要成对的行为和视觉检查。共享一套业务真源可以限制风险；移动路径不得复制 Session 状态、命令分发或 Host 权威。现有 compact 相关 Agent Note 继续负责各自的局部保证；只有在本决策定义更宽的呈现策略处才被部分取代。

## 实现证据

客户端包测试车道通过 279 个测试文件、3,749 个测试。响应式外壳浏览器车道在 compact、short-compact、medium、expanded 和往返尺寸下通过。需要实时 WebSocket 会话流的 seeded 浏览器车道在当前本地 Chromium 无法完成 `/api/events.mux` 与 `/api/events.host` 升级时仍受环境阻塞；UI 改动没有改变这些协议路由。
