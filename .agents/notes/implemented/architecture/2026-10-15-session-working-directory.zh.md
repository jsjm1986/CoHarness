# Agent Note: Session 工作目录

Status: implemented

[English](2026-10-15-session-working-directory.md) | 中文

## 问题

固定的 Session 创建目录无法表达在对话过程中切换检出目录的任务。不同工具各自解析路径时可能读写不同的项目，而改变进程目录又会波及无关的 Session。把可变的目录信息放进系统提示词会改变可复用的提示词前缀。

CoHarness 比上游多两条约束：每个 Session 可以在自己的 SSH realm 中执行（而非共享一个进程级远端），且目录选择不得越出原始项目——工作区归属、沙箱可写根目录和文件侧栏视图都以原始项目为锚。

## 决策

`dsh-working-directory` 拥有每个 Session 唯一的日志化有效目录。其投影从不可变的原始项目初始化，并折叠 `working-directory/change`；消费方读取该 owner，而不是从 header 或沙箱根推导执行路径。目录变更经由 Session 执行世界的文件系统提供方校验——绑定 SSH 的 Session 通过 `environmentForAgent` 在其 realm 内解析与检查，该文件系统缺失时直接失败而不回落主机——在 Session 内串行化，且只在新目录可用后才发布。

选择在符号链接解析后必须留在原始项目内。`resolve` 与 `set` 拒绝越界路径；`ensure` 在记录目录消失或不再满足边界约束时恢复原始项目。校验遇到文件系统传输故障时保留记录目录并按 Session 告警一次，不提交替代目录，因此不可达的 SSH 主机不会移动执行位置。

`dsh-base` 组合全局挂载 `working_directory({ cd? })`。该工具读取或修改 Session 目录，因此每个 Agent preset 都能选择或恢复目录，包括没有文件编辑工具的 preset。Web 组合将动作类工具保留在 preset 作用域中。

必需的用户上下文快照携带当前值；每次已提交的变更都会尝试通过普通 Agent 收件箱排入通知。取消或销毁可能丢弃尚未进入请求的通知，而目录事件对后续请求仍然有效。`refreshContext` 在请求准入时重新评估已注册的上下文提供方，因此某次工具调用提交的变更能到达同一轮中的下一个模型请求。写权限保持独立。

子智能体捕获父级当前目录，或经 `resolve` 解析显式覆盖值（同样执行边界约束）；子级在创建时提交所选目录，此后独立拥有自己的目录。既有进程、终端和持久 shell 保留各自进程本地目录。项目指令、技能和文件补全跟随有效目录，但不改变 Session 身份、分组或运行时组合。

活跃 Session 的技能目录与文件补全经由同一目录 owner 校验。这些读取可以在发现之前提交恢复并排入其通知，使发现的文件与后续操作始终绑定在已提交的 Session 目录上。冷态技能目录读取已记录的投影而不激活 Agent。

终端控制器侧栏查询读取有效目录但不做文件系统校验或恢复，因此目录缺失不会妨碍重连保留的终端。新建终端在 spawn 前经目录 owner 校验并恢复；进程此后独立于 Session 的后续变更保留该目录。

browser-use 运行时在获取 Session 的 MCP 连接时校验有效目录，并用它启动服务。后续目录变更不会重启保留的服务或改变其进程目录。

文件链接与命令目录标签使用各操作执行时捕获的结果元数据，因此历史行在后续目录变更后仍然正确。

[提示词变量笔记](2026-07-05-prompt-variables-and-tool-guidance-ownership.zh.md) 保留严格插值、路由变量归属和工具指导归属；loop 继续将 `cwd` 变量绑定到原始项目，使既有 persona 仍能解析。本决策拥有有效目录状态及其在用户上下文中的放置。

## 曾考虑的替代方案

**改写 Session header。** header 是用于存储、分组和权限根的不可变身份元数据。改写它会把当前执行状态与原始项目混为一谈。

**让 worktree 工具拥有目录状态。** 普通目录变更、文件系统工具和子智能体需要同一个值。Git 专用 owner 会重复选择与恢复逻辑。

**改变进程目录或同步所有 shell。** 并发 Session 与既有子进程拥有独立生命周期。Session 变更影响新的目录相关操作，而 shell 中的 `cd` 保持局部。

**把目录文本留在系统提示词中。** 可变的操作上下文属于保留历史之后，使用与权限状态相同的用户上下文机制。

**SSH Session 用主机文件系统校验。** 上游假设单一进程级执行世界，其检查读取环境文件系统。对绑定 SSH 的 Session 读主机文件系统，会批准远端看不到的目录、拒绝远端实际存在的目录；校验必须在 Session 的 realm 内执行，否则就不执行。

## 后果

运行时暴露唯一的目录 owner，同时保留原始项目。消费方一起迁移，包括文件系统、shell、指令、技能、子智能体和两个 SDK。目录存在性可能在 harness 之外变化，因此校验与日志化恢复发生在使用时。即使可选上下文被抑制，必需的运行时上下文仍然可见。

`{{cwd}}` 解析为原始项目而非有效目录；需要展示有效目录的 persona 应读取用户上下文快照而非变量。不认识 `working-directory/change` 的发行版会拒绝读取包含它的 Session 日志，因此回滚越过本特性会使记录过变更的 Session 无法打开；[持久化变更记录](../../../../docs/persistence-changes/2026-10-13-working-directory.zh.md) 拥有兼容性约定。当当前目录与其恢复目标都不可用时，提示词组装会拒绝模型轮次；[目录服务恢复指引](../../../../packages/session/working-directory/README.zh.md) 要求恢复目录，或通过 SDK 或宿主服务选择一个存在的绝对目录。

验证覆盖独立 Session、相对变更、回放、取消、边界内外的恢复、传输降级 Session、工具销毁、用户上下文渲染、提供方继承以及真实的目录相关操作。
