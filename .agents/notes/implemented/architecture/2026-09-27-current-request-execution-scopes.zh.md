# Agent Note: 当前请求的执行范围

Status: implemented

[English](2026-09-27-current-request-execution-scopes.md) | 中文

## Problem

共享会话可包含许多相互独立的人类请求。将所有历史贡献者用于每次授权，会让有资格用户因无关普通参与人曾经发言而无法使用 Auto。只核验最近显示的作者也不正确：编辑、回答、子任务和延迟回调可能有多位真实贡献者，旧任务不能借用新用户的权限。

## Decision

[执行身份服务](../../../../packages/context/execution-authority/README.zh.md) 区分不可变输入凭据、不可变执行范围和当前权限检查。[Gateway](../../../../gateway/deploy/postgres/migrations/047_execution_scopes.sql) 拥有每个范围的运行时、会话、输入集合、主要参与人及不确定状态。范围引用不携带权限。历史输入凭据仍用于审计和延迟用量归因。

新的根回合从本次接纳的输入开始。同一执行回合接纳的输入合并参与人，包括此前的编辑者。受管子 Agent 的直接人类输入保留继承执行链，显式新委派携带自己捕获的来源。选择 Auto 核验当前选择者，真实执行独立核验所有实际参与人。当前输入来源未知时拒绝特权，但无关的未知历史不阻止新的已验证根请求。

工具调用保留注册表的不可伪造父调用令牌。Auto 派发前检查即使早于其他执行包装器也使用该令牌。Workflow 回调在跨 worker 边界前捕获来源。任务为活跃执行和自动完成通知保留来源。新请求将已终止任务输出作为历史数据读取，不继承其原参与人。Team 消息随持久投递保存捕获的范围。迟到的执行结果不能替换其他当前请求。

Remote 调用仅在授权与全部 Agent 查找结束后绑定人类执行。共享 Remote 策略要求每个修改入口声明执行归因由派发、具体操作负责，或不改变执行来源。Goal 激活记录已验证发起人，供之后自动回合使用；状态、暂停、清除和中断不创建新执行。嵌套命令保留捕获的根或子执行链。问题捕获提问操作；回答将已验证响应者加入该操作，并合并并发回答，而不重写新请求身份。

必读的 `gateway/scoped-execution` 准入标记在保存或传出新式执行范围前写入，包括继承范围、转发和直接命令。旧读取者必须拒绝该标记，不能把缩小后的范围解释成会话级累积。`gateway/continuation` 独立记录自动执行来源，两种事件均不改变结构格式。新读取者拒绝缺标记的执行范围记录。旧累计记录保持可读且保留限制，新的已证明根请求建立显式执行范围。无法验证继承身份的旧子会话仍可读取，但不能把新调用人当作根请求来恢复执行；有效的已捕获父参与人凭据可恢复其委派范围。旧问题不得覆盖新的范围请求。范围记录缺失、授权更新不可用、资格撤销或生命周期归属丢失时均拒绝执行。

本决定部分替代[受管执行的已验证参与人](2026-09-22-verified-execution-participants.zh.md) 中的会话级授权生命周期。该文关于输入证明、保留编辑者、传输独立性和部署隔离的理由继续有效。

## Alternatives considered

**每次授权都保留全部历史参与人。** 这混淆了会话历史与当前执行链，会阻止有效的独立请求。

**只授权主要参与人。** 主要参与人用于计费归因，不能消除编辑者、响应者或继承参与人的限制。

**回调到达时使用会话当前身份。** 后台结果可能在另一位用户请求之后才到达。捕获的不可变引用保留其真实来源。

**复用 HTTP 异步上下文。** 请求与委派任务的生命周期不同。显式操作范围在传输结束后保留来源，而不保留浏览器权限授权。

## Consequences

每次能力核验仍读取当前账号与会话权限。执行范围保存来源，而非缓存的允许决定。旧任务运行期间即使同一会话已有合资格的新请求，也仍可撤销旧任务。取消继续遵守现有资源归属与停止等待要求。

执行范围行与输入凭据在后续请求后继续用于审计。相同范围构造具有幂等性。源码与产物导入采用同一类型定义，生成的消费者目录必须包含执行方法与范围字段。

相对上游 `dsh-v0.1.6-alpha.2`，`jobs/jobs/src/types.ts` 仅增加类型导入与可选的 `JobSnapshot.executionScope` 字段，把任务捕获的范围传递给受管任务完成消费者。本地注册表捕获该字段，活跃执行消费者验证它；独立本机配置不填此字段。任务归属、状态转换、等待和取消继续以上游 Jobs 机制为准。上游修改这些生产者或消费者时，须重放延迟完成与按参与人定向撤权的回归。

## Testing

真实 Gateway HTTP 与 PostgreSQL 测试区分新的合资格请求与无资格历史参与人，保留当前编辑者，拒绝删减或跨范围继承，并将迟到子任务和问题回答绑定到原执行。经 Loader 组装的 Agent 转录覆盖工具效果的拒绝与允许，并核验落盘文件。源码回归覆盖嵌套 PTC 身份、worker 回调、任务来源、撤权和冷范围读取。这些测试不能替代最终部署验收。
