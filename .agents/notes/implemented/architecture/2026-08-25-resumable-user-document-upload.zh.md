# Agent Note: Resumable user-document uploads

Status: implemented

English | [中文](2026-08-25-resumable-user-document-upload.md)

## Problem

公网 Web UI 过去把每个文档作为一个 HTTP 请求发送。生产 Cloudflare 入口对单个请求体的限制约为 100 MB，因此 100.23 MB 的文档在运行时发布前就被边缘节点终止。桌面端和移动端共用同一条链路，所以两端同时失败；浏览器又把中断请求压缩成了笼统的上传失败。

## Decision

用户文档 seam 现在所有浏览器上传都使用版本化 `resumable-v1` 上传会话。客户端创建或恢复会话，发送顺序且有大小上限的原始分片，为每个分片提供 SHA-256，并提交最终摘要。本地 Provider 将私有 manifest 和部分文件保存到 `.upload-sessions/v1/`，验证完整文件后才原子发布普通文档引用。浏览器只保存不透明会话元数据，用户重新选择同一文件即可继续；未完成会话按配置的默认 24 小时过期。

协议继续把文件字节放在运行时目录，不新增数据库 migration。Provider 通过 `UserDocLimits.upload` 发布分片大小和会话保留期；默认分片为 8 MiB。Provider 不设置业务层单文件配额，但会预留可配置磁盘空间并限制活动会话数。旧的单请求 `POST /api/documents` 不再写入，而是返回 `UPLOAD_PROTOCOL_REQUIRED`，因此前端和 Gateway 必须一起切换版本。

对话 composer 和文档管理器共用同一个浏览器上传器包。Gateway 文档复制 broker 也改用同一套会话协议，不再把整个源响应转发到一个请求中。分片和进度查询不再各自写一条 API 审计记录；上传生命周期结果仍可观察，避免审计表被分片请求淹没。

单文件准入默认可为空以及连接中断文案仍由[默认不限制文档上传大小的决策](../bug-fix/2026-08-22-unlimited-document-upload.zh.md)负责。

## Alternatives considered

**提高或取消 Cloudflare 限制。** 这只能保留单请求上传，无法提供断点续传和弱网恢复，并且仍会让移动端受连接中断影响。应用必须能在入口限制不由运行时控制的部署中工作。

**把文档字节存入 R2/S3。** 对象存储能提供独立的可扩展传输，但会增加凭据、签名 URL、生命周期策略和第二套持久存储模型。运行时目录是现有产品约定，因此继续作为 Provider 边界。

**让 composer 和管理器各自维护上传实现。** 两套状态机最终会在重试、校验和恢复行为上漂移。浏览器共享包统一协议和恢复行为，各 UI 只提供自己的 HTTP 错误适配器。

**永久保留旧单请求接口。** 永久第二写入路径仍会保留入口失败，并增加安全与测试表面。发布采用明确的协议切换；不匹配的缓存页面收到可刷新解决的协议错误。

## Consequences

每个分片只占用一个公网请求和一个有界浏览器缓冲区，因此超过入口限制的文件也能完成，暂时性网络错误不会重传整个文件。最终校验使用短暂的异步状态，避免公网请求等待大文件哈希。临时 manifest 会增加文件系统条目和清理工作，部署必须配置磁盘余量和并发安全。会话记录按配置的保留期过期，已发布文档仍沿用手动删除策略。
