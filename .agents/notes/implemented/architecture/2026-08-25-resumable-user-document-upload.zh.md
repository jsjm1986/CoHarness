# Agent Note: Resumable user-document uploads

Status: implemented

English | [中文](2026-08-25-resumable-user-document-upload.md)

## Problem

公网 Web UI 过去把每个文档作为一个 HTTP 请求发送。生产 Cloudflare 入口对单个请求体的限制约为 100 MB，因此 100.23 MB 的文档在运行时发布前就被边缘节点终止。桌面端和移动端共用同一条链路，所以两端同时失败；浏览器又把中断请求压缩成了笼统的上传失败。

## Decision

用户文档 seam 现在所有浏览器上传都使用版本化 `resumable-v1` 上传会话。客户端创建或恢复会话，发送顺序且有大小上限的原始分片，为每个分片提供 SHA-256，并提交最终摘要。本地 Provider 将私有 manifest 和部分文件保存到 `.upload-sessions/v1/`，验证完整文件后才原子发布普通文档引用。浏览器只保存不透明会话元数据，用户重新选择同一文件即可继续；接收中会话按配置的默认 24 小时过期。

协议继续把文件字节放在运行时目录，不新增数据库 migration。Provider 通过 `UserDocLimits.upload` 发布分片大小和会话保留期；默认分片为 8 MiB。Provider 不设置业务层单文件配额，但会预留可配置磁盘空间并限制活动会话数。旧的单请求 `POST /api/documents` 不再写入，而是返回 `UPLOAD_PROTOCOL_REQUIRED`，因此前端和 Gateway 必须一起切换版本。

对话 composer 和文档管理器共用同一个浏览器上传器包。Gateway 文档复制 broker 也改用同一套会话协议，不再把整个源响应转发到一个请求中。分片和进度查询不再各自写一条 API 审计记录；上传生命周期结果仍可观察，避免审计表被分片请求淹没。

已认证上传的操作权属于发起参与者，与共享项目写权限相互独立。服务端通过浏览器元数据之外的带品牌所有者参数传递身份；每次会话操作都在修改、过期清理或取消最终化之前校验身份。绑定身份的 manifest 必须使用第 2 版，旧读取器会拒绝它。第 1 版会话仍然没有身份，已认证参与者不能认领，因为清单没有原始上传者的证据。指纹复用包含参与者身份；准入锁为活动目标预留名称，并执行整个根目录共用的资源预算。

个人 Gateway 运行时未挂载 collaboration 提供方时，会从已验证的请求 principal 取得 HTTP 上传者。受管项目在读取上传元数据期间失去 collaboration 授权时会拒绝创建，不会写入无所有者会话。个人请求身份缺失时也会拒绝全部上传会话操作。只有两个身份服务都不存在时，HTTP 请求才可使用无所有者会话；现有无所有者记录不会被认领。

单文件准入默认可为空以及连接中断文案仍由[默认不限制文档上传大小的决策](../bug-fix/2026-08-22-unlimited-document-upload.zh.md)负责。

Gateway 为每项已接收的后台操作独立持有维护写入计数，包括初始化、上传校验与发布、过期会话清理和回收站保留期清理。HTTP 响应结束不会释放最终确认任务的写入计数。拒绝准入发生在其文件系统写入前，并保留持久化的待校验状态，供后续状态请求或重启恢复。即使所有模型运行时已停止，备份的停止写入判断也必须包含这些任务。

携带文档实例身份的已完成发布使用第 3 版上传清单，防止读取器在恢复时静默抹去该版本。Gateway 和 Host 投影会保留校验后的身份字段并移除私有路径；浏览器只有在引用有效且字节数匹配时才接受完成。身份元数据记录原始发布参与者和来源，当前授权仍须独立检查。浏览器引入纯 `/identity` 入口；客户端打包仍拒绝文档服务及其他子路径。

已接受的校验是持久工作，而不是空闲的接收中会话。其 manifest 保留字节、目标名称及并发占用，直到发布、失败或经认证的取消。不同实例的清理都会保留该状态；即使接收期限已过，进程停止后的启动仍会恢复该工作。浏览器校验使用自己的五分钟等待预算，接收时间戳不会缩短它。

无法读取的清单不能证明过期时间。清理保留其字节，不把解析拒绝当作删除许可。缺少清单时保留孤立部分文件以供恢复；无效、未知或超出大小上限的清单会明确失败。全部清理任务结束后才释放准入锁和维护写入计数，独立错误会一并保留。

## Alternatives considered

**提高或取消 Cloudflare 限制。** 这只能保留单请求上传，无法提供断点续传和弱网恢复，并且仍会让移动端受连接中断影响。应用必须能在入口限制不由运行时控制的部署中工作。

**把文档字节存入 R2/S3。** 对象存储能提供独立的可扩展传输，但会增加凭据、签名 URL、生命周期策略和第二套持久存储模型。运行时目录是现有产品约定，因此继续作为 Provider 边界。

**让 composer 和管理器各自维护上传实现。** 两套状态机最终会在重试、校验和恢复行为上漂移。浏览器共享包统一协议和恢复行为，各 UI 只提供自己的 HTTP 错误适配器。

**永久保留旧单请求接口。** 永久第二写入路径仍会保留入口失败，并增加安全与测试表面。发布采用明确的协议切换；不匹配的缓存页面收到可刷新解决的协议错误。

## Consequences

只有全部字节写入并同步后，才能确认已接收字节数。普通保存和续传写入共用一个写入器，按系统调用实际写入的字节数推进，拒绝零进度，并在两次写入之间检查取消。部分分片写入失败时保持原有持久进度，重试会重写相同范围；普通保存失败时会清除尚未发布的部分文件。

每个分片只占用一个公网请求和一个有界浏览器缓冲区，因此超过入口限制的文件也能完成，暂时性网络错误不会重传整个文件。最终校验使用短暂的异步状态，避免公网请求等待大文件哈希。临时 manifest 会增加文件系统条目和清理工作，部署必须配置磁盘余量和并发安全。接收中及终态记录按配置的保留期过期；已接受的校验在结束前保持可恢复，已发布文档仍沿用手动删除策略。
