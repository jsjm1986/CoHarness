# Agent Note: 个人对话准备使用共享实例锁

Status: implemented

[English](2026-11-21-personal-prepare-instance-lock.md) | 中文

## 问题

工作区目录发布持有共享实例行锁，保证代次和归属在提交前有效。打开或新建对话时，写入 Runtime 的开始活动需要排他锁，可能等待目录事务。远端节点跨网等待 PostgreSQL 响应期间，事务仍持有行锁。

## 决策

对于已受监督的 Runtime 上精确定位的个人对话准备请求，[浏览器准入](../../../../gateway/src/runtime-asset-admission.ts)先校验请求，然后对目标就绪实例取得共享锁，再读取当前权限。浏览器会话、电脑授权、转发签发方、服务写入代次及 Runtime 代次在一次数据库往返内校验。所属 Gateway 在分派前复核撤权监听状态，Host 继续执行既有对话授权。

[实例管理器](../../../../gateway/src/instances.ts)在准入前保留精确代次引用，直到完成活动写入结束。写入单调递增，并绑定该代次。项目对话准备、事件升级和提示受理沿用开始及完成活动写入。

所属 Gateway 也为[符合条件的浏览器读取](../../../../gateway/README.zh.md#performance-and-runtime-admission)复用这项准入。启动、目录和历史读取沿用原 Host 方法。例如，历史续页保留原分页上限和排他游标，并遵循同一套归档会话读取权限。就绪个人 Runtime 在共享锁后核验权限修订号。当前代次不可用时，普通路由继续处理启动和手动停机规则。

## 已考虑的替代方案

**使用普通授权读取。** 共享锁等待并发实例写入，锁后第二次授权读取能看到等待期间已提交的变更。普通读取可能在代次变更期间使用旧实例行进行授权。

**将目录发布移出事务。** 目录写入在发布完成前需要保护归属和代次。移除该锁需要另外设计治理库和节点存储之间的归属协议。

**把续页发到显式准备入口。** 该入口可启动已停止的 Runtime，并拒绝归档会话。在 Gateway 复用它的就绪准入，既有客户端也能沿原读取规则获得更短的请求路径。

## 后果

个人对话准备可以和目录发布的共享实例锁并行执行。实例变更或其他排他写入仍可引起等待。准入读取不推进持久活动时间，完成时在释放 Runtime 引用前推进时间。

[PostgreSQL 准入测试](../../../../gateway/tests/runtime-asset-admission-postgres.spec.ts)覆盖并发共享锁、当前转发签发方、精确代次完成，以及排他锁等待期间提交的撤权。[Gateway 性能参考](../../../../gateway/README.zh.md#performance-and-runtime-admission)说明 Host 与所属 Gateway 的计时字段。
