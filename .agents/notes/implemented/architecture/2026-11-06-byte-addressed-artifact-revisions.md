# Agent Note: Byte-addressed artifact revisions and unpinned immutable delivery

Status: implemented

English | [中文](2026-11-06-byte-addressed-artifact-revisions.zh.md)

## Problem

Two properties kept the same release bytes from sharing caches across computers. First, client plugin revisions were derived from filesystem metadata — the entry's mtime, ctime, and size — so identical artifacts on different computers produced different revisions, a metadata-only rewrite republished a plugin that did not change, and a chunk-only edit only moved the revision indirectly through the build preset's `client.js` stamp. A revision could not name bytes, so a URL carrying it could not be trusted to name the same bytes on every Runtime. Second, the Gateway answered every unpinned browser resource request with a `302` that appended `dshRuntime` to the URL, which re-keyed browser and CDN caches per Runtime: switching Runtimes re-downloaded the multi-megabyte combo even when both Runtimes served identical bytes, and the first request paid a redirect round-trip plus a remote-node hop. Immutable responses additionally shipped identity bytes, since the gzip middleware re-compresses per request and does not produce Brotli — an expensive fit for multi-megabyte immutable bodies.

## Decision

Artifact and combo revisions now identify served bytes. `artifactRevision()` hashes the entry bundle plus every sorted `client*.js`/`client*.js.map` sibling, so identical artifacts on different computers produce identical revisions, a chunk- or map-only change moves the owner revision on its own, and startup and `rebuilt(id)` share one derivation. `rebuilt(id)` keeps metadata as the cheap detector: it compares the entry's mtime, ctime, and size first and reads the full snapshot only on a delta (the tsdown preset's `client.js` completion stamp is what surfaces a chunk-only edit as a stat delta), then preserves the published revision and leaves the graph untouched when the bytes hash identically. Stale revisions and unknown resource lists still return 404.

Immutable bodies precompress once on the libuv pool. `dsh-host-webserver` exports `precompressBody(identity, onError)`, `selectVariant(body, acceptEncoding)`, `acceptableEncodings`, and `PrecompressedBody`: the first read schedules Brotli (quality 9 — quality 10/11 measured ~4 s/~12 s against ~0.3 s on an 11.5 MB script corpus, for marginal savings) and gzip (level 1) variants, a variant enters the table only after its compression resolves, and `selectVariant` picks the best *settled* coding for one `Accept-Encoding` header — Brotli preferred, a still-compressing coding falling through to a ready one or identity. The owner sets `content-encoding` and `vary: accept-encoding`; the existing compression middleware skips responses that already carry `content-encoding`, so the two paths cannot stack, and a failed variant only logs while the remaining codings and identity keep serving. `dsh-client-modules` wraps every lazy combo, chunk, and map body in the helper and negotiates per request inside `bundleResource` — shared by `fetchBundle()` and the `/plugins` route — while `dsh-host-frontend-static` holds one `StaticBodyEntry` per content-hashed asset generation and stamps it by mtime+size. HEAD keeps identical headers with no materialized body.

The Gateway forwards byte-deterministic browser URLs instead of pinning them. Inside the existing Referer block, after `resolveForAccount` authorizes the Referer-selected Runtime, `shareableImmutableRequest` classifies a GET or HEAD to a content-hashed `/assets/*` path, a `combo.js??` URL carrying `rev`, or a `rev`-stamped `client.*.js` chunk or map as byte-deterministic; the request URL is pinned with `dshRuntime` internally and falls through to the normal selected-runtime pipeline, which forwards remote through the existing `nodeServiceProxy.http()` or serves local — no second transport, and the browser URL never shows the pin. Runtime-specific or unrevisioned paths (`/plugins/events`, `/favicon.svg`, unrevisioned plugin or asset URLs) and every non-GET/HEAD method keep the 302 redirect. The asset predicate is mirrored from `IMMUTABLE_ASSET_PATH` in `dsh-host-frontend-static` and the chunk form from `CLIENT_CHUNK` in `dsh-client-modules`; both sides carry alignment comments. The combo path's `combo.js` filename continues to place it under CDN static-extension caching per the [combo-route note](2026-10-20-combo-route-static-extension.md), and the loading model's revision mechanics are updated in place in the [client plugin loading note](2026-07-23-client-plugin-loading-model.md).

## Alternatives considered

**Keep the 302 pin and re-key caches per Runtime.** Rejected: every Runtime switch re-downloads the same combo bytes and every first request pays a redirect plus a remote hop, which is the cost this work removes.

**Hash the entry bundle only.** Rejected: a chunk-only edit would keep the published revision, and the retained URL would serve bytes its revision no longer describes — the sibling set must fold into the hash.

**Compress through the existing per-request gzip middleware.** Rejected: it re-compresses the same immutable megabytes on every request and cannot emit Brotli; background variants amortize once per body and unlock the better coding.

**Brotli quality 10 or 11.** Rejected by measurement on an 11.5 MB corpus: quality 9 compresses in ~0.3 s, quality 10 in ~4 s, and quality 11 in ~12 s, while saving at most ~10% over quality 9 — quality 9 stays inside the background budget where the higher levels do not.

**Share one exported asset predicate across the package boundary.** Rejected: the Gateway is a separate deployable and does not import `dsh-host-*` packages, so each side keeps a mirrored regex with an alignment comment; the same applies to the `CLIENT_CHUNK` form.

## Consequences

A revisioned combo or chunk URL names the same bytes on every computer running the same artifacts, so browsers and CDNs share one cache entry across Runtimes and Runtime switches stop re-downloading identical bundles; the first request still runs the Referer-runtime authorization before any forwarding, and unauthorized requests are rejected without contacting a node. Byte-identical rewrites — including Host restarts over unchanged artifacts — keep their published revisions, so SSE reconnection does not replace browser plugins; content a stat cannot see can no longer hide inside a kept revision. Brotli delivers roughly 30% smaller responses than gzip on script bodies once its variant settles, and a response that already carries `content-encoding` is never compressed twice. The costs are a full-artifact read plus hash on each stat-detected rebuild — bounded by the same stat gate that already filtered HMR polls — two background zlib tasks per newly materialized immutable body, one retained variant set per cached response, and the `vary: accept-encoding` split every shared cache must key on.

## Testing

`packages/client/modules/tests/node-half.client.spec.ts` pins byte-derived revisions (identical artifacts share URLs, a chunk-only edit moves them), Accept-Encoding negotiation on the bundle route, and 404 for stale revisions and bad package lists. `packages/host/frontend-static/tests/frontend-static.spec.ts` proves the immutable cache header, `vary`, Brotli preference once settled, and gzip fallback. `packages/host/webserver/tests/webserver.spec.ts` proves an already-`content-encoding` response is not compressed twice. `gateway/tests/node-service.spec.ts` and `gateway/tests/server.spec.ts` pin direct forwarding for revisioned combo/chunk/map and hashed asset paths, the retained redirect for `/plugins/events` and unrevisioned paths, and rejection before forwarding when authorization fails.
