# Agent Note：保持跨电脑交互准入响应

Status: implemented

[English](2026-11-21-multicomputer-interactive-admission.md) | 中文

## 问题

双 Gateway 测量可以在所属电脑分派请求前数秒，记录主入口已写完请求。冷启动准备夹具中，刚启动的 Gateway 在返回准备中响应后，为第一个 Runtime 同步计算发布闭包的指纹。一次插桩运行记录到所属进程读取 18,149 个文件，事件循环延迟约 2.7 秒。负载较高时，下一次准备请求超出期限。远端页面也会等待渲染资源才提供原生草稿框，重连可能等待两个旧连接关闭。

## 决策

Gateway 在监听前计算启动指纹，包括没有遗留 Runtime 的部署。首个请求仍核验确切的代次和 Runtime 启动变体。项目和个人策略、启动准入及遗留任务的执行归属继续沿用现有检查。

精确定位的个人事件连接在通用 Runtime 解析前复用实时[组合准入](2026-11-06-governance-round-trip-collapse.zh.md)。所属电脑核验原浏览器会话、目标、受管租约和权限修订号。验证后的转发断言可用时，同一条语句也核验当前发布的签名密钥和签发节点租约。分派前消费一次性标识，关闭连接时释放生命周期与权限引用。事件流继续沿用[期限和撤权规则](2026-10-23-event-stream-principal-renewal.zh.md)续租。

Web 入口在加载渲染模块表前挂载与账号绑定的启动草稿。Chromium 夹具将 vendor 响应延迟 750 毫秒，每个构建使用五个新浏览上下文，能打字的中位数从 870 毫秒降到 28 毫秒。草稿由原浏览文档持有，直到确切的输入框接收。取消 WebSocket 读取立即丢弃旧连接的帧，物理关闭独立收尾，下一代连接可接入并续读。

## 备选方案

**准备中响应后淘汰连接。** 清理请求正文、调整响应分帧和重新建连时，冷请求仍要等所属 Gateway 完成闭包哈希。将计算放在监听前，正常请求可继续复用连接。

## 后果

指纹计算计入 Gateway 启动。Runtime 就绪仍有独立期限。数据库取连接耗时和语句耗时独立记录，沿用现有的有界元数据记录。浏览器和双 Gateway 测量对应各自的受控负载。部署分位数在已发布构建按相同操作采集，并同时测量网络。
