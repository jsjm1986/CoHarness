# Agent Note: 在现有授权工作区资源上提供 Office 预览

Status: implemented

[English](2026-09-23-authorized-office-preview.md) | 中文

## 问题

Office 转换可能比发起请求存活更久，也可能返回共享缓存中的 PDF。元数据可见性并不代表内容读取权限。另一套文件服务会重复 CoHarness 的会话授权、运行节点路由及资源生命周期，而远端 FS 提供方未必能在一次操作中读取完整文档。

## 决定

上游 [Office 转换器](../../../../packages/document/office-to-pdf/README.zh.md)保留准入队列、延迟源读取、内容缓存、渲染限制及引擎所有权。[有界转换决定](2026-09-15-bounded-office-conversion.zh.md)负责这些机制。ApiProxy 现有的 Workspace 文件域提供唯一的浏览器转换入口。它核验会话及文件权限，在查询缓存前探测内容授权，并在转换后复核权限及源身份。请求和响应使用工作区相对路径；引擎诊断及 Host 路径留在内部。

延迟读取在已准入容量内使用受版本保护的 FS 字节窗口。这既保留 SSH 提供方的窗口限制，也不截断已接受的文档或弱化版本校验。冷会话头即可满足读取要求；转换不激活 Agent，也不追加会话事件。发起人撤权、请求取消及插件释放会使在途结果失效。

现有 Workbench 文件标签选择 Office 或 PDF 展示。上游 PDF.js 的 Worker 所有权、同版本内嵌资源、可见页面延迟渲染、可选择文本及字体提示适配到该标签。标签隐藏时保留页码偏好；正文释放 Worker 和字节。不增加第二份资源订阅或客户端 PDF 缓存。源元数据变化要求显式重新加载；访问被拒后立即隐藏并释放内容。

## 考虑过的替代方案

- **在 ApiProxy 旁挂载上游 Workspace Files Remote：**会产生相互竞争的授权及资源所有者。
- **队列准入前读取完整远端源文件：**会绕过内存预留，并超出传输限制。
- **使用浏览器原生 PDF 嵌入：**会失去统一取消、可选择文本验证及一致的缺失字体展示。

## 相关决定

平台引擎及独立 kit 决定继续负责引擎所有权。[授权历史审阅注记](2026-09-23-authorized-workspace-review.zh.md)继续区分当前文件预览与不可变轮次比较。本适配仅替代有界转换注记中的 Remote 传输所有权说明。

## 后果

普通 PDF 读取保留 Workspace 字节窗口大小限制。Office 输入与转换输出采用转换器的部署限制。运行时支持要求声明的引擎资源真实可用；源码测试不能证明原生或 WASM 可用性。部署控制及发行平台验收仍是预览实现之外的独立义务。
