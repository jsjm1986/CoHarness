# Agent Note：按身份归属的 Workbench 布局

Status: implemented

[English](2026-09-23-principal-owned-workbench-layouts.md) | 中文

## 问题

viewport 和命名 Workbench 分别保存浏览器记录，可能对活动面板和比例产生分歧。没有账号作用域的记录，还会在其他账号使用同一 origin 时暴露私有布局名称和 Session 引用。

## 决策

会话 viewport 按已验证身份持有一份版本化记录。Workbench 呈现包不暴露独立的持久化写入者。账户目录解析会在可选事件序号和提示词时间戳参与恢复或排序前校验它们。每个命名布局包含面板 id、活动面板和比例；文档包含当前选中的布局和呈现模式。根 store 只保存当前内存状态。身份失效先清空布局和 staged 引用，其他身份才能恢复自己的记录。恢复的面板必须通过当前目录可见性检查，才能建立 staged 持有。面板替换被拒绝时，导航会在活动会话改变前中止；浏览器保留现有视图并报告拒绝。

Host 必须明确声明独立本机执行，才能使用本机身份。缺少 Gateway 身份不能选用本机身份。只有独立本机操作者可以迁移旧的无账号元数据，而且必须等待 Session 目录就绪并移除不可访问引用。Gateway 不认领这些记录，因为无法证明它们之前属于哪个账号。浏览器存储不可用时，当前内存布局仍可使用。

[Workbench 侧栏决策](../feature/2026-09-17-workbench-sidebar-panel.zh.md)继续负责面板导航和窄面板渲染。[辅助侧栏决策](2026-09-23-account-scoped-auxiliary-sidebar.zh.md)负责资源标签持久化和持有，不拥有中间 Workbench 布局。

## 考虑过的替代方案

**保留两份记录。** 部分写入和独立恢复可能选择不同的活动面板，或丢失手动比例。

**将旧元数据归给下一个登录者。** 共享 Session 可见，不代表私有布局名称属于该账号。

## 影响

解析器会在请求 Session 资源前拒绝格式错误的记录。测试覆盖账号切换、身份失效、存储拒绝、损坏元数据、旧记录可见性检查、活动面板恢复和比例保留。浏览器恢复仍依赖可用的 Session 与项目目录；持久化 id 本身永远不能授权历史访问。
