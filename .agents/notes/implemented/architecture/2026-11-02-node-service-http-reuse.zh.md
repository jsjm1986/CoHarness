# Agent Note: 节点服务 HTTP 连接复用

Status: implemented

[English](2026-11-02-node-service-http-reuse.md) | 中文

## 问题

数据库往返延迟较高时，连接准备和串行权限读取会累积耗时。每个 HTTP 请求新建服务流，会在前一次请求成功完成后再次执行目标身份检查和 WebSocket 握手。

## 决策

主入口 Gateway 为每台电脑持有有界的空闲 HTTP 服务连接池。每条连接同一时刻只承载一个 HTTP 请求。浏览器 WebSocket 保留独占的独立流。空闲容量和过期时间由现有节点服务配置管理，并计入其连接上限。

HTTP 突发达到服务上限时，连接获取等待已有借用者或物理清理完成。队列明确限制等待请求数量和累计等待时间；响应完成后将连接交给等待者，使用前重新核验授权。取消仅撤回该等待者。关闭会停止准入并等待队列与活跃传输收敛。仅由无关活跃流占满的预算仍返回繁忙。队列唤醒不会重放 HTTP 操作。

传输复用保留两端 Gateway 的授权。每次借用都在主入口重新检查准确的节点凭据、连接 UUID 和租约代次；目标端继续检查账号、电脑、项目和 Runtime 权限。撤权、通道替换和关闭会终止相应的流。请求取消只关闭其借用的连接，不取消其他请求。归还和销毁只结束一次借用；该借用者迟到的回调不能关闭后继请求的连接。复用连接失败后不重放已转发操作。

节点凭据查找和行锁定使用物化的 PostgreSQL 查询。凭据查找固定原节点，锁读取其当前行，外层查询在获得锁后判断租约时间。退出受管、替换凭据、组织状态和连接代次保留原有拒绝语义。事务仍等待提交确认。

## 备选方案

**随连接缓存节点授权。** 这会让已撤销凭据继续生效直到传输过期。因此每次借用都重新检查凭据和准确租约，再转发请求。

**让 HTTP 请求体共用控制通道。** 这会让文件和流式传输的背压影响控制探测及租约监督。因此 HTTP 沿用独立的服务流协议。

## 影响

传输复用省去重复的目标身份握手，不保存权限结果。每次操作仍检查凭据和租约。空闲连接消耗有界服务容量，阻挡新连接准入时会被回收。[退出清理的准入决策](../bug-fix/2026-11-01-node-service-retirement-admission.zh.md)继续管理清理容量和后继请求准入；连接池不把取消视为已经完成清理。

## 验证

套接字测试覆盖复用、空闲容量约束、过期、取消、凭据撤销、通道替换、独立 WebSocket 流、退出接入和关闭。PostgreSQL 测试覆盖等待锁期间的凭据替换、撤销、代次和组织状态变化，以及没有行更新但自然过期的租约。用户验收分别测量部署后的 Gateway 路径与模型响应时间，并验证电脑、Runtime、工作区和浏览器标签页的身份独立性。
