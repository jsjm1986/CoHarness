# Agent Note: 为对话操作预留浏览器连接

Status: implemented

[English](2026-11-22-browser-advisory-read-scheduling.md) | 中文

## 问题

打开 Runtime 对话会同时读取模型、技能、终端和插件目录。一次公网 HTTP/1 采样中，发送与十二条待完成请求共用连接池。浏览器等了 11.34 秒，才通过复用连接写出请求。185 毫秒后，主入口 Gateway 收到请求。连接复用和 Runtime 处理速度的优化无法消除这段浏览器排队。

限制这些目录读取后，有一次发送仍等待了 4.14 秒。会话列表和草稿自动保存先后占用同一条复用连接。之后一次无模型调用的新建等待权限目录释放连接用了 2.83 秒。同一份浏览器记录中，工作台首批数据、设置读取和历史索引占用了其他连接。

发送还与自动 Host 同步争用连接。另一次 HTTP/1 采样中，会话激活、插件清单同步、草稿自动保存和会话列表同时在途，工作台首批读取占用了分配给发送的连接 5.03 秒。

## 决策

[页面 Connection](../../../../packages/client/connection/README.zh.md) 为 HTTP/1 或协议未知的页面设置共享上限，最多三条后台请求同时等待响应头，其中读取最多两条。会话激活和插件清单同步优先，随后是会话列表、历史索引和工作台首批合并页，再到辅助目录及设置读取。HTTP/2 和 HTTP/3 保留并发请求。显式高优先级请求直接发出。HTTP/1 的组合新建、发送受理和发送状态查询采用较高的 Fetch 优先级。

队列只保留待发请求，不保存响应体或重试。页面销毁和调用方取消会移除待发请求。每条请求仍绑定原账号和 Runtime，由 Gateway 校验授权。草稿读取及版本化写入直接发出，使用原有修订号和回执。

## 备选方案

**依靠连接复用和更快的 Runtime 处理。** 采样中的发送先在浏览器里等待，随后使用复用连接发出。Gateway 和 Runtime 要等请求到达后才会处理。

**只调整目录读取的 Fetch 优先级。** 降低优先级仍会把整批目录请求交给浏览器。HTTP/1 下，发送请求可能需要等待正在读取目录的连接释放。

## 影响

HTTP/1 下辅助目录可能晚一些呈现。并发限制为同一标签页的对话操作让出连接，浏览器仍可能在多个标签页间共享连接池。测量分别记录协议、浏览器排队、建连和从浏览器写出请求到 Gateway 收到的时间。
