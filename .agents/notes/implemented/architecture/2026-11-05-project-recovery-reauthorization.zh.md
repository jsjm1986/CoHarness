# Agent Note：按范围声明备份覆盖与恢复重新授权

Status: implemented

[English](2026-11-05-project-recovery-reauthorization.md) | 中文

## 问题

恢复点不能证明全部存储域均已采集。Runtime 文件、账号文档、插件状态和定时投递可以分别推进。策略变更使恢复审批失效后，已停止的源端也不能安全地重新开放写入。

## 决策

每个导出器声明已覆盖的数据域，并保留明确缺口。个人 PostgreSQL 记录限定到所选组织、电脑、账号和 Runtime；账号文档继续使用账号与电脑共享的身份。一致的原生文件快照只包含获准的根目录。未知插件状态、独立水位和缺少文件快照均阻止完整保护。获准的限定范围提供方可以经独立验证证明个人数据域覆盖，但仅安装提供方不构成覆盖证明。治理清单版本 7 保留不含业务名称的归属、电脑权限、配额、名称 HMAC、不含正文的审计、灾难隔离及执行审批字段，版本 1–6 仍可作为部分清单读取。所有版本均不恢复登录、节点凭据或写入权限。

Linux 项目导出会排除 Gateway 在 Runtime 主目录保留路径生成的私有模型策略。该文件持有节点本地的用量接收凭据，Gateway 在启动时重新签发。首个 Runtime 代次写入内容库前，空目录或仅含此策略的目录没有可导出的托管文件清单。已有代次的 Runtime 缺少清单，或目录出现未申报文件时，备份仍记录覆盖缺口。[Linux 备份条件](../../../../gateway/deploy/node-content/README.zh.md)定义受保护的快照根目录。

同节点文件迁移保留已发布的路径和写入归属。离线重新绑定核验保留目录的物理身份、复制文件的字节内容和 UserDoc 根，再在新的内容修订中替换 inode 凭证。UserDoc 公开文件和私有对象须通过同一个挂载访问才能创建硬链接。Btrfs 快照从同一个已核验的源子卷解析配置中的绑定挂载。重新挂载后，文件系统 UUID、子卷 UUID 和保留的 inode 一致时才更新内核设备号。Linux 发布构建要求编译后的 Gateway 配备可执行的内核探针。保留 Btrfs 路径的回退版本必须能核验同一批已登记的文件身份。

项目恢复在不可逆提交前，重新核验当前管理员、项目所有者、目标电脑使用权、节点准入和现行策略。继续接管会为同一恢复点、目标和审阅过的策略修订单独保存不可变审批，要求先完成当前修订下的独立演练。源端封存凭证保持不可变。常规配额与恢复点目标调整不能改变尚未完成的接管。

目标在安装候选数据前，先记录目录的排他归属。父目录与 inode 凭证只允许重用本次操作安装的根目录。取消会撤下候选并记录清理完成，其他操作之后才能使用该目标。撤下的非空目录保留在活动布局之外供管理员检查。由本机操作系统提供的项目锁串行执行 worker，避免借用其他连接时仍占用治理数据库连接。

目标核验文件与投递回执后，只能激活已发布的更高写入代次。同一个治理事务记录激活，并暂停原源端的策略。保护新源需要单独配置策略、接收电脑及凭据。源端不可达和租约过期均不能证明写入进程已经停止。[维护恢复](2026-09-25-gateway-deployment-maintenance.zh.md)独立保留当前审批和写入约束。

定时证据遵守有限回执保留和明确删除任务的规则。任务或回执已经不存在时，所有已提交的定时消息仍进入恢复摘要。保留的回执须对应已提交的消息，活动任务的下次投递须晚于同一 Session 已记录的投递。收件箱已提交而任务尚未推进的歧义状态会阻止正式接管；单纯裁剪历史不会。

故障恢复接受管理员确认的物理隔离证明，绑定源进程代次、写入代次、恢复点及策略修订。系统隔离整台源电脑身份，撤销凭据与租约，保留原进程观察状态的未知性；每个项目分别保留审批。目标只在恢复后的私有副本暂停定时任务，计算新的文件与投递摘要，源端摘要和监督停止证明保持为空。恢复治理库不能抹除隔离证明、电脑隔离、执行隔离或审核凭证。

已停止的目标可以单独准备新对话许可，同时保持历史任务隔离。不可变的节点私有策略绑定恢复点、Runtime、电脑、写入代次、旧 Session 集合及审核过的安装文件与配置摘要。治理库只保存摘要、数量及管理元数据。Runtime 在组合预设前拒绝旧 Session 执行，启动和重新加载要求与获准组合精确匹配。逐项组件审批会排队等待停止后的再次检查，绝不停止活动任务。无法检查的动态代码保持暂停。项目加密备份与维护文件选择均包含这些策略文件；缺失或篡改的字节不能产生权限。

准备先提交排队请求，由 SQL 拒绝 Runtime 准入。操作系统提供的项目锁覆盖配置投影与检查，但不占用治理连接。发布审核时重新检查同一请求、当前节点租约、Runtime 已停止及精确数据归属，既避免单连接自等，也避免第二个 Gateway 在首个审核允许启动后继续修改配置。

物理隔离与正常退出接入授予不同的运行权限。不可变隔离证明、已撤销凭据、已消耗接入码和停止的期望状态，使组织管理可以从维护及关闭聚合的阻塞项中排除退役写入端，而不改写进程观察记录。模式变化后，原身份仍被隔离，不能重新接入或成为主入口；替换电脑使用新身份。

治理重建重置凭据及授权，不重放过期的访问决定。引导管理员使用新密码；其他账号保持停用，审核后以普通成员身份恢复。原授权作为不含正文的管理元数据保留供复核，实际授权默认拒绝。配额及用量保持不变。最新的单调重建代次决定 Runtime 准入，时钟时间和旧范围许可不能选择早期权限。放开允许账号配置，不等于允许 Runtime 执行。

治理审核期间，只有使用新凭据的引导管理员可访问专用恢复页面。普通业务、原 Admin 路由、内部 API 和 WebSocket 均保持关闭。集群处于恢复状态时，恢复命令通过自身事务检查写入，不使用部署和备份的通用豁免。没有重建记录的组织沿用普通请求路径，不增加数据库查询。全新导入将拒绝访问的权限投影记为各节点的失效通知基线；已丢弃的旧通知历史不会阻止受限入口启动。

仍可用的电脑只有在完成监督进程的只读停止证明、精确进程代次检查和本地 Session/索引验证后，才能绑定已有数据。恢复不会停止状态未知的写入进程。绑定将真实路径及冻结 Session ID 保存为节点私有不可变文件，治理库只存摘要和不透明标识。Runtime 准备、启动、模型及目录权限投影、个人文档和备份采集使用同一组验证后的节点本地路径；证据缺失或变化时不会回退到空的标准目录。手动检查失败后需要明确重新提交路径，不能进入自动标准路径队列。模型投影在策略查询前后核验保留目录的 inode，并禁止共用原子写入工具创建父目录。存储搬迁保留已封存的 Runtime 目录，不根据根目录设置重新推导位置。停止检查成功后只释放陈旧的内存容量计数。新一轮重建要求重新绑定和审核组件，即使旧范围许可已经丢失。

账号数据的生命周期独立于各个 Runtime 分配。来源 Runtime 退役后，已接受的私有账号根目录凭证仍可使用；同一账号与电脑的所有已接受凭证必须一致，且物理根目录仍有效。新建普通 Runtime 只共享该账号目录，使用独立的 Runtime 存储，不继承执行许可。缺少绑定时，在占用配额或创建文件前拒绝分配；保留的根目录消失时，不能重新创建空目录代替。

治理重建后的计划迁移绑定当前已审核治理策略，不能替换成更早的项目许可。不可变移交链只把冻结的 Session 集合带入目标的新审核。目标记录已安装移交策略的证明后，才允许进入退休阶段，因此不支持该协议的工作进程不能迁移写入归属。写入代次只与写入代次比较，进程代次分别保留原有约束。

密文接收电脑与替代写入电脑具有独立且不可变的身份。独立、有到期时间的读取凭据绑定当前策略、拓扑及连接代次；其期限由已配置的备份操作时限约束。事务内准入在演练确认及写入切换期间锁定代次和授权。恢复点限制操作与清单访问；共享 Restic 数据块及仓库密钥不提供历史点之间的密码学隔离。新的灾难隔离记录要求目标先验证平台、数据卷、文件及暂停工作。旧版本已隔离的操作可在不连接源电脑的情况下补验缺少的目标证明。

schema 135 治理重建包导入 schema 136 时保留原校验和及字段验证。新增读取审批与节点协议心跳属于临时状态，重建后保持为空。心跳区分仓库协议与实际装配的项目、个人恢复工作器，续期独立于长时间备份任务。Gateway 关闭时等待两个循环结束。旧有接收机即替代机的操作保留原身份；源恢复点清单永不重写。

治理重建按历史包原有的字段清单和对应迁移前缀验证。schema 145 捕获将投递状态和设备登记归为临时数据。即使源组织从未进入维护，导入也会建立处于 `restoring` 状态的集群记录。新 Gateway 在提供恢复身份的服务前先进行受限审阅。[重建组织治理](../../../../gateway/docs/peer-backup/README.zh.md#governance-rebuild)

## 考虑过的替代方案

**将复制的目录称为完整备份。** 可变文件不能证明与数据库或外部插件副作用处于同一检查点。缺少证据时必须保留覆盖缺口。

**恢复旧策略修订或重新开放源端。** 这可能复活已撤销的凭据，或者产生两个写入端。新的不可变审批允许继续接管，同时保留封存结果。

**重试前删除任何占用暂存路径的数据。** 该路径可能含有其他操作或管理员的数据。清理必须依据已记录的物理归属凭证。

## 影响

原生个人格式 3 可在独立核验后替换个人电脑，保留账号与 Runtime，要求既有目标权限和配额，保留标签页身份，并以一条不可变发布凭证管理账号共享文档。目标被占用、Session 路径不兼容及恢复点不完整均会拒绝准备。个人执行使用独立审批及相同的旧 Session 守卫，全部恢复工作保持暂停。版本 1–7 治理清单仍为部分覆盖。独立重建包可在关闭准入的空数据库中恢复经过审核的管理身份。Mac 缺少快照服务或数据卷尚未核验时，仍是部署缺口。日常备份不会为了获取快照而停止运行任务。替换电脑后保留 Runtime 身份和项目成员关系，成员仍须具备目标电脑使用权。故障替换允许经过审核的新对话，同时保留只读旧历史。二次故障要求在新的写入代次上重新签发许可。计划迁移绑定当前源电脑的首份不可变审核，并在封存前验证其加密策略。迁移保留原冻结集合及后续对话，要求重新审批目标电脑，不会导入源电脑的组件审批。单电脑模式保留精确对应本机已发布归属的执行审核，不授予远程管理或新接管权限。主入口不能在其当前服务入口确认隔离自身。

个人和项目故障恢复会在目标副本中暂停旧 `HGW_*`、`DSH_*`、libpq 连接设置及 `DATABASE_URL`。Admin 只显示受影响的设置名称，供管理员按目标电脑明确重新配置；源加密恢复点保留原值。业务环境设置保持不变。普通升级和计划迁移保留其当前环境。

## 验证

三身份项目和个人用例使用真实 Restic HTTP 传输、独立目标演练，并在移除源后发布目标。没有个人所有者的管理员项目沿用相同恢复检查。schema 135 用例在目标准备前记录隔离，应用迁移 136 后，从加密恢复点补验缺少的目标证据再发布，保留源端不可用、暂停的定时任务及只读旧会话。数据库屏障覆盖演练确认期间的读取撤销；更新节点身份后拒绝旧审批。这些检查不证明原生 Windows 快照覆盖。

真实 SQL 导出和加密 restic 恢复在移除源文件后写入全新的治理数据库。导入库不含旧 cookie 或节点凭据；真实 Admin HTTP 审核要求新密码，保持授权默认拒绝，并在放开后继续保留 Runtime 执行隔离。操作系统提供的所有权锁、真实 SQLite/JSONL 数据和受管配置验证非标准 Runtime 目录、冻结的根及子会话历史和节点私有备份覆盖。真实 Gateway 源码入口以受限模式启动导入后的数据库，接受新引导凭据，放开已审核访问时不创建管家或启动 Runtime，并在维护期间暂停排队检查。真实文档读取和已停止实例的退役验证新分配 Runtime 的账号目录连续性、冲突或篡改证据被拒绝，以及退役 Runtime 继续无法访问。这些用例不表示生产电脑已经完成重建。

独立 PostgreSQL 实例覆盖所有者撤权、策略轮换、过期确认、当前修订演练、维护恢复保护、二次故障恢复及激活。restic 组合在恢复前移除源端，并通过桌面和手机上的真实 Admin HTTP 请求审批。执行审核使用单连接治理池，拒绝并发启动和过期请求，并排除第二个准备 worker。私有策略导出、摘要核验及缺失文件拒绝均使用真实还原文件。后续真实 restic 计划迁移保留原冻结集合、保持后建对话可执行、保留 Schedule 字节，并要求重新审批目标电脑。缺少迁移策略会在原写入端封存前拒绝准备。

个人组合使用完整原生用例、真实 restic HTTP 传输、独立演练，并在移走源文件后由目标安装文件。它核验根对话和子对话历史不变、账号文档身份、独立标签页草稿及已停止 Runtime 的新执行审批。移除电脑互备配置不会绕过或禁用已有许可检查。

TypeScript 源码 CLI、SDK 与构建后的 Python SDK 共用恢复输出：拒绝旧根及子会话的恢复与发送请求，既有 JSONL 和收件箱字节保持不变，新对话通过真实回环模型 HTTP 获得回复。完整 WebHost 回放只读历史、保留草稿及新消息的 ARIA 输出。这些隔离组合不代表新一轮三台原生电脑验收。

文件系统用例在不同准备阶段中断，保留外来文件，并核验取消后的重试。独立进程核验 worker 死亡后项目锁能够释放。较早的 Mac 到 Windows 原生加密恢复在删除源端、断开通道后核对文件字节、Session 顺序和投递回执；它不代表生产数据已完整覆盖，也不代表完整接管耗时。
