# Agent Note：按账号隔离的辅助侧栏

Status: implemented

[English](2026-09-23-account-scoped-auxiliary-sidebar.md) | 中文

## 问题

单会话停靠控制器无法推断由哪个 CoHarness Workbench 窗格发起操作。仅以 Session 为键的浏览器存储也会让同源下的不同账号共享私有标签元数据。

## 决定

复用上游 dockkit、侧栏规划器、注册表、标签生命周期与渲染器。现有 Workbench 保持为唯一中间布局。框架负责尺寸，侧栏负责标签可见性、分栏和关闭操作。工具详情标签携带明确的 Session 与调用地址，资源导航在修改布局前验证归属。

产品持久化要求已验证的 Gateway 账号，或 Host 明确声明独立本机模式。存储键包含身份主体、runtime 目标和 Session。未验证身份没有持久化作用域，也不能回退为本机权限。身份失效会清空当前标签记录，并取消其独立 Session 引用。重新验证后只恢复匹配且有效的记录。启动清单不枚举未经身份核验的布局。

保留上游停靠与标签类型注记，因为它们解释可复用的所有权和扩展规则。本注记负责 CoHarness 的账号与多窗格适配，[Session 引用注记](2026-09-23-client-session-references.zh.md)负责代次生命周期。

Browser 复用上游 iframe 导航、受控历史、未知 URL 提示和临时 sandbox 状态。消息链接明确指向所属 Session；带修饰键的操作保留原生外部导航。Browser 历史使用侧栏的已验证归属 key，恢复前校验存储 URL 的策略。Loopback 地址属于访问者机器，不属于执行目标。

Markdown 文件导航复用资源所有者和带版本保护的有界读取器。行号片段改变文本页起点，不改变文件标识或授权。通用 Markdown 渲染器通过当前所有者委派，包括流式期间缓存的链接。

工具详情通过现有 Session 观察服务读取确切调用所属完整轮次，并使用已注册的 Conversation 定义组装，不扩大可见聊天窗口或唤醒冷 Agent。Fetch 传输将选中轮次视为不可拆分单元。侧栏在标签生命周期替换时重新挂载内容，包括不同已验证账号恢复相同标签标识的情形；进行中的读取不能发布到新标签生命周期。

## 考虑过的方案

**两个右侧栏。** 同时保留旧详情栏和停靠侧栏，会产生互相竞争的呈现与资源所有者。

**仅按 Session 持久化。** 持久 Session 标识不等于经过验证的身份主体或 runtime 路由证明。

## 影响

Workspace 文件导航复用同一标签所有者和现有鉴权资源注册表。runtime 归属变化会在导航前被拒绝。隐藏标签停止内容读取，标签实例继续持有元数据；关闭标签释放实例。不再保留并行的预览弹窗选择状态。

单测覆盖写入前拒绝资源归属错误、账号隔离、验证失效、恢复、关闭失败和插件卸载。产品测试覆盖真实装配的 Workbench 与导航；侧栏专项检查验证折叠、刷新恢复和窄屏呈现。其他资源类型仍需各自的授权内容提供方及真实入口测试，仅注册标签类型不代表资源功能完成。
