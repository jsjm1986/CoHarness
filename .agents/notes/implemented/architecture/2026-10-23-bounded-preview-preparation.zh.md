# Agent Note: 有界工作区预览准备

Status: implemented

[English](2026-10-23-bounded-preview-preparation.md) | 中文

## 问题

文件读取、Office 转换与查看器代码下载各有独立前置条件。将它们串联会在首次内容出现前再增加一段网络等待。HTML 预览可能包含许多互不依赖的本地资源；逐项等待读取会让公网延迟随资源数累加，即使文件很小也如此。直接提高并行度而不预留字节预算，则会把等待换成难以预测的内存留存。

## 决定

预览只重叠不依赖文档内容的准备工作。授权元数据可用后，当前文件所需的 PDF 或表格代码导入与原有内容读取同时启动。组件持有的导入 Promise 会接住提前发生的拒绝，并为 React 渲染错误处理保留同一个失败；没有成功授权的字节，导入完成也不能挂载正文或启动 Worker。[授权 Office 预览](2026-09-23-authorized-office-preview.zh.md)继续负责全部内容检查与 Worker 所有权，[包 README](../../../../packages/client/ui-workbench/README.zh.md#composition)负责加载与取消行为。

HTML 资源批次宽度由既有单资源与总字节上限推导。为每个在读资源预留最大可能字节数，无需增加部署调参值即可约束留存的资源字节。剩余预算低于单资源上限时逐项读取，因为实际资源仍可能放得下。结果保留原文顺序；失败会取消同批其他读取，并等待它们结算后再拒绝打包操作。[HTML 预览决策](../feature/2026-09-25-workbench-html-markdown-previews.zh.md)继续负责资源寻址、鉴权、静态依赖准入与 iframe 隔离。

表格导入直接指向带许可证的渲染器／解析器分块。体积很小的加载界面属于主包；单独的转发分块不执行独立工作，却增加一次请求依赖。[表格预览决策](../feature/2026-10-01-workbench-spreadsheet-preview.zh.md)继续负责解析保真度、限制与只读展示。

## 考虑过的替代方案

**内容完成后才导入。** 这可避免为失败的读取下载查看器，但每次冷开文档都会串联本可独立的工作。提前启动 Worker 或执行文档字节仍被排除：代码准备不等于内容授权。

**应用启动时预载全部查看器。** 每位访问者都要传输并初始化 PDF 与表格依赖，包括从不打开这两类文件的用户。当前预览提供了足够具体的准备意图。

**用一个无约束的 `Promise.all` 读取全部 HTML 资源。** 仅有资源数量上限时，打包总量检查拒绝前，仍可能已有许多最大体积文件在读。根据既有字节上限预留空间，既约束这部分分配，也保留尾部逐文件读取的能力。

**增加共享内容或导入缓存。** 内容始终受每个预览的授权与撤权生命周期约束。客户端模块加载器已持有代码传输的单次在途复用与模块身份；再加模块级缓存会增加失效与释放责任，却不减少请求依赖。

**保留表格转发分块。** 重分块既有的动态导入已承担工作延后，转发分块的小体积传输不再推迟额外工作。它增加冷开延迟，却不能进一步减少主包中的解析器或渲染器代码。

## 验证

[合成打包器诊断](../../../../packages/client/ui-workbench/tests/html-pack-perf.client.ts)在受控完成屏障处释放当时全部在读请求。24 个直接脚本资源在串行参照中需要 24 个完成波次，在本准备策略下需要 4 个；读取总数同为 24，资源顺序与包摘要一致。波次衡量读取依赖，而非毫秒、HTTP 请求数、CPU 成本或首次绘制；每个资源读取器自身仍可能发出多次授权 RPC。浏览器延迟需要完整应用的独立证据。

生产组件回归分别挂起内容读取与导入，以证明仅预载选中格式且迟到结果不挂载正文。打包器回归覆盖字节预留、上限、顺序、拒绝、同批取消与收尾等待。发布包测试要求重依赖经直接懒加载导入并保留许可证；重新引入转发分块会违反包的封闭文件清单。

## 后果

冷开预览可让代码传输与授权读取或转换重叠。读取失败时，当前查看器的下载可能白费；JavaScript 导入 API 无法取消底层传输，因此取消保证的是不发布结果、不创建 Worker，而不宣称停止该网络请求。HTML 打包在已完成资源旁只保留按字节预算约束的一个批次，并在自身读取全部结算后才拒绝。这里的上限描述包字节数，而非还含解码与查看器状态的浏览器总堆内存。
