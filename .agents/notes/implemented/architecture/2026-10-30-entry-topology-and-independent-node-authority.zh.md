# Agent Note: 入口拓扑与电脑独立授权

Status: implemented

[English](2026-10-30-entry-topology-and-independent-node-authority.md) | 中文

## 问题

浏览器可以选中另一台电脑的 Runtime，同时保留原来的 Gateway 来源。若用远程 Runtime 元数据决定部署范围，远程选择就能改变自己的路由授权。仅控制展示的开关也无法阻止远程 URL 和已缓存的变更目标。

## 决策

组织策略指定唯一聚合入口。每个浏览器在转发前从原 Gateway 读取策略，资源目录在分页前按入口范围过滤，路由核验解析出的目标。Runtime 身份和电脑权限与部署策略分离。单电脑模式改变聚合和展示，不改变本机多用户、多 Runtime 存储。文档目录绑定只序列化逻辑所有者类型和 id，使同一电脑作用域下的其他 Runtime 能重新打开原有私有存储。Runtime UUID 和代次仍用于执行授权。

账号重新验证期间暂停聚合，并清除账号范围的入口详情，直到取得新验证结果。位置标签是否显示仍遵循上次核实的来源模式，使多个个人文档位置在元数据刷新时保留可区分的名称。这一展示信息不授予电脑权限，也不保留上一账号的目录。

电脑接入分为待接入、受管和独立运行。签发接入码保留本机授权。正式接入和退出受管状态与进程代次准入串行化，并要求 Runtime 已确认停止。退出时暂停受管服务准入，拒绝存在活动传输的操作，使凭据和连接代次失效。新的独立进程代次使用本机授权，旧受管代次不能通过改标签取得独立运行权。

数据库恢复保留目标部署的拓扑和接入授权，推进连接代次，并将私有连接控制文件排除在应用数据根目录之外。签发者 UUID 保留为历史事实，不要求其存在于恢复后的账号数据中；保留无关的现行账号会扩大恢复后的权限。历史部署保留受管租约有效性，直到原转发入口明确初始化策略。新组织默认单电脑模式。

## 考虑过的替代方案

- 按电脑数量推测模式，无法区分聚合已关闭、节点不可用或直接访问接入电脑。
- 模式变化时清空远程选择，可能使未保存表单提交到另一台电脑。已捕获的目标保持不变并显示不可用。
- 租约过期时自动退出接入，将未知进程视为停止，仍需确认进程终止。
- 从数据快照恢复拓扑，可能复活已撤销接入或静默更换主入口。

## 结果

模式转换要求明确退出接入，更换主入口需要停止接入后重新配置。主入口本机工作保持独立。浏览器标签页只交换修订号失效通知，不同步当前选择和草稿。元数据按需读取，不启动其他 Runtime。明确进入工作区或 Session 时，通过账号范围接口准备捕获的分配，不导航页面或写入选择 Cookie。操作取消信号和配置的元数据时限约束准备过程；异步期间改变选择不能重定向后续操作。维护模式允许管理员按所属用户、项目或准确 Runtime 停止进程，代次检查和恢复后陈旧进程的限制仍然有效。操作流程和 API 细节由部署文档维护。
