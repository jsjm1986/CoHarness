# Agent Note: 由生命周期所有者完成空闲会话清理

Status: implemented

[English](2026-09-27-idle-session-purge.md) | 中文

## 问题

Agent 显示 `idle` 时，仍可能有维护任务、停放的输入或插件持有的资源。生命周期所有者释放这些资源前删除持久数据，会让执行继续却丢失历史。归档命令还会跨越单次 HTTP 请求，运行时无法执行时必须保留明确的失败记录。

## 决定

Host API 保存创建、恢复和 fork 返回的工厂句柄。永久清理通过 `AgentRegistry` 预留所有 Session 标识：正在进行的生命周期请求会拒绝预留，预留期间拒绝新的创建、子级准入和资源分配。只有创建者持有的句柄可调用 `tryDisposeIdle()`；真实空闲阶段、inbox、活跃子级及同步的 `agent/idle-release-check` 观察者均允许释放后，才关闭输入。资源插件检查自己持有的待处理工作与资源。普通 `dispose()` 与取消收敛保留原有行为。

释放顺序遵循实时注册表的所有权：每个选中的后代完成释放后，才检查其父级。Team 日志事务从进入队列到持久检查点完成期间持有 Lead 标识。队友创建、准入恢复、邮箱投递及异步回执处理在整个异步工作期间持有相关根与子级标识。Goal 驱动任务在合并调度的检查点期间持有其 Session，直到运行回合接管或放弃续行；暂停的目标不会继续占用空闲会话。完成、失败或取消时，各自释放自己的预留。上述操作尚未结束时，清理会拒绝并保留持久数据。

清理请求先进入 Gateway 命令台账，不删除数据库内容。在线运行时轻量查询待处理命令，不重复扫描空闲历史。会话忙碌或释放所有权不明时，在持久删除前拒绝。先删除 Review 数据，再删除日志。个人日志按最深子级到根的顺序删除，每次先移出归档集合：中断后，剩余子级仍有完整祖先供重试发现。项目数据仅在 Gateway 回执事务内删除一次。运行时保持标识预留，直到回执完成。

Gateway 先锁归档所有者记录，再锁命令记录，核验运行时身份，并拒绝相互矛盾的回执。待处理的清理不能与恢复竞争。普通快照刷新不能抹掉排队操作或失败记录。Admin 状态轮询只读取元数据；请求被接纳后仍显示等待，直到运行时确认。

## 考虑过的替代方案

仅由 Gateway 清理无法检查运行时持有的资源。删除时强制取消活跃任务，会将清理与用户应单独作出的执行决定合并。要求手动关闭每个空闲 Session 会增加操作步骤，却仍不能证明资源已经释放。所属工厂句柄能够确认空闲释放，同时保留活跃资源的否决权。

## 结果

忙碌拒绝会保留持久数据。清理开始后的存储或网络失败可能留下部分删除；冲突记录支持重试，不宣称已经回滚。离线运行时保留待处理命令，后台不会启动它。历史 Review 在普通会话释放后保留，只有明确的永久清理才删除。日志声明存在 Review 而清理提供方缺失时，拒绝删除。

只返回裸 Agent 仍适合读取与路由，但不会移交释放权限。向同步释放检查注册异步监听器会重新引入准入竞态，其返回类型不允许这种实现。
