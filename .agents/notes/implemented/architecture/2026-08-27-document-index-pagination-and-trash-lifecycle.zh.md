# Agent Note: Document index pagination and recoverable trash

Status: implemented

[English](2026-08-27-document-index-pagination-and-trash-lifecycle.md) | 中文

## Problem

大型文档工作区每次完整扫描运行时并在浏览器筛选都会增加响应和渲染成本。删除也没有持久化的恢复窗口：文件从运行时移除后可能在用户或管理员纠正前消失，组织级目录也无法区分可恢复删除和永久清理。

## Decision

用户文档服务提供有界的目录和回收站分页，接受经过校验的筛选条件，使用稳定排序和不透明的延续游标。Host 与 Gateway 转发分页参数，绝不公开运行时路径；Web 管理器在提供方声明支持时使用游标分页，并为旧提供方保留本地分页回退。管理器持续挂载期间保留已获取的页面，筛选条件改变时创建新的游标链。

删除会把普通文件移入提供方持有的隐藏回收站。版本化清单保留原始文档 id、展示元数据、删除时间和清理截止时间。恢复会重建已被删除的原目录，并解析一个不覆盖现有文件的目标；永久清理需要显式操作或等待配置的保留期限。运行时路由使用与活动文档相同的作用域授权，提供列出、恢复和永久清理操作。

PostgreSQL 目录以 `active`、`trash` 和 `purged` 状态镜像该生命周期，记录保留时间、操作者和追加式 `restored`／`purged` 历史。已有的 `deleted` 行迁移为 `trash`，并使用默认 30 天截止时间。管理员 API 提供游标列表以及单条或批量移入回收站、恢复和永久清理；Gateway broker 可用时先修改运行时字节，再提交目录状态。

Migration 018 为文档目录中的用户外键附加 `organization_id`（包括所有者、操作操作者和历史操作者），因此导入的 UUID 不能跨企业连接所有权或审计记录；同时增加供 SQL overview 筛选和分页使用的活跃修改时间与 trigram 索引。

## Alternatives considered

**保留完整列表，只在浏览器分页。** 对支持分页约定的提供方否决：响应大小和元数据工作量会随工作区增长；旧提供方仍把它作为兼容回退。

**立即删除文件，只保留目录元数据。** 否决：元数据无法在误删后恢复字节。提供方在截止时间前持有回收站字节，目录继续作为审计投影。

**允许管理员只修改目录状态而不联系运行时。** 否决：界面可能在文件仍被删除时报告已恢复，或在字节仍可读时报告已清理。Gateway broker 在目录记录结果前先执行运行时操作。

## Consequences

当前文件夹和全部作用域元数据的列表、搜索流量受请求页面大小限制。游标绑定一条查询链，不能被当作文件系统路径使用。没有索引的提供方仍可能扫描所选目录生成页面，但重复的进行中读取会合并，提示词使用的递归列表保持为独立操作。

回收站在保留期间占用存储，需要维护任务定期清理。运行时或目录服务中断可能留下待对账状态，因此用户错误保持可重试，管理员操作按行返回结果。永久清理会删除提供方字节并保留目录历史，不会再次使文档可读。

## Verification

本地提供方测试覆盖清单持久化、恢复冲突、幂等清理和重启恢复。Host 与 Gateway 测试覆盖有界分页、无路径元数据、内联预览响应、作用域授权、流式转发和生命周期错误映射。Client 测试覆盖游标导航、筛选重置、持续挂载的页面复用、回收站恢复和移动端控件。配置 `HGW_TEST_DATABASE_URL` 时，PostgreSQL 迁移和目录集成测试覆盖状态转换、保留字段、索引和审计历史。
