# Agent Note：移动端排版与呈现基线

状态：已实现

[English](2026-08-24-mobile-typography-and-presenter-baseline.md) | 中文

## 问题

紧凑 Web 页面共用桌面密度规则，信息层级复杂的页面只能不断缩小文字、让控件换行直到塞进屏幕。结果虽然保留了操作入口，却让 320px 与短屏上的主要信息难以阅读。

## 决定

由 `ui-theme` 统一拥有 compact 排版角色、图标视觉尺寸、页面内边距与区块节奏。手机主要内容使用正文角色或更大字号，caption 只用于元数据；44px 触控目标不等于 12px 图标。信息层级在手机上发生实质变化的功能使用手机 presenter 或卡片／列表投影，但继续共用同一 slot、对象层数据、动作与持久语义。桌面表格不得靠缩小行高与字号来适配手机。

手机 Sheet 使用一个不透明的阅读层和一层共享遮罩。摘要内容只保留一个滚动位置，短屏先以普通流展示状态和值，再展示次级详情。最窄宽度下的多动作工具栏使用明确的 grid 轨道，避免次要控件意外掉到孤立行。

## Alternatives considered

**继续在手机上缩小桌面排版与行密度。** 被拒：这会保留桌面信息层级，却牺牲主要内容的可读性，在 320px 与短屏上尤其明显。

**创建独立的移动端 store 与 slot 路径。** 被拒：重复的业务状态与动作会让移动端投影逐渐偏离桌面端，并增加另一位生命周期拥有者。

**让每个功能自行定义移动 token 与 Sheet 几何。** 被拒：重复值会在插件之间漂移；共享度量由 `ui-theme` 单一拥有，而每个功能仍保留自己的呈现选择。

## 结果

新的移动 UI 使用 `--dsw-mobile-*` 角色与共享 Sheet 度量，明确声明最窄档位布局，并把截图审查与行为测试配对。功能可以改变手机信息层级，但不能创建第二套业务 store 或 slot 路径。compact 视觉审计覆盖 320×568、375×667 与 390×844 的浅色和深色主题。
