# Agent Note: 保留 webhook 创建会话的执行身份

Status: implemented

[English](2026-09-23-webhook-execution-identity.md) | 中文

## Problem

已验证的提供方交付只能证明谁签署了载荷，不能证明哪个 Gateway 账号有权执行。上游 webhook 运行时创建会话时没有账号归因。把签名验证当作执行权限会绕过资格检查并错误归属模型用量。

## Decision

[webhook 运行时](../../../../packages/webhook/webhook/README.zh.md)保留上游规则注册、取消、Workspace 附加和提示词来源语义。受管会话创建通过已有执行授权服务登记输入身份，再核验请求的权限预设，随后才能应用预设和接收提示词。异步核验期间授权提供方必须保持一致。取消或拒绝会解除会话附加并释放 Agent，不接收提示词。独立本机部署保留本机操作者权限。

[GitHub 适配器](../../../../packages/webhook/webhook-github/README.zh.md)保留上游原始正文限制、签名验证和秘密不可用时的行为。其进程内 HTTP 接收只证明完成分发。交付的 profile 不挂载 webhook 端点。Gateway 账号绑定、持久交付去重、限制和管理需要由 Gateway 接收方负责；原始适配器不能替代这些控制。

Gateway 投递存储在派发前将每个端点／投递标识预留到 PostgreSQL。共享端点锁在跨节点情况下执行受理窗口限制；重复投递复用原回执，不再占用额度。同一投递标识下内容变化会被拒绝。相同正文摘要即使使用新投递 ID，也会在配置的 `replayWindowMs` 内复用原回执；该窗口与受理限流窗口独立。持久化的投递别名在正文窗口过期后仍保持幂等。派发中或结果未知的回执也会在窗口之外阻止相同正文。存储接口不接受客户端控制的重放绕过参数。配置与签名密钥变化不改变回执标识。只有预留节点能记录提交、拒绝或结果未知；冲突的结果提交会失败。未知结果保持预留，绝不自动重新派发。这些存储保证不替代端点授权，也不能证明 Agent 已完成。

受管接收方可通过 `invoke()` 等待单个已注册规则，取得已接纳提示词的 Session id；不采取动作时取得 `null`。它与广播分发使用同一创建和卸载路径，传播失败，结合调用方取消与注册卸载，绝不等待模型轮次。

Gateway 接收方的所有者是 `gateway/src/webhook-intake.ts`，基于 `webhook_endpoints` 表（迁移 039）。每个端点携带结构化匹配规则、标题与提示词模板、执行账号、目标运行时和加密的签名密钥；端点创建即停用，由管理员显式启用。公共提供方路由先验证内容类型、限界正文、签名与投递标识，再预留投递；随后检查配置的执行账号与运行时存活性，在派发期间持有一个运行时操作引用，渲染模板并签发限定用途的 `webhook-dispatch` 断言。受管运行时暴露仅环回可达的派发路由，验证断言、接纳限界请求并通过 `createWebhookSession` 创建会话；Gateway 把持久回执完结为 submitted、ignored、rejected 或 unknown，并在 `finally` 中释放该引用。管理员重跑在完成事务内重读端点，被删除的端点不能被重放。

分离派发没有交互主体，因此执行授权仅在当前主体携带 `webhook-dispatch` 时回退到当前主体；Gateway 只在执行输入与权限选择两条路径上接受该用途，其余 `/internal/runtime/*` 端点仍拒绝带用途的断言。

## Alternatives considered

**把签名当作执行授权。** 提供方签名不包含 Gateway 用户、项目成员资格或 Auto 资格，也不能建立这些事实。

**赋予 webhook 本机操作者权限。** 受管身份缺失必须拒绝；后台触发器不能获得超过其配置执行账号的权限。

**用第二套 Agent 编排循环替换上游运行时。** 已有创建与回滚路径已拥有会话生命周期。薄身份适配保留该所有者及其回归测试。

## Consequences

通用运行时仍限于进程内，不宣称持久接收或 Agent 成功。受管调用方必须提供已验证的请求上下文。身份拒绝、资格拒绝、取消和提供方替换均在提示词接收前接受测试。移植的上游 HTTP 与生命周期测试保持启用；Gateway 端到端验收另行提供证据。
