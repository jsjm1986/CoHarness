# Agent Note: Gateway 自有模型请求准入

Status: implemented

[English](2026-10-24-gateway-model-ownership.md) | 中文

## 问题

Gateway 辅助功能可以在没有执行中 Runtime 的情况下发起推理。项目进展生成需要与 Runtime 模型共用节点调度，同时在 HTTP 取消、数据库断连、进程退出和部署静默期间保留实际所有权。

## 决策

`GatewayModelBudget` 在 PostgreSQL 节点记账器中登记独立的 Gateway 代次。模型请求共用已有的压力额度和按用户、项目公平排队。手动请求保留经过验证的发起用户用于调度；自动扫描使用基础设施用户零。调度请求仅使用 model 类型；管理[破坏性操作](../bug-fix/2026-10-28-project-deletion-lifecycle.zh.md) 持续持有同一进程证明，不消耗调度额度。其进程退出不能证明独立子进程后代已经停止。

登记前，所有者在稳定私有目录 `stateRoot/gateway-model-locks/<node-id>` 中的唯一文件上持有 POSIX 内核锁。PostgreSQL 保留 UUID、代次、设备号和 inode。恢复时不跟随符号链接地打开已有文件，核对描述符与路径是否匹配所记标识，再尝试独占非阻塞锁。只有匹配且成功取得的锁才能授权回收占用。文件丢失、inode 改变、锁仍被持有以及数据库断连都不能证明进程退出。Gateway 运行期间须保留该目录。

所有者串行登记请求，通过单调序号隔离确认丢失，并在准入后调用 HTTP 回调。回调负责请求、受限响应读取及取消；回调结束后才释放记账。关闭会取消模型回调，并等待全部模型及管理回调；清理失败保留锁和记账，供重试或确认进程退出后恢复。此机制补充 [Runtime 代次所有权决策](2026-10-23-gateway-runtime-admission.zh.md)。

项目进展在准入后复查维护状态、数据代次、组织/节点/项目是否活跃、发起者写权限、共享来源可见性以及实际服务的模型路由。凭据从最新路由解析。后台手动任务在结束前持续计入控制平面写入者，关闭时先等待手动与定时任务，再关闭记账器或数据库池。

## 考虑过的替代方案

- 借用项目 Runtime 代次会让 Runtime 终止回收仍在 Gateway 中运行的 HTTP 请求。
- 心跳或到期租约无法区分断连但存活的进程与已退出进程。运行中占用须有完成报告或内核锁证据。
- 每个 Gateway 单独使用内存信号量会拆散跨协调器公平调度和占用，并在重启后丢失未结束的所有权。

## 后果

Gateway 模型所有权增加 PostgreSQL 迁移 065，以及编译版 Gateway 必需的原生 flock 入口。发布校验仅对导入 Gateway 模型所有者的版本检查该入口，保留旧编译版回滚目标。此所有者中的模型调用不获得子进程隔离能力。

[进展纪要决策](../feature/2026-10-21-project-progress-journal.zh.md) 负责请求证据、记账重放、来源失效和发布代次检查。基础设施用量计入项目，不虚构 Session 参与者。

## 验证

真实 PostgreSQL 测试覆盖 Runtime/Gateway 共享排队、队列取消、登记确认丢失、活跃锁保留及 inode 替换。通过源码启动的子进程持有未结束的回环 HTTP 响应，收到 SIGKILL 后仍持续占用，直至取得匹配的内核锁。中断请求仅重放一次，并标记用量缺失。进程退出用例在本地 macOS 执行，不能据此推断 Linux systemd Runtime 隔离已经验证。
