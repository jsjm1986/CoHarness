# Agent Note: Gateway 管理员宿主机目录浏览器

Status: implemented

[English](2026-08-17-gateway-admin-host-directory-browser.md) | 中文

## 问题

Gateway 支持管理员按名称创建受管项目，其 JSON API 也接受既有宿主机目录。管理 SPA 只暴露受管模式，因此纳入既有项目仍需要 shell 访问或手工构造 API 请求。浏览器原生文件夹选择器会选择管理员客户端的文件系统，而不是项目运行时使用的 Gateway 宿主机文件系统。

## 决策

管理员新建项目弹窗提供两种明确模式。**默认目录**提交 `{ name }`，保留[受管项目目录](2026-08-16-gateway-managed-project-directories.md)行为。**现有目录**使用内嵌的 Gateway 宿主机浏览器并提交 `{ name, path }`；只有项目名称为空时，选择目录才会建议其 basename。现有目录模式不会创建文件夹。普通用户新建项目仍只提交名称，并落在 `HGW_USER_PROJECTS_ROOT` 下。

`GET /admin/api/project-directories?path=<绝对路径>` 返回一层排序后的目录、规范面包屑、当前目录是否可选、隐藏目录标记和截断标记。每次最多列出 1,000 个目录。UI 默认隐藏点目录，在存在隐藏目录时提供开关，并要求选定目录后才能创建项目。

本地启动器从文件系统根开始浏览。在 macOS 上，只要 Gateway 进程具有操作系统权限，就可通过 `/Volumes` 访问已挂载的外接磁盘。systemd 启动器改为显示一个只包含规范 `HGW_PROJECT_PATH_ROOTS` 条目的虚拟根。这些配置根只能用于导航；项目必须是其严格后代。`HGW_PROJECT_PATH_ROOTS` 仍禁止使用 `/`。

目录符号链接只有在规范化后才会跟随。systemd 下离开配置根的符号链接会从列表省略，直接请求时也会被拒绝。Gateway 管理的用户数据、项目运行时数据、principal 与凭据数据、Gateway 与 dsh 发布代码、directory-guard 与模型治理代码、公司环境文件所在目录、用户受管项目存储、用户 home 和已登记项目目录都不能选择。为了让管理员到达不相关的同级目录，这些目录的祖先仍可导航；但如果选择祖先会包含保留数据，则祖先不可选择。

目录浏览器只提供辅助。`POST /admin/api/projects` 会再次解析提交路径，并在持久化前执行相同的绝对路径、配置根、保留目录、用户 home 和既有项目重叠检查。稳定诊断会区分非绝对路径、不存在、不是目录、不可访问、根外、保留和重叠路径。重命名项目只改变目录中的名称；删除项目会保留宿主机目录。

## 安全模型

只有通过认证的管理员才能调用目录列表端点。本地模式会有意让该角色检查 Gateway 进程可读的各宿主机目录树名称，但仍受保留目录排除和 macOS/Linux 权限约束。systemd 部署把枚举和项目挂载保持在管理员配置的根内；导入目录仍必须为 `HGW_PROJECT_RUNTIME_USER` 提供 Unix 读写权限。

远程 Web 浏览器绝不会要求客户端操作系统选择目录。独立的[原生工作区目录选择器](2026-07-27-native-workspace-directory-picker.md)仍只用于回环桌面载体，并选择该载体的本地文件系统。

## 验证

目录浏览器测试覆盖本地与 systemd 根、隐藏条目、排序、1,000 条上限、保留路径、规范符号链接和 systemd 逃逸。SQLite 项目服务和管理 API 测试覆盖绝对路径、保留路径与重叠诊断，以及仅管理员可列目录。管理 UI 测试覆盖两种创建模式、导航、隐藏目录显示、选择、basename 建议、错误恢复和提交载荷。一个无密钥真实服务快照会登录、列出宿主机目录、导入该目录，并证明已登记目录会从后续列表消失。配置 `HGW_TEST_DATABASE_URL` 时，PostgreSQL 集成覆盖会应用同一套最终路径策略。

## 曾考虑的替代方案

**使用浏览器客户端的原生文件夹选择器。** 否决，因为远程管理员会选到错误电脑上的文件。原生对话框仍适用于回环桌面载体，其信任与传输由[原生选择器决策](2026-07-27-native-workspace-directory-picker.md)负责。

**恢复自由文本绝对路径字段。** 否决，因为它会暴露部署前缀、引入可避免的输入错误，也无法显示 Gateway 进程的真实权限。

**在 systemd 部署中暴露完整文件系统。** 否决，因为项目单元只能挂载已配置项目根；展示永远无法满足隔离策略的路径既会误导，也会泄露无关宿主机布局。

**从目录浏览器创建任意文件夹。** 否决，因为获批流程是纳入既有项目，而默认目录模式已经能按所需所有权和权限策略创建新项目目录。

## 后果

管理员无需 shell 访问，即可纳入 Gateway 宿主机上任何获准位置的既有项目，同时受管项目创建仍是默认的低输入路径。本地部署获得整机导航能力，但继承宿主账户权限和 macOS 隐私控制。Linux 部署可以配置多个项目根来暴露多个存储卷，而不会削弱严格后代挂载规则。

Gateway 负责一个有界文件系统枚举 API 及其匹配的最终校验策略。新增 Gateway 自有秘密或运行时目录时，必须把它加入保留路径集合，使浏览和项目创建继续排除该目录。
