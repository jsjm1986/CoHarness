# Agent Note: document workspace folders and migration

Status: implemented

[English](2026-08-19-document-workspace-folders.md) | 中文

## 问题

真实文件用户文档存储原本把新上传内容放在 `<home>/uploads` 下按日期命名的目录中。该布局能让文件工具访问上传内容，但没有提供稳定的用户命名文档工作区、普通文件夹管理或项目本地的文档目录。更改默认根目录还可能导致既有上传内容被遗弃，或永久保留两个可见根目录。

## 决策

本地提供方使用 `<runtime HOME>/documents` 作为默认根目录。个人运行时因此把文档存入用户私有主目录，项目运行时则存入 `<project path>/documents`，因为项目路径就是该运行时的主目录和工作目录。网关在创建个人用户时建立该目录；对于既有用户、独立运行时和项目，提供方在首次使用时惰性创建。

本决策扩展[把用户上传文档存为真实文件](2026-08-14-user-uploaded-documents.zh.md)。文件系统仍是索引：文件夹是普通目录，文档是普通文件，模型继续使用同一套文件系统和 shell 工具，而不是文档专用取回工具。

### 存储与迁移

`LocalUserDocFs` 在第一次存储操作时初始化，并合并该引擎的并发初始化。独立引擎和进程通过 atomic-write 共享的持有者记录锁串行执行迁移。新建但尚未完整写入的持有者记录不能被解释为进程不存在；只有完整记录且已证明进程退出时才允许接管。获取锁的等待有界，初始化失败后可以重试。如果 `<home>/uploads` 不存在，初始化会创建 `documents`；如果 `documents` 不存在，迁移会直接重命名整棵 `uploads` 目录树；如果两者都存在，迁移会递归合并且不替换任何条目，冲突项使用与上传相同且有上限的 ` (2)` 后缀。不受支持的旧条目、相互重叠的根目录和符号链接形式的旧根目录都会以 `DOCUMENT_MIGRATION_FAILED` 失败。

迁移成功后会删除旧根目录，且不保留兼容符号链接。因此，迁移前记录的绝对路径可能不再解析，但对应文件仍位于 `documents` 下相同的相对位置。这属于预发布阶段接受的磁盘格式变更，而不是永久维护双根目录的兼容承诺。

### 操作与归属

`UserDocId` 与 `UserDocDirectoryId` 是相对于单个文档根目录、采用 POSIX 风格路径的品牌类型；空目录 id 表示根目录。提供方在读取或修改条目前都会重新推导词法路径并证明真实路径仍在根目录内。列举、上传、移动和读取都不会跟随目录符号链接。

除既有文档操作外，`UserDocStore` 还提供直接子目录列举、递归目标目录列举、文件夹创建与重命名、空文件夹删除和文档移动。移动不会替换已占用名称，文件夹删除也绝不递归。重命名目录或移动文档会改变其根相对 id 和绝对路径，因此旧引用可能失效，与普通文件在 UI 外被重新组织时相同。

受管身份存储先把所选目录捕获到受保护的保留对象根下，再发布新的普通路径。日志同时记录所选目录对象和完整的已授权文件清单；仅凭移动后的标记不能确定目录身份。捕获和发布都在保留父目录的情况下使用原生排他改名。被替换的源条目排他返回原位置；位置被占用时保留私有副本和两个失败原因。持久捕获证据区分尚未发布的意图与重启后结果不确定的发布。缺少目录对象证据的第 2 版意图，在已知源或目标得到核验前保持保守处理。

已接纳的文件清单在私有存储中核验。发布后，目录对象证据标识已完成的改名，原子保存、新文件、删除及子文件移动则作为后续普通观察独立对账。反复要求公开清单不变，会让正常编辑器保存之后的恢复无限失败。改名保留其发起人和原文档创建者；替代文件获得独立、未归属的文档实例。未记录目录对象的旧意图继续核验完整清单。

取消时，如果普通编辑器已把公开标记链接移到别处，提供方会保留私有标记锚点。读取、扫描和后续目录选择只回收与受保护锚点匹配的标记链接；同名用户文件仍是普通文档。经过验证的备份恢复会根据原始对象证据重建这些标记链接，使文件复制后仍保留该证明。因此重启和重新选择后可以重试，而文件名本身没有删除数据的权限。

Host 拥有 `/api/documents` 路由和稳定错误映射。浏览器管理器拥有面包屑、文件夹命令、当前文件夹上传，以及单个或批量移动。网关只在创建个人用户时预建 `documents` 目录；项目和独立运行时的根目录仍由提供方管理，因此账户管理不会在运行时真正使用文档存储之前写入外部或只读项目。

## 验证

本地提供方测试固定直接迁移、保留冲突项的合并、并发引擎串行执行、保留活跃或不完整锁记录且不修改文件、已确认退出的持有者恢复、重叠与符号链接拒绝、遍历与目录符号链接包含性、只能删除空目录，以及不替换目标的移动。Host 测试覆盖所有文件夹路由和新增错误码状态。组件与无密钥 Web 测试覆盖文件夹导航、当前文件夹上传、创建／重命名／删除、单个与批量移动，以及紧凑布局的行几何。

无密钥 Loader 快照通过组合后的文档服务和真实文件验证拒绝与重试。文件系统故障测试保证发布、源文件删除、回滚或目录重命名失败后原始字节仍然保留，并在迁移期间目标目录出现时保留两侧文档。

## 备选方案

**维护独立的迁移锁协议和进程全局 Promise 缓存。** 专用实现重复了持有者记录解析与接管协调；把不完整记录解释为持有者不存在会放入并发写入者。共享 atomic-write 锁负责这些规则，每个文件系统引擎则拥有自己的初始化 Promise，状态随运行时释放。

**永久保留 `<home>/uploads` 根目录或留下兼容符号链接。** 否决，因为产品暴露的是文档工作区，而不是上传暂存区。用两个名称指向同一棵目录树会使包含性和运维清理更复杂，而保留旧绝对路径会把预发布实现细节变成持久兼容承诺。

**在保持扁平文件系统的同时，用伴随元数据表示文件夹。** 否决，因为 agent 的常规工具会看到与浏览器不同的组织方式，而且元数据可能与 UI 外修改的文件失去同步。真实目录只保留一个真源。

**允许覆盖式移动或递归删除文件夹。** 否决，因为两种操作都可能因一次错误的目标选择而破坏文档。冲突和非空错误要求用户显式处理受影响条目。

## 影响

个人与项目文档作用域拥有可预测的真实路径，并在不同对话间独立持久存在。既有默认上传内容会在首次使用时移入新根目录，不产生重复存储，冲突时两项都会保留。

第一次存储操作可能等待迁移；旧目录树无法安全表示时会明确失败。移动和重命名会有意使旧的路径引用失效，用户必须先清空文件夹才能删除。这些代价保留了普通文件系统语义、不覆盖的修改操作和唯一可见的文档根目录。
