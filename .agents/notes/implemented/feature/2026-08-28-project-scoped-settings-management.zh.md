# Agent Note：项目作用域设置管理

Status: implemented

[English](2026-08-28-project-scoped-settings-management.md) | 中文

## Problem

项目作用域过去把整个运行时设置文档视为只读，项目 owner 和组织管理员无法管理安全的项目行为，普通成员也只能看到没有解释的禁用控件。账户偏好、项目策略、模型凭据和服务器文件系统操作分别属于不同所有者，却共用一条展示路径。

## Decision

设置注册现在声明逻辑所有者和明确的项目管理员写入标记。Gateway 在项目作用域只暴露项目安全的 namespace；项目 owner 和组织管理员可以写入标记为 `projectWrite: manager` 的 namespace，账户、组织、部署以及未标记的项目 namespace 仍保持只读。账户语言、主题和忙碌时 Enter 偏好使用 PostgreSQL 账户行、revision 校验和旧设置文件惰性迁移，因此用户处于项目作用域时仍能写入自己的私有偏好。

用户前端拥有项目设置入口。每位项目成员都可以打开项目设置面板，查看项目 owner、管理状态、可用能力和仅限 `/admin` 的文件系统边界。owner 和管理员操作会进入共享的插件、Agent 预设和模型页面；不可用能力与只读归属使用行内说明，而不是只显示禁用控件。项目 Provider 配置与加密凭据使用按项目隔离的 PostgreSQL 存储、已有的 Provider 编辑器和 schema 操作，以及项目 revision 栅栏。成功 mutation 后会刷新项目模型治理策略；浏览器响应不包含项目凭据值，凭据只能通过项目 API 写入。

运行时凭据请求通过服务对象调用选定的治理方法，因此项目解密状态在分派期间保持绑定。

Gateway 项目路由在读取当前成员资格时一并取得管理权限和主题策略，代理复核使用同一授权读取。每个 Runtime 请求读取完整项目成员目录会增加远程电脑的数据库往返次数，而缓存权限会延迟撤权生效。授权投影移除这些详情读取，同时保留当前账户、电脑、项目及成员资格检查。

管理员控制台仍是服务器目录、挂载、生命周期、额度、组织模型治理和成员覆盖规则的权威来源。项目详情页展示配置归属，并提供安全链接以项目作用域进入用户前端；它不复制项目逻辑设置。项目凭据和策略写入会先获取项目配置锁，再获取 Provider 行锁，确保并发编辑、凭据轮换和删除使用一致顺序。

管理写入将认证参与者传入所属服务事务。账户及组织成员共享锁先于项目锁获取，与成员变更使用相同顺序；当前项目所有者、组织可用状态及维护空间资格共同决定准入。Provider 与凭据变更在此之前获取[组织模型配置锁](../bug-fix/2026-10-29-model-administration-authority.zh.md)。保留的账户与项目锁防止角色或所有者变更在提交前使已接纳的数据库变更失去权限。过期的浏览器视图不能授权名称、主题、Provider 或凭据变更。模型发现在同一权限下准备与端点匹配的凭据，并在目录探测前释放数据库连接。浏览器传输始终提供认证参与者；服务调用省略参与者时允许受信任的内部维护。

项目模型响应在配置、凭据状态或目录数据准备完成后复核认证读取者。一次 PostgreSQL 快照检查当前组织、账户、强制改密要求、组织及项目成员资格、目标电脑授权、有效挂载和维护空间资格。其当前管理标记决定设置与凭据字段能否编辑；模型发现要求该标记为真。该读取校验不加载节点元数据，目录 HTTP 请求期间不占用数据库连接。所有权转移后，其他条件仍有效的成员获得只读视图；账户、成员资格、项目或电脑权限撤销时，不返回已准备的数据。已提交写入保留其变更响应。

项目管理准入在项目及权限等待之后检查[改密资格](../bug-fix/2026-10-28-user-administration-authority.zh.md)。在准入前提交的重置会拒绝新的设置、凭据、主题和名称写入；已经获准的变更保留其完成结果。

管理员成员覆盖操作在所属事务内要求当前有效的组织管理员角色；项目所有权不授予该权限。目标账户先于项目锁保留，使操作继续与账户删除串行化。认证管理员路由传入服务端选定的参与者。带类型的权限拒绝返回403并生成失败尝试审计；它们不会发布成员失效通知或应用目录授权。

浏览器项目元数据在准备完成后，使用[当前项目读取权限](../bug-fix/2026-11-05-project-read-publication.zh.md)发布。其能力标志采用该读取返回的管理权限。

## Alternatives considered

**让所有 `rw` 成员都能写项目设置。** 目录写权限不等于共享运行时或凭据管理权限，这会让任意贡献者修改所有成员的行为。显式 namespace 所有权可以把授权范围保持在最小程度。

**把所有项目配置留在运行时设置文件中。** 运行时文件是共享且属于单个实例，而项目 Provider 凭据需要跨进程持久所有权和加密。Gateway 项目存储提供单一事实来源，同时不暴露秘密值。

**重新实现一套项目 Models 编辑器。** 复制 schema 解析和 Provider 表单会让个人与项目兼容性逐渐分叉。项目 transport 适配已有编辑器，因此两种作用域共用字段和校验词汇。

**把项目逻辑控件放进 `/admin`。** `/admin` 专门处理服务器资源，普通项目 owner 不能使用。通过认证的用户前端路由逻辑设置，可以复用运行时自身的作用域和成员检查。

## Consequences

项目管理员获得范围明确的运行时、预设、主题和 Provider 控制，但不会获得宿主机路径访问或任意设置写入权限。普通成员可以查看同一项目面板，并理解每项禁用能力的所有者。PostgreSQL 部署需要 migration 020 至 022 以及 owner-only 的模型凭据密钥；没有账户/项目 transport 的旧主机或 fixture 会显示明确的不可用状态。共享编辑器、revision 栅栏和策略刷新扩大了跨界面测试范围，今后的项目设置注册必须主动声明所有权。
