# Agent Note: 会话头部拆分身份分区，引入状态点与元数据席位

Status: implemented

[English](2026-10-12-session-header-identity-zones-and-status-dots.md) | 中文

## 问题

会话头部把标题、标签页与每个贡献方的控件混排在同一条无差别的 flex 行里。Agent 预设以胶囊样式待在 `header.actions` 中，看起来是可点控件却不承载任何动作。会话状态不打开面板就不可见：没有任何迹象提示当前轮次正在等待交互。各贡献方触发器的视觉词汇互相打架——胶囊圆角挨着幽灵方块、14px 标签挨着纯图标按钮——且整行没有溢出策略，控件密集时可能换行或被裁掉。紧凑模式下 AppFrame 掌管的标题还会重复出现。

## 决策

头部在一条不换行的行内声明明确分区：引导内容、居中身份簇、标签页、动作区与工具区。身份簇掌管会话的语义存在——面包屑之前的 `StateDot` 状态点、面包屑链，以及新的 `conversation.session.header.titleMeta` 席位，用于非交互的身份后缀。

- **状态点镜像 `sessionDotState`。** 警告态标记等待交互的轮次，进行态标记活跃工作，空闲会话不画点。状态文案通过视觉隐藏 span 传达给屏幕阅读器；点本身保持纯呈现。
- **`titleMeta` 是身份后缀契约。** 描述"会话是什么"而非"会话能做什么"的贡献方注册到该席位，以发丝分隔线后的纯文本呈现。`ui-agent-preset` 从 `header.actions` 迁入该席位，其胶囊外观与点击暗示随之消失——这正是意图所在：它从来就不是一个动作。
- **头部控件收敛到同一词汇。** 纯图标触发器统一为 28px 安静幽灵按钮配 `--dsw-radius-md`；保留文字的控件降到 13px 字号档。工作台触发器去掉胶囊圆角，桌面确认触发器改为承载状态点的显示器字形（已确认、待确认、不可用），右侧栏展开控件并入同一几何规范。
- **承载状态的触发器挂载即读。** 桌面确认控件在挂载时按当前连接与会话绑定读取状态，打开对话框时再刷新；状态读取契约从打开时刻前移到挂载时刻——等对话框打开才读取的头部状态点什么都宣告不了。
- **任何宽度都保持单行。** `.titleRow` 设定 `flex-wrap: nowrap`；面包屑条带横向滚动且无滚动条外观，不换行。紧凑模式隐藏整个身份簇——面包屑、状态点与元数据——因为 AppFrame 已掌管手机端标题；标签页与控件保留。

## 备选方案

**标签页留在居中簇内。** 放弃：标签页是整个会话面的模式开关，不是身份文本——与标题并置居中会同时挤占两者，并破坏居中标题的视觉锚点。

**溢出换行为第二行。** 放弃：头部行高锚定整个面板的外框；可变高度的头部会让其下方的全部布局重排。让面包屑条带内部横向滚动，优先降级的是身份信息，外框永不降级。

**只改预设胶囊样式不迁移席位。** 放弃：问题在席位而非外观——`header.actions` 里一个惰性元素读起来就是坏掉的按钮。

## 影响

新贡献方按意图选择席位：身份文本进 `titleMeta`，控件进 `actions` 或 `utilities`，这一区分从约定变成结构。在头部呈现实时状态的触发器组件必须预算一次挂载期的状态读取（按连接与会话绑定键控），而非打开期读取。`titleMeta` 席位已进入 `ConversationSessionHeaderSlotProps` 类型，消费方直接对其编译；工作台面板头部抑制重复的身份外框，因为父行已承载。
