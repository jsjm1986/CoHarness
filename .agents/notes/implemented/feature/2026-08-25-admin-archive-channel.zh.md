# Agent Note: Admin 归档频道与 Gateway 生命周期索引

Status: implemented

[English](2026-08-25-admin-archive-channel.md) | 中文

## 问题

运行时的归档成员关系只保存在各自的 Workspace 注册表中。普通 Web 客户端会有意隐藏这些会话，也没有恢复或管理入口，因此组织管理员无法跨个人与项目运行时查找、查看、恢复或清理归档对话。

## 决策

**Gateway 拥有组织级归档生命周期索引，各运行时保留本地 Workspace 投影。** Admin SPA 提供按根对话展示的归档频道，支持服务端筛选、分页事件阅读器、导出、批量恢复、可配置 30 天回收站以及显式永久清理。运行时用单调 revision 和原 Workspace 位置发送快照；Gateway 命令在所属运行时确认前保持待处理。项目正文从 PostgreSQL 读取；个人正文在打开时按需启动所属运行时读取。

即使个人日志不在 PostgreSQL，索引也保留根记录，因此旧 JSONL 运行时可以先回填元数据而不复制完整日志。搜索只保存标题、Session ID 以及用户／助手正文。管理员查看、导出和变更都会写入审计事件，但审计记录不保存消息正文。

## 已考虑的替代方案

**让 Admin 扫描各运行时的 `workspace.json`。** 否决：运行时可能离线，也可能由不同用户或项目账号运行，文件系统路径不是稳定的组织级 API。

**把全部会话正文复制到 PostgreSQL。** 否决：这会重复个人存储并扩大隐私与保留范围；按需读取保留现有持久化所有权。

**直接移除归档 ID，不增加 revision 快照。** 否决：现有只追加客户端合并会让旧载体重新隐藏或显示错误状态；恢复必须使用显式 revision/reset 协议。

## 后果

Gateway migration 增加归档记录、个人运行时可搜索投影和可重试命令账本。永久清理会删除项目会话行，并要求运行时持久化提供方删除个人或项目工件；tombstone 与审计记录保留。独立启动的本地 DSH 继续使用原有归档行为，不进入组织 Admin 索引。
