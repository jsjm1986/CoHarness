# Agent Note：组织 Provider 所有权与项目模型分配

Status: implemented

[English](2026-08-17-organization-model-provider-ownership.md) | 中文

## 问题

Gateway 模型目录最初只授权和计价 `(provider, model)` 路由，并不拥有 Provider 端点、协议或凭据。每个用户仍需在个人设置中配置这些字段，因此管理员无法通过一次操作让组织模型真正可用，共享项目运行时也没有独立于成员的权威 Provider 配置。若让项目运行时继承某位成员的个人 Provider 或密钥，模型可用性会取决于谁打开项目，还可能让一位成员的凭据承担其他成员的调用费用。

## 决策

**Gateway 拥有组织 Provider。** 受管 Provider id 使用保留的 `org-*` 命名空间。PostgreSQL 存储端点、协议、生命周期状态、生成的凭据引用、模型、角色/用户权限、项目权限、价格以及单调递增的组织配置修订号。API Key 值使用 AES-256-GCM 和仅所有者可读的主密钥加密，并把组织 UUID 与 Provider UUID 作为附加认证数据；管理员读取接口只暴露 `credentialConfigured`。

**管理端复用共享模型设置插件。** Gateway 管理端把 `ui-settings-models` 挂载到组织模型 REST facade，因此管理员可以通过与个人设置相同的编辑器维护完整 pi-ai Provider profile、模型列表、发现字段和只写凭据。组织凭据引用使用保留的 `DSH_` 前缀，个人 pi-ai 设置会拒绝该前缀，从而隔离两种所有权，同时允许组织 profile 轮换到另一个 `DSH_` 引用。

**个人运行时组合组织与个人配置。** 运行时策略通过 `ctx.modelProviderConfig` 投影已启用的组织 Provider 配置。组织模型授权遵循角色默认值与用户覆盖。个人 settings user 层还可以按[模型治理 default-deny 与用户声明路由授权](2026-08-17-model-governance-byok.md)中记录的既有规则声明 BYOK Provider。组织配置绝不进入可编辑的用户设置，个人配置也不能使用保留的 `org-*` 命名空间。

**项目运行时只使用组织 Provider。** 项目模型集合只来自显式 `model_project_access` 分配，不继承角色默认值、用户覆盖或个人 BYOK Provider。所有成员连接同一个项目运行时，因此共享一份 Provider 快照与一套项目模型权限；未分配模型一律拒绝。

**组织凭据引用独占且只读。** 治理插件注册一个随当前受管 Provider 快照变化声明范围的凭据层。它在每次模型请求时通过运行时令牌鉴权的 `/internal/runtime/model-credential` 端点解析所拥有的引用。只有运行时主体在该 Provider 上至少拥有一个已启用且获授权的模型时，Gateway 才返回值。组织引用未配置、未授权或不可用时绝不回退到同名个人存储；只要该层拥有引用，`set`/`unset` 就会拒绝。

**所有调用进入同一本用量账本。** 适配器把 Gateway 提供的密钥标记为凭据来源 `organization`，并归入公司成本。个人凭据来源仍归入个人成本。个人与项目主体共用同一套摄取、计价、额度、去重和汇总路径。

## 备选方案

**继续把 Provider 配置保存在每个用户的设置中。** 否决，因为管理操作仍需额外的逐用户步骤，项目无法获得稳定的 Provider 集合，凭据轮换也必须扩散到各个用户目录。

**把组织密钥复制到运行时 `.env` 或 `.credentials.yaml`。** 否决，因为复制机密会增加持久化明文位置，并可能让缺失的组织密钥回退到同名个人值或环境值。

**让所有模型请求通过 Gateway 代理。** 否决，因为现有适配器已经负责 Provider 协议、流式输出、重试和用量提取。按操作进行的鉴权凭据查询无需增加第二条模型传输链路，也能保留这些职责。

**在项目运行时内应用成员角色或用户授权。** 否决，因为共享进程无法按连接成员暴露不同的适配器路由集合，否则项目行为会依赖当前身份。项目分配是项目授权的唯一来源。

## 影响

管理员只需配置一次组织 Provider 及其只写密钥，随后即可向角色、用户与项目分配模型。个人运行时可以同时使用获授权的组织模型和自己的 BYOK 模型。项目运行时只暴露显式分配的组织模型，所有成员得到一致结果。适配器按操作解析凭据，因此替换后的密钥作用于下一次请求；新增 Provider 在授权生效前先注册，移除 Provider 在授权变化后再撤下。组织密钥调用依赖 Gateway 数据库与主密钥基础设施，个人 BYOK 则仍只在个人运行时可用。PostgreSQL 集成覆盖需要 `HGW_TEST_DATABASE_URL`；缺失时凭据持久化与跨组织测试会跳过，不以进程内替身代替。
