# Agent Note：空间切换器改为随侧边栏宽度自适应的面板菜单

状态：已实现

[English](2026-10-03-scope-control-panel-menu.md) | 中文

## 问题

空间切换弹层固定在共享 `Menu` 的最小宽度上，项目名挤到第二行、旁边跟着一行说明小字，浮动框与可拖动的侧边栏边缘明显脱节。触发按钮本身已经跟随底部行宽，但菜单没有办法跟随它。

## 决定

**空间菜单测量触发按钮宽度，并渲染为单行列项的面板。**

- `Menu` 新增 `listStyle`：一个合并到 portal 计算的 `left`/`top` 之下的 `CSSProperties` 覆盖；测量与视口钳制逻辑不变，因为覆盖作用于定位代码测量的同一个元素。
- `ScopeControl` 用 `ResizeObserver` 观察触发按钮，以 `width: clamp(trigger.offsetWidth, 240, 400)` 作为 `listStyle` 传入；拖动侧边栏时无需重开菜单即随之变宽变窄。
- 空间行渲染为单行：状态圆点（当前空间使用品牌色）、名称、以及钉在行尾的模式徽标。面板上部在搜索框上方新增 `scope.menuTitle` 标题。

## 备选方案

- **使用 `--dsh-sidebar-width` CSS 自定义属性。** 否决：布局 store 目前没有发布该变量，而且从实际渲染的触发按钮取宽，测量对象始终是真正约束它的元素，包括窄栏模式和底部布局将来的变化。
- **每个空间生成色块头像。** 设计评审否决：生成的彩色首字增加了视觉重量，但对辨识没有帮助。

## 影响

`Menu` 只增加了一个可选 prop，其他调用方不变。长项目名截断而不再折行，弹层在任意侧边栏宽度下与侧边栏保持一致的视觉关系。窄栏模式的触发按钮仍把菜单钳制在 240px 下限。
