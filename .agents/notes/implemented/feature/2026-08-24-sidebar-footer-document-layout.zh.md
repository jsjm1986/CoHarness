# Agent Note: 侧边栏页脚与文档布局层级

Status: implemented

[English](2026-08-24-sidebar-footer-document-layout.md) | 中文

## 问题

侧边栏页脚把 scope、文档、退出登录和 Settings 渲染成彼此独立的 42px 行。控件虽然由不同包负责，却没有共享间距约定，因此退出登录与工作区操作具有相同视觉重量，Settings 的分组也不容易被看见。文档管理器还把筛选和变更操作放在同一个会换行的工具栏中，窄屏下不易扫描操作顺序。

## 决策

`SidebarRoot` 通过继承的自定义属性持有页脚节奏。展开页脚行使用 36px 视觉高度、统一圆角和 2px 行间距；粗指针与紧凑视口把每行提升到既有的 44px 触控热区。轨道控件仍是 36px 圆形，并使用外壳统一的轨道间距。

scope 选择器是上下文行，使用安静的层级填充和边框提示。文档与 Settings 使用扁平行。Settings 以分隔线开始独立的账户区。退出登录继续使用 Gateway 原生表单和可访问名称，但桌面端使用次要文字色和 14px 图标；悬停与聚焦时才显示危险色。轨道状态保持中性悬停样式，不会仅因为侧栏收起就显示危险提示。

文档管理器工具栏拆成筛选组和操作组，并分别处理响应式布局。桌面端两组并排，紧凑布局纵向堆叠并保留触控热区。文档行使用稳定的水平内边距和轻量悬停状态，沿用已有的操作换行规则，避免长名称把操作按钮挤出可视区域。

## 考虑过的替代方案

**只缩小退出登录行。** 这样仍会留下四套互不关联的间距系统，也无法说明哪个控件代表当前运行时。由外壳持有统一节奏后，未来新增的页脚注册项也会自动对齐。

**把所有页脚控件放进一个带填充的卡片。** 这样会让 Settings 与退出登录看起来属于同一任务组，并在侧栏中增加嵌套框面。使用分隔线可以建立账户分组，而无需再增加容器。

**只依靠 CSS 自然换行文档工具栏。** 自然换行会让刷新控件在中间宽度时落到筛选和变更操作之间。显式分组可以保持操作顺序，并让紧凑布局拥有可预测的纵向顺序。

## 结果

页脚包继续拥有各自的内容、注册顺序、表单和工具提示；它们只消费继承的几何变量，包边界不变。桌面行变短不会削弱已有的 44px 粗指针保证。文档管理器增加两个本地化分组名称供辅助技术使用，但视觉布局不增加解释性文案。

## 验证

聚焦 Vitest 覆盖页脚变量、上下文处理、次要样式的退出登录、分组后的文档工具栏、紧凑规则和侧栏快照。组装后的 Web 客户端在展开与轨道宽度（包括紧凑视口）检查裁切、对齐和长文档名称。
