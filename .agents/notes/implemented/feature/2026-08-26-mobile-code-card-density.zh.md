# Agent Note: 紧凑的移动端代码与结果卡片

Status: implemented

[English](2026-08-26-mobile-code-card-density.md) | 中文

## Problem

在手机视口中，代码和工具结果卡片把 44px 的复制热区与桌面端横幅内边距叠加，导致短的 `text` 代码块及其复制控件占据不必要的高度。同样的 chrome 模式还出现在读取、搜索、终端和差异卡片中，而网页与 JSON 卡片仍保留较大的移动端内边距和高度上限。

## Decision

共享原语卡片在 768px 以下使用紧凑的移动端几何。复制和折叠控件保留 44px 最小热区，同时移除周围横幅的桌面端垂直内边距并使用 10px 水平内边距。代码、读取、搜索、终端和差异卡片使用移动代码节奏与更小的内边距；网页和 JSON 表层使用更紧凑的手机内边距与内容上限。空围栏代码块为保持 Markdown DOM 一致性继续保留 DOM，但给外层标记，使移动端样式移除空白内容槽。

长输出仍在卡片内部滚动，桌面端几何保持不变。紧凑规则位于原语中，因此所有消费方都获得一致处理，无需为每个工具添加覆盖样式。

## Alternatives considered

**把复制控件缩小到 44px 以下。** 不采用，因为这样会违背移动端其余界面使用的粗指针最小热区约定。

**完全隐藏空围栏代码块。** 不采用，因为 Markdown renderer 的空围栏 DOM 属于一致性约定；只折叠移动端空内容区既能保留约定，也能移除视觉浪费。

**分别调整每个工具行。** 不采用，因为 CodeBlock、ReadBlock、SearchBlock、TerminalBlock 和 DiffBlock 是多个渲染位置共用的原语；局部覆盖会逐渐漂移，也会让独立 Markdown 呈现不一致。

## Consequences

短代码围栏在手机上不再预留空白内容槽，复制控件仍然容易点击。结果卡片占用更少的垂直空间，同时保留横向滚动和长输出的高度限制。显式覆盖原语 margin 或代码字体的消费方仍可通过现有的 class 级自定义属性继续覆盖。
