# Agent Note: 保持 Gateway 管理端的视觉与语言一致

Status: implemented

[English](2026-08-25-admin-ui-visual-language-consistency.md) | 中文

## Problem

Gateway 管理端页面虽然共享设计 token，却没有全部使用同一组基础组件。文档 dashboard 使用了没有对应样式的本地指标元素 class，使汇总指标塌缩成一条很薄的行。模型登记页的控件没有可见标签，日期依赖浏览器占位符，`model`／`模型` 混用，并且每输入一个字符都会发起请求。

## Decision

管理端 dashboard 统一使用共享 `Metric` 组件及其 `.metric` 状态 class。个人模型登记筛选使用带标签的响应式网格，并通过明确的“应用筛选”和“重置”提交；编辑草稿时不请求 API，只有提交后才刷新。Provider 保留为正式产品术语，面向用户的名词统一使用“模型”。数据表表头保留源码写入的大小写，不再全局强制转换为大写。管理端品牌副标题与其余中文导航统一使用“管理端”，移动导航为六个目的地各保留一个栏位。

## Alternatives considered

**为文档指标另写一套样式。** 这只能掩盖 class 不匹配，并会留下两套可能再次分叉的指标约定，因此页面改为消费现有共享组件。

**继续在每次输入时实时筛选登记记录。** 慢速网络下会产生无意义的请求，也和其他管理端筛选器不一致，因此采用草稿与提交分离，一次筛选变化只发起一次明确请求。

**把 Provider、BYOK、API 和 Token 翻译成近似中文。** 这些是运行时各处共用的产品或协议术语，因此保持稳定的技术名称；只把不一致的小写 `model` 展示统一为“模型”。

## Consequences

文档和用量页面的指标卡现在共享高度、字体、警告色和响应式行为。模型登记页在桌面、窄桌面和移动宽度下都有可预期的筛选布局，控件带可见标签，并使用可键盘操作的分段控件。用户输入期间不会反复触发登记查询，但需要明确点击一次应用筛选；六项移动导航在支持的紧凑宽度下保持单行。管理端单元测试覆盖共享指标 class 和筛选提交边界。
