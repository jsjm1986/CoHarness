# Agent Note: 保持 Gateway 管理端的视觉与语言一致

Status: implemented

[English](2026-08-25-admin-ui-visual-language-consistency.md) | 中文

## Problem

Gateway 管理端页面虽然共享设计 token，却没有全部使用同一组基础组件。文档 dashboard 使用了没有对应样式的本地指标元素 class，使汇总指标塌缩成一条很薄的行。模型登记页的控件没有可见标签，日期依赖浏览器占位符，`model`／`模型` 混用，并且每输入一个字符都会发起请求。少数 API 枚举值还会未经翻译直接显示，模型说明在桌面宽度也会留下孤立的末尾字符。

## Decision

管理端 dashboard 统一使用共享 `Metric` 组件及其 `.metric` 状态 class。个人模型登记筛选使用带标签的响应式网格，日期明确使用 `YYYY-MM-DD`，并通过“应用筛选”和“重置”提交；编辑草稿时不请求 API，日期无效时在请求前失败。Provider 保留为正式产品术语，面向用户的名词统一使用“模型”。数据表表头保留源码写入的大小写，不再全局强制转换为大写。管理端可见的 API 枚举值使用中文标签，包括文档来源和 Gateway 的 `ready` 实例状态。Gateway 自有的登录、修改密码、启动和管理端页面统一使用 `CoHarness` 产品品牌，管理端界面另加中文副标题“管理端”。模型说明在桌面宽度保持紧凑，移动端模型视图控件铺满内容宽度，移动导航为六个目的地各保留一个栏位。

## Alternatives considered

**为文档指标另写一套样式。** 这只能掩盖 class 不匹配，并会留下两套可能再次分叉的指标约定，因此页面改为消费现有共享组件。

**继续在每次输入时实时筛选登记记录。** 慢速网络下会产生无意义的请求，也和其他管理端筛选器不一致，因此采用草稿与提交分离，一次筛选变化只发起一次明确请求。

**把 Provider、BYOK、API 和 Token 翻译成近似中文。** 这些是运行时各处共用的产品或协议术语，因此保持稳定的技术名称；只把不一致的小写 `model` 展示统一为“模型”。

## Consequences

文档和用量页面的指标卡现在共享高度、字体、警告色和响应式行为。模型登记页在桌面、窄桌面和移动宽度下都有可预期的筛选布局，控件带可见标签，并使用可键盘操作的分段控件；紧凑屏幕上的模型视图控件保持单行。用户输入期间不会反复触发登记查询，但需要明确点击一次应用筛选；日期解析在本地快速失败。六项移动导航在支持的紧凑宽度下保持单行，界面不再泄漏英文枚举值。Gateway 入口页面与管理端使用同一产品身份。Gateway HTML 和管理端单元测试覆盖产品品牌、共享指标 class、筛选提交与日期校验边界、文档来源标签和 ready 状态标签。
