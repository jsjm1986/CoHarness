# Agent Note: 从管理器加入已有文档

Status: implemented

[English](2026-08-22-document-manager-attach-existing-documents.md) | 中文

## Problem

文档管理器与对话输入框使用同一个持久用户文档存储，但管理器没有提供复用已有文档的操作。即使当前范围内已经存在文档，用户仍必须再次选择浏览器文件并上传。

## Decision

对话服务提供 `IConversation.attachDocument(sessionId, ref)`。它创建一个就绪的输入框草稿，其 `docId` 指向传入的持久 `UserDocRef`，然后把草稿 id 加入会话输入 shell。草稿条目记录自己是否拥有浏览器上传产生的持久文件。浏览器上传仍保持移除时删除文件的行为；管理器加入的文档只释放输入框元数据，不会删除存储中的文档。

`ui-documents` 插件把 `attachDocument` 回调注入侧边栏操作。回调从 `ctx.sessions.list` 读取当前会话，委托给 `ctx.conversation`；没有当前会话、没有对话服务，或输入 shell 因提交而锁定时返回 false。每个文档行显示“加入对话”/“Add to conversation”；加入成功后关闭管理器，拒绝时保留管理器并显示本地化失败提示。同一个持久 `docId` 在同一会话中重复加入是幂等的。

提交提示词仍使用现有的 `{ type: 'document', docId }` 内容部件，因此管理器操作本身不会新增会话事件或模型可见输入。

## Alternatives considered

**把存储内容读取成浏览器 `File` 后再次上传。** 否决，因为这会复制持久存储，增加不必要的传输与失败状态，也让输入框草稿移除时的所有权变得不明确。

**让管理器直接访问 `InputBar` 或派发浏览器事件。** 否决，因为展示组件不拥有跨包上下文访问；对话服务才是现有的输入框变更服务面。

**持久化独立的管理器加入事件。** 否决，因为加入草稿是浏览器本地状态，用户发送消息时已有文档 id 会被记录。

## Consequences

存储中的文档可以从管理器进入当前输入框，无需再次上传。移除这种草稿不会再误删可能被历史消息引用的文档。该操作要求存在当前会话，且输入框不处于提交接纳阶段；任一条件不满足时，管理器显示本地化失败提示。对话公共服务面新增一个供文档插件使用的、按会话寻址的变更方法。

## Verification

对话编排测试覆盖就绪草稿投影、持久 id 保留、重复加入幂等性，以及移除时不删除持久文件。文档管理器组件测试覆盖行操作、成功关闭回调和失败提示。包级与 Web GUI 检查覆盖组装后的操作和本地化文案。
