# Agent Note：跨作用域文档目录与工作台

Status: implemented

[English](2026-08-24-cross-scope-document-workbench.md) | 中文

## 问题

文档只存在于当前运行时，Gateway 复制路径也只知道个人到项目。因此项目到项目复制、按所有权控制变更、全部作用域元数据、可靠谱系和独立管理员视图都没有持久化权威来源。

## 决策

Migration 011 增加组织级元数据目录、操作条目和追加式历史。运行时根目录继续拥有文件字节与路径。主机文档路由在列举和写入后同步元数据，签名的 Gateway 运行时路由从认证运行时身份推导当前作用域。项目所有权未知时，破坏性变更拒绝执行。

复制 broker 接受已授权的个人/项目作用域组合，包括项目到项目。短期元数据计划在提交时消费；重试会重新校验权限，并保留逐文件结果。目标文件夹通过目标运行时列出或创建，管理员多目标分发只允许组织管理员。浏览器的全部作用域视图只收到元数据，预览内容前必须进入作用域或创建快照。

Web 管理器改为全高覆盖层，提供作用域侧栏、仅元数据概览、目标文件夹复制流程和当前作用域历史。Admin 增加独立文档路由，提供指标、筛选表格、谱系/历史详情、所有权转移和带明确确认的元数据删除。

## 曾考虑的替代方案

**保留每个运行时的内存目录。** 否决：进程重启后数据消失，无法支持组织级 Admin 视图，也无法跨项目审计所有权和谱系。

**把其他运行时的路径暴露给浏览器。** 否决：路径不能跨运行时移植，会把元数据选择器变成跨作用域文件泄露通道。

**在作用域之间实时同步文件。** 否决：它会引入模糊的所有权和冲突语义，而需求只需要个人到协作空间的明确工作流；复制应当是显式快照。

## 后果

历史文件在运行时列举到目录时惰性归档，并保留历史标记。目录暂时不可用不会阻塞普通上传，但项目破坏性操作在所有权同步前会拒绝。快照复制不会变成实时链接。Migration 011 之后的版本才是有效回滚目标，因为旧版本无法理解新 schema。

## 验证

Gateway 复制/目录聚焦测试、主机文档测试、客户端文档测试、Admin UI 测试与构建、全仓类型检查和契约 lint 已在本地通过。未设置 `HGW_TEST_DATABASE_URL` 时 PostgreSQL 集成测试按既有策略跳过。
