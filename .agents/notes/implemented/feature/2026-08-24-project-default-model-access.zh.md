# Agent Note: 项目默认模型授权

Status: implemented

[English](2026-08-24-project-default-model-access.md) | 中文

## Problem

项目模型授权过去只由单模型记录表示。新建项目没有任何记录，管理员必须打开项目逐个分配模型后才能使用组织模型；这种表示也无法让已经启用默认规则的项目自动跟随组织目录中新加入的模型。

## Decision

项目保存 `model_access_default_allowed` 标志。新项目把该标志设为 `true`；迁移前已经存在的项目保留 `false` 默认值。项目策略解析先读取单模型记录，再读取项目默认标志，因此默认开启的项目会自动授权新加入的组织托管、未归档模型，而单模型 `false` 记录仍然是拒绝例外。Provider 和 model 的启用状态仍然决定最终路由是否可用。

管理员的“全部”操作切换项目级模式并删除项目显式记录。“全部开启”启用目录跟随；“全部关闭”记录明确关闭状态。单模型控件在默认开启时写入 `true` 或 `false` 例外，在关闭模式下恢复继承时删除记录。凭据解析使用与策略投影相同的有效规则，因此默认授权既作用于界面，也作用于实际组织模型请求。

SQLite schema 同步保存该项目标志，以保持迁移与导入一致。运行中的 PostgreSQL Gateway 负责项目运行时实现；个人 Provider/model 仍由个人 BYOK settings 控制，不会因为项目默认标志而放行。

## Alternatives considered

**创建项目时为每个模型插入允许记录。** 不采用，因为每次组织新增模型都需要扇出写入或触发器，而且无法区分从未配置的项目和明确“全部关闭”的项目。

**把缺少项目记录解释为允许。** 不采用，因为删除记录是现有的“清除例外”操作，这样会无法表示“全部关闭”，除非再引入第二套隐式例外系统。

**只对用户发起项目默认授权。** 不采用，因为产品策略要求所有新建项目使用同一默认规则，不区分管理员还是用户创建。

**回填已有项目。** 不采用，因为必须保留管理员已经作出的决定；迁移为旧项目设置关闭默认值，只改变之后的新建项目。

## Consequences

新项目立即可以使用组织目录，目录新增模型无需逐项目维护。管理员仍可拒绝单个路由或完全关闭项目。项目访问 API 单独返回项目模式，而运行时策略继续使用始终为 `false` 的全局 fallback，保持目录外路由 fail-closed。既有项目有意保持不变，需要显式执行“全部开启”才能加入自动跟随。

## Verification

SQLite schema 与项目创建测试覆盖新列和版本 7 升级。PostgreSQL suite 覆盖 migration、项目服务、项目策略、模型新增、显式拒绝、全部开启/关闭和凭据解析。Admin UI 测试覆盖生效计数、目录跟随提示和拒绝例外。
