# Agent Note: 可扩展的项目空间选择器

Status: implemented

[English](2026-08-25-project-scope-picker.md) | 中文

## 问题

个人／项目 scope 菜单会一次渲染全部项目行。成员项目持续增加后，菜单可能占据大部分视口，选择项目也需要扫描完整列表。紧凑布局还需要在不让操作被手机键盘或安全区遮挡的前提下，提供相同的搜索和滚动行为。

## 决策

`ScopeControl` 在存在项目成员关系时提供本地化的项目名称搜索框。筛选只作用于打开的菜单，个人空间和项目管理操作仍然可用；没有匹配项时显示明确的空状态；菜单关闭或项目列表变空时清除查询。已有的 scope 选择标记和待用可见性勾选仍然是菜单的选择标记。

共享 `Menu` 原语接受不滚动的 `header` 内容和用于列表几何的 `listClassName`。空间控件把列表限制为 480px，并进一步按视口收缩；条目视口独立滚动，项目管理操作固定在 footer。768px 以下菜单使用共享的安全区手机 Sheet；条目视口仍是唯一滚动区，搜索和清除控件扩大到统一触控热区。Sheet 已有的视觉视口高度变量会让列表保持在屏幕键盘上方。

## 考虑过的替代方案

**让项目列表不设上限，依赖浏览器页面滚动。** 不采用，因为 portal 菜单可能覆盖侧栏，并把创建／成员操作推到不可达位置；局部滚动区能保持锚点交互。

**用单独的项目管理弹窗替代菜单。** 不采用，因为 scope 切换是轻量选择操作，引入弹窗会为同一组条目增加第二套呈现和关闭模型。

**只增加搜索而不限制高度。** 不采用，因为搜索能帮助定向选择，却不能保护浏览项目列表的用户，菜单仍会随项目数增长。

## 结果

大型项目列表保持有界，也可以按项目名称收窄；个人空间、当前选择标记、可见性选择和管理操作继续保持原有语义。原语新增的 header 与列表 class hook 可以复用于其他锚定列表，手机消费方继承相同的 Sheet 安全区和键盘处理。搜索文本是临时界面状态，不会持久化或发送到 Gateway。

## 验证

组件测试覆盖筛选、空结果、清除／重置、保留个人空间和固定管理操作。原语测试覆盖 header 位置与列表 class。样式测试固定空间菜单高度上限和紧凑触控热区规则。组装后的 Web replay 固定桌面菜单与手机 Sheet 的结构；聚焦的 collaboration 与 primitive GUI suite 已通过。
