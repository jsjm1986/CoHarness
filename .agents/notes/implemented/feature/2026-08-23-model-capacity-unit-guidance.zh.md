# Agent Note：模型容量单位说明

Status: implemented

[English](2026-08-23-model-capacity-unit-guidance.md) | 中文

## 问题

模型设置卡片中的 `contextWindow` 与 `maxTokens` 都按 token 数保存，但字段标签没有说明单位，也没有解释十进制 `K`／`M` 后缀。`1M` 与 provider 返回的 `393216` 并列时，精确 token 数看起来像使用了另一种单位。这两个字段的含义也不同：上下文容量覆盖请求，输出上限限制生成。

## 决策

模型编辑器在两个字段标签中加入 `（token）`，并在每个展开行提供可见且可访问的统一说明。说明明确支持纯整数和十进制 `K`／`M` 后缀（`K` = 1,000，`M` = 1,000,000），空字段继承提供方默认值，上下文与输出限制相互独立。现有解析器、正整数校验、最短往返显示和 JSON 数值存储保持不变，因此 `393216` 这类不是 1000 整数倍的 provider 值仍保持精确。

DeepSeek 模型目录编辑器和 pi-ai 模型列表编辑器共用同一份文案和 `aria-describedby` 关系。错误文案与 README 约定也使用相同的单位词汇和示例。

## 曾考虑的替代方案

**将所有值转换为二进制 `Ki` 单位**：不予采纳，因为现有公开解析器和已保存设置使用十进制 `K`／`M`，改变解释会静默改变已有配置。

**把 provider 值四舍五入为友好后缀**：不予采纳，因为 `393216` 与 `384K` 是不同的 token 预算；界面不能为了显示而改变 provider 的精确限制。

**只显示原始整数**：不予采纳，因为 `1000000` 等大数不易扫描，而卡片已经支持安全且可逆的缩写。

## 验证

专项组件测试覆盖十进制后缀解析、非整千值的精确显示、可见说明，以及两种编辑器的可访问描述关联。样式 token 测试覆盖新的帮助规则。软件包 README 配对和 Agent Note 配对由文档门禁检查。

## 后果

用户无需猜测容量值是字节、字符、十进制单位还是二进制单位，即可填写和理解模型容量。传输与持久化格式仍是正整数 token 数；上下文容量与输出预算之间的实际 provider 兼容关系仍由部署配置负责。
