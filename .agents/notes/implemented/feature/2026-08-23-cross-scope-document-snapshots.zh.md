# Agent Note：跨作用域文档快照

状态：已实现

[English](2026-08-23-cross-scope-document-snapshots.md) | 中文

## 问题

个人文档与项目文档属于不同的运行时进程，文档 id 也只在所属存储中有效。跨进程传递路径或实时引用会绕过运行时文件系统策略，并使后续提示词重放依赖外部存储。

## 决策

跨作用域文档使用显式的 v1 Gateway broker 操作。请求声明个人或项目的源和目标，但当前运行时必须是其中一个端点。个人到项目要求项目 `rw` 权限；项目到个人要求项目读取权限；项目到项目以及同作用域复制均拒绝。

Gateway 通过 loopback 运行时端点打开源文档，再把响应直接流式写入目标运行时上传端点。浏览器只收到安全的逐文件元数据，不会收到源文件字节。目标存储重新解析文件名，冲突沿用非覆盖后缀策略。每个文件独立提交，单个失败不会撤销之前成功的复制。

应答与审计记录携带 transfer id、源和目标的安全作用域名称、源文档 id/名称、目标文档 id/名称、字节数和结果码。绝对路径与内部运行时 id 只保留在 Gateway 审计详情中。请求和应答都带版本号，为后续协议升级保留明确入口。

文档 HTTP consumer 对列表、读取、上传、文件夹操作、移动和删除统一执行项目成员模式检查。项目协作授权缺失时以授权服务不可用的方式 fail closed。Web 文档管理器可以把选中的文档复制到可写项目或个人存储；成功的目标引用可以作为不拥有文件的草稿附加到当前会话，移除草稿不会删除复制后的文件。

broker 还提供只含元数据的其他作用域列表和能力投影。其他作用域的行不能通过当前运行时预览、下载、移动或删除，只能在获得授权后选择并复制快照。

## 验证

Host 文档测试覆盖个人行为、项目 `ro` 读写 ACL、协作服务缺失、传输元数据转发和路由错误。Gateway 测试覆盖个人到项目、项目到个人的流式复制、只读拒绝、非法及不支持的作用域、逐文件失败隔离、安全元数据和运行时 principal 校验。Client 测试覆盖目标选择、复制结果和附加到 composer。

## 考虑过的方案

**在运行时之间共享实时路径或文档 id。** 放弃，因为 id 只属于单个存储，路径会绕过目标运行时的文件系统策略。

**让源字节经过浏览器。** 放弃，因为这会把项目内容暴露给客户端数据面并重复缓冲；Gateway 已经能认证访问两个 loopback 端点。

**维护实时同步。** 暂缓，因为它需要冲突解决、源删除语义和另一套持久事件协议；v1 只需要带明确提交点的快照。

## 结果

复制是不可同步的快照，不提供实时联动。源作用域后续修改不会影响目标，源不可用时目标仍可使用。跨作用域操作依赖 Gateway；普通个人文档上传在 standalone composition 中继续可用。
