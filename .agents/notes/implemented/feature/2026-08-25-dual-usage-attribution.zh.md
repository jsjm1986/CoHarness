# Agent Note: 分离账务归属与项目活动归属

Status: implemented

[English](2026-08-25-dual-usage-attribution.md) | 中文

## 问题

共享项目的模型调用由项目运行时承担账务，而管理员用户表按个人运行时归属统计。因此项目成员实际使用模型时，个人用量仍可能显示为零。把项目总量复制给每个成员又会重复计算组织 Token 和成本。

## 决策

用量始终只保留一个账务主体：个人运行时使用 `user_id`，共享运行时使用 `project_id`。新记录在能够从模型请求中的已认证 participant 元数据确认时，额外保存 `actor_user_id`；Gateway 会先把 participant 的项目 ID 与项目 intake 主体核对。actor 只用于贡献者活动报告，不参与额度或账务汇总。无法可靠确认 participant 的请求保持未归属。

历史项目记录不回填。它们继续作为项目历史记录单独展示，与已确认的贡献活动分开。新 actor 在 intake 阶段无法验证时，运行时会用同一账务事件去掉 actor 字段重试，保留项目总量并将活动留为未归属。价格覆盖状态独立记录，因此缺少价格的调用不会被显示为免费。

## 曾考虑的替代方案

**把每次项目调用归给对话创建者。** 不采用，因为协作者可以参与创建者拥有的对话，创建者不一定是实际调用者。

**把项目用量连接到全部项目成员。** 不采用，因为每次调用都会被复制，Token、成本和额度都会膨胀。

**用最近的 participant 消息推断所有历史 actor。** 不采用，因为 fork、后台任务、重试和旧日志无法可靠提供一一对应的请求发起人。

## 后果

管理员界面必须分开标注个人、项目和贡献者总量，不能把贡献者行加到账务总量。历史未归属用量保持可见而不被静默分配。用量 wire 和 PostgreSQL schema 增加可空 actor 与价格状态字段，因此旧运行时仍可上报账务用量，但不会产生贡献者归属。
