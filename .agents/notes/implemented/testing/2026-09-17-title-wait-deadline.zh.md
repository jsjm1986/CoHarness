# Agent Note: 标题等待的截止诊断

Status: implemented

[English](2026-09-17-title-wait-deadline.md) | 中文

## 问题

Vitest 的 `waitFor` 在首次异步回调直到截止时间仍未完成时返回通用超时。标题等待期限较短时，读取持久日志可能因此丢失会话专属诊断。

## 决策

标题等待保留原轮询间隔、截止时间及标题顺序判断。观测错误初始为会话专属诊断，并保留后续读取、解析或条件判断错误。外层拒绝报告该观测错误，独立截止计时器仍由 Vitest 管理。

## 替代方案

增加超时只能掩盖慢读取，不能修复诊断。只在读取返回后检查截止时间无法终止被阻塞的等待。替换 Vitest 轮询会引入不必要的计时器管理。

## 后果

真实启动的 fake ACP 子进程发布提前出现的标题；受控读取闸门让第一次匹配日志读取超过原有 20ms 期限。修复前回归返回通用错误，修复后与普通读取对照一同通过。测试在 finally 释放闸门。完整 harness 文件 63 项测试、包级编译和局部 lint 通过。未改变模型可见输出，因此无需更新应用转录。其他持久化等待和全量测试中的 Python 失败不属于本次修复。截止时间不会取消在途文件读取。
