# Agent Note: 现有部署延迟采样

Status: implemented

[English](2026-11-17-existing-deployment-latency-sampling.md) | 中文

## 问题

本机启动的多电脑夹具可以复现传输延迟，却不能证明已部署节点、存储或浏览器的延迟。把夹具端口当成目标设置，可能启动竞争服务。定期资源采样也不等于已完成的用户操作测量。

## 决策

[手工采样器](../../../../scripts/existing-deployment-latency/README.zh.md)通过明确的私有坐标访问已有且获授权的个人 Runtime。计划模式不执行网络、认证或浏览器操作。执行要求 `--execute`、已经就绪的分配、独占测量窗口和合成测试历史。它复用浏览器启动器与点击时钟，不导入应用夹具。

新建、历史打开和持久发送的记录彼此独立。发送只有经过版本化持久准入路径，并且 Session、应用请求和 RPC 响应身份匹配时才算成功。浏览器事件耗时、驱动开销、回答可见和轮次完成分别记录。结果未知时停止后续写入，不自动重发、取消或清理数据。

## 考虑过的替代方案

**把合成夹具耗时当成部署证据。** 夹具没有覆盖真实节点及存储路径，因此保留回归验证用途，不能替代部署测量。

**重试失败样本直到凑够成功数量。** 这会隐藏失败，还可能重复结果不确定的写入。报告保留原始失败尝试和未执行的剩余数量。

**只测量 API 成功或本地回显。** 两者都不能证明持久受理或浏览器何时可用。采样器分别保留这些终点。

## 影响

默认每项操作最多尝试五十次，分别报告 P50、P95、失败和超时。专用测试 Session 保留以便检查。驱动端要求 POSIX 私有文件和已就绪的个人 Runtime；共享项目、冷启动、原生 Windows 驱动端 ACL 及崩溃恢复不在此采样器范围内。离线测试验证计划、目标限制、回执关联和统计；引用耗时前仍须实际执行部署测量。已有合成性能及准入说明继续有效，其回归与产品语义独立于此工具决策。
