# Agent Note: 有界 Gateway 观测与离线基线

Status: implemented

[English](2026-10-23-gateway-performance-observation.md) | 中文

## 问题

一个 Gateway 承接大量浏览器连接时，需要先取得请求并发、延迟、事件循环和内存证据，再校准节点容量。保留每个计时样本会让观测本身随流量增长。将 WebSocket 存活时间混入普通 HTTP 响应会掩盖 API 延迟，而仅测 handler 结束时间又会漏掉流式响应交付。隐含使用合成认证、或与发压端共享 CPU 的基准不能证明生产 PostgreSQL 或多人容量。

## 决策

[进程观测器](../../../../gateway/src/performance-observer.ts) 保存总量计数及三个固定分类：`http`、`internal` 和 `websocket`。HTTP 包含下载；WebSocket 时长覆盖完整 socket 生命周期。`observeResponse()` 计数至响应 `finish` 或提前 `close`，结算时移除两个监听器，并单独记录中断。`beginRequest()` 为 socket 及外部拥有的生命周期提供幂等完成回调。错误计数包含 5xx 响应及中断；4xx 响应另行计数。路由、用户、Session 和文件系统值均不成为指标标签。

请求时长使用从 1 ms 到 60 秒的十五个固定上界，再加一个溢出桶。每份累计快照包含 schema 版本、以单调时长推进的墙钟起点、分类计数、总时长、最大值、溢出次数和非累计桶计数。`p50Ms`、`p95Ms`、`p99Ms` 是桶上界估计；分位落入溢出桶时使用已观测最大值。它们不是精确延迟样本。相同测量起点的快照差分能够得到区间次数、总时长和桶计数。累计最大值、并发峰值和分位数不能通过相减得到区间值。

Node 原生事件循环延迟直方图和事件循环利用率覆盖观测器生命周期。进程内存在读取快照时采样。Runtime 容量由其所属服务提供，数据库观测仍由 Gateway 装配层拥有。禁用观测时不安装请求监听器或原生采样器。释放会禁用采样器、拆除待决响应监听器，并冻结请求计数、时长和利用率；未完成操作在释放时仍显示为在途。观测器不添加上报定时器或 HTTP 路由。[Gateway 服务器](../../../../gateway/src/server.ts) 拥有经过管理员认证的路由及其 `no-store` 响应。

[计数器诊断](../../../../gateway/tests/performance-observer.perf.ts) 在相同固定同步操作上交错禁用与启用观测，以 JSON 输出每个原始样本。它测量源码执行，不包含 HTTP 监听器和异步采样器调度。[HTTP 诊断](../../../../gateway/scripts/performance-baseline.ts) 经真实 `createGatewayServer()` 入口交错运行两种模式，消费每个响应体，并同时报告独立客户端样本与测量区间前后的累计快照。其私有监听器绑定 loopback 端口零；临时文件、客户端 keep-alive socket 和服务器生命周期均有等待完成的清理。CLI 不接受部署 URL。

HTTP 工作负载包含 50,000 个请求、并发 20、预热 20,000 个请求，每种模式采样三次。每十个请求有一个读取存活状态，其余经过固定认证、principal 和个人 scope 路由，取得合成的 4,887 字节 runtime 响应。`source` 标识源码诊断。`built` 导入编译后的 Gateway server 和 observer，不回退源码；CLI 和 fixture 仍是源码编排。认证、存储及 runtime 输出采用显式替代项。固定闭环发压端与服务器处于同一进程，因此两种模式均不证明开环容量、300 用户行为、AI 并发、PostgreSQL 成本、浏览器交互、WebSocket 扇出、隧道开销或模型延迟。

[Session 基准](2026-09-04-session-open-performance-gate.zh.md) 和[浏览器预算](2026-09-06-frontend-performance-budgets.zh.md) 保留各自独立的工作负载、计时和校准决策。本观测机制不取代其中任何一项。

## 已考虑的替代方案

**保留每个请求的样本或标签。** 不予采纳，因为内存及基数将随流量或账户数据增长。固定分类及桶使保留的计时数据不随已完成请求数增长。

**测量 HTTP handler promise。** 不予采纳，因为下载及代理流可以晚于 handler 结束。响应完成和 socket 关闭覆盖实际传输生命周期。

**将本地吞吐诊断当作容量门禁。** 不予采纳，因为固定外部服务替代项和同机闭环发压端遗漏了主要生产资源及排队路径。容量验收需要独立负载机、工作负载混合及部署链路。

## 后果

诊断将本地观测成本与应用容量区分。观测器的已完成请求存储保持固定；监听器保留量随当前观测的 HTTP 响应数量变化，在响应完成或释放时清理。直方图以分位精度换取有界存储，长时间运行的累计值需要通过区间差分分析近期流量。计时脚本没有性能通过/失败阈值，也不引入容量结论或 CI 校准。

## 验证

聚焦观测器测试覆盖同时进行的分类、桶边缘及溢出、重复完成、禁用状态、累计快照独立性、响应中断以及晚到完成前的释放。HTTP fixture 验证两种模式完成响应次数及字节相同、所有响应体均被消费、完成后不存在待决测量请求，以及监听器关闭。计时测量保持为显式诊断；报告观测开销时必须提供原始 JSON。功能测试耗时不构成校准证据。
