# Agent Note：将有状态 Web 快照套件隔离到独立进程

状态：已实现

[English](2026-09-05-web-snapshot-process-isolation.md) | 中文

## 问题

长时间运行的 Web 快照门禁在同一个 Vitest 进程先运行其他文件后，会间歇性地让有状态套件失败。同一批套件单独运行时通过，而 CI 每次失败的文件集合会变化。

## 决策

`scripts/run-web-snapshots.ts` 在有界并发池启动前，使用独立 Vitest 进程运行有状态浏览器套件。隔离集合覆盖会在长场景中保留浏览器、会话、回放或布局状态的套件；其余套件继续使用现有并发池和 worker 限制。

## 结果

每个隔离套件会增加一次进程启动开销，但它的模块状态、环境恢复、浏览器生命周期和回放游标不会泄漏到其他套件。只有在单独运行成功且完整门禁显示进程间干扰时，才应将套件加入隔离列表。

## 曾考虑的替代方案

**提高浏览器超时或重试失败断言。** 不采用：失败文件会在运行之间变化，而同一套件单独运行时通过；重试会掩盖进程状态泄漏。**让整个 Web 门禁继续共用一个进程。** 不采用：这会保留导致非确定性失败的共享模块状态和环境状态。

## 测试

受影响的套件在干净工作树中一起运行通过。必须重新运行完整 Web 快照门禁，验证托管 runner 上的进程拆分。
