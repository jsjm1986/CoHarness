# Agent Note: 目标停止失败后继续处理关闭队列

Status: implemented

[English](2026-09-17-stop-all-worker-failures.md) | 中文

## 问题

停止操作被拒绝可能耗尽有界 worker 池，使已跟踪的运行时仍未获得停止尝试。

## 决策

[`stopAll()`](../../../../gateway/src/instances.ts) 捕获单个目标的失败，各 worker 继续处理剩余队列，处理完毕后以自身遇到的第一个错误拒绝。外层 `Promise.allSettled` 等待全部 worker 结束，按数组顺序报告第一个被拒绝的 worker，而非全局时间上最早的错误。

## 考虑过的替代方案

**失败即退出的 worker。** 否决，因为即使关闭时间尚有余量，同时发生的失败也可能使剩余队列完全未被处理。

## 影响

停止失败仍会被报告，但不会仅因拒绝而放弃排队中的工作。systemd 仍不执行操作；[本地进程退出时的强制清理](2026-08-18-gateway-startup-resilience.zh.md)与外层关闭截止时间保持不变。截止时间到期或停止操作始终未结束，都可能阻止队列处理完毕；这不保证无限期等待并尝试所有目标。

## 测试

[实例回归测试](../../../../gateway/tests/instances.spec.ts)覆盖前八个目标失败后仍处理第九个目标。缺口：未区分 worker 数组顺序与错误发生时间顺序，也未覆盖截止时间到期或始终未结束的停止操作；未新增完整应用组装的关闭快照。
