# Agent Note：持久记忆修改的结果

Status: implemented

[English](2026-10-23-memory-mutation-outcomes.md) | 中文

## 问题

条目持久化和整理计数器位于不同记录中。条目持久化后的游标失败会把成功修改报告为失败，抛出异常的变更观察者也会如此。调用者重试时遇到的数据已与失败结果不符。

## 决定

先持久化保守的整理标记，再修改权威条目。标记失败时条目保持不变。条目写入失败可能留下额外标记，内容摘要检查会处理这种情况，不会把未改变的内容当作新工作。条目提交后通知观察者，同步观察者异常会被包含并记录警告。

## 备选方案

**回滚已提交的条目。** 补偿写入也可能失败，使已提交修订变成不确定结果。把权威修改放在最后可以避免第二次事务。

**忽略游标写入失败。** 已提交条目可能因此缺少重启后触发整理所需的持久计数。

## 影响

计数器是获准变更的上界，不是多记录事务。这种取舍允许条目写入失败后多做一次摘要检查，以保证每次已提交变更都具有整理标记。变更通知仍是提交后的观察，其诊断不能撤销持久化结果。

## 验证

创建、更新和删除回归分别注入游标失败与观察者异常。游标失败保留原数据且不发出变更；观察者异常保持成功修改结果和已提交状态。

无密钥 headless 快照针对 JSON 存储运行真实的 `memory_delete` 工具回合并注入观察者异常，验证成功工具结果与持久删除同时保留。
