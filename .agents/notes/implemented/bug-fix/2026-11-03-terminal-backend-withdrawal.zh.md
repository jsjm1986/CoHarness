# Agent Note：终端后端离开时等待未发布的启动

Status: implemented

[English](2026-11-03-terminal-backend-withdrawal.md) | 中文

## 问题

异步终端启动仍持有原生 PTY 时，后端注册可能已经撤下。仅从注册表删除类型，会允许该启动在插件停止后继续发布，也使插件无法等待回滚。

## 决策

每条[注册](../../../../packages/terminal/terminal/src/index.ts)拥有取消控制器及其未发布的启动记录。撤下只删除确切的贡献，以 `NO_BACKEND` 取消启动，并等待结算与回滚。返回的释放函数可以等待，并会报告回滚失败；并发的插件撤下与显式撤下调用方会等待同一次工作。失败的回滚仍作为所有者活动受跟踪，直到所有者或服务清理消费并报告它。

已发布的会话在后端重载后仍归属于原来的确切 Agent。替换贡献拥有独立的取消信号，所有者内的名称则在之前的启动结算后才释放。调用方取消保留原始原因。Session 删除仍可在启动完成后拒绝发布。

## 考虑过的替代方案

**只删除后端类型。** 待完成的启动可能在后端插件停止后发布终端。

**后端重载时关闭所有已发布终端。** 这会丢弃生命周期归属于 Agent 的持久会话。

**等待启动但不取消它。** 配合取消的提供方无法收到释放未发布资源的信号。

## 影响

显式等待后端撤下的消费者必须等待返回的 promise。释放会等待提供方结算，而不会遗弃其原生工作。提供方必须通过已有错误路径报告清理状态不确定。整个 Host 崩溃与平台进程约束仍由子进程提供方负责。

## 验证

真实 Loader [示例](../../../../packages/terminal/terminal/tests/fixtures/backend-lifetime.mjs)在发布前保留运行中的 Bash PTY，撤下后端，观察取消，并验证释放会等待物理进程退出。单元用例覆盖回滚失败、替换准入、名称预留、已发布会话存续和启动中的删除预留。
