# Agent 笔记：`@` 候选项持有浏览会话，行内只保留区分信息

状态：已实现

[English](2026-10-15-reference-candidate-session-retention.md) | 中文

## 问题

统一的 `@` source 在查询到达时就以裸 session id 发起两项 Remote 发现调用。它既不持有发起浏览的 Client Session，也不等待其初始历史打开，因此候选请求可能重新打开已释放的会话、与其首次打开竞争，或在会话结束后仍然存活。行内还对内容重复标注：每个文件与会话都带 `File ·`／`Folder ·`／`Session ·` 领域前缀，每个文件行重复完整路径，每个会话行在稳定 id 之外再附绝对创建时间戳，而下钻目录列表在面包屑已显示目录后仍为每行标出该目录。会话按创建时间计龄，使菜单与会话列表对同一行的"年龄"不一致；浏览会话的直接 subagent 也与普通会话混在一起排序。

## 决策

候选查询持有一个 `referenceCandidates` 会话引用。`candidates` 先检查 `sessions.binding`——未持有的会话让查询失败而不是重新打开它——随后在 `sessions.using` 内运行两项查询；该调用在请求期间持有会话，并先结算初始历史打开。在此等待期间被中止的查询会在不启动任何 Remote 调用的情况下取消。会话快照是打开的见证：`openState` 不为 `open` 时抛出已记录的错误（或普通的未打开错误），任何查询都不会启动。

行内只保留区分信息。文件仅在其父目录未在工作区根目录、且下钻列表尚未发布已表达该目录的面包屑标题时，标出父目录。会话仅在 `sameWorkspace` 为 false 时标出工作区，并借助绑定的宿主 home 做缩写；无 cwd 时回退到"（无工作目录）"文案。每个会话行都携带 `relativeTime` 给出的相对时间，按 Client 会话列表的 `updatedAt` 计龄，列表中不存在的会话回退到候选项的 `createdAt`，因此菜单与会话列表对同一行的"年龄"永远一致。直接 subagent——列表中 `origin` 为 `subagent`、且 `subagentAddress` 指向浏览会话为父级的行——在自己的"子智能体"分组标题下排在普通会话之前。

## 备选方案

**保留立即的无状态查询。** 所有生命周期风险（会话被重新打开、首次打开前竞争、请求结束后泄漏）都会保持静默；`sessions.using` 契约正是为先持有再操作的模式而存在，而 `SessionReferenceSourceMap` 合并让持有关系可审计。

**保留领域前缀的行标签。** 分组标题已经对领域分组，选中后的引用也显示领域图标，前缀只是在重复行的位置与结果已经表达的内容；路径、id 与 ISO 时间戳则是 pick 从不需要的重复细节。

## 后果

候选请求不会再复活或超出浏览会话的生命周期，历史打开期间被取消的查询也不会到达宿主。`@` 菜单与其所命名的界面保持一致：目录面包屑拥有下钻位置，会话列表拥有会话"年龄"，直接 subagent 排在普通会话之前。与本文件上游历史相邻的 `openReference`／侧栏预览面仍是相邻缺口，不属于本批范围。
