# Agent Note: Startup reads no longer race the silent resume marker

Status: implemented

English | [中文](2026-11-06-cold-open-silent-resume-marker.zh.md)

## Problem

Opening a saved session issued `/api/session.history` twice: a detached prefetch read finished before the session attached, the `Session` constructor then appended `session/end-seed` — a durable event committed before store entry, so no `session/event` observer ever saw it — and the `session/subscribed` baseline reported `session.seq - 1` past the client's window tail, forcing `repairGap` to repull the identical page for one marker. The same open flow also resumed an Agent behind the user's back — twice over. `sessions.models` called `agentFor` merely to populate the picker, and the command input source's scope-birth `warm` hook fired `commands.list`, whose `agent` parameter resolves through `agentFor`; each read-only load cold-resumed the session, appended the marker, and created the gap plus an unexpected live Agent. A fourth producer surfaced only under managed deployments: the desktop-confirmation header utility calls `desktop.status` whenever `executionAuthorityRequired` verifies true, and the RPC resolved `agentFor` before reading consent — resuming the merely-presented session in exactly the account compositions the startup spec holds cold.

## Decision

The mux `subscribe()` streams the silent suffix — durable events at or after `session.firstLifecycleSeq` that never produced a `session/event` frame — ahead of the `session/subscribed` baseline. An open client window stitches the marker live (`tail + 1`), so the baseline lands already covered and no gap repair fires. The replay lives inside the shared `subscribe()` rather than the `session/created` listener because resume-time `session/event` emissions queue their own `subscribe(seq - 1)` publishes ahead of the created publish; sessions already attached when the stream opens take the same path through `initialSessions`, so every subscription route covers the silent window once. The `session/created` publish replays up to the attach-time `seq - 1` to include enter-window appends; every other route stops at `firstLiveSeq` — the constructor window — since post-construction events either reached an earlier stream generation or are covered by the client's history read, and replaying them would push a session's whole lifecycle onto each reconnect.

`sessions.models` serves a session whose Agent is neither live nor already resuming from its durable log instead of `agentFor`: `detachedSelection` folds the events through `modelSelectionProjectionDefinition` for the pending tier and `foldRequestHeader` for the recorded request header, mirroring `selectionFor`'s tiers including the adapter-defaulted reasoning-effort omission. The subagent-ownership fence runs before any branch, matching `agentFor`'s ordering; in-flight resumes are still joined.

The command source no longer registers a `warm` hook: anticipatory catalog warming resolves an `agent`-typed remote parameter and cannot run without activating the cold session it warms for. `CommandDirectory` already pulls lazily — the first `candidates`/`matchEnter`/`matchSpace` read calls `ensureReady` — so the catalog now loads on `/` intent, which is exactly when resuming the session's Agent is legitimate. `directory.warm()` had no remaining caller and is removed.

Removing `warm` also removed the open flow's only Agent resolution, so `session.activate` now carries the open-publishes-Agent contract: a typed RPC that authorizes write scope, rejects archived sessions, and resolves `agentFor`, which resumes idempotently. The client fires it from `sessions.open` — the selection boundary — not from presentation: `SessionManager.activate` records the intent and posts the RPC, while automatic selection paths (startup `startInitialSelection`, retained workbench pane focus, personal-directory restore) pass `activate: false`. `desktop.status` reads consent through `ctx.agents.get` under a `liveOnly` branch: a Session with no live Agent answers `null` — no managed consent can exist without the Agent that owns it — while `desktop.confirm` keeps the full resolution because an explicit write is entitled to resume. Mount could never be the boundary: the conversation slot renders beneath the selection loading overlay, and the startup spec requires the auto-restored current Session to stay cold after presentation. `handleConnected` re-activates only identities already in the `activated` set, so a restart re-publishes the Agent the user had opened without resuming one that was merely presented.

## Alternatives considered

**Report a page-visible `lastSeq` in the baseline.** `session.seq` is the contiguous log length and every sequence is a real event — including the marker — so no "filtered" basis exists; under-reporting it would hide a durable append from projections.

**Defer the gap repair until live events arrive.** It papers over the symptom: the marker is still durable and still absent from the stream, so a reconnect or stage-activated open hits the same repull later.

**Keep `agentFor` for `sessions.models` and only replay the marker.** It fixes the history count but still resumes an Agent for a read the durable log can answer, violating the startup contract that opening a saved session creates no Agent.

**Keep `warm` but pull only when a live Agent exists.** Client snapshots expose no Agent-liveness fact, so the hook cannot tell a free warm from a cold resume; gating on heuristics like `running` misfires on live-at-rest Agents. `commands.list` could also gain a detached standing-scope catalog like `sessions.models`, but the standing composition's command view differs from the Agent's resolved view and the lazy path already satisfies every consumer.

**Fire `activate` at conversation mount, gated on readiness.** The slot inject exposed `activate` plus a `hooks.activationReady` source — false while initial selection was pending or a required authority lacked a verified account — and the component activated on the readiness flip. It failed two ways: mount still fired for the auto-restored current Session (the startup spec holds `agents.get(id) === undefined` after presentation, so presentation is not intent), and a server restart never re-ran the gate so the reconnected client lost the `session/created` → `session/subscribed` attach that a resume produces. The selection boundary solves both: explicit `sessions.open` is the user intent the contract rewards, and reconnect re-activation replays the intent the restart destroyed.

## Consequences

The startup auto-selection end-to-end assertion `historyCalls === 1` now holds on slow CI ordering, and the same spec's `ctx.agents.get(id) === undefined` holds after presentation because the restored current Session never passes through `sessions.open`. Any constructor-time silent append — not just `session/end-seed` — is replayed by the same loop on every subscription path, and genuinely missing history still repairs through `mergeTail` unchanged. `sessions.models` on a cold session no longer runs live SSH admission; authorization still gates the read. Typing `/` in a cold session resumes its Agent — that is the intent-driven activation the contract reserves for. Explicit `sessions.open` publishes the live Agent through `session.activate`, restoring the open-publishes-Agent contract background-job, schedule, and plan-review flows assert, while startup restores and pane focus stay cold; a reconnect re-publishes exactly the sessions the user had explicitly opened, so restart e2e keeps observing the attach baseline. Ambient reads mounted per presentation, such as the desktop-confirmation status dot, no longer resume the session they decorate.

## Verification

`api-proxy-collaboration.spec.ts` asserts the mux stream yields `session/event(session/end-seed, seq 1)` before `session/subscribed(lastSeq 1)` for a seeded restore. `api-proxy-models.spec.ts` and `api-proxy-cold.spec.ts` cover the detached selection tiers and the ownership fence (48 cases). `service.client.spec.ts` pins the contract: the `/` source registers no `warm` hook, and the first `candidates` pull fetches the session key once. The web end-to-end spec retains `historyCalls === 1` and the post-presentation no-Agent assertion, the explicit-open suites poll for a live Agent through `session.activate`, `server-restart.e2e.ts` covers the reconnect re-publish, `session-api.client.spec.ts` routes `sessions.activate` to its runtime owner, and `desktop.spec.ts` asserts `status` on a Session without a live Agent returns `null` without calling the resolver.
