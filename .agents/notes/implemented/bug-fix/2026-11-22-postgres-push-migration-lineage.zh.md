# Agent Note: 保留两条已发布的 PostgreSQL 迁移历史

状态：已实现

[English](2026-11-22-postgres-push-migration-lineage.md) | 中文

## 问题

仅含推送迁移的发布版与合并版共用 1–129。前者的 130–131 对应合并版在 144–145 发布的 SQL。两种部署都有持久的校验和，也可能已有设备登记和回执。

## 决定

仅识别通过校验的共同前缀及其后精确匹配的一条或两条推送记录。协调迁移在锁住维护记录期间重新登记版本，并保留每条记录的校验和及应用时间。重新登记与截至 145 的待执行 SQL 一起提交。后续迁移各自保留独立事务。

## 备选方案

让两套文件同时占用 130–131 会使迁移序列产生歧义。重跑推送 SQL 或放宽校验和验证会危及现有登记，并失去恢复和回退依赖的依据。

## 后果

激活和回退必须通过适用的迁移记录检查，检查只读。部署人员遵循[推送迁移记录升级](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/push-migration-lineage/guide.zh.md)。PostgreSQL 预检覆盖两种推送前缀、写入未收敛、校验和漂移、事务失败和设备登记保留。
