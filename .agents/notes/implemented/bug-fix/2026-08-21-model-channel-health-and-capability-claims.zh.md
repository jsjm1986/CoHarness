# Agent Note: 模型渠道健康状态与能力声明

Status: implemented

[English](2026-08-21-model-channel-health-and-capability-claims.md) | 中文

## 问题

Gateway 将确切的提供方声明与可能拒绝模型、忽略请求模型 id 或暴露非聊天端点的上游路由组合在一起。前端目录若信任名称或过期的目录行，就会提供无法完成请求的路由；若猜测思考或图片能力，持久输入会在后续请求中被提供方拒绝。

## 决策

组织模型变更通过 Gateway 治理服务完成，并以确切路由探测或权威协议声明为依据。DeepSeek V4 Flash、V4 Pro 与 V4 Flash Vision Exp 暴露已测试的 `low`、`high` 和 `max` 思考拼写；Vision Exp 明确接受 `text` 与 `image`。Neko GPT 路由使用 `/v1` 端点，只保留已确认的聊天模型。图片生成 id 不进入聊天模型列表。当前凭据或账号池拒绝所有请求的提供方仍保留在数据库中并标记为 `disabled`，以便通过显式恢复操作保留配置。`runtimeProviders()` 只注册启用的目录行，因此停用模型不会进入运行时适配器或前端目录。

组织设置投影仍是用户与项目运行时的持久来源。配置编辑使用带 revision 检查的路径 facade，并通过 `applyModelGovernanceToUser` 与 `applyModelGovernanceToProject` 重写投影；不会直接编辑生成的 JSON 文件。

## 曾考虑的替代方案

- **根据模型名称或提供方品牌推断能力。** 否决：名称无法证明思考线上的拼写、接受的模态或端点类型。
- **删除失败的提供方与模型。** 否决：删除会丢失上游事故恢复所需的凭据引用与配置。
- **手动修改生成的用户文件。** 否决：数据库 revision 与文件监听器会覆盖越权修改，并可能让用户使用不同策略。
- **保留停用目录行的运行时注册，只依赖授权检查。** 否决：适配器发现与前端选择器仍可能观察到过期模型，而只注册启用行可以直接移除它们。

## 后果

选择器只呈现已声明且当前获授权的路由。恢复停用的上游路由需要显式修改状态并重新探测；本流程不会自动推断恢复。能力元数据保持保守且按路由区分，因此新增上游模型必须先验证，才能获得图片或思考控制项。
