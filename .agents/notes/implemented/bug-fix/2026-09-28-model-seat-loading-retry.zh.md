# Agent Note：模型座位自动重试失败的挂载加载

Status: implemented

[English](2026-09-28-model-seat-loading-retry.md) | 中文

## 问题

composer 模型座位挂载即渲染回退文案（`选择模型`），因为 `current` 在该会话的 `session.models` RPC 返回前是 `null`。这次加载是 fire-and-forget（错误只落在目录 store），每次挂载只跑一次且从不重试：生产环境上慢请求会让触发器在数秒到数分钟内没有模型名，失败的请求则一直保持该状态，直到用户碰巧打开菜单或座位重新挂载。已在生产部署复现（2026-09-28）：选定工作区后触发器显示裸回退文案，数分钟后才自行恢复。

## 决定

座位现在区分瞬态并自行恢复。首次加载进行中且尚无已解析选择时，触发器读取 `trigger.loading`（`模型加载中…`），把"加载中"与"坏了"区分开。挂载加载失败后按退避表自动重试（1 秒 / 3 秒 / 8 秒，三次）；重试由 tick 状态驱动并重跑挂载效果，不依赖连续的 store 状态迁移。计数器在 `ready` 状态归零。只有 load 动作重试；被拒绝的选择仍走 toast 路径。打开菜单的手动刷新保持不变。

未选工作区的 hero 草稿仍然完全没有模型座位——没有会话就没有模型可选——本 note 不改变这一点。

## 考虑过的替代方案

**在注入的 `load` 包装器里重试。** 该包装器同时支撑菜单打开时的刷新，那里的手动重试应当保持即时且单发；把退避埋进去会与座位自己的调度重复触发。

**把错误显示在触发器上。** 菜单已通过错误条承接加载错误；在折叠触发器上重复错误文案，会给 composer 阻断时唯一保持活跃的控件添噪。

**选定工作区时预取目录。** 缩小窗口但失败仍不可恢复；留作可能的后续，不作为替代。

## 后果

触发器文案对共享 store 响应式更新，加载成功后模型名无需交互即可出现。持续失败的目录在三次重试后停止并保持回退文案——无无限循环。计数器位于座位实例上，目录报告 ready 即归零，包括菜单打开后成功的手动刷新。section 呈现（会话设置）挂载时不加载也不重试，不受影响。

## 测试

`model-select.client.spec.tsx` 覆盖加载中文案、直到晚期成功并解析触发器文案的退避链，以及耗尽后的调度终止（共四次调用、不再增长）。包内全套件：43 通过。
