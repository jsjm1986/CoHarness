# Agent Note: 文档操作排空

Status: implemented

[English](2026-10-26-document-operation-drain.md) | 中文

## 问题

本地文档引擎除分块上传最终确认任务外，还拥有普通保存和目录修改。若只关闭扫描和上传管理器，已接收的文件系统工作就会游离于所有者的关闭任务之外。分块上传等待下一个请求体字节时，仅在读取之间检查信号也无法响应取消。文件关闭失败还可能覆盖触发清理的写入失败。

broker 的授权查询可能在当前引擎快照关闭后仍未完成。若目录传递队列没有会被等待的所有者，它也可能越过 HTTP Consumer 的生命周期。

## 决策

每个引擎操作均持有所有者引用，直到其返回的 promise 结束。关闭会同步停止接收新操作，中止请求体读取与扫描，等待已接收操作和初始化，等待初始化期间新建的扫描，然后停止最终确认任务。重复关闭返回同一任务。不可取消的修改会在所有者仍然可用时完成。分块取消会打断待定读取，并等待源的取消结束后才释放读取器。操作与句柄关闭若分别失败，会同时保留两者；失败分块不会确认进度。

Gateway broker 拥有完整的浏览器操作，包括选定引擎前的授权查询。关闭会拒绝新操作、等待已接收请求、关闭每个 HTTP 作用域，然后关闭所有引擎。HTTP 作用域会在路由移除期间保留已接收处理器及各自拥有的目录同步队列。一个作用域关闭失败不会跳过其他引擎的清理，关闭会保留全部清理失败。延后的目录回调保留原始请求上下文，不会借用后续查看者的传递权限。

普通暂存文件只有在排他创建成功后才归该操作所有。创建失败不能授权删除该路径。已打开的句柄只有在元数据读取成功后才转交调用方；初始元数据读取失败时会关闭句柄。普通与分块读写会同时保留各自独立的操作、源取消和句柄关闭失败。自有临时文件的清理失败也会保留，文件已不存在时则无需移除。

已打开的下载会把流与文件句柄转交调用方。其字节不需要后续引擎操作，因此由调用方独立于引擎关闭来读取完或取消。

移动回滚会先恢复源硬链接，再删除目标。若恢复失败，目标会保留供恢复使用，错误同时保留两个原因。并发占用源位置的文档不会被覆盖。可移植故障注入验证恢复成功和源位置被占用两种情况；Linux Loader 场景在源移除与目录验证之间替换目标父目录。

这是广义[运行时关闭决策](2026-08-27-bounded-runtime-work-and-teardown-fences.zh.md)下文档所有者的具体关闭顺序。[Gateway broker 决策](../architecture/2026-10-15-gateway-local-document-broker.zh.md)继续负责 broker 作用域和运行时独立性。两项决策均未被替代。

## 考虑过的替代方案

**只中止而不等待。** 取消请求不能证明源已释放读取器、扫描已结束或文件系统修改已完成。

**只等待请求体而不取消。** 发送方可以无限期不发送下一个字节，所有者关闭时已接收工作就无法排空。

**关闭所有已返回的下载。** 所有权已转交调用方；已打开文件不需要活跃的引擎资源，取消它会截断原本有效的响应。

**只用主机对象给后台工作分组。** WeakMap 可以串行化工作，但不能明确由谁在释放目录传输前等待它。

## 影响

关闭会等待已接收且不可取消的文件系统操作，以及协作式流取消。取消一直不结束的源仍会延迟关闭。计时器不能代替结束等待。源代码测试通过显式屏障控制初始化、扫描、普通请求体、分块请求体和目录修改。真实 Loader 记录验证提供方关闭会取消两个待定上传请求体、不发布普通文件，也不确认分块字节。文件句柄故障用例会保留两个原因，并保持持久化分块进度不变。

共享 Gateway／Runtime Loader 场景使用真实签名 principal 与 HTTP，验证路由移除后的目录传递，以及插件卸载期间已接收的文档读取。无所有者的 Consumer 对照在此前复制授权场景通过后，于目录结束断言处失败。编译后的 broker 探针分别保留两个项目操作者，并在关闭后读取已传递的目录标记。这些检查不能证明 Linux 系统账户隔离，也没有完成持久身份与目录集成。
