# Agent Note: 会话字面搜索优先于模糊候选

Status: implemented

[English](2026-10-25-gateway-literal-conversation-search.md) | 中文

## 问题

PostgreSQL trigram 相似度将查询与整个已索引事件比较。长消息中实际包含的短查询可能低于阈值，数据库字符分类也可能不为中文生成 trigram。因此，已正确索引的嵌套工具结果仍可能无法搜到。结果上限较小时，模糊候选还可能挤掉字面匹配。

## 决策

[会话仓库](../../../../gateway/src/postgres/conversation-repository.ts)在选定企业内接纳包含的字面匹配或 trigram 匹配。字面模式转义反斜杠、百分号和下划线；空白查询不返回记录。字面匹配排在模糊候选之前，再按相似度与时间排序。已有搜索文本和 trigram 索引继续有效。

## 考虑过的替代方案

**降低全局相似度阈值。** 这仍依赖数据库字符分类，会接纳更多无关事件，却无法保证返回字面匹配。

**将查询标点视作通配符语法。** 搜索文本是字面输入；普通百分号或下划线不能扩大结果集。

## 后果

普通索引值保留字面搜索行为。含 NUL 的文本使用[无损表示](../architecture/2026-10-30-conversation-nul-search-and-query-fields.zh.md)。很短或未分类的文本可能需要扫描企业内的记录。它不启用独立配置的 Session-query 提供方，也不新增产品端点。

## 验证

真实 PostgreSQL 回归保留事件 JSON，搜索嵌套中文工具文本、长消息中的短查询、字面通配字符与反斜杠。结果上限为一时，包含查询的记录优先于更接近的模糊候选。数据库事实记录 C 字符分类下中文 trigram 相似度为零；原有遗漏和错误的模糊优先级均有失败回执。
