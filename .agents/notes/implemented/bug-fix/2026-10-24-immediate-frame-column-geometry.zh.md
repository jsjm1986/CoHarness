# Agent Note: 框架列几何位置立即生效

Status: implemented

[English](2026-10-24-immediate-frame-column-geometry.md) | 中文

## Problem

恢复辅助面板时，历史文字开始显示的同时，会话区域的宽度可能发生变化。对网格列做插值会让同一文字沿连续宽度反复换行并重新计算布局。一次公网导航诊断记录到 0.29 的累计布局偏移；同版本减少动态效果的对照记录为 0.00。这个对照确认了动画的影响，但不是对某项样式修改的测量。

## Decision

AppFrame 直接应用列宽和调整条位置。尺寸与让步仍由列求解器决定；显示、轨道预留和全屏呈现仍由[辅助面板所有者](../feature/2026-09-04-right-sidebar-docking-infrastructure.zh.md)决定。面板平移和透明度使用各自独立的动画规则。

每个调整条自行持有指针捕获状态与悬停提示。列几何位置不做插值时，无需框架级的拖动状态。

## Alternatives considered

**关闭所有动画。** 减少动态效果可作为诊断对照，但布局优化无需移除无关指示器和面板过渡，也无需改变用户的动态效果偏好。

**仅在恢复完成后启用动画。** 这需要另外区分恢复和交互触发的布局变化，而且后续面板变化仍会让文字反复重排。两种情况下，框架都已经知道最终尺寸。

## Consequences

打开或关闭一列时，会话宽度立即改变，不做缓动。真实 Web 组合从展开提交开始，连续四个动画帧记录内容列宽；几何预期要求只有一个不同宽度。现有辅助面板快照还覆盖折叠、刷新和窄屏呈现。这些检查验证 DOM 几何位置，公网导航测量验证最终的布局稳定性。
