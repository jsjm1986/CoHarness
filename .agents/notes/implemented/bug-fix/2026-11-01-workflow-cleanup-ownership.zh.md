# Agent Note: 工作流清理失败时保留所有者

Status: implemented

[English](2026-11-01-workflow-cleanup-ownership.md) | 中文

## Problem

已接受的运行仍存活时，工具插件撤下可能移除记录监听器及空闲释放否决，丢失后续成员结束。

子任务资源释放失败意味着实际清理尚未确认。移除其句柄会阻止重试。此时将后台任务标为完成，还会撤销任务对空闲释放的否决，使所属 Agent 在子任务可能仍活动时被回收。

## Decision

工作流 Host 仅在资源释放成功后移除子任务，并将释放 Promise 与待完成的子任务工作一起跟踪。并发的公开资源释放调用共享一次尝试；尝试被拒绝时保留未完成的子任务，供后续重试。脚本结果与清理确认分别处理。

前台 Workflow 与 Ralph 消费方在启动前进入确切引擎的 `withForeground()`。引擎撤下会取消并等待完整的结果收集与清理移交，同时保留确切父级。PTC 提供方还把准入接入其原 subagent 运行时，阻止运行时先于迟到清理移交结束退出等待。独立原始启动与后台 Job 保留持有方控制。

前台工作流与 Ralph 消费方在丢弃句柄前，通过 `WorkflowRun.retainFailedCleanup()` 同步移交被拒绝的清理。原 subagent 服务把每份失败租约保留在其确切父级之下。确认 Promise 在失败尝试后继续等待，释放后才兑现；工作流随后确认自身资源释放。消费方在失败调用之外观察此 Promise。后续准入或服务释放重试保留的工作，不会重放脚本或子 agent 提示。工作流记录器保留原 Agent 与 Session，对空闲释放保持忙碌否决，直到确认清理并追加唯一持久结束记录。

持久记录订阅归原父级 Agent 作用域所有，独立于工具注册。每份记录在结束或放弃后释放其确切订阅释放器。后台父作用域释放时保留订阅，直到 Job 写入最终记录；取消与清理控制仍归 Job。前台父作用域结束时放弃未完成记录，不接受迟到回调经退役所有者继续写入。

瞬态进度订阅同样归原父作用域所有。每个镜像只筛选确切运行并写入原 Job，工具替换与父作用域释放期间保留到生产方停止镜像。清理失败时停止镜像，防止后续进度覆盖恢复提示。停止操作释放订阅，不接管 Job 的取消控制。

后台工作流在资源释放失败后保持任务活动。它发布清理未确认的提示，保留所有者，并等待下一次终止请求触发重试。确认清理后，才产生一次失败任务结果和一次持久化运行结束记录；不发布脚本的部分返回值。任务的 `done` Promise 继续表示资源已被释放。

## Alternatives considered

**告警后完成任务。** 告警既不能确认清理，也不能保留所有者对空闲释放的否决。

**拒绝任务的 `done` Promise。** 注册表将这类拒绝作为生产方违反约定进行隔离处理，并不能提供生产方缺失的清理保证。

**用定时器重试，或到期放弃清理。** 工作流清理没有隐式的放弃期限。显式终止重试复用现有控制操作，避免无界的自动重试循环。

## Consequences

持续后台清理失败会使任务与所有者保持活动，包括所有者或服务拆卸期间。底层清理能够成功后，需要再次尝试终止来恢复。消息字段、事件类型与 Session 代际保持原有定义。[持久工作流记录决策](../feature/2026-08-10-durable-workflow-runs-in-chat.zh.md) 继续要求在完全停稳后写 run-end；本决策保留该规则。

## Verification

受控 Host 场景拒绝失败清理，并重试保留的子任务。任务场景验证空闲释放仍保持忙碌，且延迟持久化结束记录。真实 Node PTC 与 SDK 场景保留开放的 HTTP 子任务传输，重试清理，并在实际连接关闭后观察唯一终态记录。完整旧工作流包会丢失清理责任，或过早结算任务。
