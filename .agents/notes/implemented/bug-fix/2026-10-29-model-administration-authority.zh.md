# Agent Note: 模型管理保留当前权限及目标有效期

Status: implemented

[English](2026-10-29-model-administration-authority.md) | 中文

## 问题

管理员请求可能在 HTTP 认证之后等待，并在角色撤销后继续修改模型配置。组织模型发现可能凭旧权限解密公司密钥并发出目录探测。Provider 与组织版本行相反的加锁顺序可能中断并发编辑器保存。目标项目可能在写入期间归档，SQLite 也接受了额度读取不会选中的数字账号别名。

## 决策

[管理 HTTP 适配器](../../../../gateway/src/admin-api.ts)把已认证账号 ID 传入每一项目录、Provider、凭据、访问及额度写入，以及模型发现准备。调用方提供的 actor 字段不授予权限。PostgreSQL 在提交前保留活跃组织及其当前活跃管理员账号和成员资格；SQLite 在立即写事务中检查当前管理员。撤权会在配置、版本或成功操作审计变化前以403拒绝。失败 HTTP 请求按实际状态写入审计。

所有 PostgreSQL 模型配置写入先以 `FOR NO KEY UPDATE` 锁定组织版本行，再锁定发起者、目标及 Provider。项目 Provider 与凭据写入也会推进该版本，因此遵守相同顺序；它们仍须满足独立的[项目管理权限](../feature/2026-08-28-project-scoped-settings-management.zh.md)。较弱的组织锁允许其他事务在归档项目或删除账号时完成外键 key-share 检查。配置写入只使用调用方的一条事务连接。

纪要选择器在读取、固定和清除时保留同样的当前管理员资格。候选与校验在所属组织内关联目录和 Provider。固定接受精确的已提供标识，包括模型 ID 中的空格。组织写入序列化先于发起者和有效目录/Provider 锁，因此排队的固定请求不能保留准入前已停用的路由。已接受的设置与候选视图从该事务返回，不受后继保存影响。

管理访问及额度写入会保留未删除的目标账号或活跃目标项目，直到提交。停用账号仍可配置。SQLite 额度写入把接受的数字账号 ID 规范为十进制文本，与读取及账号清理一致。替换额度、恢复继承及删除账号会在同一事务中移除该账号的历史数字别名。零、不限及受支持的继承模式保持原有含义。

SQLite 导入保留有效额度的选择规则：只有规范十进制账号键提供覆盖项，未生效的数字别名计入 `skippedQuotaAliases`。重复导入只替换当前源库中账号的额度覆盖；没有规范覆盖项时恢复继承。仅在 PostgreSQL 中存在的账号保留其额度。无效数字键或缺失账号引用会回滚整笔导入。冻结 SQLite 源库保持不变；单独的别名不会在迁移期间激活额度。

共享管理准入还会在权限等待之后检查[强制改密资格](2026-10-28-user-administration-authority.zh.md)。重置发起账户的密码后，早先浏览器会话不能继续授权排队的模型配置、凭据或额度写入。

组织模型发现在读取已存凭据或使用草稿密钥前检查当前管理员权限。只有端点匹配时才复用已存密钥，浏览器无法读取其值。准备事务在外部目录请求前释放；后续撤权不会取消已经发出的探测。返回模型元数据前，HTTP 适配器通过[读取回应器](2026-11-05-administrator-read-publication.zh.md)复核当前管理员资格。角色、账号、成员、组织或要求修改密码发生变化时返回403，不发布模型目录。配置提交先于策略文件刷新，后者仍独立检查[当前账号权限](2026-10-29-model-policy-authority.zh.md)。治理服务省略发起者时允许受信任的内部维护；HTTP 适配器始终提供发起者。纪要管理必须提供发起者。

## 考虑过的替代方案

**复用 HTTP 管理员快照。** 数据库连接或锁等待期间可能发生角色或成员资格变化，旧快照不能授权最终写入或凭据准备。

**先锁定每个 Provider 再推进组织版本。** 组织编辑器写入已经先获取版本锁；相反顺序会使这两种操作发生确定性死锁。

**模型发现期间保留准备事务。** 远端服务器不参与数据库写入。保留连接会在网络操作期间占用连接池并延迟权限变化。

**规范化每个导入的数字额度键。** SQLite 从未选中别名行作为有效额度。导入时激活它们会改变策略，冲突别名也没有可用于确定权威替代值的持久写入顺序。

## 影响

HTTP 请求字段与数据库结构保持不变。自定义治理适配器必须在自身写入期间保留传入的发起者及当前目标权限。组织写入会跨项目串行，以配置并行吞吐换取一致的版本及锁顺序。配置提交不依赖后续文件投影或网络成功。

## 验证

纪要 HTTP 回放隔离跨组织同名 Provider，并覆盖不透明候选 ID。行屏障覆盖并行固定、资格撤销及已接受视图归属。实际 SQLite 与 PostgreSQL Gateway 回放覆盖管理员降权、当前管理员、已删除目标账号、已归档目标项目、数字额度别名、已存及显式发现密钥、策略刷新与审计结果。PostgreSQL 行锁测试覆盖账号、成员资格及组织撤销，跨组织发起者及等待中的项目归档。Provider trigger 与 advisory 屏障复现原有锁顺序死锁。真实导入命令回放验证重复导入保持有效额度，并保留冻结源库字节。已存密钥发现使用本地 HTTP 服务，不需要真实模型 API。

目录 HTTP 响应屏障以已存及显式草稿凭据覆盖十四种后期资格撤销。已获准探测不保留事务即可完成；撤权后其元数据仍不发布。
