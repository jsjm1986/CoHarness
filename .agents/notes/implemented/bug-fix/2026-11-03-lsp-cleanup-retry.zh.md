# Agent Note：替换语言服务器前保留失败清理的归属

Status: implemented

[English](2026-11-03-lsp-cleanup-retry.md) | 中文

## 问题

受管理进程范围的观察失败不能证明语言服务器已经停止。如果从工作区池中移除失效实例，提供方就会丢失清理引用，后续查询可能在旧原生服务器仍然存活时分配替代进程。永久缓存失败的释放操作也会阻止后续清理恢复。

## 决策

[实例池](../../../../packages/lsp/lsp-stdio/src/index.ts) 只在清理成功后移除实例。后续查询会先重试保留失效实例的清理，再分配替代进程。提供方释放时会保留失败项，等待其他清理结束后报告错误；后续清理尝试可以重试这些项。

[实例](../../../../packages/lsp/lsp-stdio/src/instance.ts) 在并发调用方之间共享每次释放尝试。显式释放观察到失败后，只清除这次失败尝试，查询准入仍保持关闭。成功的释放继续缓存。内部取消会保留当前尝试，直到提供方观察并报告结果。

## 考虑过的替代方案

**移除所有失效实例。** 传输失败会阻止查询，但不能证明物理进程已经停稳。

**永久缓存失败的释放。** 可恢复的观察失败会使后续清理始终报错，而不会再次尝试原生清理。

**保留独立失败列表，同时启动替代进程。** 这会允许同一提供方和工作区存在重叠的原生服务器。

## 后果

未确认的清理会拒绝受影响查询，而不创建另一台服务器。后续查询或提供方清理尝试可以恢复清理。原生隔离与整个 Host 的崩溃恢复仍由子进程提供方负责，本决策不增加更广泛的平台保证。

## 验证

真实 Loader [示例](../../../../packages/lsp/lsp-stdio/tests/fixtures/cleanup-retry.mjs) 通过受控的原生清理观察失败保留一个真实 stdio 服务器。它验证旧服务器清理结束后才开始替代分配，最后等待两台原生服务器退出。单元用例覆盖并发释放失败、查询准入关闭、失败池项保留和其他实例清理错误的汇总。
