# Agent Note: 文档移动端节奏与共享滚动条几何

Status: implemented

[English](2026-08-26-document-mobile-rhythm-and-scrollbar.md) | 中文

## Problem

文档管理器的紧凑工作台把通用 Modal 间距与功能包自己的操作层标题叠加在一起，导致手机端出现重复拖拽提示、文字起始线不一致、行高过大以及多个看似独立的滚动区域。共享 WebKit 滚动条也比文档布局需要的宽度更大，而卡片内部滑块的内缩值仍按旧宽度计算。

## Decision

文档管理器继续使用现有 Modal portal、底部 Sheet 交互、焦点行为、作用域状态和文档操作。紧凑 presenter 为每个操作层提供一个标题行和一个滚动区域，管理器保留一个主要文档列表滚动区域。文件夹行和文档行使用同一套手机网格，使名称和元数据共享起始线；视觉按钮使用本地化短文案，无障碍名称保留完整操作语义。

主题的 WebKit 滚动条宽度和高度均为 4px，`--dsh-scrollbar-width` 继续作为占用滚动条空间的表面所读取的几何值。卡片内部的 WebKit 滑块使用共享的 1px 透明内缩，确保有色内芯仍然可见。工作区和对话区域的几何测试读取共享值，不再各自携带另一份宽度。

文档 endpoint、权限规则、上传协议、分页规则和公共组件 prop 均不变。紧凑筛选和操作层导航仍是客户端本地操作，打开它们不会增加请求、观察器或轮询循环。

## Alternatives considered

**保留功能包自己的拖拽条并叠加 Modal 的拖拽条。** 否决，因为两个相同提示会占用垂直空间，并让操作层标题看起来像两个嵌套表面。

**隐藏手机滚动条，或只在文档包内写伪元素样式。** 否决，因为隐藏滚动条会移除主要的继续阅读提示，而功能包自己的伪元素规则会分裂主题的样式权威，让其他滚动消费者继续使用旧几何。

**改用左滑操作或整卡预览等独立的手机行交互。** 否决，因为这会引入手势状态，并与批量选择、文件夹导航和只读权限发生冲突。

## Consequences

手机用户获得更紧凑且对齐的行、单一可预测滚动区域以及适合窄屏的短控件，同时保留完整无障碍名称。桌面端继续使用现有作用域侧栏和行内操作，并共享同一套文字层级。4px 滚动条会减少客户端的可见和预留宽度，因此共享宽度及滑块内缩消费者、侧栏几何、composer 补偿和浏览器 golden 必须同步变更。

## Verification

组件和样式测试锁定单拖拽条 presenter、手机网格、紧凑字号角色、本地化元数据、共享滚动条值和自定义滑块内缩。无密钥 Web e2e 在窄屏手机、明暗主题和不同作用域权限下覆盖文档管理器操作层，并验证无横向溢出。侧栏和 composer 几何 e2e 覆盖 4px 共享滚动条及其补偿消费者。
