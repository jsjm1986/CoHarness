# Agent Note: 资源策略读取保留当前管理员资格

Status: implemented

[English](2026-11-05-resource-policy-read-authority.md) | 中文

## 问题

已认证管理员可能在资源查询等待期间失去角色、账号、成员关系或组织资格。仅检查 HTTP 入口，会让已接受的请求在撤销提交后仍暴露其他账号的资格或管家成员目录。策略读取需要与策略变更相同的当前管理员身份。

## 决策

[ResourceAccess](../../../../gateway/src/resource-access.ts) 在读取策略的事务连接上保留活动组织、账号和管理员成员资格。[StewardAccess](../../../../gateway/src/steward-access.ts) 对成员目录使用同一读取器。Admin 路由把已认证账号 id 传给两种方法，请求字段不能选择它。准入前已提交的撤销返回403。读取器保留资格后，并发撤销会等待其事务完成。读取全程只占用一个池连接。

省略服务操作者表示可信内部读取，保留内部策略检查能力，同时不开放未认证 HTTP 路径。资源资格、电脑使用许可与执行准入仍是独立决策。[管家准入](../feature/2026-10-10-steward-admin-layered-admission.zh.md)与[插件授权](../feature/2026-10-02-grant-gated-plugin-enablement.zh.md)记录继续规定各自的执行规则。

## 考虑过的替代方案

**发起独立策略查询前检查角色。** 排队的查询可能超过该检查的有效时间，在撤销提交后读取数据。保留数据库共享锁可确定读取与资格变更的先后顺序。

**在一个连接上保留资格，再经连接池查询。** 只有一个可用连接时，这会等待自身持有的事务；独立快照也使授权更复杂。所有读取都使用传入的事务连接。

## 影响

管理元数据读取增加短事务和管理员查询。已准入的数据库读取先完成，撤销随后提交；之后的读取会被拒绝。[JSON 发送器](2026-11-05-administrator-read-publication.zh.md)在返回该结果前独立复核当前资格。读取不改变权限记录及修订号。无密钥 Gateway 回放检查六类资格与管家目录的角色、账号、成员关系和组织撤销，并以关系锁控制并发降级。测试使用一个业务连接、真实认证与 PostgreSQL，不分配 Runtime，也不调用模型。
