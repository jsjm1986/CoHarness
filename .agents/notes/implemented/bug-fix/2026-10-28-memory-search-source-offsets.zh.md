# Agent Note：记忆搜索摘要保留原文位置

Status: implemented

[English](2026-10-28-memory-search-source-offsets.md) | 中文

## 问题

NFKC 与小写匹配可以展开或组合字符。规范化后的匹配偏移不能直接索引原文。较长前缀包含连字、兼容单位、分解重音或小写展开时，搜索虽能命中，摘要却可能遗漏匹配内容。

## 决定

将规范化的 UTF-16 命中位置，通过 NFKD 字素簇对应回原文码点位置。每次搜索持有自己的 ICU 分段器。先做兼容分解再分段，使兼容韩文 Jamo 在同组内组合。摘要使用原文，连同省略号最多 160 个码点。

[Unicode 规范化](https://www.unicode.org/reports/tr15/)定义兼容分解及组合。[字素规则](https://www.unicode.org/reports/tr29/#Normalization)在分解文本中保留规范组合组。原文位置由分解长度推导，字符表继续由运行时维护。

## 备选方案

**用规范化偏移索引原文。** 兼容展开、规范组合与小写展开会改变这些位置。

**展示规范化摘要。** 这会改变原文大小写和兼容字符。阅读者需要已存事实的原文片段。

**在兼容分解前对原文分段。** 相邻兼容 Jamo 可以属于不同的原文字素簇，却在规范化后组合，仍然产生偏移错误。

## 影响

排序使用规范化文本，摘要保留匹配内容的原文表示。映射各遍历一次分解文本与原文，并使用运行时的规范化与字素分段。

## 验证

源代码回归覆盖七类前缀、包含边界的 160 码点上限和有效 Unicode。无密钥 Loader、Agent、记忆工具与真实 JSON 存储快照，比较回传模型的完整摘要。先前构建版本在其中六类前缀下遗漏匹配内容。
