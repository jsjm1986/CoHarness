# Agent Note：异步完成时的记忆可用性

Status: implemented

[English](2026-10-31-memory-live-availability.md) | 中文

## 问题

记忆作用域由实时设置决定，存储读取和辅助模型调用却可能等待。功能关闭前获准的操作，仍可能在作用域撤回后发布目录、返回私密工具结果或注入召回正文。等待模型容量的选择器也可能在召回关闭后继续发送。

## 决策

目录发布把完成读取的存储行按 Agent 当前作用域重新筛选。召回在模型元数据和准备完成后、每次读取所选条目前，以及注入前，重新检查开关与精确作用域地址。只有当前提供的行可进入新记录的选择器请求或注入提醒。关闭 `enabled` 或 `recall` 会通过[辅助生命周期所有者](2026-10-24-memory-auxiliary-ownership.zh.md)保留的请求信号取消活动选择器。正常 LLM 准入负责随后返回的额度及其释放。

[模型工具作用域规则](2026-10-31-memory-tool-scopes.zh.md)也适用于读取与搜索的存储完成之后：请求作用域已经撤回时，以 `memory_invalid` 拒绝返回结果。这包含隐式多作用域搜索，以及 personal、workspace 和 project 地址。在途存储操作由原所有者完成；功能撤回不能提前确认其清理结束。

取消遵循记忆服务的[有效来源通知](2026-11-01-memory-provider-availability.zh.md)，包括没有命名空间编辑时的提供者挂载与组合配置回退。

## 备选方案

**关闭功能时拒绝全部服务读取。** 面向成员的读取需要继续查看保留条目。模型消费者强制执行自己更窄的已提供作用域集合。

**仅在调用入口检查。** 存储、模型准备和模型准入都可能在设置变化后完成。入口检查无法决定现在能否发布已完成的结果。

**只取消选择器，不检查完成的数据。** 取消依赖提供者处理信号，也不能授权目录或工具结果。发布仍受当前开关和作用域控制。

## 后果

功能撤回阻止新的数据泄露，不删除条目、不改变修订号，也不重写对话历史。重新启用允许新的操作。现有请求事件、资源归属、额度与存储格式保持不变。整理同时遵守[独立实时开关与游标规则](2026-10-31-memory-curation-live-availability.zh.md)和[审阅作用域限制](2026-10-28-memory-curation-scope.zh.md)。

## 验证

单元用例让目录读取、模型元数据与准备、选择器回复、完整条目读取和延迟准入额度跨越开关变化，检查取消后不发送请求、迟到额度仅释放一次，且不注入已撤回内容。真实 headless CLI 用例采用文件设置、JSON 存储、Agent 循环和实际记忆工具，观察模型输入与所有者保留数据。隔离的完整旧包可复现发布和结果错误，不修改共享源码。
