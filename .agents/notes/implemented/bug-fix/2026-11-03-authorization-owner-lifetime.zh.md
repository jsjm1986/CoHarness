# Agent Note：授权尝试保留其服务和凭据所有者

Status: implemented

[English](2026-11-03-authorization-owner-lifetime.md) | 中文

## 问题

保留的授权服务引用可能在服务释放后启动新的凭据流程。已取消或完成的流程也可能保留 Session 回调，继续显示通知或密钥输入框。在排队修改或提交确认时重新查找凭据服务，会把替代存储混入原始授权尝试。

## 决策

[服务](../../../../packages/credentials/authorization/src/index.ts) 在 fiber 开始停止时关闭准入，撤回活动尝试，并等待完整流程和提交尾部工作。每次尝试都保留原始凭据提供器，用于修改和确认。释放仍会保留[已经接纳的写入](2026-10-01-authorization-session-scoped-commit.zh.md)；活动取消不会把写入转给替代提供器。

已退役的回调不发布通知，问题和新提交会以 `WITHDRAWN` 拒绝。问题同时接收尝试和问题自身的取消，并拒绝迟到回答。同步流程异常与异步拒绝采用相同的结算处理。

每次尝试只在自身工作结束后释放一次保留的键；后继尝试不能提前占用。提交队列吸收错误，并在阶段状态中保留已经接纳的存储失败；释放等待该队列和实际流程结果。

## 考虑过的替代方案

**依赖每个流程检查取消。** 延迟的第三方回调可能在调用方离开后重新打开问题。

**卸载时取消全部待完成写入。** 已被存储接纳的凭据必须完成，并报告自身结果。

**每一步都解析当前凭据提供器。** 产生的记录可能属于与原始尝试不同的提供器。

## 后果

消费者需要重新获取已停止的服务，并完成自身被取消的流程工作。释放会等待不配合的流程回调，而不会遗弃它们。凭据格式、键保留和不可撤回的写入准入沿用现有语义。

## 验证

真实 Loader [示例](../../../../packages/credentials/authorization/tests/fixtures/owner-lifetime.mjs) 检查保留服务拒绝、活动流程撤回、隐藏迟到交互，以及原本地凭据文件中的已提交字节。单元用例覆盖已接纳写入期间的提供器替换、问题取消、已完成回调和并发结算观察器。
