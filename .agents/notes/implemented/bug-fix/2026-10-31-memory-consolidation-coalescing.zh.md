# Agent Note: 记忆合并对共享作用域合并触发

Status: implemented

[English](2026-10-31-memory-consolidation-coalescing.md) | 中文

## 问题

合并资格属于记忆作用域，而完成回合的运行队列属于 Session。两个 Session 可能在任一模型请求结束之前，读取同一个符合条件的游标。条件游标发布保护更新的数据，却无法阻止两个审查对同一目录花费模型资源。

## 决策

整理插件拥有一个活跃作用域身份集合。它在读取资格前取得作用域，并持续持有到模型迭代器清理和条件游标发布完成。其他 Session 对该作用域的并发触发会合并到活跃审查。完整作用域身份区分目录和 SSH 目标；无关工作区保持并发。拒绝、模型失败、取消以及游标不符合条件等所有退出路径都会释放作用域。

每次作用域判定读取当前功能开关，并验证触发回合所捕获的执行提供方。活跃审查可以完成已准入的工作，后续作用域拒绝已关闭的功能或已替换的授权。失败或取消的审查保留原进度，使后续完成的回合仍可重试。

[条件游标决策](2026-10-23-consolidation-cursor-concurrency.zh.md)仍保护审查期间的成员编辑。[作用域执行决策](2026-10-28-memory-curation-scope.zh.md)负责工具访问。[执行身份](2026-10-23-curation-execution-identity.zh.md)、[请求所有权](2026-10-24-memory-auxiliary-ownership.zh.md)与[取消](2026-10-23-curation-cancellation.zh.md)决策继续承担各自独立的责任。

## 考虑过的替代方案

**只依赖最终游标比较。** 此时重复模型工作已经运行，比较只能拒绝陈旧的完成元数据。

**将每个 Session 排在活跃审查之后。** 第二层功能队列会在模型资源准入前保留捕获的 Session 状态。合并重复触发避免该队列；耐久变更标记为后续回合保留待处理工作。

**串行运行所有合并。** 不同工作区与 SSH 作用域有独立的目录和游标。全局互斥会拖延无关工作。

## 后果

一个整理插件在每个作用域中最多运行一次活跃审查。成员写入保持并发，其游标变更可能要求另一次审查。合并的触发不会逐个重试；合并工作仍在回合完成时运行。互斥属于插件，不提供跨进程锁。

## 验证

受控重叠的 Session 判定复现同一项目作用域中的两次模型调用。移除作用域互斥后，真实 Loader、两个 Agent、JSON 存储及模型准入提供方复现两次并发辅助请求。维护的记录要求一次辅助请求、总计三次模型准入，并确认每次准入均已释放。源码场景还覆盖独立目录与 SSH 身份、失败和取消后的恢复、功能撤销，以及作用域之间执行提供方的替换。
