# Agent Note: 在 Session 提交前预留 JSONL 提供者容量

Status: implemented

[English](2026-10-23-jsonl-provider-retention-admission.md) | 中文

## Problem

JSONL 活动写句柄可以跨任意多个 Session 保留失败写入与后续事件。存储停滞时，批处理截止时间不能限制待写字节数。仅在 `session/event` 中拒绝事件已经太晚：Session 已提交事件，并会包含观察者异常，因此限制持久化副本可能使已接受事件未进入存储。

## Decision

`SessionStore.registerAppendAdmission()` 对冻结候选事件注册由 fiber 拥有的同步预留。已挂接的 Session 在表层和分发校验前预留资源，拒绝重入，并在接受失败时按逆序回滚先前预留。成功提交的预留交给提交后的事件消费方。独立构造不受部署准入影响。

JSONL 在同一提供者的所有写句柄间共享 `maxPendingEvents` 和 `maxPendingBytes`，包含已预留候选事件、排队的显式追加和正在写入的批次。默认上限是 100,000 个事件与 64 MiB 完整 UTF-8 JSON 事件字节；两者均接受正安全整数。活动队列借用不可变的已接受事件，避免额外复制载荷。显式追加先快照调用方拥有的输入，再预留容量，批次无法容纳时释放已经取得的部分预留。失败写入保留容量，直到重试成功或句柄关闭。

活动容量拒绝在新候选事件的序号提交前拒绝它，并使该写句柄拒绝后续候选事件。flush 排空已接受前缀后仍报告拒绝；close 排空并释放所有权后报告拒绝。最后一轮关闭排空完成后，写入租约开始释放前会拒绝后续候选事件。重新打开已存储的 Session 会通过现有恢复路径补齐中断步骤或轮次。此机制明确允许拒绝终止记录，而不是维护无界的异常关闭队列。持续 I/O 故障仍可能阻止排队事件落盘；close 会报告故障并释放句柄，不能保证未刷新的事件得以保存。容量恢复与存储持久性是两个独立结果。

[共享 write-behind 准入决策](2026-10-23-write-behind-admission-failure.zh.md)仍约束 SQLite 和 Gateway：其提交后控制器在拒绝已接受事件后保留终止故障。本决策修改 JSONL 独立路由，并添加可选核心扩展，不迁移其他提供者。[事件与字节留存决策](2026-08-27-bounded-session-write-behind-retention.zh.md)仍拥有共享控制器的每 Session 作用域及重试依据。两份记录均未被完全取代。

## Alternatives considered

- **从提交后观察者抛出异常。** 观察者异常包含机制保留活动追加，可能掩盖缺失的持久化序号。
- **在预算之外保留拒绝的载荷。** 磁盘故障会换一种名称继续保留无界数据。
- **预留任意关闭空间。** 工具恢复结果大小可变；异常队列需要独立的完整容量，也无法保证每次关闭都能容纳。
- **分别限制每个 Session。** 每 Session 额度乘以并发 Session 数，不能限制一个 Host 的持久化积压。跨 Host 进程仍需要独立的节点总资源治理。
- **溢出后从 Session 同步重新读取已接受事件。** 此做法会新增被禁止的任意内存历史依赖，而不是在接受前预留资源。

## Consequences

一个提供者限制自己保留的序列化事件体积，不限制 JavaScript 堆、调用方拥有的显式输入、持久化历史总量或全部 Host 进程。容量拒绝要求排空并替换当前活动写句柄；另一个 Session 释放容量后不会静默恢复。不改变 Session 事件、持久化格式版本或成功 SDK 文本记录。依赖成功关闭记录的消费方必须处理明确的存储拒绝，并恢复已接受前缀。

## Verification

核心测试覆盖逆序回滚、回滚异常、表层与分发拒绝、重入、独立 Session、插件记录及注册释放。JSONL 测试覆盖多字节精确限额、跨 Session 共享的活动写入、失败排空后的留存、拒绝时序号不增长、显式 flush 失败及重新打开恢复。真实 Loader 组合的 agent loop（智能体循环）拒绝超大回复，在不重复模型调用的情况下回到 idle，报告持久化和释放失败，释放写句柄，修复中断轮次，再完成后续短回复。发行的 headless profile 快照覆盖可见拒绝，并在提高配置容量后恢复未变更的持久化前缀。

离线 Node 25.8.1 对比在一次模拟磁盘故障后提交 2,001 个不可变的 4 KiB 载荷事件，两边使用相同的 64 事件／256 KiB 限额。原句柄接受全部 2,001 个事件，GC 后额外保留 8,663,568 字节堆；有界句柄接受 62 个、拒绝 1,939 个，保留 103,080 字节。完整 JSON envelope 使字节限额先于 64 事件上限触发。准入耗时分别是 2.856 和 2.926 ms。这些单进程样本证明接受量有界且减少复制，不代表吞吐提升或生产容量。
