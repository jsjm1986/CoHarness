# Agent Note：Gateway 夹具状态隔离

状态：已实现

[English](2026-09-28-gateway-fixture-state-isolation.md) | 中文

## 问题

Gateway 默认路径指向调用账号的运行时和状态目录。隔离夹具的数据库与用户目录，并不能隔离项目策略投影：HTTP 设置变更无需启动运行时，也能写入项目运行时的策略和 home 补丁。

## 决策

资源夹具将自己拥有的临时根目录传给 `gateway/tests/test-config.ts`。辅助函数提供用户、项目、项目运行时、状态与 systemd 路径，再解析真实配置并拒绝超出夹具根目录的可写位置。派生密钥、备份文件、节点配置和可选恢复目标执行相同检查。子进程使用与进程内夹具相同的显式环境，不从调用 shell 继承部署配置。

配置解析器测试保留真实生产默认值。只读的 launcher 分类测试与注入发送器的传输夹具，不通过这些配置路径写入文件。源码包和迁移输入保留真实的只读位置。

## 考虑过的替代方案

进程级修改 `HOME` 或模拟 `homedir()` 会隐藏默认路径解析错误，并在并发测试之间引入共享状态。向每个夹具复制零散路径覆盖，会让新使用的资源领域缺乏隔离。明确归属的临时根目录在服务启动前界定了允许写入的位置。

## 影响

真实项目策略写入器在隔离根目录下执行，无效路径覆盖在写入前被拒绝。夹具作者仍负责停止子进程、关闭数据库和清理临时目录。直接保存在夹具数据库行或持久清单中的路径，需要独立核验归属；配置隔离不会改写这些记录。
