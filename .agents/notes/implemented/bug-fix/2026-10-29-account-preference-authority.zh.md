# Agent Note: 账号偏好保留当前资格并重试失败的迁移

Status: implemented

[English](2026-10-29-account-preference-authority.md) | 中文

## 问题

已认证的账号偏好请求可能在等待数据库连接或偏好行时，遇到账号、成员资格或组织失效。仅解析未删除用户 ID 会允许停用账号与已撤销成员继续读取或修改偏好，并将已删除账号误判为输入错误。把所有旧设置读取失败都当成空文档，会提交默认值，阻止后续重试导入真实设置。

## 决策

[账号权限辅助函数](../../../../gateway/src/postgres/account-authority.ts)以共享锁保留活跃组织、未删除的活跃账号与活跃成员资格。[偏好读写](../../../../gateway/src/postgres/account-preferences-service.ts)在初始化或锁定偏好行之前获取该权限，并保留至提交。已认证的公共 ID 选择当前账号 UUID 与用户名；缓存角色、状态及浏览器身份字段不授予权限。账号偏好不要求电脑执行授权，也不随当前项目选择改变归属。

资格在准入前撤销的请求以403拒绝，不初始化偏好、不推进版本，也不写成功更新审计。已接纳的数据库工作会在冲突的账号撤销提交之前完成。既有版本栅栏仍只允许使用相同期望版本的并发首次写入成功一次。该账号规则补充独立的[项目管理设置规则](../feature/2026-08-28-project-scoped-settings-management.zh.md)。

旧文件缺失或 YAML 格式错误时初始化已有默认值。旧文件以非阻塞描述符打开，在读取前拒绝非普通文件；无需 FIFO 写入者也能拒绝该类型，描述符会在事务结束前关闭。其他文件读取失败会抛出保留原始原因的类型化不可用错误，并回滚初始化。[HTTP 所有者](../../../../gateway/src/server.ts)记录一次原因，返回带 no-store 且不含路径的503响应。修复文件后，下一次请求可以迁移其真实值。未预期的解析器缺陷会继续抛出，不转成默认值；这与[模型策略凭据验证](2026-10-29-model-policy-authority.zh.md)采用相同的恢复区分。

## 考虑过的替代方案

**信任 HTTP 认证时返回的账号。** 连接与行锁等待可能超过该次观察的有效期；它不保留当前成员或组织资格。

**只在最终 UPDATE 时重读用户 ID。** 此前的读取可能已经披露撤权账号数据，第二次查询也可能把并发删除转成无关的更新故障。保留身份可同时覆盖初始化、查看与写入。

**任意迁移异常后都初始化默认值。** 临时存储故障不能证明没有旧偏好。提交默认值会使故障永久化，因为既有偏好行会绕过迁移。

## 影响

偏好 JSON 字段与数据库结构保持不变。自定义服务在自身操作期间保留当前账号权限。403要求恢复账号资格；503允许在存储恢复后重试。偏好事务在读取旧文件时持有账号锁，运维应恢复不可用存储，不能把默认响应视为迁移成功的证据。

## 验证

真实 PostgreSQL 连接准入屏障覆盖查看和修改期间的账号删除／停用、组织停用及成员资格撤销。偏好行屏障证明已接纳工作会保留账号直到提交。并发初始化和跨账号场景保留版本与组织隔离。真实循环设置路径会在不提交偏好行的情况下失败，并在修复后迁移。已认证 Gateway 回放覆盖相同失败、身份伪造字段、成功审计归属及安全503重试；编译产物回放不需要模型 API。
