# Agent Note: Subagent 路由跟随父会话当前目标

Status: implemented

[English](2026-08-22-subagent-current-model-route.md) | 中文

## 问题

进程内 subagent 创建选项以前直接复制 `parent.options`；该值记录的是父 Agent 创建时的路由。模型选择器或 `agent/request` 贡献可以为后续请求选择其他提供方／模型，而该选择会记录在父会话最新的 `request/header` 中。父会话已经使用授权路由时，如果此后创建子 Agent 仍读取旧默认值，模型治理就可能拒绝这个过期路由。可继续子 Agent 还会把过期路由写入描述符，因此冷恢复会重复使用它。

## 决定

`resolveChildAgentOptions()` 在父会话存在最新 `request/header` 时读取其中的提供方／模型；父会话尚未发出请求时，才回退到创建选项。父级 `maxTokens` 仍属于创建时选项。显式的子 Agent `agentOptions` 覆盖继承值。

可继续启动在第一次 await 之前解析这些选项，并把同一份分离后的值同时用于持久化描述符和新建子 Agent。冷恢复使用描述符中的路由，因此委派之后父会话的模型切换不会改写已有子 Agent。

## 备选方案

**每次都复制 `parent.options`。** 否决，因为它是创建时选项，不是会话当前路由。

**读取实时选择器注册表。** 否决，因为它是进程内、入口特定的状态，也不是 loop 或恢复子 Agent 使用的持久来源。

**父路由发生变化时使用部署默认值。** 否决，因为会话日志中的选择可能有意指向未列出或由网关提供的路由；治理必须检查已选路由，不能静默替换。

**子 Agent 创建后再解析路由。** 否决，因为子 Agent 在第一次请求前必须拥有完整路由，可继续描述符也必须记录冷恢复所使用的确切路由。

## 后果

Spawn、fork 和可继续的进程内子 Agent 会跟随父会话最新记录的提供方／模型路由，同时保留显式子 Agent 覆盖。委派后发生的路由变化只影响后续委派，不会改写已经创建的子 Agent。进程外提供方运行独立运行时或产品进程，因此继续使用其部署拥有的路由。

进程内继承与继续执行测试套件会固定这条回归，包括持久化描述符和冷恢复路由断言。
