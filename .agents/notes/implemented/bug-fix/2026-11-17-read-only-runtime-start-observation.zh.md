# Agent Note: Runtime 启动响应丢失后的只读状态确认

Status: implemented

[English](2026-11-17-read-only-runtime-start-observation.md) | 中文

## 问题

远端可能已经受理启动，但 HTTP 响应丢失。把这种情况当作确定失败会诱发重复启动；刷新 POST 页面也可能重放请求。空间 Cookie 不能标识原标签页访问的是哪台电脑。

## 决策

账号表单提交的转发在收到响应头之前中断时，浏览器进入只读等待页。Gateway 使用进程持有的密钥，为已认证账号、已解析电脑、Runtime、空间及固定截止时间签名，并在转发前固定这些选择项。每次等待 GET 都重新解析当前归属和拓扑，不启动进程；就绪后只跳转到确切目标。排队与就绪配置限制额外等待时间。到期、Gateway 重启、停止状态、归属变化或撤权会结束轮询，不停止已受理的工作，也不选择其他电脑。

管理员发起启动前，界面记录所选归属、电脑、分配标识和进程代次。中心已有按标识查询 Runtime 并核验管理员权限的接口。传输中断后，页面通过该接口观察当前电脑的预期代次，就绪且电脑在线时才予以确认。冷启动等待下一代，已启动中或已就绪的进程沿用所示代次。分配标识或代次变化会结束核实。目标资料缺失或观察到期时，结果仍为未知。

这扩展了[浏览器 Runtime 身份](../architecture/2026-10-29-browser-runtime-and-document-location.zh.md)的确切目标规则；该记录中的文档、Session 和配置归属决策仍独立有效。

## 已考虑的替代方案

**重复 POST。** 重复请求无法区分响应丢失和请求未被受理，可能重复已经受理的工作。

**增加代理超时。** 更大的超时只会推迟同一种不确定结果。

**保留服务端票据。** 无限增长的票据表会保留每次点击的状态；进程内签名可保留原选择，无需这类存储或浏览器持久状态。

## 影响

等待链接不是执行授权，不授予权限、不改变空间 Cookie，也不能唤醒已停止的 Runtime。连接获取失败、取消和明确的远端拒绝沿用现有失败处理。

## 验证

可运行的 Gateway 重放在真实本地 Runtime 启动被暂挂时丢弃已提交响应，随后确认经过认证的就绪结果，没有第二次启动。路由测试覆盖个人与项目目标、归属变化、当前拒绝和到期。两个等待标签页保留各自原选择。
