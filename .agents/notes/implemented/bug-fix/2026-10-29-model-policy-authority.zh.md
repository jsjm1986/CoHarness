# Agent Note: 模型投影保留当前账号权限

Status: implemented

[English](2026-10-29-model-policy-authority.md) | 中文

## 问题

策略请求可能跨越配置锁和投影队列等待，仍保留旧管理员角色。账号角色变化不会推进模型目录版本，因此即使重新读取策略，仅比较版本的文件与内存缓存也可能保留旧授权。把凭据存储故障当成 JSON 损坏处理，还可能静默轮换 intake 凭据并替换策略数据。

## 决策

[PostgreSQL 模型服务](../../../../gateway/src/postgres/model-governance-service.ts)先锁定组织配置版本，再读取当前活跃、未删除的账号及活跃成员资格。账号与成员行的共享锁在策略构建期间保留该角色。SQLite 服务在同一事务中读取当前符合条件的账号和模型策略。请求携带的角色不授予模型权限。资格已撤销时在投影前拒绝；[逐请求执行与凭据授权](../feature/2026-08-14-gateway-model-governance-and-usage.zh.md)仍独立生效。

[投影器](../../../../gateway/src/apply-model-governance.ts)在有界内存缓存和持久文件复用中，都比较版本、默认规则、路由及 Provider 设置。因此仅账号发生变化时也能替换策略，并保留目录版本及有效的主体绑定 intake 凭据。运行中的[策略消费者](../feature/2026-08-14-gateway-model-governance-live-policy-reload.zh.md)无需重启即可应用内容变化。

凭据校验位于 JSON 恢复逻辑之外。无效 JSON 或非对象文档可以根据当前策略重建。文件读取和凭据存储失败会在替换投影或签发新 Bearer 前传播。有效的现有 token 在策略变化期间保持稳定。

批量及单账号刷新跳过停用账号。Admin 查看停用账号时保留已配置的覆盖项，并以当前配置版本返回空的有效策略；没有版本读取方法的旧适配器返回503。同一次角色和状态变更会写入目录授权并确认停止，不会尝试重启停用账号。重新启用后遵循正常的最新启动和投影要求。

## 考虑过的替代方案

**信任传入账号角色。** 先前获准的请求不能跨后续等待保留该角色。

**把模型版本作为完整缓存键。** 账号变更独立持久化，无需编辑目录也可能改变有效授权。

**旧文件处理发生任何失败后都签发新的 intake token。** 查询失败不证明旧凭据失效；故障期间替换可能撤销仍有效的消费者。

## 影响

策略 JSON 字段和模型版本含义保持不变。自定义治理适配器解析当前资格及角色；停用账号的查看功能还需要 `configurationRevision`。策略投影是最终收敛的缓存，不是执行租约：其后撤权仍需要当前请求授权及既有失效或停止处理。刷新失败后保留的文件和凭据不证明授权有效。

## 验证

确定性回归将账号变更安排在真实 PostgreSQL 配置锁和投影准入队列之后。存储回放覆盖提权、降权、主动与惰性刷新、显式拒绝、凭据查询失败及账号资格撤销。实际 Loader 回放验证角色变更无需推进目录版本，也会撤销管理员模型路由。真实 Gateway 和 LocalLauncher 回放确认角色与停用组合变更会停止进程，不产生替代代次。这些检查不需要模型 API。
