# Agent Note: 有界响应读取失败不等待取消确认

Status: implemented

[English](2026-11-01-gateway-response-cancellation.md) | 中文

## Problem

响应 body 可能要等另一个分支或底层清理完成，才确认取消。超出字节上限后等待这份确认，会阻止有界读取返回错误，即使调用方随后取消也无法结束等待。两次读取之间发生取消时也可能进入同样的等待。调用方在读取开始前已取消时，提供的响应 body 也需要被取消。

## Decision

Gateway 响应读取器发起 body 取消后，直接返回原有的大小限制或取消错误，不等待清理确认。取消失败由独立的拒绝处理器接收，既不会成为未处理的拒绝，也不会覆盖主要读取错误。读取结束时释放 reader 锁，即使底层清理仍未完成。

归档同步在报告 HTTP 状态前取消快照、回执和探测请求被拒绝后的未使用响应体。拒绝结果不等待取消确认，成功响应继续采用有界 JSON 读取。同步重试与命令归属规则保持原有定义。

## Alternatives considered

**等待取消以证明清理完成。** 共享响应的另一个分支可能属于其他 Consumer，不能决定当前读取何时结束。

**只依赖 fetch 的取消信号。** 导出的读取器接收既有响应及其自身的取消信号。调用方取消读取时，使用的信号未必是建立传输时的信号。

## Consequences

读取失败只能证明调用方不再接收后续响应字节，不能证明实际传输已经清理完成。传输所有者仍保留这项责任。资源占用继续取决于[已确认的执行清理](2026-11-01-uncertain-resource-cancellation.zh.md)，与响应读取器的结果分别处理。消息协议、配置、Session 数据与 schema 版本均保持原有定义。

## Verification

受控响应流保持取消确认未完成，同时验证声明长度超限、分块读取超限和分块之间取消均能返回错误。预先取消的读取会取消 body；清理失败仍保留主要错误。可运行的 SDK 场景读取真实开放 HTTP 响应的超限分支，在关闭另一个分支前保留大小限制错误，随后等待服务端实际响应关闭。完整旧版源码及构建后的 Runtime 包只在新增场景中失败，原有资源场景继续通过。

归档提供方仍加载时，未结束的原生 HTTP 拒绝响应已关闭，后续持久归档经两个 SDK 正常同步。快照、回执和探测请求的清理拒绝均保留 HTTP 状态。旧版归档提供方会把未结束的响应保留至卸载。
