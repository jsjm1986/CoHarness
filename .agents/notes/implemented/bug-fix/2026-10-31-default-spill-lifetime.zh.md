# Agent Note: 默认 spill 存储拥有其退出清理

Status: implemented

[English](2026-10-31-default-spill-lifetime.md) | 中文

## Problem

导入子进程输出辅助函数时，即使默认 spill 目录不存在，也会注册进程退出回调。重复导入的提供方模块积累了没有资源可清理的回调，在生命周期测试中触发监听器警告，掩盖实际的归属失败。

## Decision

默认目录分配器在成功创建存储后，为该目录注册一次清理。回调保留分配得到的路径。仅导入模块或使用调用方目录不注册默认清理。可观察的进程退出会移除空的默认目录；已完成文件保留以供恢复。首次创建失败时不注册回调，外部移除的目录也不会重新创建。

## Alternatives considered

**提高进程监听器上限。** 上限会掩盖没有资源可清理的回调。

**移除退出清理。** 空目录会在正常进程终止后残留。

## Consequences

进程拥有默认存储直到退出；插件卸载不能丢弃已完成输出。公开输出 API 和 spill 限制不变。此说明拥有目录生命周期，[完整写入说明](2026-10-25-subprocess-complete-spill-writes.zh.md) 拥有收集器追加语义，两项决策不互相取代。

## Verification

隔离的 Node 进程分别在导入前、选择调用方存储后和重复默认分配后统计回调。导入与调用方存储不新增回调；重复默认分配新增一个。实际退出会移除空目录并保留已完成文件。源码与构建导出均执行这两种结果。提供方生命周期测试还会销毁服务重复注册夹具的根上下文，运行时不再出现该监听器警告。
