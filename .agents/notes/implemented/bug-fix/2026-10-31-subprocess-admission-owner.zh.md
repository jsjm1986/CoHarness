# Agent Note: 子进程分配保留其资源提供方

Status: implemented

[English](2026-10-31-subprocess-admission-owner.md) | 中文

## Problem

排队的进程或终端许可可能在资源提供方被撤销或替换后才返回。若提供方停止接受新工作，却没有中止已授予的许可，仅靠取消不能识别变化。分配此时可能依赖当前 Runtime 已不再拥有的准入创建子进程。

## Decision

共享子进程服务在等待前捕获资源提供方。准入返回后，紧接调用进程或终端提供方之前，同步检查同一个底层 Cordis Service 和当前托管要求。新的跟踪代理保留该身份。所有者变化或缺少必需提供方时，以原因值 `unavailable` 抛出 `ResourceAdmissionError`，未使用的许可归还原提供方。调用者取消保留原有错误与清理行为。

独立分配也会重新检查准入是否在交接期间出现。旧请求不能静默采用新容量。新请求正常解析当前提供方。

异步提供方在入口捕获 `captureAdmissionCheck(spec)`，在派发物理启动前立即调用。SSH 在预备及鉴权流连接后检查。确认回滚后，`rejectAfterCleanup(failure)` 通知共享服务归还许可并以原始失败拒绝；无法确认的回滚保留占用。资源报告失败时，同时保留原始分配失败。失败的普通 SSH 句柄在确认范围退出并关闭流后移除，因此被拒绝的启动不会积累到提供方卸载。

本地提供方在普通进程的参数／宽限期校验、终端的空程序校验或任一方法的目标环境校验于启动前拒绝时，也使用 `rejectAfterCleanup`。这包括 argv、cwd 及环境变量键或值中的空字节；原始错误类别、code 和消息均保留。这些位置尚不存在进程，不确定报告会保留未使用的容量。物理分配后的失败仍须确认清理，才能归还容量。

## Alternatives considered

**通过替代提供方重新取得许可。** 旧许可及其待完成报告仍属于原所有者，迁移请求会混用两次分配。

**仅在准入辅助函数内检查。** 该异步函数返回后，到提供方被调用之前还有一次交接。在此期间撤销或取消仍需要最终检查。

## Consequences

两种分配方法共享同一归属检查，不改变提供方签名、配置或持久化数据。已有进程范围仍负责确认清理及保留不确定占用。[SDK 传输归属说明](../architecture/2026-10-24-sdk-subagent-process-ownership.zh.md) 覆盖其独立拥有的私有启动 API，[模型操作说明](../architecture/2026-10-24-prepared-model-operations.zh.md) 覆盖模型派发。

## Verification

确定性用例覆盖两种分配方法、排队和许可交接期间的撤销与替换、独立请求新增托管要求，以及有效的跟踪 Service。Loader 应用使用真实本地 Node 进程与 PTY：过期准入不创建标记，提供方不变时正常启动。不可变的旧构建代码在全部八个过期所有者场景中都会创建标记。清理用例保留 Session 归属、终端控制及不确定占用，直到后续确认关闭，包括调用者取消后才完成的迟到分配。本地与 SSH 提供方测试覆盖公开服务消费方；这些检查不代表新的物理 Linux/Windows 或生产 Gateway 验收。

第二个 Loader 应用通过本地 carrier 运行真实 SSH helper 和鉴权 socket 转发。源码与构建流程在 RPC 派发前拒绝八个过期所有者启动，归还原许可，并保留两个正常进程/PTY 启动。旧构建提供方会物理启动全部过期场景。单元用例在资源完成报告失败时保留两项失败，并保留无法确认的远端清理。carrier 不验证 OpenSSH 加密或另一台物理主机。
