# Agent Note: 个人 Runtime 准入使用当前账号权限

Status: implemented

[English](2026-10-28-personal-runtime-authority.md) | 中文

## 问题

个人 Runtime 请求读取账号后，可能继续等待常驻容量、策略准备或节点压力准入。如果保留请求中的管理员角色，降权后仍可能获得管理员覆盖层、根目录访问或特权进程配置。热运行时刷新策略也可能沿用旧角色，或复用资格已撤销的账号。Admin 错误映射还可能把合法的启动拒绝误报为请求格式错误。

## 决策

[`InstanceRepository.personalPolicy`](../../../../gateway/src/instances.ts) 解析当前符合条件账号的 id、用户名、主目录、角色及活跃状态。PostgreSQL 要求选定组织可用、账号及成员资格活跃，并且分配属于当前节点；SQLite 要求账号活跃、未删除且保有分配。[`InstanceManager`](../../../../gateway/src/instances.ts) 在常驻容量和维护准入完成后、生成进程身份和策略文件之前解析这些信息。热复用向 `beforeUse` 提供当前信息，资格已撤销时拒绝复用。

每个启动器在异步准备完成后调用 `beforeAllocation`。管理器在此等待节点压力准入，再次解析个人策略，并在分配进程或发出 systemd 启动命令前，拒绝缺失或身份、主目录、角色发生变化的策略。失败代次遵循现有的确认停止与预留清理规则。新请求可按当前角色重新准备策略。被拒绝准备过程中留下的策略文件不授予执行权。

本决策以最终策略读取作为授权时点。其后发生的撤权仍遵循现有访问失效和 Runtime 停止要求，不会为监督操作持续占用数据库连接，也不改变恢复和停止停用账号时所需的资格规则。进程与压力所有权仍由[准入决策](../architecture/2026-10-23-gateway-runtime-admission.zh.md)规定；[账号管理](2026-10-28-user-administration-authority.zh.md)独立检查发起管理员的权限。

[Admin 路由](../../../../gateway/src/admin-api.ts) 为有类型的 Runtime 准入失败保留可读错误文本，并增加稳定的 `code`。策略不可用或容量不足返回503；持久停止状态与资源代次失配返回409。Linux 账号预检在凭据、单元创建与进程准入之前执行。账号缺失返回409 `RUNTIME_ACCOUNT_NOT_PROVISIONED`；查询不可用返回503 `RUNTIME_ACCOUNT_VERIFICATION_UNAVAILABLE`。Admin 和普通 HTTP 响应提供对应账号的准备指引；命令详情只保留在服务端原因中。失败请求审计记录对应状态，不产生启动成功事件。

## 考虑过的替代方案

**信任浏览器认证或目标查询返回的账号。** 这些对象都无法反映后续等待期间发生的撤权。

**仅在取得常驻容量后刷新。** 策略准备和节点压力准入仍可能超过已选权限的有效时段。

**最终检测到变化后替换策略文件，继续同一次启动。** 进程身份、主目录、已准备的监督状态和策略文件可能对应不同账号信息。拒绝后需要重新完成整个准备过程。

## 影响

自定义实例仓库根据当前资格实现 `personalPolicy`，不能返回缓存的请求对象。自定义启动器在实际分配前等待 `beforeAllocation`。准备期间策略变化可能返回503，即使新的普通角色仍可启动；新请求会解析该角色。热策略刷新本身不证明此前的特权进程已经停止。一般管理员生命周期操作权限和多电脑设备授权仍有各自的准入要求。

## 验证

存储回归覆盖当前角色、组织和节点隔离、账号或成员资格撤销、常驻容量等待、节点压力等待、主目录与用户名变化，以及热复用。可运行 Gateway 回放通过已认证 HTTP、实际 LocalLauncher 监督、生成的权限与目录文件、受管资源注册和经过认证的就绪检查验证两种存储。被拒绝的启动不分配承载进程，降权后的重试使用普通策略。这些检查不需要模型 API，也不证明原生 Windows 或跨电脑执行。
