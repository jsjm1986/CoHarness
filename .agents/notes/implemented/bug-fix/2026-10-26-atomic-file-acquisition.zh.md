# Agent Note: 原子文件取得

Status: implemented

[English](2026-10-26-atomic-file-acquisition.md) | 中文

## 问题

排他创建临时文件可能因另一写入方已占用该路径而失败。若创建失败后仍删除该路径，清理就会删除另一写入方的数据。锁创建失败后，部分写入的记录也可能保留当前进程的 PID，阻止后续写入方进入。句柄关闭与清理若独立失败，也必须与原始失败一起保留。

## 决策

原子替换、写锁和恢复声明均通过排他创建取得文件描述符。成功取得描述符后，该操作负责文件写入、可选的操作系统账号设置和关闭。取得失败会保留已占用的条目。写入、账号设置或关闭失败时，移除已取得的文件；多个失败会一起保留。完整临时文件随后交由替换操作负责，替换失败时移除临时文件，并保留额外的清理失败。

特权写入方的调用者可以显式提供用户数字标识和主组数字标识。账号会在发布替换或进入持锁操作之前设置，恢复声明也使用同一账号。调用者负责解析账号和准备目录。文件所有权提供操作系统访问能力；应用授权仍由所属服务负责。

原子替换接受调用方拥有的取消信号，在准备前及每次 rename 尝试前检查，包括重试。临时字节写完后取消只移除本次取得的临时文件，并保留已提交目标。所属服务提供生命周期权限；取消不能撤回已发起的 rename。远程桌面管理在所保留的 PostgreSQL 连接丢失时使用该信号。

持久节点配置写入在保留文件与目录同步的同时遵循同样的获取规则。清理只在排他打开成功后、rename 发布前拥有暂存路径；发布后在旧暂存名称上创建的其他条目保持不动。句柄释放同时保留主要 I/O 失败及独立的关闭失败。

[文档操作排空决策](2026-10-26-document-operation-drain.zh.md)继续规定文档暂存文件的对应规则。本决策把这些规则应用于设置和其他持久化领域使用的共享原子写入库。

## 考虑过的替代方案

**每次创建失败后都移除临时路径。** 错误不能证明该路径归当前操作所有，排他创建失败也不例外。

**替换后再设置所有权。** 另一进程可能在获得所需访问权前就观察到新文件；设置失败还会留下一个已发布、但目标账号无法使用的替换文件。

## 影响

操作失败会保留原有目标和任何其他写入方的临时条目。清理失败可能留下已取得的临时文件供诊断，并与原始失败一起报告。确定性的文件系统故障验证覆盖碰撞保留、部分写入、句柄关闭、清理、账号设置和恢复声明。受支持 Node 的源码与已生成库检查补充这些用例；跨账号 Linux 隔离需要单独的平台证据。
