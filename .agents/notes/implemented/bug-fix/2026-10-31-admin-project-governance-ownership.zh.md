# Agent Note: Admin 项目治理请求的归属

Status: implemented

[English](2026-10-31-admin-project-governance-ownership.md) | 中文

## 问题

Admin 的模型、额度和用量 URL 同时承载组织资源与项目资源。仅按 URL 前缀划分所有请求，会把远端项目的模型分配、额度或报表发到主入口电脑，其本机项目目录无法解析该项目。

## 决策

项目治理调用方在构造请求时明确声明电脑归属，请求辅助函数将其绑定到当前文档 Admin URL 中的电脑。组织模型配置、账号权限、角色／用户额度和汇总报表保持组织归属。节点接入和由入口管理的部署接口保持主入口路由。

[部署参考](../../../../gateway/docs/deployment-topology/README.zh.md) 说明各资源范围。现有 Gateway 鉴权、拓扑限制和项目查找仍是权限依据；请求被拒绝后，浏览器不会替换项目或电脑。

## 考虑过的替代方案

**所有治理请求都发到所选电脑。** 组织配置和汇总报表将依赖该电脑是否可用。

**所有治理请求都发到主入口。** 项目配置和策略文件投影属于项目所在电脑。

**仅按路径推断归属。** 不同主体的额度写入与贡献读取共用相同路径，调用方已经知道当前主体。

## 影响

本机 Admin 地址保留本机项目行为。电脑选择由各文档 URL 持有，其他标签页无法重定向项目写入。元数据读取和治理编辑不会启动项目 Runtime。现有角色／用户模型默认权限与项目分配保持独立。
