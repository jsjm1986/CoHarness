# Agent Note：整理游标的并发提交

Status: implemented

[English](2026-10-23-consolidation-cursor-concurrency.md) | 中文

## 问题

作用域审查在辅助模型调用前读取目录。成员可以在模型运行期间编辑该作用域。无条件记录最终目录摘要并清零计数，会把这些未经审查的修改标为已处理，并压制待运行的审查。

## 决定

记忆服务在修改队列中提供原子的条件游标写入。整理期望值由已观察游标及本轮自身成功修改组成；不相关的计数或审查元数据变更会阻止陈旧完成状态的发布。空作用域审查使用同样的比较。冲突轮次保留待处理变更，不推进摘要或间隔时间。

[作用域调度器](2026-10-31-memory-consolidation-coalescing.zh.md)在模型准入前合并重叠的审查。条件发布仍保护活跃审查期间的成员编辑和其他游标写者。

## 备选方案

**模型运行期间持有修改队列。** 审查经由同一队列执行记忆工具；持有它会阻塞这些写入及成员操作。

**调用普通 setter 前比较游标。** 条目修改可以落在比较和持久化之间，因此比较与写入属于同一个串行操作。

## 影响

并发变更可能需要另一次有界审查。游标保留所有不相关修改，不会声称模型已经审查了较新的目录。同时结束的审查不能替换较新的审查元数据。

## 验证

屏障分别验证模型请求期间及空目录快照后的编辑。真实 Loader 快照针对 JSON 记忆运行两个 Agent 回合与两次辅助审查，两次模型输入之间发生一次成员删除。
