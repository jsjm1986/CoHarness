# Agent Note: 交接模型输入在派发前保留

Status: implemented

[English](2026-11-01-session-handoff-input.md) | 中文

## Problem

会话交接将另一个 Session 的投影对话发送给辅助模型，却没有在调用方 Session 内记录这份输入。返回的 capsule 会丢弃源细节，源界面也可能变化。因此调用方日志无法重建辅助请求使用的提示词。

源对话可能包含美元符号序列。把它们解释成替换指令，会改变送达模型的文本。

## Decision

每次提取在进入现有模型流之前，通过 `session/handoff-llm-request` 记录源 Session、请求路由及完整输入消息。源对话（包括美元符号序列）按字面进入提示词。请求输入被冻结。记录失败时，提取返回现有本地回退，不派发模型。关闭提取、超限或没有路由的请求不创建输入记录。

提供方默认值仍在 `llm.stream` 内解析。因此治理在异步模型预备前保留执行归属。输入记录保存提交的提示词与路由，不描述提供方特定的 HTTP 请求体。完成状态、调用方取消、资源准入及最终跨会话可读性继续遵循现有规则。

## Alternatives considered

**仅记录返回的 capsule 或源 Session id。** 两者都不能保留该次请求使用的投影源文本。

**在重建时重新读取源会话。** 后续投影或访问权限可能与原请求准入时不同。

**将调用预备移到模型流之前。** 执行归属捕获必须先于异步预备；记录现有输入不要求移动这项工作。

## Consequences

新增事件仅日志可见，读取时必须认识。不认识它的旧构建会按现有事件词汇规则拒绝受影响日志。Session 头部、结构格式与工具 schema 保持现有内容；提取继续使用现有单次模型请求。既有已提交代次保持原样。[持久化记录](../../../../docs/persistence-changes/2026-11-01-session-handoff-input.zh.md) 与[升级指南](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/session-handoff-input/guide.zh.md) 定义兼容性及部署要求。

## Verification

查询工具与真实 SQLite 测试覆盖请求输入、中断提取以及记录失败时不派发。实际源码及构建后的 TypeScript SDK 和 Python SDK 组合验证记录在物理派发前存在，并通过真实持久化提供方读回。两套 SDK 比较同一请求证明与交接简报。私有完整原工具包的七个源码场景均因缺失记录而失败。另一个已经具备记录功能的完整包，在源码与构建模式的字面文本场景中失败。
