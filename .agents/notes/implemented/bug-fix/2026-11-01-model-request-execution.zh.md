# Agent Note：模型流保留执行与计费所有者

Status: implemented

[English](2026-11-01-model-request-execution.md) | 中文

## 问题

执行权威改变时，模型策略插件可能仍然安装。流可以从一个权威捕获计费见证，等待容量后再从另一个权威获得权限。返回字段相同不能证明服务归属。后来的输入集合或主要发起人也可能授权仍保留旧账单的工作。自动压缩因此可能发出旧请求，并在不同授权下替换历史。

## 决策

流进入治理中间件时，治理保留执行权威与实际 Agent。初次归因在授权后确认同一签发方仍存在。每次下游迭代器取值与提前关闭，都在实例拥有的异步上下文中运行，携带该请求的签发方、Agent、见证与 signal。并发调用方不能相互借用这些值。

既有派发前检查在容量准入后与物理请求时，通过原服务授权保留的 Agent。返回的输入与主要发起人必须匹配计费见证。核心在异步监听器完成后检查最终策略决定时，保留的模型访问提供方还会同步确认签发方身份。这项确认不增加授权查询或容量预留。模型流之外的路由选择保留普通路由决定。

观察到可选执行权威会在本插件生命周期内建立受管行为。移除该权威不能把在途或后续工作转为独立调用。缺少执行 Agent 时仍拒绝 Auto；未显式提供计费证明的 Runtime 基础设施调用，即使有 Session 跟踪或环境 Agent 也保持未归属。[基础设施活动决策](2026-11-01-infrastructure-model-activity.zh.md)定义了该归属。初次归因期间取消会产生 aborted finish 与 cancelled 用量，而不是身份失败。

卸载立即将策略标为不可用。异步上下文保留到最后一个活动迭代器结清，模型运行时继续负责传输与许可关闭。outbox 的发送器停止后仍接受迟到的持久记录，由下一次激活投递。

## 考虑过的替代方案

**授权等待后存在的任意服务。** 替换提供方可以批准属于其前任的操作，即使字段相同也一样。

**对旧账单使用最新 Agent 或参与人。** 授权与计费会指向不同执行。新请求可以捕获新所有者；既有请求必须保留自身见证。

**仅在异步监听器中检查。** 另一个监听器可能在检查后继续等待。运行时的同步最终模型策略决定会在传输开始前确认捕获的签发方。

**共享一个当前请求，或卸载时释放其上下文。** 并发流与待完成的迭代器清理分别拥有完成时点。每个请求将自身数据保留到迭代器结束。

## 影响

执行身份失败保留 `MODEL_EXECUTION_IDENTITY_FAILED`；取消保留 `ABORTED`。策略、用量和 Session 格式均不变。请求日志仍由各模型消费者负责。此决策补充[模型策略归属](../architecture/2026-10-24-model-policy-owner-lifetime.zh.md)、[Auto 工具准入](2026-11-01-auto-review-authority.zh.md)与[召回发布](2026-11-01-memory-recall-authority.zh.md)；它们各自的策略、工具作用域与发布规则继续有效。

## 验证

真实 LlmRuntime 测试用确定的等待点控制计费、模型准备、容量、后续授权与物理传输，覆盖同状态替换、见证改变、并发账号、可选权威撤回、调用方取消，以及两个待完成调用失去策略后的迟到用量。发布 SDK 组合使用实际治理插件和 outbox，运行自动压缩及其持久历史替换。失败的旧请求保留原发起人与完整源历史；后续请求使用新权威；所有取得的许可均结清。完整私有旧源码包和构建包复现过期摘要与授权错配，普通允许场景仍然有效。
