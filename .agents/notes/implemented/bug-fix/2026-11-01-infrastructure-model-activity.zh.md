# Agent Note: Runtime 模型维护具有独立活动归属

Status: implemented

[English](2026-11-01-infrastructure-model-activity.md) | 中文

## 问题

标题请求明确选择 Runtime 基础设施准入，并携带 Session 用于跟踪。治理仍可能查到该 Session 当前的 Agent，为计费授权其后续执行。标题因此获得了另一个发起人的活动归属。无关的环境 initiator 则可能触发归因冲突，使标题在到达准入前失败。

## 决策

对于基础设施来源，治理使用显式 Session 引用，不推断 initiator、执行 Agent、计费见证或旧 participant 发起人。即使跟踪的 Agent 仍存活，默认活动也保持未归属。调用方显式提供的执行身份保留现有证明检查。必需权威的可用性、保留的服务身份和模型策略继续保护派发。普通执行保留 Agent 与显式 Session 冲突检查。

资源提供方已经把此来源映射到 Runtime。治理遵循同一所有者，不依赖 Session 是否仍运行或调用方 scope。项目用量仍计费到项目，个人用量仍计费到其所有者。项目贡献者报告单独统计未指定发起人的基础设施活动。重复上报保留事件去重。

## 考虑过的替代方案

**使用跟踪 Session 的最新执行 Agent。** 后台任务可能晚于该执行结束，并读到另一位用户的输入。

**将环境调用者作为维护发起人。** 标题提供方可能在无关调用者下被调用，该身份的存在不构成计费证明。

**拒绝所有携带计费证明的基础设施请求。** 现有显式证明是调用方的有意决定，应保留当前校验。问题在于默认推断。

## 影响

策略、用量、SDK wire 与 Session 格式均不改变。模型可见的标题输入及其请求日志保持现有内容。历史记录保留原上报归属。[执行所有者决策](2026-11-01-model-request-execution.zh.md)仍负责执行请求与保留的服务生命周期。

## 验证

真实 LlmRuntime 测试区分 Session 跟踪、环境发起、已结束的执行回调、复制的旧 participant 和显式计费证明。执行来源的冲突仍拒绝派发。可运行 SDK 组合装配真实标题服务、首条提示词提供方、治理与 outbox；受控模型准备与额度等待会改变执行账号，同时普通主请求保持活动。TypeScript 与 Python 比较持久化标题输入、已接纳标题、资源来源、许可归还和用量。原始私有治理源码与构建包会误归属活动或拒绝标题。PostgreSQL 接收未归属的跟踪事件，重复上报后仅计一项项目调用，并且不创建贡献者归属。
