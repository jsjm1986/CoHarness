# Agent Note: Administrator-owned Auto review eligibility

Status: implemented

[English](2026-09-22-admin-auto-review-eligibility.md) | 中文

## 问题

Auto 审查需要用户无法自行授予的管理员授权。授权必须在 Gateway 重启后保留，并与 Session 中选中的权限预设区分。用户偏好和共享项目设置不能持有这项权限，因为它们的普通编辑者也是该权限的消费方。

## 决策

Gateway 用户记录持有 `auto_review_eligible`，并以必填布尔值 `autoReviewEligible` 对外提供。新建账户与从不含此授权的格式升级而来的账户初始值均为 false，包括管理员。既有管理员用户 PATCH 与编辑对话框负责授予或撤销资格；桌面和手机列表独立于账户状态显示已保存的授权。非管理员和项目管理者不能使用管理员路由。无效布尔输入会在任何用户字段变更之前拒绝整个 patch，不支持原子 patch 的旧用户服务会拒绝该操作。

每次管理员更新都在既有审计日志中记录操作者和目标，并使目标用户的访问失效。PostgreSQL 迁移 [031](../../../../gateway/deploy/postgres/migrations/031_auto_review_eligibility.sql) 将授权列加入既有用户访问触发器，使已提交的撤权通过现有 outbox 和通知通道抵达其他 Gateway 连接。这复用访问版本机制，不引入独立的资格缓存。

授予资格不会启用 Auto，不写入 Session 权限事件，不改变新会话默认值，也不启动运行时。[运行时执行授权](2026-09-22-auto-review-execution-attribution.zh.md)独立消费该资格，仍要求经过认证的发起人、活动账户以及既有项目和 Session ACL。项目所有权不包含修改授权的权限，项目也没有第二个 Auto 资格开关。

SQLite schema v8 将相同授权保存为受约束的零或一整数。只读 SQLite 导入器接受 v7，并明确将每个账户的资格设为 false；接受 v8 时校验并保留显式值。导入损坏的 v8 记录会使事务失败，导入期间不会升级或重写源数据库。

## 考虑过的替代方案

**将资格存入权限默认值或账户偏好。** 这些设置表达用户选择，而非管理员权限。混合两者会让默认设置写入获得授权，或让管理员授权静默选中 Session 预设。

**从管理员角色推断资格。** 管理权限与使用 Auto 的资格是不同决策。默认 false 的授权让管理员和普通用户都采用同样的显式分配行为。

**增加项目级资格开关。** 既有项目成员权限和 Session ACL 已经限制项目访问。第二个开关增加了一种管理状态，却不能表达实际发起用户资格的必要交集。

## 后果

用户记录消费方必须携带必填布尔值；只读消费方可以观察它，但不会获得写入方法。资格变更沿用既有访问失效行为，包括已配置的运行时失效。旧 v7 导入不会授予新权限，当前 v8 导入则保留有意分配的资格。

## 测试

真实 Gateway HTTP 测试覆盖管理员授予与撤销、严格输入拒绝、无关字段保持不变、个人用户和项目所有者请求被拒、审计记录以及访问失效。由 PostgreSQL 支撑的 HTTP 场景在第二个数据库连接上观察撤权，并检查其持久 outbox 版本。导入测试覆盖 v7 默认值、v8 保留、损坏当前格式的回滚，以及源数据库字节不变。用户页面测试覆盖两种布局的可见状态，以及通过既有编辑对话框授予和撤销资格；这些组件测试不能替代管理员页面与真实用户 Session 之间的构建后浏览器验证。
