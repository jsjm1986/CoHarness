# Agent Note：记忆整理的取消与清理

Status: implemented

[English](2026-10-23-curation-cancellation.md) | 中文

## 问题

一次整理响应可以包含多条记忆工具。只在下一次模型请求前检查取消，会让同一响应中后续工具在插件卸载后继续修改记忆。移除 Session 的运行队列还会丢失等待模型迭代器清理所需的任务句柄。

## 决定

每条工具在执行前检查队列信号。记忆服务将该信号传递至条目准入及排队中的完成游标写入，在开始持久化前检查它。活跃队列任务由独立于 Session 路由映射的集合持有，直到任务结束。卸载会取消队列并等待这些任务；一个队列在同一任务内处理待运行的捕获。最终清理只移除仍属于该队列的路由记录。

## 备选方案

**只检查下一模型轮次。** 已完成的单次响应在下一轮模型请求前，可以包含多次变更。

**只等待 Session 映射中仍存在的任务。** Session 释放会先移除映射记录，而取消中的提供方迭代器可能尚未清理完成。

## 影响

取消会阻止后续工具分发以及条目或完成游标准入，包括排在其他写入者之后的工作。已准入的耐久写入不会被回滚。插件卸载等待核心模型运行时完成取消及迭代器清理，避免留下失去所有权的后台工作。

## 验证

已构建产品的复现使用真实模型运行时及 JSON 记忆：第一次保存后卸载，两个条目仍被持久化。回归验证只保留第一条写入，并阻塞真实迭代器清理，证明整理的释放操作会等待它。headless Loader 快照在两条记忆工具之间停止真实条目，并检查耐久键和提取进度。

排队提取与条件合并游标的回归会在取消后保留原有进度。提取运行队列测试在进度排于其他写入者之后时停止 Session，等待插件释放后检查完成游标不存在。另一条 Loader 快照在整理标记之后、条目变更之前停止整理。
