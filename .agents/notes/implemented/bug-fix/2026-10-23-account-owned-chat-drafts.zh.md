# Agent Note: 账号归属的聊天草稿

Status: implemented

[English](2026-10-23-account-owned-chat-drafts.md) | 中文

## 问题

带运行时身份的 Session id 能区分共享项目，却不能识别浏览器当前账号。仅按该 id 持久化未发送草稿，会让在同一浏览器打开相同共享会话的另一位成员恢复私有文字。[辅助侧栏决策](../architecture/2026-09-23-account-scoped-auxiliary-sidebar.zh.md)为标签页元数据确立了对应的归属规则。

## 决策

Gateway 聊天持久化使用已验证的账号、运行时和原始 Session id。读取或写入要求目录中存在当前归属。未验证账号没有存储键，不能接纳旧记录，也不能在验证到达时发布尚未归属的草稿。明确声明独立运行的 Host 保留其本地存储键。

浏览器文档身份约束持有已确认账号，直到账号、凭据或 Runtime 身份明确失效。即将过期的事件流续连会撤销当前权限资格，同时保留该文档归属。Host 元数据暂时缺失不能取消待完成的 Session 导航，也不能用空草稿覆盖当前输入；私有键仍要求目录中的可见 Session 及其准确 Runtime。没有文档身份所有者的组合在上下文失效时撤销身份。

会话插件拥有持久化订阅和 store 代次。替换及插件销毁会停止旧实例写入。会话删除可在目录撤下后解析清理键，但仍限于当前已验证主体；清理不授权读取。身份先于通知发生变化时，旧实例的写入或删除不能转向另一账号的记录。

各标签页将归属记录同步镜像到 session storage，恢复时优先使用该副本，再考虑共用的 local storage 副本。新标签页从持久记录初始化自己的副本。允许恢复要求归属仍有效且保存快照完全一致；只有共用持久记录，不能证明刷新会恢复哪一页的草稿。图片、文档引用、未镜像输入、待初始化草稿和正在提交的内容保留在原标签页；空间导航提供在新标签页打开已准备目标的操作，不销毁这些输入。

旧 Gateway 记录没有账号来源证明，因此不予导入。[升级指南](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/account-owned-chat-drafts/guide.zh.md)说明如何保留所有者尚未发送的文字。

本页面仍持有输入时，侧栏保留已授权空白 Session 的入口。它观察现有 `composer` 引用计数，覆盖附件及提交中的输入，不获取 Session scope、不打开 Runtime 连接，也不读取草稿正文。目录撤下和插件销毁会移除相应订阅。分组和单列表保留同一电脑及 Workspace 归属，没有输入的闲置空白会话继续隐藏。

## 已考虑的替代方案

**复用带运行时身份的 Session 键。** 成员有意共享这些身份，因此它们不能隔离未发送的输入。

**将旧记录导入下一个登录账号。** 记录不能证明由哪个账号写入。自动导入会再次造成泄露。

**删除也要求目录中可见。** 会话移除可能先撤下目录行，再清理 store，从而遗留私有记录。

## 后果

省略持久化策略会创建仅存于内存的聊天 store。只有插件提供的已验证归属策略才能启用浏览器存储。Gateway 用户在升级前保留自己的旧草稿；独立 Host 保留本地恢复能力。浏览器存储损坏或拒绝访问时，输入区仍可在内存中使用。

## 验证

组装后的 Web profile 在同一浏览器以两个账号重新打开同一个共享会话，并记录四次访问中各自独立的草稿。Store 和 SlotRegistry 回归覆盖身份撤下、延迟通知、替换、销毁及会话删除。存储归属和聊天持久化模块接受逐文件 100% 覆盖率检查，不沿用宽泛的 GUI 组合豁免。

统一空间浏览器场景让同一会话的两个标签页保留不同草稿，只刷新和切换其中一页，保护图片草稿，并在离开原空间后完成一次真实 AgentLoop 的录制回放回合。
