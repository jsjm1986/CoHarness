# Agent Note: 保持活动会话的对话历史窗口

Status: implemented

[English](2026-08-24-live-conversation-history-retention.md) | 中文

## Problem

浏览器使用有界历史尾页来降低重新进入长对话的成本。活动会话的缺口修复却复用了尾页安装逻辑，导致模型仍在输出时已经显示的记录被移除，并出现“加载更早”控件。这个优化改变了当前可见文本记录，而不是只降低之后重新进入的加载工作。

## Decision

会话历史具有舞台保持模式。空闲舞台打开 conversation 档尾页；prompt 被接受、观察到会话运行，或进入一个已经运行的会话时，模式变为 `expanding`，并在一个可取消的后台操作中顺序拉取更早的 conversation 页面，直到[有界活动窗口记录](2026-09-03-bounded-live-window-and-incremental-reconnect.zh.md)中记载的保留上限。模型请求和实时事件流不等待该操作。走到日志头部的补齐使模式变为 `live`；补齐失败、无法前进或被上限截断时保留当前节点，并恢复普通的更早分页入口。

离开舞台中的会话时，只清除浏览器事件窗口并使进行中的历史请求失效。队列、待处理交互、投影、运行状态和 Session 对象继续保留。下一次进入舞台时重新读取尾页。Chat 与 Trajectory 标签页之间切换不算离开舞台。

缺口修复按序合并恢复的尾页、省略区间和缓冲的实时事件到已有窗口，绝不把较短尾页安装到已经打开的窗口上；尾页探测也不能把已经完整的窗口重新改成 `hasMore: true`。历史变更共用一个串行操作，因此自动补齐、手动分页、detail 补全和缺口修复不会并发发布互相覆盖的窗口。

浏览器快照发布 `historyWindowMode: 'tail' | 'expanding' | 'live'`。只有不在运行中的尾页才显示更早历史控件；补齐和 live 保持不会用分页提示替换已显示记录。

## Alternatives considered

**运行期间只隐藏更早控件。** 这只会隐藏缺失的前缀，不会恢复它，活动文本记录仍不完整，轮次结束后控件还会再次出现。

**发送 prompt 前同步补齐历史。** 这会让模型接纳等待所有更早页面，使公开路径上的历史延迟进入轮次关键路径。

**让缺口修复继续使用 `installWindow()`。** 恢复尾页只是后缀探测，不是新的舞台进入。替换窗口会丢失阅读状态，并重新产生本缺陷。

**在所有会话切换中保留完整窗口。** 这可以避免重新读取，但会破坏重新进入的成本上限，并使浏览器内存随导航无界增长。

## Consequences

即使模型正在输出或 mux 需要缺口恢复，活动文本记录仍然可读。后台历史使用 conversation 档，在页面之间让出事件循环，并在舞台变化时取消，因此不会为每个 chunk 增加请求，也不会阻塞模型。短暂的历史失败只保留可用的当前窗口，并留下手动恢复路径。

舞台切换会有意丢弃仅存在于浏览器的事件节点；重新打开会话可能先显示尾页和更早控件，直到用户展开历史或再次开始活动轮次。持久化、Session 事件格式、Host history wire 字段和模型上下文均不变。

Runtime 测试覆盖自动补齐、取消、重新进入、历史操作串行化和不收缩的缺口修复；浏览器测试覆盖活动流式输出、阅读锚点保持、隐藏分页控件以及会话切换后的尾页重载。
