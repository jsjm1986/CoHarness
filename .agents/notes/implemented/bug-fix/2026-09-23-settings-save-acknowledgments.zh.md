# Agent Note：设置保存逐项确认已提交草稿

Status: implemented

[English](2026-09-23-settings-save-acknowledgments.md) | 中文

## 问题

凭据存在性读取不能证明替换成功：写入被拒绝后，旧密钥仍然已配置。异步保存结束时清空整个表单，还会丢弃从未提交的编辑。同一凭据引用的两次读取可能倒序返回，并恢复过时状态。

## 决策

[插件卡片表单](../../../../packages/client/ui-settings-plugins/src/client/card-form.ts)只清除成功写入确认的确切草稿。拒绝、传输失败或命名空间失去写权限会停止剩余操作、结束保存状态并保留待处理编辑。凭据替换必须取得本次 RPC 的成功结果，且目标引用不能改变；凭据存在本身不足以证明成功。读取代次拒绝相同或不同引用的过时响应。

[插件自有设置决策](../architecture/2026-08-12-plugin-owned-settings-surface.zh.md)继续负责注册和展示。本决策调整确认及草稿生命周期，不引入另一套设置写入者，也不改变账户与项目归属。

## 考虑过的替代方案

**保存时禁用全部编辑器。** 这能防止并发编辑，却不能确认被拒绝的凭据写入是否成功。保留新草稿允许继续编辑，而不把它们误认为已经保存。

**任何已配置密钥都视为成功。** 这会混淆凭据存在与替换确认，并隐藏授权或传输失败。

**后续字段失败后回滚先前字段。** 字段通过独立的 revision 约束操作保存；补偿写入可能覆盖其他编辑者。表单报告部分接受，只保留待处理编辑。

## 后果

保存期间设置仍可编辑，失败写入保持可见且可重试。保存不是多字段事务。确定性的延迟响应测试保护草稿归属和读取顺序；真实组装浏览器测试覆盖设置持久化及凭据提供方拒绝，不调用模型。
