# Agent Note: 后台子代理清理保持可重试

Status: implemented

[English](2026-11-01-subagent-job-cleanup.md) | 中文

## 问题

子级结果可能已经结算，但其连接或原生进程仍需释放。释放被拒绝后立即报告 Job 失败，会关闭任务的终止控制，并在没有确认资源释放时发布持久化结局。子代理服务保留的 run 会继续阻止空闲释放，却不能为 Job 提供另一次清理尝试。

## 决策

一次性后台 Consumer 保留已发布的 run，直到释放成功。失败会发布清理尚未确认的进度提示，并使 `JobHooks.done` 保持等待。另一次终止请求会重试同一个 run 的清理。释放尚在等待时收到的请求会保留为一次合并后的重试，直到失败尝试进入重试等待。重试开始前的请求会合并；再次失败时保留占用，直到另一个显式终止请求到达。确认释放后才允许产生一个失败的 Job 结果，保留独立的结果错误详情，且不交付子级回答。

现有结果映射器接收一个等待清理确认的释放函数。它的公共 API、子代理提供方和 Job 协议保持不变。[后台注册决策](../feature/2026-07-08-background-subagent-tasks.zh.md)仍负责调度、权限和结果交付；[工作流清理决策](2026-11-01-workflow-cleanup-ownership.zh.md)独立负责 WorkflowPtc 子级保留与工作流记录。

## 考虑过的替代方案

**立即结算为失败。** 失败记录描述结果，不能证明资源释放，也不能为已终止 Job 保留终止控制。

**拒绝完成 Promise。** 注册表的异常收容同样会终止记录，生产者的清理义务仍未履行。

**自动重试或遗忘保留的 run。** 自动重试需要新的策略。遗忘 run 会丢弃唯一能够确认资源释放的持有者。显式终止沿用现有控制操作。

## 影响

清理持续失败时，所有者与服务的释放可能一直等待，直到另一次终止尝试成功。Consumer 不设放弃清理的期限。不改变事件、传输字段、Session 代际文件或数据库 schema。

## 验证

提供方受控用例覆盖结果完成、结果被拒绝、释放同步抛错和无法渲染的异常。内置 SDK profile 在清理失败期间保留自有 HTTP 子级响应，不发布持久化 Job 结局；重试终止后，观察到连接实际关闭，再产生唯一的失败结局。两个 SDK 固定进度与终态详情。完整的原版 Consumer 会提前结算，无法通过相同断言。

屏障把任务、所有者和注册表终止放在一次仍等待且随后失败的释放期间。重复请求会合并，再次失败后 Job 继续存活，直到新的终止请求到达。SDK 用例在一次待处理终止请求后关闭自有原生响应，并保留子级结果已完成或被拒绝时的诊断。
