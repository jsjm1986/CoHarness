# Agent Note：管理端 SPA 缓存策略与区块内控件行

Status: implemented

[English](2026-10-09-admin-shell-cache-and-section-layout.md) | 中文

## 问题

三处缺陷导致管理端把内容贴着甚至渲染到区块卡片边缘之外。`serveAdmin` 不发送任何 `cache-control`，启发式缓存可能在版本切换后钉住 `index.html`：旧外壳继而引用已不存在的哈希分块，过期或残缺加载的 bundle 把控件画在卡片外。`Section` 直接裸渲染子内容，留白的 `.sectionBody` 条带成了每个页面自己的义务——多数区块没有补，自由内容（字段、徽标、段落、操作行）全部贴着卡片边缘。另外，两个页面的操作位没有遵守共享的行容器约定：插件页的管理对象选择器让裸 `Button` 直接贴着 `Field`，没有任何行容器；部署页的维护表单把提交操作作为 `formGrid` 里的裸单元格，浮在输入框旁边而非与之对齐。

## 决策

`serveAdmin` 为每个管理端响应发送显式缓存策略：SPA 外壳与错误响应携带 `no-store`；被服务的文件（`assets/` 下按内容哈希命名）携带 `private, max-age=31536000, immutable`。`private` 让需要鉴权的 bundle 不进入共享缓存。

管理端构建提前压缩 JavaScript 和 CSS，冷请求可以直接使用 gzip，压缩工作在构建阶段完成。两种响应都使用源文件的 MIME 类型，并通过 `Vary: Accept-Encoding` 区分缓存。构建缺少对应压缩文件时，协商回退到原文件。

首屏包包含默认的用户管理页。用户列表成功加载、部署上下文就绪，且页面有机会绘制后，后台任务会启动与导航共享的模型治理动态导入。页面隐藏、浏览器离线或启用流量节省时跳过。离开用户管理会取消尚未启动的任务。模型治理页面挂载时才发起模型 API 请求。

模型治理导航会复用后台发起的动态导入。导入失败会释放共享的 Promise，导航可再次请求模块。若导航导入失败，页面保留目标地址并提供重新加载操作。版本发布替换分块或浏览器缓存模块加载失败时，重新加载会取得最新外壳。其余次级路由在匹配时导入各自页面。

模型治理路由加载组织模型目录和编辑器。目录渲染就绪快照且模型列表加载后，首个动画帧会排入「权限与计价」与「个人登记」共用的后台导入。用户模型权限读取填充例外配置控件，可以与导入并行完成。用户管理页的后台准备会留出两个动画帧。浏览器没有任务调度器时，两处都使用可取消的定时器。打开页签即请求对应数据，与共用分块的导入并行。活跃页签在导入期间显示加载状态，导入完成后通过普通状态更新渲染组件，避开 React 在 Suspense 占位近期出现后对提交的 300 毫秒节流。导入和梳理读取只更新发起它们的页签选择。首次渲染权限与计价页签时会使用已返回的梳理配置，同一次打开期间的后续渲染保留表单状态。[React 重试调度源码](https://github.com/facebook/react/blob/v19.2.0/packages/react-reconciler/src/ReactFiberWorkLoop.js#L1348-L1399)

目录编辑器直接调用设置包的[同步 schema 操作](../../../../packages/client/ui-settings/src/client/schema-operations.ts)，设置服务也委托给这套操作。两个编辑器共用 schema 和路径编辑逻辑，模型页只加载独立编辑器的依赖。

留白划分由 `Section` 承担：子内容默认渲染进 `.sectionBody`，`flush` 标记刻意通栏到卡片边缘的区块——表格、筛选条、批量操作条、指标网格与移动端列表都自带留白。flush 区块里裸放的横幅与段落仍获得两侧外边距，漏标条带也不会贴到边框。混合区块用 `flush` 配合显式 `.sectionBody` 条带包住说明文字与操作行。

字段与操作配对的控件放进专用行容器：插件页的对象选择与重新读取共享 `.targetPicker`（底边对齐的 flex 行，窄屏下换行），部署页的维护提交放在字段下方的 `.formActions` 中。

## 备选方案

**给外壳本身加指纹。** 否决：外壳的文件名就是它的 URL，`index.html` 用 `no-store` 加内容哈希资产是标准做法，代价只是每次导航多一次条件请求。

**插件选择器复用 `.filterPanel`。** 否决：该类的 filter-grid 间距为多控件筛选条而调；专用的双项行容器让选择器保持最小化，同时沿用同一底边对齐约定。

**只给涉事区块补留白而不动组件。** 否决：逐页补留白正是漂移的成因——默认包裹让贴边布局无法再被引入，`flush` 则把条带契约显式留在每个调用点。

## 后果

版本切换不会再让被钉住的外壳指向已删除的分块；每次导航都会重新验证外壳，而哈希资产保持缓存。自由区块内容默认获得留白，只有 `flush` 区块能触到卡片边缘，通栏条带因此保持显式。表单操作在桌面端与字段对齐，在手机端收进卡片内换行。凡是字段与操作配对的新区块都应复用这些行容器，而不是平铺裸控件。

## 验证

`gateway/tests/admin-static.spec.ts` 断言外壳和资产的缓存策略、GET 与 HEAD 的 gzip 协商，以及压缩文件解析到资产根目录之外时的回退。`apps/web/tests/admin-layout.e2e.ts` 通过鉴权 HTTP 驱动构建产物，断言重新读取与维护按钮在桌面端与各自字段同行底边对齐、自由字段距区块边缘至少 `16px`，并在 `390px` 下保持在各自区块卡片内、无页面级横向溢出。

浏览器套件会分别暂停用户列表和模型目录请求，验证每次后台导入都在对应页面渲染后启动。单独暂停用户模型权限读取，验证页签脚本可以先于例外配置数据到达。用例验证导航复用脚本、发起首次模型 API 读取，并在脚本不可用时提供重新加载操作。暂停共用脚本时，各页签仍可完成数据请求。放行脚本后，权限与计价页签首次渲染就包含梳理配置控件。

`gateway/admin-ui/src/components/async-route.spec.tsx` 驱动动画帧回调，验证每次准备何时入队，以及回退定时器的取消。
