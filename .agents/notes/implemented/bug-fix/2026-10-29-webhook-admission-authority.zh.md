# Agent Note: Webhook 准入保留管理员与端点资格

Status: implemented

[English](2026-10-29-webhook-admission-authority.md) | 中文

## Problem

Webhook 管理请求等待期间，HTTP 认证之后的账户或成员资格可能被撤销。端点修改、特权元数据读取和手动重新派发因此可能使用过期的管理员身份。提供方签名验证也会捕获一份配置，而该配置可能在持久化派发预留前被停用、删除或替换。无法在 JSON 序列化中保留的解析数字还会改变存量事件和后续重放。

## Decision

[端点管理](../../../../gateway/src/postgres/webhook-endpoint-service.ts)与[回执诊断](../../../../gateway/src/postgres/webhook-delivery-service.ts)通过企业、账户和成员资格共享锁保留当前管理员权限。认证后的公共 id 是显式服务参数。修改和读取在事务结束前保留该资格；重新派发在配置查询后的新预留创建时再次核验。较早的 HTTP 角色不能授权后续数据库工作。

投递预留在分配接收额度或回执前保留有效企业，以及精确的端点版本、执行账户和目标。提供方准入要求端点已启用。准入前提交的配置变更会被拒绝且不生成持久化预留；已接受的工作在冲突的端点变更提交前完成。规则版本不符返回409供提供方重试；企业或端点不可用返回404。网络派发期间不保留数据库事务。

解析后的提供方载荷在分配接收额度或回执前满足共享的无损 JSON 规则。非有限数字和负零返回400，而不会在存储时发生变化。普通有限 JSON 值在重放中保留解析后的值，与原始 GitHub 适配器一致。

管理员手动重新派发可以使用已停用端点的当前配置。该显式重放权限不会重新开放公开接收。新回执在提交前同时保留当前发起管理员和已捕获的端点版本。配置轮换后，存量回执、别名与正文去重仍保留；按当前配置验证的重试仍可复用原回执而不再次派发。

[执行身份决策](../architecture/2026-09-23-webhook-execution-identity.zh.md)继续定义执行账户资格、限定用途主体、用量归属和运行时派发。[仓库筛选](../feature/2026-09-25-webhook-structured-repository-filter.zh.md)保留独立的匹配语义。两份记录均未被完全取代。

## Alternatives considered

**在派发前一直信任 HTTP 管理员或已验证签名。** 认证证明的是较早的观察结果；数据库和请求正文等待可能超过其有效期。

**只检查端点仍存在。** 同一行可能已经具有另一密钥、执行者、目标或停用状态。已捕获版本必须仍是当前版本。

**在运行时 HTTP 期间保留管理员和端点锁。** 远端延迟会阻止资格撤销。网络派发开始前，已提交的预留记录已接受的工作。

## Consequences

自定义 Gateway 服务为端点管理、诊断读取和重新派发传入服务端认证的管理员 id。请求 JSON 字段和数据库 schema 保持不变。部署使用当前配置重试提供方409响应。管理请求403要求恢复有效管理员资格。持久化回执仍然证明准入，不证明 Agent 成功。

## Verification

认证 Gateway 回放覆盖八类管理操作的六种资格撤销状态、当前管理员对照、提供方配置撤销和停用规则的显式重放。真实 PostgreSQL 测试覆盖旧预留拒绝、行等待期间资格保留，以及角色或规则变更后的重新派发。无密钥源码与构建回放不使用真实提供方凭据或模型 API。
