# Agent Note: Gateway 部署环境不进入运行时继承

Status: implemented

[English](2026-10-25-gateway-runtime-environment.md) | 中文

## 问题

本地启动器移除名称类似凭据的变量，却继承 `HGW_DATABASE_URL`、其他 Gateway 设置和通用数据库 URL。即使 Gateway 凭据只授予一个运行时代次，运行时工具或插件仍能读取这些继承值。独立监督进程也会收到 Gateway 启动环境。

## 决策

本地 Runtime、监督进程与受管隧道子进程环境均排除 `HGW_*` 部署配置、`DSH_*` 状态，以及名称包含 `KEY`、`PASSWORD`、`SECRET`、`TOKEN`、`CREDENTIAL` 或 `DATABASE_URL` 的变量，另排除 `PGPASSFILE`。前缀与凭据名称匹配不区分大小写。过滤后，启动器显式提供运行时 HOME、私有 DSH 路径和凭据描述符；恢复能力凭证通过私有 IPC 传递，不放入环境变量。

普通主机工具设置继续继承，包括 PATH 和代理配置。运维选择的 `HGW_DEFAULT_ENV_FILE` 与运行时自己的配置文件仍为显式输入。这项变更作用于 Gateway 托管的启动继承；独立凭据提供方的[环境来源决策](../architecture/2026-07-30-credential-boundaries-and-atomic-registration.zh.md)继续适用于独立组合。

隧道 PATH 查找、所选二进制版本探测和归档解压使用相同的环境过滤。即使连接器尚未运行，发现过程也会执行能够读取自身环境的代码。

## 考虑过的替代方案

**只移除 `HGW_DATABASE_URL`。** 其他部署变量与凭据别名仍会到达运行时；部署前缀属于 Gateway。

**为全部主机环境变量建立允许列表。** 这要求维护与问题无关的语言区域、证书、代理和工具链设置。过滤所属前缀与已知凭据名称，可以处理已观察到的继承缺陷，而不替换主机工具配置。

**隐藏读取环境的工具。** 插件与子进程能直接读取自己的环境，工具呈现规则无法移除继承的权限。

## 后果

Gateway 部署设置不能通过环境继承为运行时提供配置。确实需要数据库或云设置的负载使用自身的显式配置。名称过滤无法识别藏在任意别名下的秘密，也不会在共用本地主机账号的进程之间建立 OS 隔离。

## 验证

父进程提供虚构值，真实 Node 运行时只记录变量是否存在。回归在修复前暴露五个保留、数据库或凭据变量，修复后均不暴露，PATH 仍可使用。编译产物启动器验收通过独立监督的进程检查同样的隔离。真实隧道进程通过经过认证的管理员动作检查共用过滤。真实 Web 配置装配覆盖 Gateway 登录访问、资源注册，以及个人和共享项目运行时的恢复。

可执行 PATH 与版本夹具只记录虚构凭据是否存在。版本回归在修复前暴露部署变量，修复后均排除。
