# Agent Note: 模型能力选择提示

Status: implemented

[English](2026-09-01-model-capability-feedback.md) | 中文

## Problem

模型选择器已经收到输入模态元数据，但包含图片的对话选择纯文本模型时只显示笼统的操作失败。用户需要自行判断哪些模型可以继续当前对话，也不知道失败的选择是否已经生效。

## Decision

选择器以每个目录行的 `inputModalities` 作为能力依据。目录明确声明支持图片的模型标记为“支持图片”，明确声明纯文本的模型标记为“仅文本”，未声明的模型不做标记。共享的会话级目录把宿主返回的图片历史拒绝转换为本地化恢复提示，说明目标模型，并建议选择支持图片的模型或新建纯文本对话。其他选择失败保留错误码和诊断信息。本次改动不增加会话扫描、wire 字段、持久化字段或数据库操作；被拒绝的选择仍保持当前模型和图片历史不变。

## Alternatives considered

**从模型名称推断能力。** 否决：提供方自有 id 不包含可靠的输入约定。

**在选择前扫描完整客户端对话并禁用目录行。** 否决：这会重复宿主的权威图片检查，并使每次模型目录渲染的成本随已加载历史增长。

**立即引入新的公共 RPC 错误码。** 暂缓：现有宿主消息已经能识别该情况，界面无需扩大 wire 词汇即可提供清晰的恢复提示。

## Consequences

用户在提交前即可理解模型选择，拒绝切换时会得到明确的下一步，不会误以为发生数据丢失或提供方故障。未声明输入模态的提供方在呈现上保持保守，界面不会宣称无法验证的能力。共享目录使 popup 和 composer 的提示一致，同时保留现有选择与持久化语义。

## Verification

浏览器插件测试覆盖能力标记，以及两个模型选择入口对图片历史拒绝的本地化提示。组件测试覆盖标记和更新后的操作文案。组装的 `declared-reasoning` Web 场景通过真实模型选择器记录并回放能力标记。契约类型检查与契约 lint 通过；组装 bundle 的完整 GUI 与 Web replay 检查仍由发布验证流程负责。
