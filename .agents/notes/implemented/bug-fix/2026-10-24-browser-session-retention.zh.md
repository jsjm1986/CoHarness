# Agent Note: Gateway 滑动会话的浏览器保留期限

Status: implemented

[English](2026-10-24-browser-session-retention.md) | 中文

## 问题

活动用户通过认证时，数据库空闲过期时间会滑动续期。浏览器 Cookie 若在最初的空闲截止时间过期，就会在数据库会话仍有效时丢弃令牌，迫使活动用户提前重新登录。把受支持的不足一秒期限向下取整，也会发出立即过期的 Cookie。

项目作用域 Cookie 也会将绝对有效期向下取整。因此，受支持的不足一秒配置会立即移除已选择的项目，即使登录令牌仍可用。

## 决定

新发出的会话与作用域 Cookie 使用配置的绝对期限，向上取整到整秒。PostgreSQL 继续决定滑动空闲期限与最初的绝对截止时间。清除会话 Cookie 时发出 `Max-Age=0`。浏览器保留期限不会延长或恢复数据库的任何截止时间。

## 曾考虑的替代方案

**只保留 Cookie 到空闲期限。** 数据库续期无法更新浏览器独立固定的 Cookie 截止时间。

**在每个 HTTP 响应中刷新 Cookie。** 通过 WebSocket 发生的活动需要另设续期机制。绝对保留期限无需依赖响应头续期，即可覆盖两种传输方式。

**活动时延长服务端绝对截止时间。** 这会移除单次登录可授权请求时长的配置上限。

## 后果

活动浏览器会话在服务端允许的绝对期限内保留令牌。即使客户端仍发送令牌，空闲或绝对过期后也无法通过认证。部署前发出的 Cookie 保留原有的浏览器截止时间，直到再次登录。真实 HTTP 快照仅伪造 Date 时钟，无需按实际时长等待，即可覆盖活动续期、空闲与绝对过期拒绝、不足一秒期限保留及注销清除。运维人员可阅读[升级说明](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/browser-session-retention/guide.zh.md)。

真实项目选择 HTTP 场景验证 900 ms 绝对有效期下的作用域 Cookie 保留、后续选择项目的请求，以及服务端过期后的拒绝。运行时启动受控；真实 Gateway 认证、项目服务、作用域选择和请求上下文仍按实际组合运行。
