# Agent Note: 整理在发送与游标准入期间保留签发方

Status: implemented

[English](2026-11-01-memory-curation-authority.md) | 中文

## 问题

project 整理可能等待目录读取、模型容量、响应、工具或串行游标队列。初次记忆资格检查无法授权后续发送或完成进度。记忆资格撤回后，通用模型执行权限仍可能存在。替换后的执行服务不得把自己的权限或操作者出借给其他签发方捕获的工作。

## 决策

每个遍保留捕获时的执行服务与参与者。异步工作后的可用性检查将当前服务的原始 Cordis 身份与签发方比较。project 资格在每轮模型请求前、响应后，以及游标写队列中持久化之前重新检查。游标服务在队列和存储等待结束后执行可选的 `beforeCommit` 回调，再次检查取消，并在持久化前立即调用返回的同步检查；回调不能在同一写链上排队写入。

插件持有一个 `AsyncLocalStorage` 实例，在既有 `runCaptured` 生命周期中传递捕获的回合。其 `llm/pre-dispatch` 监听器在容量准入后、适配器实际发送请求前复核该操作。无关请求没有整理上下文。Session id 注册表或当前浏览器身份都不能替代捕获的参与者。复核使用原始签发方，在授权返回后再次比较身份，并且不会将工作转移到替代方。

这些权限检查不获取模型许可，也不报告用量。请求保留原有计费依据、精确日志输入和执行资源归属。已经发送的请求继续由其提供者清理持有方负责；拒绝会阻止结果开启下一轮或提交完成进度。已准入的耐久条目写入保留其既有结果。设置取消仍遵循[独立操作生命周期](2026-10-31-memory-curation-live-availability.zh.md)与[提供者可用性通知](2026-11-01-memory-provider-availability.zh.md)。

## 考虑过的替代方案

**使用通用执行权限。** project 记忆还要求记忆资格与符合条件的会话可见性；仅有执行权限无法证明这两点。

**只在调用模型服务或将游标入队前检查。** 容量等待与串行存储等待可能超过检查的有效时间。实际发送和提交准入必须复核当前授权。

**每轮查找当前签发方或 Session 操作者。** 替代方可能证明不同操作者。操作应保留捕获的签发方，并在替换时拒绝，而不是转移身份。

**授权所有共享 Session id 的请求。** 召回、主请求与多个捕获回合可能重叠。操作的异步上下文标识其自身发送，不改变独立请求。

## 后果

project 资格撤回或签发方替换后，未完成审查仍可由后续获准遍处理。共享条目仍按既有成员权限读取。不改变模型授权、额度、计费格式或 Session/存储模式。可选回调扩展内部游标 API；仓库内所有消费者继续保留取消与提交顺序。更大范围的 Gateway 成员资格、物理电脑与生产验收仍是独立审查工作。

## 验证

真实 LLM 测试在资格撤回或签发方替换期间保持目录读取、容量许可、模型响应、适配器准备和游标队列等待，并在任务完成后断言实际发送、许可释放与耐久游标结果。被替换签发方迟到的授权结果会被拒绝。实际 SDK 进程通过真实模型准入与工具轮次执行提取和整理，保留原始操作者与精确日志请求。完整的私有前版本包在不编辑活动源码的情况下复现过期发送、额外模型准入或游标推进。既有正常整理和辅助请求快照继续提供回归覆盖。
