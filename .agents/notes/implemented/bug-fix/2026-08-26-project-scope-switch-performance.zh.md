# Agent Note: 让重复的项目作用域重载保持轻量

Status: implemented

[English](2026-08-26-project-scope-switch-performance.md) | 中文

## Problem

项目作用域切换使用独立 Runtime 并重载 Web 页面。每次重载都可能向同一个仍在运行的 Runtime 请求相同的对话详情尾页。即使追加日志和 presenter 注册没有变化，Host 仍会为每次请求复制并分页整个内存事件日志。Gateway 的账户上下文也会在成员查询已经建立授权集合后，再为每个成员项目单独查询详情。

## Decision

Host ApiProxy 为 Web 的 `detail: 'conversation'` 尾页维护每个 Runtime 一份有界 LRU。条目只有在已附加/分离的来源类型、会话追加日志身份、请求的 `maxMessages` 和投影注册集版本都相同时才有效；分离来源还必须匹配持久化版本，因此重复冷读可以只检查轻量版本而不再次加载完整事件日志。值在写入和读取时都会复制，最多保留 16 条、总 JSON 大小 2 MiB；会话事件、会话销毁、工具注册表变化或投影 key 变化都会清除相关条目。带 `beforeSeq` 的分页和 `detail: 'full'` 请求继续走原有未缓存路径；历史协议值和分页规则不变。

投影注册表提供单调递增的注册集版本。只有投影 key 加入或离开注册表时才递增，因此缓存的历史块不会跨越可出现在该块中的 key 集变化。

Gateway 上下文接口复用请求分派时解析的所选作用域。`projectForUser` 从已授权的项目行返回管理权限和可选主题元数据；PostgreSQL 在成员关系 SELECT 中计算 owner 资格并读取主题，不查询或物化完整成员名单。代理准入和事件流续租分别保留新鲜权限读取及既有的等待后检查。项目 id 直接用于该查询的过滤。公开项目列表显式投影现有字段，不暴露内部权限元数据。成员关系解析后，上下文接口通过 `getScopeMetadataByIds` 批量读取 owner、来源和主题字段，范围限定为当前节点上挂载的活动项目；此投影不加载或计数成员。未提供该可选方法的服务保留批量详情／目录路径，缺少 owner 元数据的旧版行保留单项详情回退。授权输出、成员语义和作用域 Cookie 均保持不变。

前端静态服务器把 `/assets/` 下符合 Vite 内容哈希命名的文件标记为一年期 immutable。HTML 入口和未带哈希的文件保持原有响应头，因此版本选择和 index 注入不变。

## Alternatives considered

**用热切换连接替换独立 Runtime 和整页重载。** 本次不采用，因为这会改变进程隔离、连接所有权、草稿生命周期和失败处理；现有作用域交接仍是权威路径。

**本次直接改成 PostgreSQL 只读取历史尾部。** 暂缓，因为消息边界分页、替换来源引用、preset 重建和投影切面需要单独的持久化读模型约定。本次缓存不改变这些语义即可消除暖 Runtime 的重复工作。

**使用无上限历史缓存。** 不采用，因为项目 Runtime 可能服务很多会话，单个大型工具结果也可能让一页很大。LRU 的条数和字节上限限制保留内存，复制则防止调用方修改缓存值。

**跨请求缓存项目授权。** 不采用，因为成员、owner、角色和主题变化必须通过当前读取到达准入及续租。窄范围的已授权投影可以消除无关的成员名单处理，而不保留授权结论。

## Consequences

当目标会话未变化且 Runtime 仍在运行时，重复重载可以跳过 Host 侧的历史复制、分页扫描和 presenter 计算；重复冷读只需轻量检查持久化版本，也可以避免重新加载完整分离日志；带哈希的前端资产也会在浏览器或 CDN 缓存中跨重载保留。冷日志或已变化日志的第一次读取仍走原有完整日志检查和 presenter 路径，只增加用于缓存安全的元数据版本检查。缓存失效采取保守策略，因此不会在注册表或事件变化后提供旧投影或旧工具视图。每次项目权限构造使用一次成员关系 SELECT，输出大小不随成员数量增长；项目管理仍可读取完整成员名单。PostgreSQL 上下文项目目录在成员关系解析后只读取一次元数据，工作量随可访问项目数增长，而不随其成员总数增长。返回的项目和管理标记保持不变，旧版服务保留详情回退。持久格式、wire schema、权限规则、Runtime 隔离规则和整页重载行为均不变。

聚焦的 ApiProxy、投影注册表、Gateway 和协作测试覆盖缓存失效及上下文行为；缓存只是优化，所有未命中仍使用原有历史实现。
