# Agent Note: 所属任务生命周期记录

Status: implemented

English | [中文](2026-10-26-owned-job-lifecycle-records.md)

## 问题

任务可以在模型未读取输出的情况下结束。仅靠工具调用与完成通知，无法确定注册时间、终止时间、原始所有者，以及生产者是否报告了结果。已声明的任务事件需要实际写入方，独立于模型收集和浏览器实时观察保留这些事实。

## 决策

本地注册表将已有的 `job/registered` 与 `job/settled` 事件追加到确切所有者的会话。两者使用同一注册表生成的任务 id。注册记录在生产者接受工作后、同步注册表观察者运行前写入；结算记录在释放等待方或宣布完成前保存第一个终止结果。无主工作没有所有者会话，因此不写入这两种记录。

注册表在调用生产者前捕获创建任务的工具调用。Bash、一次性子 agent、工作流和终端发送提供确切调用 id 与根调用 id，使嵌套执行保留模型请求的根调用。即使后续工作改变了调用方状态，两种生命周期记录仍保留该归属。记录不包含输出字节，也不消耗模型的输出游标。

只有 `done` 成功履约时，`producerReported` 才为 true。Promise 被拒绝或清理强制失败时记录 false。此标记确认生产者作出了报告，不证明故障提供方释放了全部资源。首次结果优先的结算可防止延迟完成覆盖强制失败。

记录失败会通过受隔离的异常文本转换写入日志。已接受的工作保留清理与等待方释放路径，因此日志失败不会在启动后抛错而使生产者失去可控制的任务记录。此类失败后，会话历史可能不完整；缺少记录不能证明工作从未运行。这些事件只提供历史证据，不授予恢复或控制任务的权限。

事件中心先预留每条通知的位置，再发布对应的会话记录。同步日志观察者与注册表观察者可以产生更多事件，但所有匹配的订阅者先收到前一条通知。终态在日志观察者运行前提交，因此观察者取消待处理的等待时，不能用等待取消错误覆盖已提交的结果。工作仍在运行时，注册表依然拒绝被取消的等待。

## 考虑过的替代方案

- **仅使用工具调用和通知。** 主机直接注册与未被收集的完成缺少可靠的生命周期配对。专用的仅日志事件可保留事实，而不增加模型上下文。
- **日志追加失败后抛错。** 生产者已经拥有执行资源。拒绝交付其公共 id 会破坏注册表对已接受工作的清理保证。
- **连同生命周期一起持久化输出与实时控制。** 输出保留和执行所有权具有不同的生命周期。[浏览器实时列表](../feature/2026-08-08-web-background-job-display.zh.md)与[通用运行时](../architecture/2026-06-20-generic-long-running-tool-runtime.zh.md)继续承担各自职责。

## 后果

会话持久化与 fork 会保留历史执行事实，而不重新启动工作。任务控制与输出仍属于当前进程。已有事件字段与会话格式保持不变。

## 验证

注册表回归覆盖观察者顺序、原始归属、时间戳、未读输出、生产者确认、强制失败、延迟完成、追加失败隔离，以及终态日志观察者触发的取消。真实 Loader 示例运行 Bash 进程和 PTC 工作流、收集结果，并将物理 JSONL 文件中的八对生命周期记录与实时会话进行比较。其中的日志观察者立即取消一个新任务，同时注册表观察者追加输出，以此验证两套观察者之间的注册、停止和输出顺序。

快照比较规范化服务自有的生命周期时钟，同时保留归属、状态、原因、确认标记和任意载荷文本。时间戳准确性由注册表测试验证，不从规范化后的文本推断。

TypeScript SDK 通过随附 profile 记录真实 SDK 子级失败，并在协议文本记录中保留两条生命周期记录。Python SDK 通过构建后的 CLI 运行同一组合，检查原始归属、调用 id、时间戳顺序和子级运行诊断。源码以及 Node 22/24 构建产物的 SDK 回放保留子级模型失败，不会用初始化失败替代它。
