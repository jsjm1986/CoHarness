# Agent Note: 恢复文档目录已确认的日志前缀

Status: implemented

[English](2026-11-21-document-catalog-recovery-gap.md) | 中文

## Problem

文档存储在目录确认后回收日志前缀。较旧的目录可能丢失这段记录，而对应文档文件仍完好。上传客户端需要明确的恢复错误，以区分缺失记录和临时投递中断。

## Decision

接收方所需记录已回收时，[本地日志](../../../../packages/attachment/userdoc-local/src/projection.ts)报告准确的身份根、接收游标、本地已确认游标和本地最新位置。[Gateway](../../../../gateway/src/documents-local.ts)将这些位置保留在运维日志中，向有权限的上传调用方返回稳定的恢复错误。检测到缺口后，Gateway 拒绝在受影响的已打开范围为新上传分配会话。后续投递验证历史成功后解除限制。

## Alternatives considered

**推进目录游标。** 这会跳过携带创建者、发起人和所有权依据的生命周期变更。

**根据当前文件重建目录。** 当前文件清单缺少恢复历史所需的早期文件实例、所有权转移及回收站决策。

**每次启动上传前读取目录。** 这会为所有正常范围增加一次网络请求。开始上传时复用正常投递已确认的故障状态。

## Consequences

拒绝新请求时保留已有上传清单、文件和剩余日志记录。下载继续使用当前授权及文件系统身份。文档管理器保留已完成文件，并请用户先联系管理员。恢复需要同一身份根的缺失记录。找回记录后，可通过正常投递确认同一个上传。
