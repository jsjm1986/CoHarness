# Agent Note: 完整写入子进程恢复文件

Status: implemented

[English](2026-10-25-subprocess-complete-spill-writes.md) | 中文

## Problem

同步文件系统写入可能只接受请求中的部分字节。子进程收集器将 spill 文件作为完整输出流提供给读取方，因此即使内存尾部和总字节计数准确，忽略返回的写入字节数仍会产生不完整的恢复文件。

## Decision

[本地子进程收集器](../../../../packages/subprocess/subprocess-local/src/output.ts)按实际写入字节数推进，覆盖溢出之前缓冲的字节和后续流分片。零进度进入既有 spill 失败流程：丢弃不完整文件、报告一次失败，并保留内存尾部。不完整文件不能作为完整输出的定位符发布。

[工具结果 spill 策略](../architecture/2026-07-08-tool-output-spill-files.zh.md)负责另一套存储 seam，与原始子进程流收集保持独立。

## Alternatives considered

**假定成功的系统调用已经写入整个缓冲区。** 调用返回的字节数才是已经确定的进度。部分写入不一定抛出异常。

**将部分文件保留为恢复产物。** 读取方无法从声称完整的文件中恢复被遗漏的 stdout。完整恢复失败时，仍可以使用有界尾部。

## Consequences

部分写入需要额外的同步系统调用，并保留既有输出上限。零进度会触发一次被隔离的文件系统失败，避免忙循环和错误的恢复路径。进程及其内存输出仍能在该失败后继续运行。

## Verification

真实文件测试对溢出前前缀和后续分片强制施加部分写入及停滞。无密钥 Loader 组合启动真实 Node 子进程，仅对其恢复文件描述符施加部分写入，并记录完整文件内容、内存尾部和进程完全停稳状态。收集器连同这些 I/O 失败情况一起接受 POSIX 逐文件覆盖检查。
