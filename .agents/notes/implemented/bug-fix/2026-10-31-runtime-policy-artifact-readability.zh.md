# Agent Note: Runtime 策略代码可由其执行账号读取

Status: implemented

[English](2026-10-31-runtime-policy-artifact-readability.md) | 中文

## 问题

以 root 运行的 Gateway 将策略包复制到私有项目 profile 后，库目录可能无法由分配的 Unix 账号遍历。文件存在，特权构建检查也能读取，但 Runtime 无法导入模型治理或目录保护插件。必需策略代码能否加载，不应取决于发布目录权限或继承的目录权限。

## 决策

`InstanceManager` 在发布策略包前，先设置其私有暂存副本的访问权限。目录使用0755、普通文件使用0644、源文件包含执行位时使用0755。遍历只接受普通文件和目录，遇到其他条目就拒绝发布。此处理覆盖嵌套代码库、补丁、包清单与语言元数据，源发布目录保持不变。

[Profile 解析决策](../architecture/2026-10-13-profile-package-refresh-and-manifest-invalidation.zh.md)继续有效：它管理包代次与缓存，本记录管理发布后策略副本的文件系统访问。

## 考虑过的替代方案

**放宽整个 Runtime 主目录的权限。** 这会暴露与可执行策略代码无关的私有数据。

**以 root 运行项目。** root 访问会绕过预期的执行账号隔离。

**依赖发布目录或进程 umask。** 副本可能继承不同目录权限，其 UID 也可能不同于 Runtime。

## 后果

只规范暂存包的权限。Runtime 主目录、受管清单、用户文件、生成的策略和凭据保留现有归属与私有权限。库可读不代表其他账号能够穿过其私有父目录访问。此处理不替代项目所有权准备，也不证明其他必需插件失败时 Runtime 已就绪。

## 验证

实例回归发布受限源代码库，覆盖嵌套代码、语言文件与可执行辅助程序，并保留私有 Runtime 父目录。Gateway HTTP 回放在隔离进程中设置严格 umask，通过公开生命周期启动真实承载进程，记录发布代码权限以及保持不变的私有权限。旧 Gateway 构建产物无法通过该回放。真实 Linux 验收使用同一项目分配的 Unix 账号读取策略入口，并在模型执行前检查插件激活。
