# Agent Note: 回收节点本地实例端口

Status: implemented

[English](2026-08-28-reclaimable-instance-port-allocation.md) | 中文

## Problem

Gateway 运行时端口以前总是分配为计算节点上现有最大端口加一。删除项目和逻辑删除用户会留下永远不会重用的空洞。账号或项目反复 churn 后，即使低位端口仍然空闲，也会最终耗尽 65535。

## Decision

PostgreSQL 用户创建、项目创建和启动时的补齐逻辑都会在持有现有节点范围事务 advisory lock 时，从 `HGW_INSTANCE_PORT_BASE` 起选择第一个空闲端口。有界查询会检查节点/端口唯一索引，并为一次补齐批次需要的数量一次性保留候选端口。SQLite 兼容提供方在自己的事务中采用相同的第一个空闲规则。运行时停止后，逻辑删除用户会删除其运行时实例行并释放端口；审计、用量、对话和 home 记录仍然保留以供历史查询。

当配置范围内没有空闲端口时，分配器会返回明确的节点耗尽错误。它不会分配低于配置下界或高于 65535 的端口，数据库唯一约束仍然是未经过分配器的其他写入方的最终保护。

## Alternatives considered

**继续使用 `MAX(port) + 1`。** 放弃，因为单调分配会把普通的用户和项目 churn 变成永久端口耗尽，即使存在空洞也无法恢复。

**新增独立的可复用端口表。** 放弃，因为这会引入另一套状态机和恢复路径；现有实例行及节点/端口唯一索引已经是权威占用集合。

**保留已删除用户的实例行作为历史记录。** 放弃，因为实例分配属于运行时状态而不是用户历史。删除该行可以释放端口，同时不删除说明账号过去活动的持久记录。

## Consequences

端口分配最多扫描配置的 1024–65535 范围，并通过节点/端口唯一索引检查占用。分配仍按节点串行，因此并发的用户、项目和启动写入不会选择同一个候选端口。已删除用户的 `instances` 行不再可供运行时查询，调用方必须把该账号缺少实例行视为已停止或已解除部署。

## Verification

SQLite 服务测试覆盖账号删除后的端口复用；PostgreSQL 集成测试覆盖删除项目后新项目和用户对空洞端口的分配。PostgreSQL 集成测试仍通过 `HGW_TEST_DATABASE_URL` 显式启用。
