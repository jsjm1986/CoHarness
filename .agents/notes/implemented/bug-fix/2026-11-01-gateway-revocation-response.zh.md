# Agent Note: Gateway 响应取消不能推迟撤权

Status: implemented

[English](2026-11-01-gateway-revocation-response.md) | 中文

## 问题

终端重新校验被拒绝，已经足以撤销其授权。若先等待响应体取消，在取消确认尚未返回时，授权与终端仍会保持活跃。无效的授权更新同样可能在等待读取器取消时，让提供方继续保持就绪状态。取消错误还可能替换原本的权限拒绝。

## 决策

Gateway 执行提供方请求取消不再使用的响应体与更新读取器，但不等待确认。取消抛错和 Promise 拒绝被独立收容。失败的校验立即终止其授权；失败的更新流会先清除就绪状态并使工作失效，再尝试重连。执行、SSH、终端、桌面确认和插件管理的拒绝响应都采用相同的响应丢弃策略。

授权取消与执行清理由不同所有者负责。撤销终端授权会触发正常的 TerminalController 所有者释放，其 `drainRevoked()` 仍确认进程清理完成。不会仅因丢弃响应就释放模型或子进程准入额度。

## 考虑过的替代方案

**先等待响应体取消，再撤权。** 其他响应分支或传输清理就会决定已被撤权的工作还能保持授权多久。

**只依赖请求信号。** 响应已经到达，其取消确认不一定遵循请求期限。

**把取消失败作为权限结果。** 清理失败不会改变 Gateway 的决定，也不应把稳定的拒绝替换为无关错误。

## 影响

丢弃响应不证明其传输已经静默。[有界读取决策](2026-11-01-gateway-response-cancellation.zh.md)仍定义读取上限与取消语义，[确认执行清理](2026-11-01-uncertain-resource-cancellation.zh.md)仍负责资源记账。这些决策相互独立。不改变公共方法、传输字段、Session 代际文件或 schema。

## 验证

受控拒绝响应保持取消待确认，同时终端授权被撤销，新的准入被拒绝。畸形更新流在读取器取消确认前取消所有者，并拒绝新授权。取消抛错与 Promise 拒绝都保留 SSH 拒绝结果。可运行 SDK 场景创建真实 PTY 子进程，保持失败响应的确认待返回，观察到撤权后子进程退出，并拒绝另一个终端。两个 SDK 固定这些结果。完整的旧版提供方会保留授权或进程，直到取消确认被释放。
