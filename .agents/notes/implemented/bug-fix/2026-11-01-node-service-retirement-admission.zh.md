# Agent Note: 节点服务退出与准入

Status: implemented

[English](2026-11-01-node-service-retirement-admission.md) | 中文

## Problem

中心可能已观察到 HTTP 请求完成并关闭其传输，但节点仍在清理对应桥接。服务名额被占满时，新请求可能在旧请求取消之后、清理完成之前到达节点。此时以忙碌为由拒绝新请求，会使已经完成的交互给后续操作带来可避免的 503，尽管旧桥接已经没有获准继续的工作。

## Decision

节点控制客户端持有服务名额，直到桥接的套接字与流水线全部清理完成。当前所有者被取消后，可在该名额中预留一个后继请求。后继请求不会在当前所有者结束前打开本地连接，保留其确切请求 ID 和发行版本要求，并可在等待期间被取消。当前所有者仍活动的名额不能预留后继请求。全部名额被活动工作占满时仍返回忙碌。

每个配置名额最多持有一个运行或清理中的桥接，以及一个预留请求。预留既不扩大物理连接容量，也不创建无界队列。探测准入继续独立。关闭会取消当前与预留请求，并等待其名额工作全部结束，再重连或返回。中心已有的获取时限与取消机制继续限制被放弃的请求；已经转发的 HTTP 操作从不重放。

## Alternatives considered

**发起取消时即释放名额。** 取消不能证明套接字与流水线已经停止。过早复用会在清理尚未结束时，允许物理桥接数超过配置预算。

**清理结束前拒绝所有后继请求。** 立即拒绝会使中心已完成的请求导致后续工作出现客户端可见失败。预留允许在保持上限的同时等待已知清理。

**将所有超额请求排队。** 在活动长连接后排队会掩盖真实饱和，还需要另一套独立的内存与等待策略。只有已取消的所有者可以预留一个后继请求。

## Consequences

配置的服务上限包括物理清理过程。已取消桥接可额外保留一条请求记录，但后继请求在派发前不占用套接字，也不向本地 Gateway 发起请求。取消预留会阻止派发；它无法撤销已经转发的操作。租约、凭证、发行版本和目标电脑检查沿用现有所有者。

协议、配置、私有凭证与数据库结构均不改变。[控制响应恢复](2026-11-01-node-control-response-recovery.zh.md)独立管理接入和租约响应的重试。[节点通道共享授权](2026-10-31-node-channel-shared-authorization.zh.md)独立管理数据库锁。本决策不代表已经确认所有线上容量拒绝或公网延迟的原因。

## Verification

真实套接字测试在中心释放旧请求后，保留节点侧的关闭通知。独立的已认证探测完成时，后继请求仍未派发；清理放行后，后继请求成功。取消后继请求会阻止其本地请求。其他测试保留活动容量拒绝、撤权、二进制传输与连续完成请求的名额复用。公网可靠性需要单独部署验收。
