# Agent Note: 在线备份保留源端磁盘空间

Status: implemented

[English](2026-11-17-peer-backup-source-space.md) | 中文

## Problem

密文配额保护接收电脑，却不能保护源端 SQL 导出、快照副本和个人数据校验文件。并发备份可能各自看到同一份可用容量，而其他任务可能在初次检查后继续消耗空间。

## Decision

Gateway 的备份写入和隔离恢复写入共用容量准入。每个源端操作都在实际 SQL、文件分块和清单写入处检查已配置的预留量。原生快照获取时登记源卷和快照控制卷，供后续写入检查，并随快照释放这些登记。容量拒绝使用稳定错误码，保留最后一个已确认恢复点，只撤销备份拥有的文件、工作线程和快照。新的归属见证使用相同准入拥有者。恢复点在个人内容校验和重建期间保留这一准入，离线演练也一样。

SQLite 投影和管理员安装的提供程序包含不透明写入步骤。它们在执行前需要满足受限的工作容量，不声称能逐字节拦截另一进程。原生 SQLite 投影另外检查每次追加和复制批次。[备份参考](../../../../gateway/docs/peer-backup/README.zh.md)定义配置和部署限制。[覆盖与重新授权](../architecture/2026-11-05-project-recovery-reauthorization.zh.md)继续定义插件缺口和执行权限。

## Alternatives considered

只在导出前检查一次，无法发现后续消耗，也不能阻止两个本地备份作业使用同一份额度。取消用户任务来回收磁盘，会因后台备份而改变前台执行。轮询计时器可能错过大块写入，也不拥有其空间分配。

## Consequences

备份写入增加本地文件系统容量读取；失败不会授予权限、把缺失覆盖提升为完整覆盖或停止 Runtime。准入队列覆盖一个正在提供服务的 Gateway，不能替代操作系统配额。外部写入方、原生快照增量和行为异常的管理员提供程序仍需要部署级存储限制。确定性屏障验证并发准入，实际文件复制验证导出途中拒绝和源字节不变。容量失败在报告完成前释放已获取的快照视图和私有采集目录。
