# Agent Note: Python SDK 订阅失败与 EOF 关闭所有权

Status: implemented

[English](2026-10-23-python-sdk-reader-and-shutdown.md) | 中文

## 问题

Python 用一个读取线程派发 RPC 回复和所有通知订阅。订阅过滤器可能在自己的有界队列已满时失败。阻塞发布该异常会阻止无关回复与订阅继续处理。运行时关闭也需要区分接受 shutdown 请求与完成 stdin EOF 后的清理。

## 决策

过滤器失败时只移除该订阅，并通过现有的非阻塞终止队列操作发布原异常。必要时，该操作丢弃一条已排队内容，为异常腾出空间。共用读取线程继续派发；失败的观察者不能向无关 RPC 施加背压。

`HarnessClient.close()` 请求 shutdown、关闭 stdin，并等待进程自然退出，然后才升级为终止和强制结束。现有 `shutdown_timeout_seconds` 分别限制确认、EOF 宽限和终止后的阶段。完成 EOF 清理的子进程无需信号即可退出；无响应的子进程仍会被回收。

[SDK 客户端决策](../feature/2026-07-27-typescript-sdk-and-sdk-subagent-backend.zh.md)继续负责 SDK 分层与 TypeScript 释放阶梯。[恢复与结算决策](../architecture/2026-10-17-sdk-resume-and-settlement-wait.zh.md)继续负责运行时后代排空和持久 Session 规则。这些 Python 传输生命周期规则不取代其中任何一项。

## 考虑过的替代方案

**阻塞直到失败订阅排空队列。** 订阅可能再也不读取。它不能决定运行时唯一回复读取线程的存活性。

**收到 shutdown 确认后立即终止。** 确认不能证明进程已经退出或 EOF 触发的清理已经完成。有界宽限阶段保留这些清理，也不使默认关闭无限等待。

**增加另一个关闭超时设置。** 现有设置已经约束关闭阶段；没有独立部署需求的新开关只会增加配置。

## 影响

过滤器的终止异常可能替换失败订阅中已排队的通知数据。成功订阅保留协议顺序。关闭可能在升级前分别消耗每个配置阶段的预算；初始化超时 fixture 声明自己的短清理预算。

真实子进程回归先填满只有一个位置的订阅队列，再让下一次过滤调用抛出异常，并验证另一个订阅与提示词回复。EOF 回归等待清理标记和自然退出的零状态；它是普通通过测试，不再是预期失败。
