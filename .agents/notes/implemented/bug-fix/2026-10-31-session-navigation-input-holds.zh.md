# Agent Note：新会话准备期间的输入归属

Status: implemented

[English](2026-10-31-session-navigation-input-holds.md) | 中文

## 问题

创建 Session 和打开其历史都是异步操作。准备期间仍显示原对话，因此保持可用的输入框可能在用户请求新会话后，继续向原 Session 接收消息。

## 决策

现有导航所有者会锁定来源 Session 的输入，直至准备结束。Session 列表在当前浏览器标签页内发布这一锁定。输入框显示等待状态，不清空草稿，也不停止任务；输入 facade 在提交文本、命令和附件前检查同一实时状态。其他 Session 面板和浏览器标签页保持独立。

新导航取代旧锁定。完成操作只解除其原始取消信号拥有的锁定，因此迟到的完成回调不能解锁较新的操作。创建失败后，原对话和草稿仍可使用。暂存的 Agent 预设固定并排除原 Session，直到目标 Session 被选中才应用选择，中间导航更新解除输入锁定也不改变这一归属。

## 考虑过的替代方案

只禁用渲染后的发送按钮，仍允许下一次渲染前到达的回调向旧 Session 提交。准备期间清空原对话，会无谓地移除用户正在阅读的内容和任务上下文。

## 影响

客户端导航 API 接受可选的来源 Session，并提供明确的完成操作。它不改变 Runtime 位置、持久 Session 身份、文件或权限。新会话创建保留新的 Agent 语义。

## 验证

导航所有权、失败及被取代的创建操作，以及文本、命令和附件提交检查覆盖锁定生命周期。真实 Web profile 会延迟 Session 创建，记录来源输入框的禁用状态，再验证重新选择历史后恢复草稿和输入。
