# Agent Note：项目预留对私有草稿的授权

Status: implemented

[English](2026-11-17-project-reservation-draft-authority.md) | 中文

## 问题

[Session 延迟物化](../architecture/2026-08-26-session-draft-lifecycle-and-content-watermarks.zh.md)有意让新项目对话在首条消息之前不产生 Session 行。如果保存浏览器私有文本或核验附件目标必须依赖该行，有效的新对话就无法完成这两项操作。

## 决策

经过认证的节点草稿提供方接受常规 Session 权限，或属于当前创建者的精确有效预留。预留必须匹配组织、项目、Runtime 和 Session，排除任何已存在的 Session 行与尚未恢复的归档身份，并要求账号、电脑及项目的当前写入权限有效。管理员身份不授予其他创建者尚未物化预留的所有权。私有文本继续沿用账号、Session 和标签页键。

最终预留读取和写入先持有 Session 物化 advisory lock 的共享形式，再保留预留行锁。非阻塞获取避免读取持有 ACL 修订时等待物化或归档操作。最终语句复核过期时间与身份；取消不能跨越已保留的预留提交。本地内容事务传给最终授权回调，有界连接池因此不会等待同一读取占用的第二条连接。

附件检查仅在常规精确 Session 检查返回 false 时尝试这项只读能力。已有权限错误继续传递。已物化且已关闭、删除、私有或归档的 Session 不能通过旧预留取得访问权。这些检查不读取消息或草稿正文，也不启动 Runtime。

## 考虑过的替代方案

**物化每一个新对话。** 放弃，因为被遗弃的草稿会取得持久 Session 身份，并绕过延迟生命周期。

**Session 不存在时只要求项目成员身份。** 放弃，因为成员身份不能证明谁拥有预留对话。预留创建者与当前权限必须同时满足。

**仅在初始快照检查预留。** 放弃，因为取消、过期和首次物化可能发生在返回数据之前；Session 插入并不推进可见性修订。

## 结果

新项目对话可以接收私有草稿并用作文档目标，无须扩大协作权限。锁竞争返回可重试的存储错误，不持有冲突锁等待。预留过期后保留已存私有文本，但不再授权读取。

## 验证

无需密钥的 Gateway 转录使用真实认证 HTTP 请求与独立治理、内容数据库，覆盖预留、两个标签页私有草稿、附件核验、首次追加与历史读取。真实 PostgreSQL 用例覆盖最终准入前后的取消与物化、预留过期、电脑权限撤销、其他账号，以及已物化的私有、关闭、删除和归档身份。HTTP 路由回归保留旧处理器的授权检查。
