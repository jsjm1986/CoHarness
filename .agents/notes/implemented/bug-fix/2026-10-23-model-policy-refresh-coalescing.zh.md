# Agent Note：模型策略刷新合并

Status: implemented

[English](2026-10-23-model-policy-refresh-coalescing.md) | 中文

## 问题

后台策略刷新可以在其他主体完成前，先发布某个主体的文件。若运行中直接丢弃新的刷新触发，较早主体的持久授权变化后，其文件仍会保持旧内容。运行时的[实时策略监视器](../feature/2026-08-14-gateway-model-governance-live-policy-reload.zh.md) 无法观察从未刷新的文件。

## 决定

收到新的触发时，worker 保留一遍待运行工作。每遍读取当前策略，并保留有界重试序列。worker 在自身结束流程内、promise 完成前移除活跃记录，使完成时到达的触发能够启动新 worker，而非被已完成任务丢弃。

## 备选方案

**依赖下一次浏览器请求。** 惰性协调最终可能刷新文件，但已运行实例可以在没有新浏览器请求时继续发起模型请求。

**每次触发都启动 worker。** 并发 worker 会重复完整目录与文件系统工作；保留一遍待运行工作即可保留新状态，避免无界任务队列。

## 影响

重叠触发最多新增一遍待运行工作。投影重试期间，成功的数据库变更仍报告成功；worker 的结束记录不会遮蔽后续刷新请求。

## 验证

确定性的 SQLite 和文件系统回归阻塞较晚主体，修改较早主体的模型授权，并再次请求刷新。解除阻塞后，较早主体的文件必须发布拒绝授权。
