# Agent Note：已声明草稿标头的 V5 后继

Status: implemented

[English](2026-09-22-v5-draft-header-successor.md) | 中文

## 问题

已接受的 V4 持久化记录在物理 JSONL 标头中省略 `draft`，却在逻辑 Session 标头中保留它。本 fork 的 V4 编码器委托给已输出该布尔字段的 V3 编码器，而较窄的 JSONL 读取器拒绝该输出。修正读取器会改变物理标头的声明，现行持久化规则要求这种变化提升版本，即使该字段可选。

## 决策

写入器通过 [V4-to-V5 相邻迁移](../../../../packages/session/session-format-v4-to-v5/README.zh.md)推进到 V5。此迁移只改变标头版本，保留省略、false 和 true 草稿状态，原样转发所有事件与继承切点标记。V5 委托给 V4／V3 校验器，由它们负责可选 `draft` 字段的校验及对旧事件的兼容处理。调用方收到的仍是原始 V5 标头。

[V4 历史参考](../../../../docs/persistence-changes/historical-formats/v4.zh.md)从已接受 PR #218 捕获完整声明目录。既有 V4 确认记录与 schema 保持不变。V5 后继在同一有序历史中确认标头修正和当前执行权威事件新增，不为旧消息推断经过认证的参与人；受管授权按自身策略处理缺失的历史证明。

JSONL 读句柄和检查操作在不发布文件的情况下重建当前产物。显式以写权限打开时，沿用既有租约与持久发布协议生成独立 V5 代次。V4 前驱的字节、inode 和修改时间保持不变。未知字段、非布尔草稿值和未来版本仍会失败。前驱只是历史证据，不能在当前代次损坏时充当回退。

## 考虑过的替代方案

**修改已接受的 V4 快照。** 既有更新命令只适用于未接受的末端记录。替换已接受声明会隐藏写入／读取不一致，而不是记录转换。

**豁免可选标头字段的版本检查。** 较旧 JSONL 读取器使用封闭键集合，会拒绝该字段。通用豁免也会放宽无关的标头和事件信封变化。

**重写既有 V4 文件。** 这会破坏代次不可变保证。既有相邻发布协议已经将转换与源文件修改分开。

## 影响

新 codec 复用 V4 事件物理编码和校验，不复制事件词汇。提供方与 SDK 期望只推进当前版本标记，历史夹具保留其来源版本。上游 V3 构建无法消费本 fork 的 V5 格式；发布状态记录在真正发布前不会推进。

回放夹具与持久化产物共用严格的构建期格式目录。不完整的信封字段对、完整行与投影行混用、非法当前事件载荷均被拒绝；夹具支持不使用宽松的旧迁移流替代该目录。有效历史录制保留来源版本与模型分片，比较编码保留 V5 两个显式 draft 布尔值。夹具预检在启动浏览器前执行这些检查。

## 测试

转换器和目录测试覆盖可选草稿状态、事件恒等转发、继承切点、无效元数据和未来版本拒绝。真实 JSONL 夹具使用既有 V4 编码器构造普通与独立帧 Zstandard 输入，验证只读检查，经实际写句柄发布并冷重开，比对前驱字节与文件系统身份。SDK 预期日志只修改八个首行版本标记，正文哈希保持不变，仍需重放验证。本地检查不声称已验证 Windows 发布或完整发布认证。
