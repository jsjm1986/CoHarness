# Agent Note：保留协作授权要求

Status: implemented

[English](2026-10-23-retained-collaboration-requirement.md) | 中文

## 问题

可选协作查询用于区分独立应用与共享项目。提供方替换期间，把服务缺失解释为独立所有者访问，会允许只读主体在提供方存在时无法执行的请求。

## 决定

共享项目 Gateway 身份与协作实例构造会在应用根上下文中保留要求。涉及参与者的消费者据此解析提供方；暂时缺失表现为授权后端拒绝。ACL 选择、引用读取、注册表控制、预设能力提示和本地打开能力检查保留同样的应用策略。

## 备选方案

**把要求放在提供方生命周期中。** 撤销提供方会恰好在需要保护应用时移除要求。

**对所有启用执行授权的应用要求协作。** 仅使用执行授权的部署及用途签名的个人 webhook 分发，明确支持不安装可选协作包。其执行策略与共享项目 ACL 保持独立。

**让持久化元数据依赖活跃提供方。** Gateway 持久化已经通过后端授权并保留获准的创建元数据；中断它会使持久工作无法完成，却不能加强用户请求的准入。

## 影响

提供方替换期间，项目访问不能变成所有者访问。独立应用保持已配置的所有者行为，替换提供方会恢复自身的参与者检查。要求持续到所属应用结束，而非某一代提供方结束。浏览器子会话控制还会在目录读取、提示准入和接受前投递期间保留最初授权的提供方。撤下会取消等待中的工作并扣留未返回的数据；替换不能转移请求权限。inbox 接受后，此取消所有权结束。

## 验证

签名 HTTP 快照启动真实 Loader、Connection、GatewayRuntime、GatewayCollaboration 和 JSON 记忆。只读请求始终被拒绝，撤销期间报告不可用，替换后签名的可写请求能够持久化成员归属。RPC 与直接服务测试验证同样的拒绝行为，并保留仅使用执行授权部署的兼容性。

可运行的子会话控制快照使用真实 Gateway 协作提供方、回环授权和持久化可继续子会话。准入期间替换提供方会拒绝旧输入且不产生 user-message 事件；新请求成功并保留项目参与者归属。两个 SDK 都重放个人与项目范围。
