# Agent Note: 锁等待后的会话写入权限

Status: implemented

[English](2026-10-24-conversation-writer-locks.md) | 中文

## 问题

PostgreSQL 查询在取得账户和项目行锁之前计算项目成员权限与管理员身份。若撤权方持有未被修改的账户或项目行，同时修改关联成员记录，等待中的写入方可能保留旧权限结果，在撤权后物化会话。行锁不会刷新同一语句快照中的其他权限记录。

## 决策

`ConversationRepository.projectWriter` 先锁定活跃账户和项目，再通过独立语句读取权限。第一条语句通过物化账户 CTE 保证先取得账户锁，再取得项目锁。第二条语句要求活跃组织成员资格，以及项目 `rw` 或管理员身份；维护项目还要求管理员身份和启用资格。创建与带参与者归属的追加操作共用该检查，`CollaborationDeniedError` 将拒绝映射为 HTTP 403。追加被拒时，事件、搜索行及贡献行一起回滚。

交互和可见性检查遵循[维护准入决策](../feature/2026-10-10-steward-admin-layered-admission.zh.md)。[升级指南](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/conversation-writer-authorization/guide.zh.md) 说明持久化客户端要求。

## 验证

真实 Gateway HTTP 回归让创建和追加操作等待实际的成员移除、角色降级及 `rw` 降为 `ro`。六个场景均返回 403，且不留下新事件。公开对话转为私密后，另一成员排队中的追加也会以 403 被拒绝；原来的通用错误返回 500。恢复原来的权限与锁合并查询后，成员移除或角色降级完成，接口仍返回 200。外键夹具也会先建立组织成员资格，再检查无关的跨组织引用。

## 性能

诊断脚本为 `gateway/tests/conversation-writer.perf.ts`。构建 Gateway 后运行，`HGW_TEST_DATABASE_URL` 需指向可丢弃数据库，`HGW_WRITER_PERF_BASELINE_REF=2896f75419ca38682a4a96151ee15beee009ccac`。脚本编译该参考版本的仓储源码，再通过全新普通 Node 子进程运行两份实际编译实现。

| 测量项 | 定义 |
| --- | --- |
| 完成条件 | 一条带参与者归属的消息经 `ConversationRepository.append` 提交 |
| 负载 | 合成的普通写入成员或隐式管理员；已有 64 或 4,096 条事件 |
| 计时 | 单连接池；预热十次；三批各二十次追加；每个版本三个全新子进程；交替版本顺序 |
| 内存 | 保留最后的插入结果；进程峰值包含准备阶段；一次 GC 后读取稳定 RSS |
| 范围 | 仅作诊断；不含 HTTP、推理、并发写入或数据库服务端内存；无计时预算 |

每次追加耗时中位数（毫秒），修复前 → 当前：普通成员/64，8.583 → 8.355；普通成员/4,096，8.476 → 9.164；管理员/64，8.201 → 9.053；管理员/4,096，8.704 → 8.950。进程峰值中位数为 79.80 → 79.57 MiB。共享主机上的这些样本说明实测代价，不代表普遍的时延改善。账户、项目、权限各用一条语句的实现测得 9.545–9.828 毫秒；仅合并取锁操作会减少一次往返，并保留后续权限快照。

## 后果

等待不会延长写入方的权限。持久化客户端收到共享的禁止结果，重试前需刷新空间权限。额外的权限语句具有实测数据库代价；现有事件格式与批次原子结果保持稳定。

## 考虑过但未采用

**把权限谓词放回取锁查询。** 拒绝，因为等待未变化的账户或项目行不会刷新关联成员谓词。即使查询返回时已持有两把锁，功能负控仍会失败。
