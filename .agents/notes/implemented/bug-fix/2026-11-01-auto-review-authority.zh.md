# Agent Note：Auto 审查在工具准入前保留签发方

Status: implemented

[English](2026-11-01-auto-review-authority.md) | 中文

## 问题

Auto 审查可能等待工作目录、模型容量、适配器准备、响应或下游工具策略。替换后的权威可以证明相同参与人字段，却不拥有原有审查。等待前的检查不能阻止资格撤销后的 reviewer 请求。可选权威也可能在任何审查调用建立受管回退状态之前消失。

## 决策

每次审查捕获签发服务，以及该服务针对准确的待执行工具返回的已验证状态。审查从此状态派生 `ExecutionInheritance`，并进入签发方的 `runCaptured` 上下文。Agent 当前状态不能替代工具作用域。插件拥有的一个异步上下文标识 reviewer 请求；其 `llm/pre-dispatch` 监听器在容量准入后及每次物理模型请求之前重新检查 Auto 资格。无关模型调用保留各自授权。

每次资格检查均保留签发方的原始服务身份，并比较作用域、版本、输入与主要发起人。最终工具准入在下游策略完成后重新检查，并在返回允许之前同步确认签发方。调用方或插件取消优先于迟到结果。资格拒绝保留结构化 Auto 拒绝；独立模型故障保留自身错误。卸载先取消审查，等待其清理完成，再释放异步上下文。

存在执行权威就会将集成归类为受管，包括在任何审查前观察到的可选提供方。该分类在提供方撤回后仍然保留，并拒绝部署转为受管时已经在途的独立审查。卸载把其 Auto Session 转为 Workspace write；真正独立的本地组合保留既有 Full access 回退。

[执行归因决策](2026-09-22-auto-review-execution-attribution.zh.md)继续负责预设选择、设置写入、计费证明及历史用量接收。[准确请求记录](2026-10-24-auto-review-request-records.zh.md)继续负责持久化模型输入。

## 考虑过的替代方案

**仅比较参与人字段。** 字段相同不能证明哪个服务准入了工作。替换服务不能授权其前任的审查。

**仅在申请容量前或 reviewer 完成时检查。** 资格可能在排队期间或适配器准备传输时改变。物理派发检查阻止该请求发出。

**重新捕获 Agent 或共享当前审查变量。** 待执行工具可能拥有更窄的作用域，不同 Session 也可能并发审查。每次操作保留自身已证明的工具状态。

**根据当前提供方缺失推断本地部署。** 移除权威或 reviewer 不能让受管 Session 获得未经审查的 Full access。

## 影响

授权不增加模型预留或账单。一个 reviewer 在其既有资源许可期间始终保留同一 Session 与已验证主要发起人。执行权威 API、reviewer 请求事件及 Session 格式均不变。自定义提供方必须支持 reviewer 工作的捕获执行。此决策不会授予替换服务访问进行中审查的权限。

## 验证

Loader 测试使用真实权限与工具运行时、受控权威提供方、确定的等待点及只写入自有文件的工具。并发 Session 证明被撤权账号不能借用另一账号的审查。发布 SDK 组合覆盖工作目录准备、容量排队、物理派发、响应完成与允许调用。完整私有旧版源码包和构建包复现了多余请求及提供方替换后的文件写入。最终授权期间取消、捕获作用域无法进入，以及任何审查前受管卸载均有针对性覆盖。
