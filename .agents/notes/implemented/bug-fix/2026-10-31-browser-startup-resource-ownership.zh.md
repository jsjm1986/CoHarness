# Agent Note：浏览器启动保留资源所有者

Status: implemented

[English](2026-10-31-browser-startup-resource-ownership.md) | 中文

## 问题

惰性浏览器获取跨越本地提供方激活、临时配置目录创建、进程准入和 Worker 就绪。发起时记账器的额度不授权在另一运行时配置下启动或发布浏览器。后续连接始终保留该记账器，也会错误归属取消操作后的新重连。仅保存成功连接的运行时，会遗失失败重连的回滚入口，并使关闭操作遗漏仍在获取的资源。

## 决定

原生 Stagehand 提供方在启动等待前捕获确切的发起 Agent 和原始 Cordis 资源 Service。同步检查随 Chromium 启动和 Worker 准入传递，也覆盖独立获取。Chromium 在子进程派发前和就绪后检查；Worker 在准入前、分配前和就绪后检查。提供方变化或缺少必需准入会拒绝获取。未使用额度归还原记账器；完成报告失败通过 `ResourceAcquisitionCleanupError` 转移合并并发调用且可重试的清理操作。

Worker 构造失败时向原记账器报告无法确认的占用。报告失败时，获取操作同时保留两项失败原因以及合并并发调用、可重试的报告。所有者完成这项清理前继续保留附加浏览器占用。确认收到不确定性报告不代表资源已静止，也不释放额度。

取消后创建的新连接捕获当前记账器。已有的自有 Chromium 进程范围在确认终止前保留原额度。额度不在提供方之间转移。提供方保存每个连接 Promise，也包括失败的重连。后续操作在尝试新连接前完成保留的回滚；关闭操作等待同一 Promise 及其清理，再释放浏览器占用。已完成回滚的普通连接失败可以直接重试。

## 考虑过的替代方案

**仅在启动准备后解析准入。** 这会使用未接受原获取请求的提供方授权旧请求。

**重连复用首次记账器。** 新 Worker 属于单独的获取操作，必须使用当前准入。

## 影响

恢复准入后，调用者以新的获取操作重试被拒绝的启动。Worker 就绪不会发布过期连接。SDK 排空、无法确认的原生分配和外部浏览器占用继续遵守现有清理义务。[提供方参考](../../../../packages/experimental/browser-use-stagehand-native/README.zh.md)说明操作行为。

## 验证

定向原生 Worker 和 Chromium 测试覆盖准入、就绪、取消和保留的完成报告。无需密钥的 [Loader 示例](../../../../packages/experimental/browser-use-stagehand-native/tests/fixtures/startup-owner.mjs)使用真实 Worker 和临时配置目录，检查发起 Session 归属，拒绝过期启动，并使用当前准入完成新重试和重连。

示例还会在构造失败后暂停不确定性报告，在原所有者排空期间拒绝另一 Session，并在报告成功后允许其获取浏览器。外部夹具编译器仅处理三份 TypeScript 模块，保留其原始导入位置；CommonJS 依赖使用 Node 自身的加载器。 SDK 的 URL 兼容夹具使用显式声明的用户态编码器；回放诊断仍执行精确比对。
