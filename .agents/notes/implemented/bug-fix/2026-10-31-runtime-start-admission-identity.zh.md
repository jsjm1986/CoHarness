# Agent Note: Runtime 启动准入身份

Status: implemented

[English](2026-10-31-runtime-start-admission-identity.md) | 中文

## Problem

Runtime 启动同时携带归属选择器和可选的持久运行环境 ID。忽略已提供的环境 ID，会让不一致的引用修改该归属代次的分配状态并消耗节点压力额度。正常托管启动中更早的身份检查，并不能使这种行为成为准入服务可接受的保证。

## Decision

压力准入查询在记录等待中或可能已分配状态之前，匹配组织、电脑、归属、代次，以及任何显式提供的 Runtime ID。不一致的引用以过时代次错误拒绝，不消耗额度。省略环境 ID 时保留现有的代次查询。归属代次分配器继续负责防止同一归属的独立环境使用重叠代次。

## Alternatives considered

**只依赖上游目标选择。** 分配操作仍会静默丢弃显式选择器，使不一致的请求影响另一个环境。

**移除旧版归属选择器。** 现有可信调用方仍使用它；代次分配器已经保证该查询具有明确的归属命名空间。

## Consequences

这项检查不改变数据库结构或代次分配。真实 PostgreSQL 用例覆盖其他账号、项目和电脑的 ID，以及未知 ID，并保留正确目标的准入对照。普通 Node 编译产物验收还检查拒绝时分配状态与额度不变、新鲜压力等待、取消以及已就绪分配的保留。这是准入服务修复；没有证实外部跨账号执行越权或代次碰撞。
