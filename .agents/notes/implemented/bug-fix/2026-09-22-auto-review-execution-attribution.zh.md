# Agent Note：Auto review 执行权威与计费归因

Status: implemented

[English](2026-09-22-auto-review-execution-attribution.md) | 中文

## 问题

共享运行时可能在提供指令的浏览器请求结束后继续执行。当前连接、消息中的展示参与人和恢复后的权限预设都不能证明谁授权了执行。Reviewer 也可能在资格撤销或新输入改变参与人之后才完成，而稍后上报的用量仍应归属于真正产生费用的请求。

## 决策

[Auto review](../../../../packages/experimental/auto-review/README.zh.md)消费轻量的执行权威服务。受管调用在付费请求 reviewer 之前，以及 reviewer 允许且下游守卫完成之后、工具正文执行之前，都必须通过实时 Auto 授权。权威检查完整的已验证参与人集合。历史无法验证、主要发起人缺失、提供方不可用，或版本、输入集合、主要发起人改变时，均拒绝待执行动作。集成不会额外调用模型来修复过期审查。独立本地 profile 保留上游审查策略，无需 Gateway。

当前 Session 仍需显式选择 Auto；[管理员资格](2026-09-22-admin-auto-review-eligibility.zh.md)只是一项授予。`/permission` 命令先等待部署授权，再同步写入预设；取消或策略移除后晚到的授权被拒绝。未来会话默认值沿用既有设置命名空间，并排除 Auto。Full 默认值通过仅用于写入的 `authorizeWrite` 钩子要求实时管理员授权。注册与提供方重载仍由 schema 和同步值校验负责；依赖请求的权威只在进程内持久化之前检查。等待期间卸载或外部版本变化会拒绝写入。

受管 Auto 卸载将存活 Session 恢复到 Workspace write，即使权威提供方已经丢失也一样。独立本地卸载仍按[上游 Auto 生命周期决策](../feature/2026-08-28-auto-review.zh.md)保留 Full access。受管部署不能通过移除 reviewer 获得未经审查的 Full access。

每次 reviewer 请求携带 Session 与 `purpose: auto-review`，受管计费还携带不可变执行见证和一位主要发起人。这些字段不进入 Provider 请求正文或模型文本。治理插件使用实际发起 Agent 或已提供的已验证见证，不用当前浏览器或展示参与人替代受管权威。没有 Agent 的辅助调用明确保持未归属。多位用户参与仍只产生一笔账单。

PostgreSQL intake 在保存用量前，按 Session、运行时、组织与主要发起人验证历史见证。子 Session 只有通过服务端记录的见证成员关系，才能使用祖先输入。撤权或软删除用户仍可归因于已证明的历史请求，但不会重新获得执行权限。项目承担账单并记录一位活动发起人；个人记录只使用账务所有者，不重复记录活动发起人。无效证明保留在 outbox，不能移除身份后重试。无证明的旧记录保留当前可写成员检查和既有未归属重试。SQLite 拒绝其无法验证的证明。

## 考虑过的替代方案

**只在使用选择器时授权。** 恢复的 Session、委派工作、提供方重载和审查期间撤权都可能晚于该检查。选择与执行需要分别准入。

**使用最近参与人或向每位参与人计费。** 展示元数据不是经过认证的权威，参与人的权限交集也只是授权规则，并非多次模型调用。一位捕获的主要发起人归因于一笔费用。

**在迟到用量到达时检查当前资格。** 这会在撤权后抹去合法费用，或令其永久滞留队列。历史回执验证证明归因，而不授权新动作。

**把设置校验改成异步。** 同一校验还会在没有实时请求的注册与存储重载期间运行。仅用于写入的钩子保留这些操作，并把实时权威放在持久化之前。

## 影响

执行权威包只承载已验证输入引用与服务方法；LLM 包保留通用生成元数据，不依赖 Gateway。受管服务缺失时仍显式失败。运行时授权与计量消费相同的输入身份，但分别回答调用是否可以执行，以及谁产生了已观察到的费用。

## 测试

真实 Loader 在受控权威提供方之外组装 Auto 集成、权限服务、LLM 运行时和 ToolRuntime；工具只写入自有临时文件。测试覆盖 reviewer 派发前拒绝、待审期间撤权与身份变化、冷恢复、取消及受管卸载。真实 CommandRuntime 与设置写入覆盖异步允许／拒绝、取消、过期策略移除、卸载及外部版本变化。治理测试观察实际 outbox 记录与 HTTP 重试。PostgreSQL 测试登记并进入真实执行输入，通过 Bearer 鉴权 intake 上报用量，验证项目／个人迟到计费、无效证明、祖先见证和去重。两种 DeepSeek 序列化器均把计费元数据排除在 Provider 正文之外。
