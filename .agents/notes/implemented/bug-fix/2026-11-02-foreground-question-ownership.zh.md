# Agent Note: 前台提问保持归属直到答案应用完成

Status: implemented

[English](2026-11-02-foreground-question-ownership.md) | 中文

## 问题

外部回答器等待期间，前台提问可能跨越取消、所属服务或调用 Agent 的释放。接受迟到答案可能应用已经失效的计划批准。在模型轮次之外提出的问题也需要阻止其 Agent 被空闲回收。

## 决策

`UserQuestionService` 持有每个前台提问直到逻辑结算。回答器收到合并调用方取消、服务撤下及原 Agent 失效的信号。每次回答器继续委托及接受答案时都会检查当前归属。服务释放会取消已接受的提问，并等待其逻辑结算，不等待忽略取消的回答器。待决前台提问及定时等待会否决其所属 Agent 的空闲回收。

同一事件循环轮次内的类型化回答器拒绝保留其类别，包括 Client 关闭和定时等待结果。其他取消最迟在 Host 的下一事件循环轮次结算，回答器的信号则立即中止。迟到完成不能替换已选定结果。[运行时根守卫](2026-08-01-ask-user-delegated-caller-guard.zh.md)继续负责准入规则。

计划评审在选择退出前立即检查自己的执行信号和原 Agent 是否仍是存活实例。提问服务返回时有效的答案，不能在调用方失效后继续授权状态修改。

## 考虑过的替代方案

**把取消交给每个回答器处理。** 忽略取消或断连的回答器可能无限保留提问，或返回失效批准。

**只在提问前检查调用方。** 等待期间或答案结算与使用方写入状态之间，都可能发生删除、替换与取消。

**中止调用方信号。** 服务或定时等待撤回时只关闭该问题，不取消调用 Turn 中无关的工作。

**让取消覆盖同时发生的业务拒绝。** 关闭计划评审与被认领等待的超时具有不同的继续语义，两者都保留其类型化结果。

## 影响

[提问服务](../../../../packages/interaction/user-questions/README.zh.md)与[计划使用方](../../../../packages/plan/plan-mode/README.zh.md)的方法签名、Session 事件和持久格式保持不变。回答器 waterfall 收到的信号对象身份会变化；受支持的接口是取消行为。现有 UI 回答器通过该信号关闭自己持有的待决请求。

真实 Agent 测试覆盖取消、服务撤下、替换、空闲回收和独立提问。[可运行的 Loader 组合](../../../../examples/headless-agent/tests/fixtures/interaction/question-lifetime/cordis.yml)使用本地提供方运行真实模型到计划评审的轮次，验证正常批准及取消后的迟到批准。
