# Agent Note: 非普通文档文件

Status: implemented

[English](2026-10-26-document-nonregular-files.md) | 中文

## 问题

POSIX 命名管道可以占用普通文档路径。以读取方式打开它会等待写入方，因此只在打开后检查类型，会让文件系统工作线程和已接收的文档操作一直等待。取消 HTTP 请求不能中断该原生打开操作。路径也可能在初始元数据查询与取得描述符之间，从普通文件变为管道。

## 决策

普通文档读取在打开前要求条目为普通文件且不是链接。POSIX 描述符取得包含 `O_NONBLOCK`，打开后的描述符仍必须报告普通文件。检查后的替换会被拒绝，描述符随之关闭。普通文档字节和调用方拥有的下载流保留现有行为。宿主提供该标志时，上传载荷读取、分块写入与身份依据也使用相同的非阻塞取得规则。

[操作排空决策](2026-10-26-document-operation-drain.zh.md)继续负责取消、等待已接收工作，以及保留独立清理失败。普通路径包含管道时，非阻塞取得让这些生命周期能够继续完成；它不替代相应清理规则。

## 考虑过的替代方案

**只在打开前检查。** 另一写入方可以在检查后替换条目。

**只使用请求期限。** 拒绝请求不能释放仍在等待管道另一端的原生文件打开操作。

## 后果

文档 API 拒绝管道和其他非普通条目，无需等待另一进程。即使路径检查成功，POSIX 打开操作也使用非阻塞标志；并发写入方可能替换条目，因此仍需检查描述符。Windows 保留普通文件检查，不依赖 POSIX 管道语义。

## 验证

真实 FIFO 会让原有源码读取器一直等待，直到测试拥有的进程被终止并回收。修复后的源码读取器会拒绝它并正常退出。真实 Loader 组合分别检查元数据、缓冲读取和流式读取，覆盖已有 FIFO 及在打开前被替换为 FIFO 的普通文件；所有已取得的替换描述符均会关闭。POSIX 用例运行在独立且有期限控制的进程内。Windows 排除此 POSIX 专用用例；普通不支持目录仍有可移植的单元覆盖。
