# Agent Note: 桌面请求授权

Status: implemented

[English](2026-10-31-desktop-request-authorization.md) | 中文

## Problem

桌面应用路由能够发布主机元数据并启动本地程序。将认证服务缺失视为允许，会在启动和重载期间暴露这些操作。在异步目录应用解析或图标处理之前获准的请求，也可能持续到认证服务、用户资格或插件实例失效之后。

## Decision

桌面插件在注册路由之前必须获得 Connection。每次插件激活各自持有请求准入生命周期；卸载使该实例失效，即使随后出现新实例也不会复活旧请求。请求在异步读取之后、发布主机数据之前，以及每次实际主启动、备用启动或刷新后的启动之前，复查当前 Connection 与浏览器资格。缺少认证服务或处理器已失效时返回 503；当前认证的拒绝保留其原有状态。已经提交给操作系统的启动保持独立生命周期。

浏览器的[本地 Runtime 选择规则](2026-10-04-open-in-app-local-runtime-gate.zh.md)仍是独立要求。根据[选择性同步决策](../architecture/2026-09-08-upstream-alpha2-selective-sync.zh.md)，此可选桌面能力仍不挂入云端 Web bundle。

## Alternatives considered

**只声明注入依赖。** 移除路由无法撤回已经分派或暂停在异步解析中的处理器。

**只捕获一次授权结果。** 在备用启动器或替换后的启动器执行之前，浏览器资格和插件可用性都可能改变。

**卸载时终止全部已启动应用。** 桌面应用在操作系统接手后本就允许独立于 Harness 存活；准入规则约束的是新的启动交接。

## Consequences

服务缺失不会授权桌面请求。受控 HTTP 交错验证权限撤回之后不再返回元数据，也不新增启动适配器调用；真实 Loader 与 Connection 回放通过合成浏览器 Cookie 覆盖启动、替换和卸载。这些夹具不会打开真实桌面应用。已经开始的有界检测工作可以在撤回后完成，但不能发布结果或授权另一次启动。
