# Agent Note: 让 torn tail 修复可见

Status: implemented

[English](2026-08-29-jsonl-torn-tail-warning.md) | 中文

## 问题

JSONL 持久化会修复不完整的末尾 frame 并从已提交前缀继续，但没有诊断输出时，运维无法区分这是普通加载还是发生过恢复。

## 决策

截断 torn tail 并追加可恢复的 closing event 后，JSONL 后端通过 logger 输出一条包含后端名称和稳定 session id 的 warning。不输出文件路径、事件内容或敏感元数据。

## 备选方案

**像以前一样静默修复。** 不予采用：运维需要知道发生了字节丢弃，并关联受影响的会话。

**记录原始路径和尾部内容。** 不予采用：路径和事件数据可能包含私有项目资料。

**让会话加载失败。** 不予采用：已提交前缀和崩溃收尾恢复仍然有效，应继续提供给调用方。

## 影响

Torn-tail 修复仍然容错且确定，同时为每次恢复产生一条可操作、保护隐私的诊断。

## 测试

zstd 恢复测试在既有事件修复和 frame 完整性断言之外，固定 warning 文本与稳定 id。
