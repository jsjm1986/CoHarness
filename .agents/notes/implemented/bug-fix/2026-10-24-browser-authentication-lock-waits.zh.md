# Agent Note: 认证锁等待后的浏览器权限

Status: implemented

[English](2026-10-24-browser-authentication-lock-waits.md) | 中文

## 问题

PostgreSQL 浏览器验证在锁定登录会话行前已经连接读取账户和成员身份。等待此锁的请求可能在并发降权提交后仍保留管理员角色。过期谓词使用事务开始时的 `now()`，因此同一等待还可能授权空闲期限或绝对期限已经到达的会话。SQLite 在任一期限相等时仍接受令牌，甚至会续期恰好空闲过期的令牌。

登录在密码验证和分布式准入之前就捕获时间戳。等待这些操作会缩短新会话实际可用的有效期；失败记录和锁定窗口检查也使用较早的到达时间。

## 决策

验证通过一条自动提交语句为匹配且仍有效的会话执行条件续期。物化加锁查询在获得行锁后才交付会话期限；续期在改变时间戳前，按当前时钟重新检查这些期限。行锁在查询结果传输前释放，远端 Gateway 不会在后续数据库往返期间保留该锁。独立读取获取新的快照，在返回身份前重新检查当前组织、账户、成员、凭据、撤销状态与两个期限。续期和过期检查使用数据库 `clock_timestamp()`；两个期限都必须严格晚于当前时间，绝对期限保持不变。SQLite 在续期前拒绝等于任一期限的情况。

登录在准入后按当前数据库时间检查失败窗口并记录失败尝试。成功登录在身份校验和加锁完成后，从同一个数据库时刻派生创建、空闲、绝对及最近访问时间。等待不会消耗新会话有效期。

成功验证使用两条自动提交语句，不保留事务，也不缓存权限。后续权限读取失败时，即使续期已提交，也不返回身份。它不在会话锁之后获取账户锁：账户禁用和删除本就先锁账户再撤销会话。[浏览器保留决策](2026-10-24-browser-session-retention.zh.md)继续定义 Cookie 有效期与清除行为。

## 影响

排队的管理员请求会看到已经完成的降权，并收到既有的禁止响应。过期的排队请求收到既有的未授权响应，不续期时间戳。令牌、数据库列、Cookie 语法与响应格式保留现有表示。在之后权限变化前已经获准的验证，仍受端点现有执行检查与访问撤销约束；本变更不会在整个 HTTP 响应期间锁住账户权限。

## 验证

真实 Gateway HTTP 回归暂停数据库结果传输，并证明其他事务已经可以取得会话行。在暂停期间改变角色、组织、成员、账户状态、凭据、撤销状态或期限，会影响恢复后的请求。其他回归持有登录会话行，观察验证器的数据库锁等待，再提交角色降权或将一个期限移至当前数据库时间。原实现对三个请求都返回 HTTP 200；修复后，已完成降权返回 403，任一过期返回 401。角色变更使用正式用户服务，测试持有并清理自己的服务器、连接池、临时路径与请求任务。交错顺序不依赖 sleep。

两个仅替换 Date 的 SQLite 用例把各个期限设为验证时刻，检查拒绝且不续期时间戳。原实现会接受两个令牌。

另一个 HTTP 锁屏障证明原签发器记录的创建时间早于锁释放。当前用例验证准入后的签发具有完整的配置空闲有效期、失败尝试按等待后的时刻记录，以及较早的失败记录在排队期间过期后能接受正确密码。已有跨 Gateway 用例仍要求窗口内的失败记录保持锁定。

## 考虑过的替代方案

**在加锁查询中继续连接读取身份，或包进物化 CTE。** 获得行锁不会将同条语句早先快照中的其他账户行刷新。

**只把续期期限限制在绝对期限内。** 限制可能在写入已过期时间戳的同时仍返回已授权身份，并不能拒绝请求。

**获得会话锁后再锁账户和成员行。** 这会逆转禁用和删除使用的账户至会话顺序，可能引入死锁。
