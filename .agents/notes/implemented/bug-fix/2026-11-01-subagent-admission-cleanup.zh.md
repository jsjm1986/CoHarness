# Agent Note: 再次准入前重试保留的一次性清理

Status: implemented

[English](2026-11-01-subagent-admission-cleanup.md) | 中文

## Problem

前台 Consumer 可能在收集一次性结果后报告释放失败，随后丢失句柄。目录发布也可能在调用方取得句柄前失败。保留父级占用可以阻止过早空闲释放，但后续委派仍可能在旧清理未确认时分配更多子级。异步工作目录准备与清理还可能让提供方注册在派发前消失。目录准备或提供方启动尚未结束时，服务撤下也可能已经完成；持有的旧服务引用随后仍能在原服务消失后分配。前台结果收集也可能晚于服务等待结束，把失败清理移交给已经结束的所有者。

## Decision

subagent 运行时按确切父级 Agent 对象，为每个已发布 run 保留一份清理租约。所有释放路径共用进行中的尝试与已成功的完成状态。失败保留租约并允许再次尝试，包括提供方同步抛错。前台 Consumer 在报告失败前，通过 `retainFailedCleanup(parent, run)` 交回失败清理。目录发布失败时，由于调用方没有取得句柄，会自动移交。

同一父级再次启动时，先重试已交回的失败租约，再准入提供方。 收集重试监听器期间交回的失败，会在派发前再次对照运行时持有的租约检查。所有选定尝试均等待结算；任何持续失败都会拒绝新启动。持有者拥有的 run 保留既有控制。并发重试合并；即使 Session id 相同，重新创建的 Agent 也拥有独立归属。准入触发的重试成功后，原始句柄仍保持幂等。服务释放会等待已接管的清理，包括等待某批清理期间新增的移交。运行时作用域的空闲监听器随等待过程结束。

已接管失败在原父作用域中持有恢复注册与空闲否决，在运行时移除后保留到释放确认。替换运行时在分配前收集并等待原恢复操作。父作用域监听器可跨运行时替换找到这些登记，并负责复用及确认清理后的释放。父作用域退出在注销监听器前重试保留清理，并收集每批等待期间新增的移交。`subagent/cleanup-retain` 向已有的确切父级恢复登记提供重试操作与不会拒绝的释放确认，包括正在等待清理的登记。每次提供仅由一个监听器接收；run 句柄不改变所有者。正在退出的父级不新增 effect。若没有恢复登记接收迟到移交，原已接管租约会启动合并重试。重试失败继续保留运行时所有权与占用。

启动捕获一份 effect 作用域的提供方注册，在清理后检查调用方取消状态，并在派发前立即比较注册身份。重新注册同一个提供方对象会产生另一份注册，不能授权先前注册下仍在等待的请求。

委派工具在子模型预检前持有 Host 操作，并捕获确切的准入运行时。预检与子级派发共享其取消信号。前台调用在结果收集、释放和失败移交期间保留该操作；后台调用在登记原所有者 Job 或接收持续型子级后释放它。已发布的后台持有者保留独立控制。子级信号包含该操作的运行时取消。服务撤下先等待 Consumer 结算，再排空新移交的清理，因此已发布的前台 run 不会把清理交给已经结束的作用域。持有方拥有的后台控制仍保持独立。

运行时撤下会关闭准入，并通过每个待完成操作自己的控制器取消操作。作用域先等待这些不会拒绝的完成 Promise，再排空移交清理。迟到的提供方发布会被释放，不写入目录，也不发布生命周期。目录成功提交后，会在生命周期发布前解除运行时取消关联；同步观察者撤下服务时，不会取消已经提交的 run。调用方取消信号仍保持连接。

准入在每批清理等待结束后，重新检查确切父级的恢复集合。等待期间新增的移交会在提供方派发前加入同一次准入；清理持续失败时拒绝分配。持有方拥有的后台工作仍被排除。

## Alternatives considered

**丢弃失败占用。** 子级资源仍在线时，这会允许空闲释放。

**定期重试。** 后台重试日程需要独立的部署策略。新的委派请求可以沿用既有的显式恢复触发点，无需增加定时器。

**失败后创建清理 Job。** Job 容量不足或控制器撤销可能拒绝这种迟到的移交。既有保留 run 无需新准入或所有权转移。

## Consequences

已交回的清理持续失败时，拒绝同一确切父级的后续一次性启动。其他父级保持独立准入。已发布结果、生命周期事件、凭据、Session 代际和 schema 版本维持原有定义。既有后台 [Job 终止重试](2026-11-01-subagent-job-cleanup.zh.md)继续由原持有者管理，不进入准入触发的清理。显式移交要求 subagent 服务与前台 Consumer 构建版本匹配。

## Verification

已发布以及目录失败后的清理均保留占用，并在释放前拒绝再次分配。并发调用共享清理；取消、提供方移除、替换和同对象重新注册均拒绝陈旧派发。其他父级或同 id 的 Agent 替代实例不能取得旧清理。两个 SDK 使用正常前台 Consumer 与真实开放的 HTTP 子级传输，验证新分配前完成关闭，并覆盖工作目录准备期间替换提供方。服务及外层所有者释放时，在清理暂停期间保留空闲监听器，并等待暂停期间新增的移交。两个 SDK 还验证服务替换前真实响应已关闭。完整旧版源码与构建后的 subagent 包在这些场景中失败。

SDK 预检夹具在子模型适配器持有原生 HTTP 元数据响应时只撤下 Core。运行时取消在撤下完成前关闭响应并完成适配器清理，不创建子级或 Job。包级屏障覆盖前台、一次性后台及持续型预检、提供方替换、获准默认路由和已发布后台控制。
