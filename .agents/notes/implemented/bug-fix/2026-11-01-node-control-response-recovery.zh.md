# Agent Note: 节点控制响应恢复

Status: implemented

[English](2026-11-01-node-control-response-recovery.md) | 中文

## Problem

节点接入、连接申请与心跳可能在响应正文到达代理前完成提交。把正文中断或过大的容量拒绝页面当作无效成功响应，会导致进程不必要地终止。替代进程申请不同的连接，可能使属于原连接的 Runtime 进程代次失去授权。

## Decision

节点代理先按 HTTP 状态分类拒绝，再解析有界错误正文：429 与 5xx 允许重试；其他拒绝仍会终止，除非其声明的协议错误码提供已有恢复路径。正文可以细化拒绝码，但正文读取失败不能把已知拒绝变成成功响应校验。

HTTP 成功响应的正文因传输故障而读取失败时，代理使用同一候选凭证、进程连接 UUID 和已知代次重试。JSON 格式错误、缺少租约字段、成功正文超限及身份不匹配仍会终止。请求与重试时限沿用现有配置。代理不会从缺失的确认推导执行权限；中心的当前凭证和租约仍是授权依据。

## Alternatives considered

**每次正文读取失败都重启。** 即使中心已提交原操作，重启仍会更换进程连接 UUID，造成可避免的租约与 Runtime 更替。

**重试所有无效响应。** 重试格式错误的成功响应或身份不匹配，会掩盖协议与部署错误。成功响应保留现有结构、身份和字节上限检查。

**提高响应上限。** 更大的上限无法修复传输中断，却会为错误页面占用更多内存。错误正文继续受限，其重试分类由 HTTP 状态决定。

## Consequences

短暂响应故障本身不会更换租约所有者。长期故障仍可能导致租约过期，已有的租约丢失恢复可以递增代次。凭证撤销、退出接入、关闭清理和 Runtime 授权隔离沿用原有规则。

诊断只暴露声明的错误码，不暴露原始响应正文或凭证。协议、私有状态文件格式、配置与数据库结构均不改变。[节点通道共享授权](2026-10-31-node-channel-shared-authorization.zh.md)独立管理准入过程中的数据库锁。

## Verification

真实 HTTP 测试在原生 fetch 收到响应头后中断正文，覆盖过大的 429 和 503 响应，并核验凭证与连接复用。测试同时保留 401／403 终止拒绝、格式错误的成功响应，以及声明式和流式响应大小上限。独立进程验证使用真实已认证 Gateway 与 PostgreSQL；回环测试不代表公网可靠性验收。
