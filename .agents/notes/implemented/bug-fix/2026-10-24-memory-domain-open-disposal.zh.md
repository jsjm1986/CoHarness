# Agent Note: 异步初始化期间的记忆域所有权

Status: implemented

[English](2026-10-24-memory-domain-open-disposal.md) | 中文

## 问题

记忆提供方异步打开存储域，初始化 effect 在打开完成后才注册另一个清理 effect。若提供方在打开期间开始卸载，Cordis 会拒绝这次迟到的 effect 注册；已经取得的域仍处于打开状态，并继续占用名称，阻止替换提供方。

## 决策

原始初始化 effect 直接返回域的清理闭包。Cordis 会等待尚未结束的初始化，并在卸载期间调用该闭包，包括域在卸载开始后才到达的情况。清理无需在失活上下文上注册新 effect。域关闭并释放名称之前，存储域设施持续拥有该资源。

此变更覆盖记忆提供方的待决资源获取，不证明其他提供方或外层所有者关闭时的资源顺序。已提交修改的语义仍由[记忆结果决策](2026-10-23-memory-mutation-outcomes.zh.md)说明。

## 考虑过但未采用

**等待域打开后再注册清理 effect。** 此时资源可能已成功取得，但卸载已经使上下文失活。

**依赖存储后端最终关闭。** 后端仍然活跃时，记忆提供方就可能被替换。把域保留到整个应用关闭，会阻止替换方打开同名域。

## 后果

提供方卸载会等待待决获取结束，并在自身完成前释放取得的句柄。替换方可以打开同一个记忆域。存储条目、schema 及模型可见的记忆结果保持既有格式。

## 验证

受控单元回归使用真实存储域设施和内存后端，在打开调用返回前卸载提供方，检查域已关闭且替换方能正常读取。原实现会留下打开的存储单元。

无密钥 headless 示例使用实际 Loader 条目与 JSON 后端，在后端打开期间停止记忆插件，检查域已释放，再重载条目并通过实际模型 `memory_save` 回合完成写入。固定预期包含已持久化的 `release-freeze` 键。恢复迟注册实现后，完整示例会在替换前失败。
