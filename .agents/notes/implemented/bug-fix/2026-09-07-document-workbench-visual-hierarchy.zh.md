# Agent Note: Document workbench visual hierarchy

Status: implemented

[English](2026-09-07-document-workbench-visual-hierarchy.md) | 中文

## Problem

文档管理器让导航、作用域状态、筛选、操作和列表行拥有近似的视觉权重。桌面端扁平的面板让工作台显得割裂，列表较大时，视口外的行仍会承担布局和绘制成本。

## Decision

管理器保留现有 DOM、操作顺序、权限和请求行为。样式表建立统一层级：作用域栏作为安静的导航区域，内容面板作为抬升的任务区域，状态和筛选控件使用一致的间距，文档、总览和回收站行使用相同的元数据节奏和悬停处理。活动作用域使用克制的品牌色边缘帮助定位，不引入第二套强调色系统。

文档行、总览行和回收站行使用 `content-visibility: auto`、固有尺寸提示以及布局、绘制和样式隔离。浏览器可以跳过视口外元数据的工作，同时保留现有滚动区域和可访问的行语义。

可滚动的导航和列表区域为滚动条预留独立的内联轨道，选中背景和行边框不会再位于滚动条滑块下方。

## Alternatives considered

**围绕新的卡片和工具栏组件重写组件树。** 否决：本次需求只涉及表现层，现有 DOM 已经具备所需的可访问关系和操作处理器。

**改用固定列的紧凑表格。** 否决：长文档名、紧凑布局和现有移动端操作面板都需要可伸缩的元数据宽度。

**在 JavaScript 中实现虚拟列表。** 否决：虚拟化会增加滚动测量状态，并可能改变选择、分页和可访问性行为；CSS 隔离可以在不改变列表语义的情况下处理绘制成本。

## Consequences

管理器现在以一个工作台呈现，导航、任务、状态和行层级更清晰。桌面行使用更安静的分隔线和一致的悬停节奏；紧凑布局保留触控尺寸和面板几何。大型列表会跳过不必要的视口外布局和绘制。样式使用 `color-mix()` 从主题 token 派生颜色，并继续以现有主题 token 作为颜色来源。

## Verification

文档管理器样式测试检查抬升的内容面板、活动作用域指示器和列表行隔离规则。组件测试套件与文档 UI TypeScript 聚合均通过，既有的作用域、操作和响应式行为覆盖保持有效。
