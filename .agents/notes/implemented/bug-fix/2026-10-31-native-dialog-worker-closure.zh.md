# Agent Note: 原生对话框工作进程的关闭确认

Status: implemented

[English](2026-10-31-native-dialog-worker-closure.md) | 中文

## 问题

对话框结果或已接受的终止请求可能先于工作进程退出。在任一点返回都会丢失剩余的进程属主。异步窗口关闭准备也可能比它所捕获线程 id 对应的工作进程存活更久。

## 决策

Win32 驱动持有首个已报告结果，直至子进程发出 `close` 且所有已启动的窗口关闭调用完成。取消会重试正常窗口关闭，随后请求 `SIGKILL`；请求失败时保留操作及其观察者，包括在迟到的 `showing` 通知后重试正常关闭。同一时刻最多运行一个窗口关闭调用。终止错误保留在中止错误的 cause 链中。驱动在关闭后移除事件订阅，子进程仍活动时不会释放其进程引用。

独立的工作进程生命周期信号在观察到进程退出时结束，也包含 spawn 失败后的关闭。窗口关闭器在异步绑定准备前后检查该信号。这会拒绝为已知退出的工作进程准备的窗口消息；尚未观察到退出时，它不能证明原生线程身份。

这补齐了[提供方生命周期](2026-10-31-native-picker-service-lifetime.zh.md)下的工作进程所有权，而 [COM 适配器](../feature/2026-08-02-win32-in-process-folder-dialog.zh.md)负责对话框创建及释放。

## 考虑过的替代方案

**收到工作进程的结果消息就返回。** IPC 消息确认的是结果，进程和流是否关闭是独立事实。

**把成功调用 kill 视为清理完成。** 它确认的是请求，而非退出。调用被拒绝时也不能丢弃属主。

**丢弃未完成的窗口关闭调用。** 它们延迟进行的绑定准备仍可能在工作进程退出后发送消息。

## 后果

提供方销毁可以通过已接受的选择任务 promise 等待原生工作进程退出。未确认终止时，该 promise 保持未完成。真实 IPC 子进程验证结果、拒绝终止和延迟关闭的间隔；公共选择器还检查其真实的原生能力不可用工作进程。原生 COM 渲染、选择和 Windows 内核终止仍需平台验收。
