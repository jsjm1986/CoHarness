# Agent Note：记忆整理的执行身份

Status: implemented

[English](2026-10-23-curation-execution-identity.md) | 中文

## 问题

记忆整理把已完成回合合并到每个会话的运行队列中。待运行回合可能属于另一位项目成员。从上一遍的异步回调启动它，会保留上一遍的执行上下文，可能把辅助请求计费和写入归属记到错误的参与者。

## 决定

每个回合在排队前捕获执行继承及签发授权提供方。每遍通过 `runCaptured` 恢复该继承，并在启动前检查提供方身份。捕获失败只跳过后台遍，不中断已完成的主回合。独立应用保留没有授权提供方时的行为。

## 备选方案

**待运行遍启动时才解析参与者。** 前一回调仍可能携带自己的异步执行上下文，而会话可能已经反映更晚的回合。两者都不能可靠地标识待运行回合。

**只保留参与者 id。** 执行授权还依赖不可变作用域和签发提供方，仅有 id 无法恢复该权限。

## 影响

排队的提取与合并在触发回合的身份下运行，不会沿用相邻成员的执行身份。替换后的提供方不能把当前权限借给更早排队的遍。

## 验证

使用 GatewayExecution 和 JSON 存储的已构建产品复现中，触发者为 `[1, 2]`，辅助请求却归属 `[1, 1]`。单元屏障覆盖排队回合、捕获拒绝和提供方替换。headless 示例快照在确定性 Gateway 线上回复下运行真实 Agent 回合、GatewayExecution、整理及 JSON 记忆，检查辅助请求归属和持久写入者。
