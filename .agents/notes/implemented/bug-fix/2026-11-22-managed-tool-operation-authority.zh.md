# Agent Note: 在实际工具操作点校验受管权限

状态：已实现

[English](2026-11-22-managed-tool-operation-authority.md) | 中文

## 问题

Office 工具与补丁操作将结构化输入交给文件系统提供方。解析后才能得到确切文件目标。只按工具参数名检查会遗漏这些操作的输入。可选 Session 存储缺少 SSH 目标字段时，也无法在重开会话后保留执行主机。

## 决定

Office 读取与补丁规划使用文件系统提供方选定的规范进程路径发起权限检查。目录保护插件在此校验读写授权。删除前由观察策略提供已观察的文件版本。SQLite Session 存储在接受绑定 SSH 的会话头之前拒绝它。

受管 profile 保护已安装的沙箱、权限、审批、文档和管家组件。组合包的补丁路径须解析到声明它的包内。管家工具转发取消信号，并按调用保留自己的审批引用，直到产生结果或 Session 释放。

## 备选方案

在目录保护插件中再次解析补丁语法会重复目标解析，让授权依赖两个解析器始终一致。写入时抹去无法保存的受管元数据会让恢复的 Session 使用不同文件系统。在各自的负责组件中检查解析后的路径并显式拒绝无法保存的输入，可以维持这两项约束。

## 后果

检查文件权限后才读取内容。补丁被拒绝时，每个文件均保持原状。Office、补丁和目录保护测试覆盖这些结果。使用可选 SQLite 存储的部署参见[绑定 SSH 的 Session 指南](../../../../docs/upgrade-guide/v0.2.1-rc.1.coharness.1/sqlite-managed-ssh/guide.zh.md)。
