# Agent Note: 受管对话先于 Host 元数据恢复

Status: implemented

[English](2026-11-20-managed-mux-reconnect.md) | 中文

## Problem

Ubuntu 正式链路中，浏览器在提交后的 22.54 秒收到首批回复数据，第 34.80 秒才显示。对话流在第 16.85 秒打开。Host 状态流在第 25.59 秒打开，随后通用历史接口又耗时 9.14 秒。

另一次强制重连中，Host 在包含标题序号的基线之前发送了唯一缺失的标题。提前恢复路径等待基线，再通过一次耗时 2.57 秒的预备历史读取请求获得了同一事件。

## Decision

浏览器重连时，新的 Host 描述和已打开的 Mux 可以恢复现有根对话，前提是账号、Runtime、电脑和序号基线相符。前一代连接在 `host.describe` 和 Mux 验证后就能确定目标，即使 Host 状态流还没打开就失联。提前处理的帧包括对话基线、持久事件和助手流。其他帧在完整握手后交付。Mux 代次结束时取消该代次的尾页读取。已覆盖的游标无需读取历史。缺失的事件走现有的精确目标预备读取，并保留[有界实时窗口](2026-09-03-bounded-live-window-and-incremental-reconnect.zh.md)。

[Host mux](../../../../packages/host/apiproxy/README.zh.md)保留完整的持久游标，在基线之后补发末尾标题。已收到标题的标签页可以接收基线。仅错过标题的标签页将其作为下一条持久事件应用，在历史请求进行时显示回复。

## Alternatives considered

**等两条流都打开再读历史。** 即使尾页读取更快，回复仍须等待 Host 状态连接。两条流共用完整就绪状态，只有现有且已验证的对话可以提前恢复。

**跨过缺少的持久序列直接显示实时片段。** 轮次和结算归并要求事件连续。补齐缺失前缀后才能把续接的回复并入现有对话。

## Consequences

Host 状态流打开期间，现有对话可以继续显示回复。尚未完成的提交和标签页内的草稿仍绑定原归属。浏览器用例延迟 Host upgrade 和历史响应。已收到末尾标题或重连后补发标题时，回复均在历史响应之前出现。缺少前序事件时，回复仍需等待一次预备读取。每种情况下回复都只显示一次。
