# Agent Note: 紧凑文档工作台使用任务导向的操作层

Status: implemented

[English](2026-08-25-mobile-documents-workbench.md) | 中文

## Problem

文档管理器把桌面端作用域侧栏、筛选控件和五个行操作压缩到手机宽度内。短屏会把控件推到卡片可视区域之外，横向作用域栏和行内危险操作也让导航和权限状态难以理解。

## Decision

文档插件保留桌面工作台，在 768px 以下使用独立的紧凑信息层级。当前作用域按钮打开支持本地搜索的作用域选择层。上传仍是工具栏主操作；筛选、历史、刷新、新建文件夹和备用源浏览统一进入“更多”层。文档和文件夹行只保留一个“更多”入口，多选使用避开安全区的批量操作条和批量操作层。

`DocumentsMobileSheet` 是基于现有 `Modal` primitive 的内部 presenter。它只在紧凑操作层打开时挂载，复用现有 portal 和 dialog 焦点行为，并在现有预览、移动、复制或删除确认层打开前关闭。文档 endpoint、权限规则、分页规则和公共组件 props 均不变。

紧凑工作台只有一个文档列表滚动区域。操作层搜索和筛选都在客户端完成，行操作控件只在打开对应层时渲染。紧凑操作树使用共享的媒体查询订阅；不增加逐行观察器、轮询、虚拟化或额外网络请求。

## Alternatives considered

**保留横向作用域栏并换行行按钮。** 否决，因为换行仍然保留桌面信息密度，无法表达操作优先级，长名称和危险控件仍会在 320px 行内竞争空间。

**扩展全局 `Menu` primitive，加入文档专用标题和表单。** 否决，因为作用域搜索和筛选需要带标题且可滚动的 dialog；仅为文档需求扩展全局 API 会扩大影响范围。

**增加移动端专用的后端列表或分页 endpoint。** 否决，因为现有客户端分页已足够支撑紧凑呈现；新增 route 会增加延迟，并在没有交互收益的情况下产生第二条权限路径。

## Consequences

手机用户获得稳定的触控热区、明确的只读状态和可预测的层级，但行操作需要多一次点击。桌面用户继续使用既有侧栏和行内操作顺序。打开操作层和输入筛选不会产生网络请求；只有明确的作用域或文档操作才调用现有客户端方法。

## Verification

组件测试覆盖紧凑作用域搜索、行操作路由、预览交接和批量权限。无密钥 Web e2e 快照覆盖紧凑管理器、作用域层、文档操作层和批量操作层，并在手机尺寸下验证；几何断言覆盖 dialog 边界、触控热区和横向溢出。紧凑视觉审计覆盖 390px、375px 和 320px 布局，暗色 token 检查仍由浏览器门禁执行。
