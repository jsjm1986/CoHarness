# Agent Note: 使用部署数据库账号验证项目名称隐私

Status: implemented

[English](2026-11-17-project-name-privacy-preflight.md) | 中文

## Problem

项目名称不能进入治理数据库的 SQL 参数日志。受限 Gateway 账号可以连接 PostgreSQL 并查询管理数据，但仍可能无权设置名称规范化所需的参数。因此，常规健康检查无法确认创建项目时能否安全处理名称。

## Decision

[部署预检](../../../../gateway/src/project-name-privacy-main.ts) 使用 Gateway 的实际连接身份，在只读事务中调用生产名称规范化逻辑。规范化仅输入固定公开值。运维人员为账号及数据库配置日志默认值，或在现有连接需要事务局部保护时，窄范围授予参数设置权限。[部署说明](../../../../gateway/deploy/node-content/README.zh.md) 负责记录这些命令。

预检不授予权限、不创建项目，也不重启服务。每次真实请求保留独立的日志检查。诊断输出不包含连接字符串、凭据或规范化字节。

## Alternatives considered

**使用超级用户健康探针。** 它能设置实际 Gateway 无权修改的参数，成功结果不能证明真实登录账号已就绪。

**删除逐次请求保护或授予超级用户。** 两者都会为适配部署错误而削弱隔离要求。显式参数权限保留现有业务数据授权。

## Consequences

运维人员可以在接受项目请求前诊断受限账号错误，无须中断长任务。预检通过只证明 SQL 名称规范化的隐私保护，不代表存储健康或项目整体就绪。可运行的 CLI 记录覆盖缺少权限、窄范围授权及安全账号默认值，同时检查现有连接的设置不变、未写入项目。
