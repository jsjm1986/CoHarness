# Agent Note: Gateway 隧道生命周期与持久化配置

Status: implemented

[English](2026-10-25-gateway-tunnel-lifecycle.md) | 中文

## 问题

Gateway 不读取输出管道时，长驻隧道会被阻塞；发现临时隧道 URL 后继续保留诊断，也会随进程寿命增加内存占用。分配失败会发出 `error` 和 `close`，不保证发出 `exit`。停止失败后丢弃进程句柄，会允许公网入口重叠；旧退出状态写入也可能覆盖替代进程的状态。关闭还可能与已接纳的启动重叠。

命名隧道配置要求创建响应包含运行令牌，但 Cloudflare 文档定义了独立令牌端点。拒绝该有效响应会丢失已确认创建的隧道标识。在远端删除之后校验替换输入，可能因无效请求破坏可用配置。

进程存活或打印 URL 不能证明已连接边缘。停止可能排在注册等待之后，陈旧的恢复读取可能复活较新的停止意图，生产关闭流程也可能因等待写操作而阻止完成该写操作所需的取消。

下载失败可能保留未读取的响应或未关闭的归档。暂存目录位于另一文件系统时，无法通过重命名安装；先发布再修改权限可能暴露未完成候选文件。取消若只覆盖连接器注册，发现、安装和 Cloudflare 准备仍会阻塞动作队列。

## 决策

[进程所有者](../../../../gateway/src/tunnel-process.ts)为两种模式持续排空两个输出流。临时地址发现分别保留 DNS 长度范围的流前缀，在就绪或失败后移除扫描，并继续排空。两种模式都在注册之前返回清理句柄。`ready` Promise 要求新建私有文件包含所持子进程的 PID；临时模式还要求取得 URL。固定版本的 [cloudflared 实现](https://github.com/cloudflare/cloudflared/blob/2026.9.3/cmd/cloudflared/tunnel/cmd.go)在连接信号之后写入该文件。文件读取有大小限制，并拒绝特殊文件；磁盘 PID 值从不决定信号目标。启动与原生关闭有分别由部署配置的期限。关闭或私有文件清理失败时保留重试所有权；父进程退出观察者属于句柄，并在原生关闭后解除。

[控制器](../../../../gateway/src/tunnel-access.ts)将退出状态写入与管理员动作串行化。停止和清除会立即取消此前已接纳的启动，包括排队请求；被取消的启动报告 `409 tunnel-start-cancelled`。意图版本阻止陈旧恢复读取复活较新的显式动作。停止失败时保留清理句柄并报告 `tunnel-stop-unconfirmed`；替换和远端清理等待本地终止得到确认。关闭会停止接纳、取消注册、等待已接纳工作，并允许重试清理，同时保留重启意图。生产关闭流程在等待 HTTP 写操作之前启动后台取消，并等待所有取消结果。

取消覆盖二进制发现、版本执行和 Cloudflare 准备；关闭还会取消安装与清理请求。原生辅助命令在取消后等待自身的关闭事件。已确认创建的标识和令牌先完成持久化，再由取消阻止后续远端工作或进程分配。自定义发现和安装实现会收到信号，等待外部工作时必须响应取消。

安装在目标二进制目录下暂存，校验字节、解压并设置可执行权限后才原子发布。[Node 流管线](https://nodejs.org/docs/latest-v22.x/api/stream.html#streampipelinesource-transforms-destination-callback)持有响应的 Node 可读适配器与归档写入器；取消到达源端，暂存清理等待写入器的原生关闭。HTTP 响应被拒绝时取消其响应体。下载、校验或解压失败均保留已安装二进制。

命名输入使用规范 DNS 名称，并在破坏性工作之前完成凭据和域名检查。选定区域提供所属账号。已确认创建的标识在请求[连接器令牌](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/token/methods/get/)之前持久化；重试复用该标识并继续未完成的配置。远端结果字段与 HTTP 状态经过校验。即使当前执行模式是临时隧道，清除仍会删除保留的命名资源。[功能决策](../feature/2026-10-18-admin-managed-public-access-tunnel.zh.md)继续负责 UI、加密与公网暴露选择。

选定的连接器令牌在环境过滤后，通过 Cloudflare 文档定义的 `TUNNEL_TOKEN` 环境项提供，不出现在进程参数中。谁能检查其他进程的环境仍由内核账号隔离决定；本地同账号执行不新增 OS 隔离。

## 考虑过的替代方案

**不读取管道，只丢弃诊断。** 内核管道填满后，生产者仍会阻塞。读取后丢弃同时避免背压与输出留存。

**请求终止后就发布停止态。** 请求不是关闭证据；保留句柄才能重试并阻止替代进程重叠。

**获取令牌失败后创建另一个隧道。** 创建已经成功，持久化已确认的标识才能保留重试与后续清理所需的资源。

## 后果

隧道子进程共用 Gateway 部署环境过滤。Cloudflare 配置是一系列外部请求；创建响应丢失时，可能需要在提供方侧核对资源，本变更不建立远端原子事务。Gateway 被强制杀死时仍依赖宿主服务约束。本地夹具无需 Cloudflare 账号即可验证协议处理，但不证明真实 Cloudflare 可用性或原生服务约束。

## 验证

真实本地进程在修复前复现命名输出阻塞，以及临时分配失败的错误报告。受控屏障复现清理丢失、关闭重叠与陈旧退出写入。API 回归拒绝损坏响应、接纳文档定义的创建字段，并在替换输入无效时保留可用配置。经过认证的 PostgreSQL／Gateway／Web 装配，让真实隧道进程连接本地 HTTP Cloudflare 替代服务，检查部署变量未继承，使用同一持久化标识重试获取令牌，让临时／命名启动停留在注册之前，并确认取消、超时与 Gateway 关闭后真实子进程套接字已关闭。回归测试对阻塞写操作执行生产关闭函数；受控启动／停止／恢复屏障证明意图顺序。

真实文件流与可执行夹具验证下载失败后的关闭、取消、版本探测关闭，以及已安装二进制的保留。编译后的管理页面记录通过经过认证的 HTTP 执行真实安装器失败，并检查响应取消。真实固定版本通过下载、SHA-256、解压、权限、发布与原生版本探测；这不证明 Cloudflare 边缘连通。
