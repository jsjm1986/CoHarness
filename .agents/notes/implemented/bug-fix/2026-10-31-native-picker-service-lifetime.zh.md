# Agent Note: 原生选择器的服务生命周期

Status: implemented

[English](2026-10-31-native-picker-service-lifetime.md) | 中文

## 问题

撤下原生选择器服务本身不会取消它已启动的命令。捕获的能力对象也可能比服务注册存活更久。缺少操作属主时，卸载后选择器可能继续运行，旧能力对象也可能再分配一个辅助进程。

## 决策

每个原生提供方实例拥有一个中止控制器及其未完成选择任务的 promise。选择任务在分派前合并调用方取消与提供方生命周期。销毁会中止提供方并等待已接受的 promise；已完成的选择任务会自行移除。生命周期中止后，同一个稳定能力对象上的后续调用会被拒绝。

[原生命令运行器](2026-10-29-native-command-cancellation.zh.md)持有 POSIX 辅助进程直至进程和流关闭。提供方所有权补上卸载取消，不改变运行器的独立职责，也不改变[客户端结果代际隔离](2026-09-16-native-picker-stale-settlement-fence.zh.md)。

## 考虑过的替代方案

**只移除服务注册。** 消费方可能仍在等待撤下前启动的命令，或持有稳定的能力对象。

**只取消调用方。** 原生后端卸载时，活动连接不一定结束。取消一个提供方也必须保持独立调用方和其他提供方实例不受影响。

**中止但不等待完成。** 取消信号不能证明已接受的操作已完成资源释放。

## 后果

提供方和外层 Host 拆卸会等待已接受的原生选择任务排空。调用方取消后，活动提供方仍可继续使用。POSIX 可运行组合检查拆卸后辅助进程确已消失，并验证旧能力对象拒绝调用；受控完成检查验证卸载会持续等待辅助进程结束。Windows 原生进程退出需要独立的驱动及平台验收。
