# Agent Note: 项目会话失败使用安全的用户提示

Status: implemented

[English](2026-08-31-project-session-failure-guidance.md) | 中文

## 问题

组织管理员无需 `project_members` 记录，就对所有活动项目拥有隐式读写权限。PostgreSQL 对话写入器却只检查显式项目成员关系，因此管理员发送消息时可能在运行时已经接纳消息后才失败。Gateway 未预期异常随后以纯文本返回给只接受 JSON 的持久化消费方，解析器细节就变成了 Chat 中显示的轮次错误。

## 决策

`ConversationRepository` 从活动的 `rw` 项目成员关系或活动的组织管理员关系中解析项目写入者。会话根实体化和贡献者记录使用同一规则；管理员可以依据既有管理员覆盖策略参与私密项目会话，而管理员降权后下一次追加立即失去该权限。

运行时 HTTP 路由的未预期异常使用稳定的 JSON 错误 envelope，堆栈、SQL 和存储细节只保留在 Gateway 日志中。`dsh-session-persistence-gateway` 将格式错误或服务器错误 body 归类为安全的依赖失败，并从面向用户的错误链中移除解析器原因。对话渲染器把持久化和授权内部细节转换为本地化重试提示，并隐藏无意义的 `UNKNOWN` 代码。

## 验证

PostgreSQL 协作测试覆盖管理员创建根会话、参与公开和私密项目会话，以及管理员降权后的拒绝。Gateway server 测试固定运行时 JSON 错误 envelope。持久化传输测试固定纯文本 500 响应和解析器细节的隐藏。客户端 runtime 与 conversation 测试固定中英文安全持久化文案。

## 备选方案

**为每个管理员添加显式项目成员记录。** 不采用，因为产品策略明确授予管理员隐式权限，且角色变化必须在不维护重复项目记录的情况下生效。

**在 Chat 中显示 Gateway 异常或解析器文本。** 不采用，因为这会泄露实现细节，无法告诉用户如何处理，也可能暴露路径或提供方诊断。

**只修改渲染器。** 不采用，因为仅隐藏文案仍会让管理员无法写入，并保留未来运行时错误的协议不一致。

## 影响

管理员项目会话现在与协作服务使用相同的授权规则，包括私密根会话。运行时失败仍可在服务端日志中诊断，而浏览器得到稳定 JSON 和简洁的本地化重试指引。追加失败保持事务性，因此被拒绝的批次不会产生部分会话事件。
