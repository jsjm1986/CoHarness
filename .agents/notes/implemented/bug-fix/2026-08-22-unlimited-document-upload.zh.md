# Agent Note: 默认不限制文档上传大小

Status: implemented

[English](2026-08-22-unlimited-document-upload.md) | 中文

## 问题

文档上传默认执行 100 MiB 的单文件准入限制，即使存储文档只是通过文件系统消费的普通文件。浏览器或隧道断开时，客户端只显示 `Document upload failed.`，无法区分传输中断和服务端拒绝。

## 决策

`UserDocLimits.maxFileBytes` 现在可为空。本地存储默认使用 `null`，流式写入器和 HTTP `Content-Length` 预检只有在部署提供有限数值时才执行检查。文档数量、消息总字节数和内联文本字节数仍作为独立保护，分别约束消息提交与模型上下文。文档管理器会说明默认不限制单个文档大小。

两套浏览器文档客户端在 XHR 以状态码 `0` 失败时报告连接中断，同时保留结构化 HTTP 错误和调用方主动取消行为。提示会把网络或隧道列为下一步诊断目标，但不会自动重试，因为响应丢失时无法确认服务端是否已经发布文件，自动重试可能创建重复文件。

## 考虑过的替代方案

**使用很大的数字哨兵表示无限上传。** 不采用，因为哨兵仍然是真实的上限，在 UI 中会显示成误导性的文件大小，并让 wire contract 依赖魔法数字。`null` 直接表达没有限制。

**完全删除可配置的单文件限制。** 不采用，因为部署可能需要针对文件系统或运维策略设置有限保护；默认不限制，同时保留显式配置能力。

**XHR 失败后自动重试。** 不采用，因为连接可能在服务端发布文件后、浏览器收到响应前失败；没有幂等 key 时重试可能创建带后缀的重复文件。客户端现在提供诊断信息，由用户决定是否重试。

**随单文件限制一起删除消息级限制。** 不采用，因为文档数量、消息总字节数和内联文本字节数独立保护提示装配和模型上下文。

## 后果

应用不再仅因文档超过原来的 100 MiB 默认值而拒绝上传。显式设置有限 `maxFileBytes` 时仍返回原有的 `DOCUMENT_TOO_LARGE` 响应；文件系统、浏览器、网关、隧道和托管计划仍可能构成外部传输或存储限制。隧道断开导致的上传失败会在输入框中显示可操作的诊断，而不再折叠成笼统失败文本。后续的[可恢复上传决策](../architecture/2026-08-25-resumable-user-document-upload.zh.md)现在负责解决外部单请求上限；本记录仍是可空准入限制和连接诊断文案的依据。
