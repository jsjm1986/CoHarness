# Agent Note: Web 浏览器交接保留其 Node 助手

Status: implemented

[English](2026-10-31-web-browser-helper-ownership.md) | 中文

## 问题

Web 运行时通过未保留的 Promise 启动浏览器交接 Node 助手。注入连接的所有者可以在助手仍存活时完成销毁。助手报错也会在原生关闭尚未确认前拒绝操作。

## 决策

[Web 运行时](../../../../packages/bundle/web-app/src/index.ts) 在连接注入上下文内保留交接 Promise。销毁会取消助手，并等待原生关闭。启动器记录首个失败，在关闭时移除取消监听器，且仅在该关闭后拒绝操作。已取消的工作不分配助手。预期的所有者取消不产生手动 URL 失败警告。

平台交接语义仍由维护中的 opener 负责。此变化持有短生命周期 Node 助手，不管理操作系统交接后的浏览器。管理界面启动独立于模型请求及受管工作负载准入。

## 考虑过的替代方案

**丢弃交接 Promise。** 所有者可能在子进程仍存活时确认销毁完成。

**报错或请求终止时就完成。** 两种事件都不能证明原生进程已关闭。

## 影响

正常启动、凭据清理、Windows 交接观察及手动失败回退保留。导出的原生测试钩子要求调用方传入 `AbortSignal`。[就绪页面决策](../feature/2026-08-12-open-ready-web-ui.zh.md) 继续有效；其应用就绪和操作系统委托决策与助手清理相互独立。

## 验证

受控子进程测试在所有者销毁、取消和错误期间保持原生关闭待完成。已发布的 `dsh --profile web` 场景仅将 opener 替换为私有模块，启动实际 Node 助手，并在 HTTP 监听器仍存活时卸载 Web 运行时。它观察助手先于所有者确认退出，无需打开桌面浏览器或调用模型 API。
