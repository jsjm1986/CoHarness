# Agent Note：节点通道共享鉴权

Status: implemented

[English](2026-10-31-node-channel-shared-authorization.md) | 中文

## 问题

每次控制连接检查与转发服务连接都认证同一个节点凭证。排他行锁会串行执行这些只读事务。Gateway 通过较慢网络访问 PostgreSQL 时，锁跨越多个网络往返，延迟其他浏览器请求及节点心跳。

## 决策

`authorizeChannel` 对节点代理行与组织行取得 `FOR SHARE`，保持到事务结束。多个鉴权读取可以并发进行。接入、连接、心跳、断开和管理员变更仍对节点代理行取得排他锁。等待变更的读取会重新检查变更后的凭证与当前有效期，不会恢复过期租约或已撤销凭证。不缓存任何鉴权结果。

## 考虑过的替代方案

`FOR KEY SHARE` 允许在读取持有行锁时更新非键的凭证与租约字段，无法保持与撤权之间要求的顺序。缓存凭证同样会延迟观察到撤权。两者都不适合准入鉴权。

## 后果

每个连接仍承担自身的数据库及网络往返。并发读取不再跨越这些操作持有节点排他锁；变更等待已准入的读取结束后提交。传输超时和连接容量继续限制准入。

## 验证

真实 PostgreSQL 节点接入夹具保留共享读取，并在释放之前完成两次通道检查。独立的受控写入等待验证：已提交的撤权和过期会拒绝后续准入。双 Gateway 组合回放覆盖同一传输鉴权，不改变 Runtime 身份或执行权限。
