# Agent Note：Gateway 运行时凭据生命周期

Status: implemented

[English](2026-10-31-gateway-runtime-credential-lifetime.md) | 中文

## 问题

Gateway 启动可以通过一次性管道提供凭据。替换传输提供方时再次读取已耗尽的描述符，会导致认证失效。此时应用仍然持有会话和托管授权要求。

## 决策

每个应用根保留已验证的启动凭据和已解码的验证公钥。这个私有且不可枚举的值使用稳定符号，使替换后的模块能够读取同一身份。根上的 effect 在应用关闭时移除该值。通道读取或公钥解码失败时，不发布保留值。环境变更不能重新绑定运行中应用的组织或 Runtime generation；新应用读取自己的凭据。

## 曾考虑的替代方案

**在提供方模块中保留身份。** 模块替换会丢弃这份状态，而应用仍然存活。

**按描述符或凭据路径缓存。** 独立应用可以复用这些名称，不能继承彼此的身份。

**每次挂载都重新读取。** 管道无法重放已消费的字节；重新读取被替换的文件可能为已有应用重新绑定身份。

## 影响

提供方替换保留启动身份，不保留正在进行的传输操作。不同的启动身份需要新应用。凭据不会被序列化，也不会作为公开服务字段暴露。真实管道回放替换提供方及其模块，拒绝另一应用使用已耗尽的管道，保持两个应用的 generation 独立，并验证首次 JSON 与公钥错误可以修复。应用根关闭会移除保留值。浏览器准入仍由[传输认证决策](../architecture/2026-10-01-browser-auth-web-transport.zh.md)持有。
