# Agent Note: 模型菜单导航保持键盘焦点

Status: implemented

[English](2026-09-22-model-menu-keyboard-navigation.md) | 中文

## 问题

两级模型菜单在切换面板时会移除获得焦点的行。如果没有明确的后续位置，焦点就会落到页面上，下一次按键也无法到达菜单。即使触发器仍然可见，内联弹窗也可能被较窄的会话列裁切。

## 决策

桌面模型控件使用上游菜单的键盘规则和 body portal。方向键从相应端点进入并循环导航；进入模型或推理强度面板时，聚焦当前值，没有对应行时退到可用行或触发器。Tab 激活当前行，Shift+Tab 和 Escape 则返回上级面板，最终回到触发器。Retry 控件保留原生 Tab 遍历。外部指针和失焦判断同时识别触发器子树及 portal 菜单。锁定或撤下控件会关闭展开状态，恢复后不会重新打开旧菜单。

弹窗在触发器上方右对齐，并在滚动、缩放、面板切换和目录更新时限制在视口内。只有已挂载行参与焦点选择；共享手机区块可以构造同一组选项，而不挂载它们的弹窗变体。

compact composer 保留 Session Settings Sheet 及其焦点所有权。独立手机组装保留内联 Sheet；按容器宽度调整的图标尺寸和触摸目标不变。[模型目录决策](../feature/2026-07-24-web-session-model-selector.zh.md)继续拥有选择逻辑，[手机模型位置决策](2026-08-17-composer-mobile-model-seat.zh.md)继续拥有宽度约束。输入能力标签、治理拒绝提示和绑定目标 Session 的 RPC 仍使用既有目录路径。

## 验证

组件回归覆盖键盘进入、循环、选择、面板返回、空目录、Retry 遍历、portal 边界以及锁定和恢复。[组装 composer 场景](../../../../apps/web/tests/composer-model-mobile.e2e.ts)在桌面上通过真实键盘事件选择推理强度，并保留既有手机几何快照。

## 备选方案

**每次渲染后聚焦首行。** 目录刷新会抢走用户当前位置的焦点。只有面板导航意图才移动焦点。

**用桌面弹窗替换手机 Sheet。** 手机共享的模型、思考和权限导航已经拥有该交互。替换它会丢弃正常工作的本地消费者。

**移植控件时同时改变模型传输。** 选择、授权和错误格式化独立于弹窗导航，仍由共享目录作为权威负责。

## 影响

指针和键盘用户可以遍历同一组模型及推理强度选项，不会丢失焦点或无法访问菜单。桌面弹窗不再受会话列裁切，同时保留手机布局和模型治理行为。
