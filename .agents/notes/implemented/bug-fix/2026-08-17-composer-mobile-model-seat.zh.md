# Agent Note: 移动端 composer 为模型保留独立区域

Status: implemented

[English](2026-08-17-composer-mobile-model-seat.md) | 中文

## 问题

composer 行左侧放置固定尺寸的触控控件，右侧放置模型、上下文和发送控件。在窄卡片中，压缩左侧 flex 项会让其子控件绘制到该项之外，而不可收缩的右侧控件组又会让模型触发器保持其固有宽度。因此，过长的模型名可能被左侧图标覆盖，也可能覆盖发送控件。

## 决策

左侧工具组使用 `flex: 0 0 auto` 保留固有宽度。右侧控件组成为可伸缩区域，同时把固定控件保持在行末。`ModelSelect` 通过 `min-width: 0`、220px 的桌面上限和全宽触发器占用剩余模型宽度，使标签只在自己的区域内截断。在行容器宽度低于 480px 时隐藏推理等级文本；菜单和触发器 title 仍保留完整选择信息。

## 验证

组装后的 Chromium 场景通过真实模型菜单选择 `deepseek-v4-flash-0731`，在 390px 和 375px 宽度检查工具栏矩形，并重放 keyless 几何 golden。测试还检查可见工具控件位于模型触发器之前、模型触发器位于发送按钮之前，以及标签保留省略号样式。聚焦的模型选择和输入栏套件共 76 个测试通过，两个受影响的 Client 包也成功完成 bundle。

## 曾考虑的替代方案

**允许行内所有子项一起收缩。** 否决，因为左侧触控控件仍可能绘制到被压缩的 flex 项之外；缩小 flex 项不会裁剪或重新排列其子项。

**让模型名换到第二行。** 否决，因为 composer 行会变高并推移发送操作，同时模型标识仍然难以快速扫描。

**在手机上缩写或移除模型标识。** 否决，因为用户会失去当前路由的身份信息；省略显示配合 title 和菜单仍能访问完整名称。

## 后果

手机宽度下模型区域可能变窄，但不会覆盖相邻控件。左侧触控目标保留原有命中区域；小行中次要的推理等级文本让出行内空间，但仍可通过模型菜单和可访问的 title 查看。
