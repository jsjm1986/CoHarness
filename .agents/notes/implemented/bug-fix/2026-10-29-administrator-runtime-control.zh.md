# Agent Note：Runtime 控制保留发起管理员身份

Status: implemented

[English](2026-10-29-administrator-runtime-control.md) | 中文

## 问题

已认证的 Runtime 控制请求可能在目标查询、生命周期串行等待、常驻准入、策略准备或节点压力准入期间，超出发起管理员权限的有效期。跨管理员共享待完成启动，也可能让已撤权调用方获得其他管理员的结果。仓库容量拒绝需要返回服务不可用，而不是内部错误。

## 决策

[Admin 路由](../../../../gateway/src/admin-api.ts)向个人与项目的启动、停止、重启传递服务端认证的管理员 id。请求体不能选择该发起者。浏览器项目设置入口也传递认证的管理员，覆盖被动启动与热复用；手动停止的 Runtime 继续拒绝被唤起。[`InstanceManager`](../../../../gateway/src/instances.ts)按目标、意图和发起管理员区分待完成启动。显式控制在串行等待和准入等待之后、取消排队启动之前、终止旧跟踪句柄之前，以及最终分配或热复用交接之前检查当前权限。

[PostgreSQL 仓库](../../../../gateway/src/postgres/instance-repository.ts)将当前组织、账号和管理员成员关系锁保留至启动或停止意图提交。最终个人准入在同一管理员事务中读取当前所有者策略；分别检查会让其中一项在等待另一项时过期。SQLite 在立即事务中完成对应读写。资源或 supervisor 等待前释放数据库连接与权限锁。

生命周期控制使用 `markControlStopping` 或用途为 `control` 的停止租约，允许管理员在没有数据资格时停止和重启保留的 Steward Runtime。精确控制保留所选代次、本地节点、Gateway 进程所有者和持久停止操作；省略租约用途时仍为 `destructive`，保留对保留项目的保护。[破坏性操作规则](2026-10-28-project-deletion-lifecycle.zh.md)保持独立。受信任的内部生命周期调用可以省略管理员；适配器保留传入的 id。当前个人进程权限仍遵循[所有者策略决策](2026-10-28-personal-runtime-authority.zh.md)。

撤权会拒绝尚未获准的工作。后续权限检查失败时，已经获准的取消或停止可能已经完成。尤其是重启可能在停止后返回403，此时 Runtime 必须保持停止。准入授权不是持续执行租约；之后的撤权仍要求失效通知和停止收敛。

终端和插件管理在签发 Runtime 请求、发布数据之前复核当前管理员角色和账号资格。终端清单与插件普通响应在代次检查、操作租约清理完成前保持私有。插件流在每个转发片段之前检查权限：首个片段前撤权返回403，已发布获准进度后撤权则中断现有流。期望状态、概览与目标读取也在数据加载后复核权限。这些检查不会撤销已获准的终端关闭或插件操作；客户端重试前先检查当前状态。

PostgreSQL 用户读取联合当前组织、成员关系和账号给出有效状态。组织不可用时，其账号不再具有资格，但不覆盖账号存储状态。恢复组织仍保留独立停用的账号和成员关系。管理响应授权使用该有效状态，不能仅信任仍为 active 的账号记录。

有界 PostgreSQL 取连接拒绝返回503，保留可读 `error` 及 `code: DB_CHECKOUT_QUEUE_FULL`。失败请求审计记录该状态。客户端先重新加载当前状态，再决定是否重试；响应不保证多阶段操作的所有先前阶段都已回滚。[连接准入决策](../architecture/2026-10-23-postgres-checkout-admission.zh.md)负责容量计数。

## 考虑过的替代方案

**在请求结束前始终信任认证结果。** 当前权限可能在后续等待期间改变。

**共享同一目标的所有待完成启动。** 不同发起管理员的权限可以独立撤销。

**在监督操作期间保持管理员锁。** 资源等待和进程控制可能很长，不能占用数据库连接或阻止账号撤权。

**普通停止也使用破坏性权限。** 控制保留 Runtime 不代表可以删除其项目或文件。

## 影响

自定义实例仓库实现当前管理员准入、独立的控制停止方法和可选的 `acquireStopLease` 用途。只有进程控制回调选择 `control`；修改数据的工作保留默认 `destructive` 用途。启动占用和最终个人策略读取保留传入发起者的权限。显式控制服务适配器向重启的两个阶段传递发起者。账号管理权限、电脑使用权和执行授权仍是独立要求。

## 验证

确定性回归在真实 PostgreSQL 锁和生命周期屏障之后撤销角色、账号、成员关系和组织。可运行 Gateway 记录覆盖两个存储、个人和项目控制、真实 LocalLauncher 进程、重启后期撤权、可读容量拒绝及失败请求审计。独立管理员启动、最终所有者与发起者联合准入以及旧句柄保留另行检查。这些验证无需模型 API。

[管理响应记录](../../../../gateway/tests/fixtures/administrator-rpc-withdrawal.mjs)使用真实 PostgreSQL 身份、浏览器认证、Runtime 凭据及当前 Runtime 准入，再撤销操作员角色或停用组织。另一账号的终端和插件元数据保持私有；已获准的流在后续私有数据到达前中断；当前管理员能收到正常响应，操作引用归零。夹具拥有回环 HTTP Runtime，不证明原生进程隔离。

[保留 Runtime 实录](../../../../gateway/tests/fixtures/central-runtime-control.mjs) 通过真实 PostgreSQL 和自有 HTTP 响应覆盖已认证的精确停止与重启、过期代次、获准停止后的管理员撤权及项目字节保留。回环载体证明实际响应已清理；不验证原生进程限制。

[项目设置实录](../../../../gateway/tests/fixtures/administrator-settings-start.ts)通过浏览器认证与 PostgreSQL 覆盖真实本地进程分配前的六种已提交资格撤销、当前及恢复权限的管理员、热复用和手动停止拒绝。该原生验证使用 macOS；Linux 账号准备和 Windows 监督仍需单独验证。
