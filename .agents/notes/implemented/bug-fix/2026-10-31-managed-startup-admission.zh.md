# Agent Note：托管启动准入

Status: implemented

[English](2026-10-31-managed-startup-admission.md) | 中文

## 问题

托管模型、资源和执行要求由 Gateway 运行时提供方发布。启动副作用可能在该提供方激活前，或首次凭据读取失败后运行，并将缺少策略服务解释为独立执行。

## 决策

CLI 从不可变启动快照读取继承的 Gateway 凭据通道标记，在 SDK 引导和 profile 条目挂载前，将三项要求发布到应用根。标记只施加要求，不会认证身份或授予权限。环境文件中的标记不能选择此模式。独立启动保留可选提供方。根持有的 effect 在提供方重载期间保留这些要求，并在应用关闭时移除。

## 曾考虑的替代方案

**等待 Gateway 提供方发布要求。** 提供方缺席正是必须拒绝启动副作用的条件。

**让所有独立 profile 都要求托管服务。** 独立组合可以合法省略这些提供方。

**在每个消费者中读取可变进程变量。** 每个消费者必须观察同一个继承启动决策；用户和项目文件不能建立该决策。

## 影响

缺少提供方的托管 profile 会通过现有服务检查拒绝模型分发、子进程分配和执行授权。真实公开 CLI 回放验证两种凭据通道形式，在 SDK 引导前要求标记已发布，并观察到没有假模型分发或子进程文件创建。独立对照会分发假模型，并创建、等待退出和移除实际 Node 子进程。不会联系付费提供方。这建立了启动要求，不代表已完成所有直接资源集成。
