# Agent Note: SSH 启动失败仍持有每次流分配

Status: implemented

[English](2026-10-31-ssh-partial-stream-allocation.md) | 中文

## 问题

并行流分配失败时，其他尝试仍可能持有原生转发控制命令。仅在 `Promise.all()` 成功后保存套接字，会遗漏部分分配。远端终止可能先于本地启动清理得到确认，从而过早完成进程许可或提供方销毁。

## 决策

[SSH 子进程提供方](../../../../packages/ssh/subprocess-ssh/src/index.ts) 立即记录每个完成鉴权的套接字。启动失败会取消其他尝试，等待每次尝试及所有已分配套接字关闭，然后拒绝结果。启动尚未结束时，已确认的远端范围不代表观察完成。提供方销毁停止已成功启动的进程后，也会等待套接字关闭。

观察取消仍然有界。不完整的观察保留不确定记账；之后的确认可以完成原许可。终止错误仍通过范围观察保留，与原启动失败相互独立。

## 考虑过的替代方案

**仅保存成功的聚合结果。** 一路拒绝会丢弃已完成的套接字，并让清理在其他尝试仍运行时结束。

**把远端终止确认当作启动完成。** 本地转发子进程与套接字仍可能属于这次分配。

## 影响

启动失败保留原错误，并拒绝进程启动。传输清理先于请求准入完成结束。协议字段与辅助程序摘要保持不变。[准入所有权](2026-10-31-subprocess-admission-owner.zh.md)、[Host 转发回滚](2026-10-31-ssh-stream-forwarding-cancellation.zh.md) 与[辅助程序清理重试](2026-10-31-ssh-helper-cleanup-ownership.zh.md) 继续承担各自职责。

## 验证

公开提供方案例保持其他流的拒绝或延迟授予，以及套接字关闭待完成，检查结果、观察、销毁与原许可完成。[Loader 预期输出应用](../../../../packages/ssh/subprocess-ssh/tests/partial-stream-allocation.expected.e2e.ts) 在一路流失败后保留实际的原生转发控制进程，并在释放前观察所有权。无需模型 API。
