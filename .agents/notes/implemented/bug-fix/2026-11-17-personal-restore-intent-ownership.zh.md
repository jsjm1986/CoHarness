# Agent Note：个人恢复持有自己的准备输入框

Status: implemented

[English](2026-11-17-personal-restore-intent-ownership.md) | 中文

## 问题

浏览器刷新可能同时恢复已保存的个人 Session 和工作台布局。选择恢复后的窗格会取代导航，但不会发布用户已提交的选择。若只取消个人恢复的历史请求，其独立准备输入框仍处于活动状态，完成回调就可能在可用窗格上方发布不可用的输入框。

## 决策

[个人目录恢复](../../../../packages/client/runtime/src/client/personal-directory.ts) 为自己的确切对话意图持有取消订阅。导航被取代时仅撤下该输入框。空输入被丢弃；非空输入仍绑定原目标，等待明确重试。重试取得新的导航生命周期，同时保留原账号和页面生命周期并重新检查当前可用性。它不能接纳另一台电脑或后续账号。

恢复成功时，将文字转移给已验证的 Session 输入框，并在选择该 Session 前移除取消订阅。随后选择操作可以取代导航，而不会取消自身转移。目录所有者持有每个尚未完成的恢复 Promise 直至结束，包括与新重试重叠的已取消读取。视图取消与释放都不提交输入，也不取消 Host 任务。

选择优先级保持独立：已保存的个人选择可以取代更早的隐式选择，后续导航会取消正在进行的恢复，用户已提交的选择则阻止新的隐式恢复。同账号续约继续沿用[准备对话意图在续约期间保留](2026-11-08-pending-intents-survive-renewal.zh.md)中的行为。

## 考虑过的替代方案

**在工作台模式隐藏所有准备输入框。** 这会移除有效的新建对话输入，并掩盖归属丢失而非纠正问题。

**让所有隐式选择都保留之前的导航。** 窗格聚焦将不再取消较早的视图操作。修正恢复归属不需要改变共享导航 API。

**明确重试仍使用已取消的信号。** 文字仍可见，却永远无法到达原输入框。重试需要新的导航生命周期，同时保留捕获的目标和账号生命周期。

## 后果

取消与成功转移具有不同的归属变化。受控完成闸门覆盖个人优先和工作台优先恢复、空与非空文字、后续无关意图、重叠重试、原目标转移、窗格草稿不变，以及没有 prompt 或 cancel 请求。[双 Host 工作台浏览器场景](../../../../apps/web/tests/workbench-cross-runtime-drafts.e2e.ts) 验证完整客户端和 Host 持久消息；部署验收还检查真实电脑与发送控件。
