# Agent Note: 召回在发布前始终跟随已准入的问题

Status: implemented

[English](2026-11-01-memory-recall-authority.md) | 中文

## 问题

首次 pre-step 发生在 Gateway 消息准入之前。在此启动召回可能使用更早的参与者状态，在此捕获授权也会保留错误状态。独立选择器控制器还会在 `turn/end` 前遗漏主回合取消。响应和条目读取可能在签发方替换后结束。合法选择器 JSON 也可能伴随失败或中止终态到达。

## 决策

pre-step 保留问题、目录和回合信号。首次 `agent/request` 准入在下游监听器确认消息并解析路由后消费该准备。选择器在此捕获签发授权与参与者，在其 `runCaptured` 上下文中运行，并携带明确的计费依据。实例持有的异步上下文标识自己的 `llm/pre-dispatch` 检查，在容量准入后及实际请求发送前复核。无关请求没有选择器上下文。

召回要求当前 `execute` 权限，而不是记忆写入资格。它在异步工作后将当前服务的原始身份与捕获签发方比较，并在注入前重新检查执行权限和当前作用域。选择器信号包含主回合信号、独立设置取消和 Session 释放。插件卸载会等待自身清理结束后再释放异步上下文。失败或中止终态会丢弃选择结果，即使文本是合法 JSON。

本决策补充[实时记忆可用性](2026-10-31-memory-live-availability.zh.md)与[提供者通知](2026-11-01-memory-provider-availability.zh.md)。要求写入资格的后台整理仍遵循其[独立授权决策](2026-11-01-memory-curation-authority.zh.md)。

## 考虑过的替代方案

**在 pre-step 捕获。** Gateway 尚未正式接纳所领取的消息；不可变捕获仍可能证明错误的参与者集合。

**完成时使用当前浏览器连接或签发方。** 不同调用方或替代方可能借出不属于问题持有者的操作者。捕获签发方应在替换时拒绝工作。

**要求 memory 能力。** 该能力控制共享记忆写入。项目读者与私有会话可以在不具备写入资格时召回。

**等到 `turn/end` 才取消，或接受所有合法选择器 JSON。** 主回合取消可能早于流清理和回合结束。终态失败不能授权发布部分文本。

## 后果

召回使用已准入问题的身份和已解析路由，不阻塞其主请求。不增加模型许可、额度、用量格式或 Session 模式。请求事件顺序跟随消息准入。运行时消费者保留现有准备 API。memory-context 包直接声明 execution-authority 依赖。

非录制的 Gateway 执行检查位于示例自己的预期输出通道。被撤权的整理观察所捕获任务的实际拒绝并保留未完成游标，不再等待权限消失后的另一次模型调用。录制 Session 往返保留原快照通道。更大范围的 Gateway 与物理电脑验收仍未完成。

## 验证

反例复现未捕获身份、替换后注入、未取消的排队许可，以及从失败或中止 JSON 响应注入。真实 GatewayExecution 与 Agent 循环在记忆写入权限被拒绝时，观察选择器发送和注入所使用的已准入参与者。完整私有前版本选择器在相同 Gateway 场景中失败。容量、待完成存储、请求取消、服务捕获失败和作用域撤回都有专项测试；既有设置、整理与录制 Session 场景继续提供回归覆盖。
